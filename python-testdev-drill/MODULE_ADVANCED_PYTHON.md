# Module: Python高阶编程

## 1. decorator_essence
**题目：** 装饰器是什么？它的本质是什么？
**标签：** Python高阶编程、装饰器、闭包
**难度：** medium
**频率：** 高频
**参考答案：**
装饰器本质上是一个接收函数并返回新函数的高阶函数，作用是在不修改原函数源码的前提下，为函数动态添加额外能力。常见用途包括日志、权限校验、缓存、重试、性能统计。`@decorator` 本质上等价于 `func = decorator(func)`。很多装饰器实现同时会利用闭包保存原函数引用。

## 2. closure_essence
**题目：** 什么是闭包？闭包形成的条件是什么？
**标签：** Python高阶编程、闭包、作用域
**难度：** medium
**频率：** 高频
**参考答案：**
闭包可以理解为“内部函数引用了外部函数作用域中的变量，并且外部函数已经执行结束，但这个变量仍然被保留下来”。形成闭包通常有三个条件：有嵌套函数、内部函数引用外部变量、外部函数返回内部函数或让内部函数在外部继续被使用。闭包常用于延迟执行、封装状态、实现装饰器。

## 3. iterator_vs_generator
**题目：** 迭代器和生成器有什么区别？
**标签：** Python高阶编程、迭代器、生成器
**难度：** medium
**频率：** 高频
**参考答案：**
迭代器是实现了迭代器协议的对象，核心是 `__iter__()` 和 `__next__()`；生成器是创建迭代器的一种更简洁方式，通常通过 `yield` 定义。生成器本质上也是迭代器，但不用手动实现 `__next__()`，写法更自然，且惰性求值、节省内存。

## 4. context_manager
**题目：** 什么是上下文管理器？`with` 语句背后的原理是什么？
**标签：** Python高阶编程、with、上下文管理器
**难度：** medium
**频率：** 高频
**参考答案：**
上下文管理器用于统一管理资源的进入和退出，比如文件、锁、数据库连接。`with` 背后依赖的是对象实现 `__enter__()` 和 `__exit__()` 方法。进入 `with` 时会调用 `__enter__()`，退出时不管是否异常都会调用 `__exit__()`。它的核心价值是让资源获取和释放更安全、更清晰。

## 5. mutable_default_param
**题目：** 可变类型默认参数为什么容易出问题？怎么规避？
**标签：** Python高阶编程、默认参数、函数
**难度：** medium
**频率：** 高频
**参考答案：**
因为函数默认参数在函数定义时只初始化一次，如果默认值是列表、字典这类可变对象，多次调用会共享同一份对象，导致状态污染。常见规避方式是把默认值设为 `None`，在函数体里再判断并初始化新对象。这是 Python 面试里非常经典的坑点。

## 6. shallow_vs_deep_copy
**题目：** 深拷贝和浅拷贝的核心区别是什么？
**标签：** Python高阶编程、拷贝、对象模型
**难度：** medium
**频率：** 高频
**参考答案：**
浅拷贝只复制最外层对象，内部嵌套对象仍然共享引用；深拷贝会递归复制内部对象，得到完全独立的新对象。对于只有一层的简单对象，两者差异不明显；一旦有嵌套列表、字典，自然就会体现出修改联动与否的区别。

## 7. new_vs_init
**题目：** `__new__` 和 `__init__` 有什么区别？
**标签：** Python高阶编程、面向对象、对象创建
**难度：** medium
**频率：** 高频
**参考答案：**
`__new__` 负责创建对象实例，返回的是实例本身；`__init__` 负责初始化这个实例。调用顺序上先 `__new__`，后 `__init__`。大多数业务代码只重写 `__init__`；只有在控制实例创建过程，比如单例、不可变对象子类化时，才更常见重写 `__new__`。

## 8. super_and_mro
**题目：** `super()` 的作用是什么？MRO 又是什么？
**标签：** Python高阶编程、super、多继承
**难度：** medium
**频率：** 高频
**参考答案：**
`super()` 用来按照 MRO（方法解析顺序）去查找父类或下一个类的方法，而不是简单地“找直接父类”。MRO 是 Python 在多继承场景下确定方法查找顺序的一套规则。理解 `super()` 不能只停留在“调用父类方法”，更准确地说，是按 MRO 链继续往后找。

## 12. gil_threads_processes
**题目：** GIL 是什么？它对 Python 线程、进程、协程的理解有什么影响？
**标签：** Python高阶编程、GIL、并发
**难度：** medium
**频率：** 中高频
**参考答案：**
GIL 是 CPython 解释器中的全局解释器锁，同一时刻通常只允许一个线程执行 Python 字节码。它意味着 CPU 密集型任务里，多线程未必能提升性能；这类场景更常考虑多进程。对于 IO 密集型任务，多线程仍然有价值。协程不是靠多核并行，而是通过事件循环在单线程里高效切换等待任务。

## 13. len_dunder

**难度：** easy
**频率：** 中高频
**参考答案：**

## 14. getitem_dunder
**题目：** __getitem__ 有什么用？
**标签：** Python高阶编程、魔术方法、容器协议
**难度：** easy
**频率：** 中高频
**参考答案：**
定义 __getitem__ 后对象就支持方括号取值：obj[key] 会调用它。两个连带效果常被面试官追问：一是没有定义 __iter__ 时，for 循环会退化到不断 __getitem__(0)、__getitem__(1)…直到 IndexError，所以只写 __getitem__ 对象也是可迭代的；二是配合切片语法，key 会是 slice 对象，自己实现序列类时要处理。测试场景里给测试数据容器加 __getitem__，用例里 data["login"] 取数据就很自然。

## 15. setitem_dunder
**题目：** __setitem__ 是干什么的？
**标签：** Python高阶编程、魔术方法、容器协议
**难度：** easy
**频率：** 中高频
**参考答案：**
和 __getitem__ 一对：__getitem__ 管 obj[key] 读，__setitem__ 管 obj[key] = value 写。典型用途是让自定义类表现得像 dict，比如写一个大小写不敏感的配置对象 CiDict，__setitem__ 里统一 lower() 再存，__getitem__ 里同样 lower() 再取，外面用起来和普通字典一模一样。回答时把它和 __getitem__、__len__ 一起说成「容器协议三件套」，结构感更好。

## 16. call_dunder
**题目：** __call__ 是什么？实例化还是调用？
**标签：** Python高阶编程、魔术方法、可调用对象
**难度：** medium
**频率：** 中高频
**参考答案：**
定义了 __call__ 的实例可以像函数一样被调用：obj() 会走 __call__。注意区分：MyClass() 走的是 __init__/__new__（实例化），instance() 走的才是 __call__（调用）。它适合「带状态的函数」——比如一个 RetryPolicy 对象，内部记着已重试次数，每次 policy() 执行时先判断次数。装饰器类也是靠它：类形式的装饰器，被装饰函数替换成实例，调用实例时进 __call__。一句话：__call__ 让对象「实例可调用」，和「类可实例化」是两回事。

## 17. iter_next_dunder
**题目：** __iter__ 和 __next__ 分别做什么？怎么让自定义类可迭代？
**标签：** Python高阶编程、迭代器协议
**难度：** medium
**频率：** 中高频
**参考答案：**
两个方法分工明确：__iter__ 返回迭代器对象，__next__ 由迭代器实现、每次返回一个值并在耗尽时抛 StopIteration。让类可迭代的标准写法是 __iter__ 里 return self，类自己同时实现 __next__——简单场景够用；更规范的是可迭代对象和迭代器分开两个类。要能主动说出区别：iter(obj) 调 __iter__，next(it) 调 __next__，for 循环内部就是这两步的封装，还要捕 StopIteration 收尾。

## 18. generator_vs_iterator
**题目：** 生成器和迭代器是什么关系？
**标签：** Python高阶编程、生成器、迭代器
**难度：** medium
**频率：** 高频
**参考答案：**
关系一句话：生成器是迭代器的一种，是「自动帮你实现 __iter__ 和 __next__」的迭代器。普通迭代器要手写两个方法、自己维护状态、自己抛 StopIteration；生成器只要函数里写 yield，状态保存、StopIteration、惰性求值全部自动完成。验证：生成器对象 hasattr __iter__ 和 __next__ 都是 True。区别记忆点：迭代器是协议（接口），生成器是实现该协议的最省事方式。加分项：yield from 委托子生成器、生成器表达式 (x*x for x in data) 也是生成器。

## 19. yield_vs_return
**题目：** yield 和 return 有什么区别？
**标签：** Python高阶编程、生成器
**难度：** medium
**频率：** 高频
**参考答案：**
三点核心区别。执行行为：return 一次性结束函数；yield 是「暂停」，交出一个值后冻结现场，下次 next() 从断点继续执行，局部变量原样保留。返回值：含 yield 的函数调用时不执行任何代码，返回的是生成器对象，不是结果。用途：return 用于普通函数直接拿结果，yield 用于生产数据流（惰性、省内存）。写法上注意生成器里也能写 return，它的作用是提前终止，return 的值会成为 StopIteration 的参数、一般忽略。记忆口诀：return 一去不回头，yield 暂停还能回来。

## 20. closure_keeps_outer_scope
**题目：** 闭包是怎么"记住"外层变量的？
**标签：** Python高阶编程、闭包
**难度：** medium
**频率：** 中高频
**参考答案：**
原理靠 __closure__ 属性：内层函数对象会把它引用到的外层变量打包成 cell 对象存在自己身上，所以外层函数就算已经返回销毁，这些变量依然活着。要点是「引用才捕获」——内层函数用到哪个外层变量，哪个进闭包，没用到的不带。查看方式：func.__closure__ 和 cell.cell_contents。典型应用就是装饰器：装饰器内层 wrapper 捕获了 func，所以装饰器返回后 func 不会丢。陷阱：循环里建闭包要小心 late binding，lambda 默认参数 `lambda i=i: i` 是经典解法。

## 21. nonlocal_vs_global
**题目：** nonlocal 和 global 的区别？
**标签：** Python高阶编程、作用域
**难度：** medium
**频率：** 中高频
**参考答案：**
两个都是「函数里要给外层变量赋值」时的声明，区别在往外找几层。global 声明变量指向模块全局作用域，无论嵌套多深；nonlocal 只往上找最近一层外层函数的作用域，跳过全局。注意它们只在「赋值/修改绑定」时需要——只是读取外层变量不用声明，Python 按 LEGB 自己往外找。典型场景：闭包计数器 counter 里 count += 1 必须写 nonlocal count，否则 Python 把 count 当局部变量先引用后赋值直接报 UnboundLocalError。一句话：global 到顶，nonlocal 只上一层。

## 22. decorator_essence_review
**题目：** 复习：一句话说清装饰器的本质。
**标签：** Python高阶编程、装饰器
**难度：** medium
**频率：** 高频
**参考答案：**
装饰器本质是一个「接收函数、返回新函数」的高等函数，@deco 只是 `f = deco(f)` 的语法糖。两层结构：外层收被装饰函数，内层 wrapper 收调用参数，wrapper 里做增强逻辑再调原函数。三个必须带出的点：一是 @deco 在函数定义时立刻执行（不是调用时）；二是 functools.wraps(func) 保元信息；三是带参数装饰器再加一层变三层。面试官听到「语法糖 + 函数替换」这个表述，就知道你是真理解而不是背模板。

## 23. iterable_vs_iterator
**题目：** 可迭代对象和迭代器有什么区别？
**标签：** Python高阶编程、迭代协议
**难度：** medium
**频率：** 高频
**参考答案：**
标准：iterable 是实现了 __iter__ 的对象（能进 for 循环），iterator 是同时实现 __iter__ 和 __next__ 的对象（能被 next() 推进）。关键区别一条：iterable 可以反复迭代（list 每次 for 都从头来，因为 iter() 会造新迭代器），iterator 是一次性的，耗尽就空了。转换关系：iter(x) 把 iterable 变成 iterator。自测代码张口就来：`iter([1,2])` 每次给新迭代器，同一个迭代器 for 完再 for 就是空的。陷阱题：把生成器当 list 用两次，第二次循环为空——就考这一条。

## 24. for_loop_iterator_protocol
**题目：** for 循环底层是怎么执行的？
**标签：** Python高阶编程、迭代协议
**难度：** medium
**频率：** 中高频
**参考答案：**
for x in obj 底层四步：第一步调 iter(obj) 拿迭代器；第二步循环调 next(it) 取下一个值；第三步把值给 x、执行循环体；第四步 next 抛 StopIteration 时捕获异常、正常结束循环。等价的 while 写法能背出来最好：`it = iter(obj); while True: try: x = next(it) except StopIteration: break`。两个推论常考：自定义类只写 __getitem__ 也能被 for（退化成旧序列协议）；StopIteration 必须在 __next__ 里抛而不是 return，否则 for 收不到结束信号。

## 25. lazy_iteration
**题目：** 什么是惰性求值/惰性迭代？有什么好处？
**标签：** Python高阶编程、惰性求值
**难度：** medium
**频率：** 中高频
**参考答案：**
惰性求值就是「数据用到才算、要多少算多少」，不是先把全部结果准备好。Python 里的代表：生成器、生成器表达式、map/filter（3.x 返回迭代器）、range、文件对象逐行读。好处三个：内存省（处理 10G 日志不用一次读进内存）、启动快（不用先算完才能开始处理）、能表达无限序列（itertools.count）。代价也要说：迭代器只能消费一次、不方便随机访问、调试时中间状态不好看。测试场景直接对口：逐行解析大日志文件、流式处理接口返回的海量数据。

## 26. generator_function_vs_normal_function
**题目：** 生成器函数和普通函数在行为上有什么不同？
**标签：** Python高阶编程、生成器
**难度：** medium
**频率：** 中高频
**参考答案：**
三点不同。调用时：普通函数立刻执行到 return；生成器函数（体内有 yield）调用时一行都不执行，只返回生成器对象，代码在 next() 时才推进。执行完：普通函数结束就没了；生成器每次 yield 暂停、可以多次恢复。返回值：普通函数返回 return 后面的值；生成器返回生成器对象，函数体里所有 yield 的值依次产出。调试小技巧：生成器对象只创建不消费的话，函数体永远不会执行——这是排查「生成器里代码没跑」问题的第一反应。

## 27. why_generator_save_memory
**题目：** 为什么生成器省内存？省在哪里？
**标签：** Python高阶编程、生成器、内存
**难度：** medium
**频率：** 高频
**参考答案：**
省在「不同时持有全部数据」。列表推导式 [x*x for x in range(10_000_000)] 立刻把一千万个结果全造出来放进一个列表，内存按结果总量算；生成器表达式 (x*x for x in ...) 只是记录「怎么算」，每 next 一次算一个、用完即可被回收，任意时刻内存里只有一个元素。用 sys.getsizeof 对比：列表几十 MB，生成器对象恒定两百字节左右。适用边界要会补一句：如果后面要反复使用、随机访问这批数据，还是老老实实建列表，惰性只赢在「一次流式消费」。

## 28. when_prefer_generator
**题目：** 什么场景优先用生成器？
**标签：** Python高阶编程、生成器、工程实践
**难度：** medium
**频率：** 中高频
**参考答案：**
判断标准一条：数据「流式、一次性消费」就用生成器。典型场景四类：大文件逐行处理（日志分析）、无限/超长序列（自然数、分页拉接口）、管道式多步处理（读→过滤→转换，每步生成器串起来，不需要中间大列表）、协程/yield 交接控制流。反面场景也说得出加分：需要随机访问、需要 len()、要用两次、结果很小——这些直接用列表。面试可以举例：接口测试逐条校验百万级返回数据，生成器管道方案内存稳定，列表方案直接 OOM。

## 29. gil_what_is_it
**题目：** GIL 到底是什么？为什么要有它？
**标签：** Python高阶编程、GIL、并发
**难度：** medium
**频率：** 高频
**参考答案：**
GIL 是 CPython 里的全局解释器锁：同一进程内任意时刻只允许一个线程执行 Python 字节码，多线程在 CPU 计算层面是串行的。存在的原因是历史设计：CPython 的内存管理（引用计数）不是线程安全的，用一把全局锁保护最简单，加细粒度锁会让单线程性能大幅下降。要点三个：一是它只锁 Python 字节码执行，IO 等待时会释放锁（所以 IO 多线程仍有效）；二是它是 CPython 实现的选择，Jython/IronPython 没有，Python 3.13 的 free-threaded 实验版也在尝试去掉它；三是它不是「Python 语言的缺陷」而是实现的取舍。

## 30. why_gil_less_affects_io
**题目：** 为什么 GIL 对 IO 密集型任务影响小？
**标签：** Python高阶编程、GIL、IO
**难度：** medium
**频率：** 高频
**参考答案：**
关键机制：线程进入 IO 等待（网络请求、读写文件、sleep）时会主动释放 GIL，其他线程立刻拿锁执行 Python 代码。所以 IO 密集场景里，GIL 只在「处理结果的那一小段 CPU 时间」生效，大部分时间（等待网络/磁盘）线程们是真正并行的——一个线程等响应时，别的线程在跑。验证思路：开 10 个线程各请求一次接口，总耗时远小于串行相加。对比着记：CPU 密集任务线程不释放锁、又不能多核并行，多线程完全无用武之地，这就是「IO 用线程、CPU 用进程」的由来。

## 31. cpu_bound_why_multiprocessing
**题目：** CPU 密集型任务为什么用多进程而不是多线程？
**标签：** Python高阶编程、并发、多进程
**难度：** medium
**频率：** 高频
**参考答案：**
因为多进程绕开了 GIL：每个进程有独立的解释器和自己的 GIL，能真正跑在多个 CPU 核上并行；多线程在一个进程里抢同一把 GIL，CPU 密集场景下不仅不加速，还多了线程切换开销，可能更慢。代价也要说全：进程重——创建/切换开销大、内存独立需要 IPC（pickle 序列化传数据）、全局状态不共享。用法上 multiprocessing.Pool 的 map 和 ProcessPoolExecutor 是最常用封装。测试场景举例：并行跑数据比对、本地大文件哈希计算。收尾口径：CPU 密集 → 多进程或换 C 扩展/numpy；IO 密集 → 多线程或异步。

## 32. thread_process_coroutine_how_to_choose
**题目：** 线程、进程、协程怎么选？
**标签：** Python高阶编程、并发选型
**难度：** medium
**频率：** 高频
**参考答案：**
选型一条主轴：看任务是 CPU 密集还是 IO 密集，再看并发量级。CPU 密集 → multiprocessing 多进程（绕开 GIL 多核并行）；IO 密集、并发量中等（几百以内）→ threading 多线程（IO 时释放 GIL，写法简单）；IO 密集、并发量大（成千上万连接）→ asyncio 协程（单线程事件循环调度，切换成本远低于线程，但要全程 async/await 生态配合）。混合负载可以组合：进程池 + 每个进程里跑事件循环。面试加分：说明协程是「协作式调度、主动 yield」，线程是「抢占式调度」，所以协程怕阻塞调用——一个同步阻塞调用会把整个事件循环卡死。

## 33. why_coroutine_good_for_high_concurrency_io
**题目：** 协程为什么适合高并发 IO？
**标签：** Python高阶编程、协程、异步
**难度：** medium
**频率：** 高频
**参考答案：**
两个成本优势。第一，调度成本：协程切换是用户态函数级别的（保存恢复几个寄存器），纳秒级；线程切换要陷入内核、保存线程上下文，微秒级，差两三个数量级，所以单机能挂几万协程但几千线程就很吃力。第二，内存成本：协程栈 KB 级、线程栈默认 MB 级。协程模式的关键是事件循环：单线程不断轮询就绪的 IO 事件，谁就绪恢复谁，等待期间零开销。适用前提必须强调：必须全链路异步库（aiohttp/asyncpg），混进一个同步阻塞调用整个循环全卡死。测试场景举例：aiohttp + asyncio 并发压几千个接口，比线程池省资源得多。

## 34. coroutine_vs_thread_core_difference
**题目：** 协程和线程的核心区别是什么？
**标签：** Python高阶编程、协程、线程
**难度：** medium
**频率：** 高频
**参考答案：**
核心区别一句话：调度方不同——线程由操作系统内核抢占式调度，你控制不了切换时机；协程由用户程序协作式调度，只在代码里 await/yield 的点主动让出，切换点完全可预期。由此带来三个推论：一是协程切换不进内核、成本极低；二是协程天然无并发竞争——两个 await 之间的代码不会被打断，很多场景不需要锁（但 await 点仍是数据不一致的隐患，要会举反例）；三是协程不利用多核（单线程事件循环），CPU 并行还是要靠多进程。收尾对比表记法：线程=内核抢跑+贵+要锁，协程=自己让路+便宜+怕阻塞。
