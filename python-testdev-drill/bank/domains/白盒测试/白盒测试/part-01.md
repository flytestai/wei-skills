## Q007105

- 题型：简答
- 难度：入门

**题目**

```text
什么是白盒测试?
```

**答案**

```text
白盒测试又称结构测试、透明盒测试、逻辑驱动测试或基于代码的测试。白盒测试是一种测试用例设计方法，盒子指的是被测试的软件，白盒指的是盒子是可视的，即清楚盒子内部的东西以及里面是如何运作的。"白盒"法全面了解程序内部逻辑结构、对所有逻辑路径进行测试。"白盒"法是穷举路径测试。在使用这一方案时，测试者必须检查程序的内部结构，从检查程序的逻辑着手，得出测试数据。贯穿程序的独立路径数是天文数字
```

**解析**

```text
【核心考点】 白盒测试 测试分类
【题目解析】
本题考查白盒测试的基本概念。白盒测试又称结构测试、透明盒测试，关注程序内部逻辑结构，通过检查代码路径来设计测试用例。与黑盒测试不同，白盒测试需要了解代码实现。
【参考答案要点】
1. 定义：白盒测试是基于程序内部结构和逻辑的测试方法，测试者需了解代码实现。
2. 别名：结构测试、逻辑驱动测试、基于代码的测试。
3. 特点：穷举路径测试，但实际路径数可能巨大，需结合覆盖标准（如语句覆盖、分支覆盖）。
【面试角度】
回答时建议对比黑盒测试，说明两者区别和适用场景。同时提及常用覆盖准则，如语句覆盖、判定覆盖、条件覆盖等，展示深度。
【易错提示】
注意白盒测试并非完全穷举，而是通过覆盖准则选择路径。面试中常混淆白盒测试与单元测试的关系，白盒测试是方法，单元测试是阶段。
```

## Q007090

- 题型：简答
- 难度：简单

**题目**

```text
__是选择若干个测试用例，运行被测程序，使得程序中的每个可执行语句至少执行一次。选项：A 条件覆盖 B 组合覆盖 C 判定覆盖 D 语句覆盖
```

**答案**

```text
D
```

**解析**

```text
【核心考点】 白盒测试 逻辑覆盖
【题目解析】
本题考察白盒测试中逻辑覆盖方法的定义。题目描述“每个可执行语句至少执行一次”是语句覆盖（Statement Coverage）的典型定义。语句覆盖是最基本的覆盖准则，要求覆盖所有语句。
【选项解析】
✗ A. 条件覆盖 — 错误。条件覆盖要求每个条件的真/假至少执行一次，而非语句。
✗ B. 组合覆盖 — 错误。组合覆盖（多条件覆盖）要求所有条件组合至少执行一次。
✗ C. 判定覆盖 — 错误。判定覆盖要求每个判定的真/假分支至少执行一次。
✓ D. 语句覆盖 — 正确。符合题目描述。
【易错提示】
语句覆盖是最弱的覆盖准则，常与判定覆盖、条件覆盖混淆。面试中需牢记各覆盖的定义和强弱关系。
```

## Q007153

- 题型：单选
- 难度：中等

**题目**

```text
白盒测试的“条件覆盖”标准强于“判定覆盖”。
```

**选项**

```text
A. 对
B. 错
```

**答案**

```text
B
```

**正确选项**

```text
B. 错
```

**解析**

```text
【核心考点】 白盒测试 逻辑覆盖
【题目解析】
本题考查白盒测试中逻辑覆盖标准的强弱关系。条件覆盖要求每个条件的真/假至少执行一次，判定覆盖要求每个判定的真/假至少执行一次。条件覆盖不一定强于判定覆盖，因为条件覆盖可能不覆盖所有判定结果，反之亦然。因此，两者没有绝对的强弱关系，题目说法错误。
【选项解析】
✗ A. 对 — 错误。条件覆盖和判定覆盖是不同维度的覆盖标准，不能简单比较强弱。条件覆盖可能遗漏某些判定分支，判定覆盖也可能遗漏某些条件组合。
✓ B. 错 — 正确。条件覆盖并不总是强于判定覆盖，两者是互补关系，实际测试中常结合使用。
【易错提示】
常见误区：认为条件覆盖覆盖了所有条件，就一定覆盖了所有判定。实际上，条件覆盖可能只覆盖部分判定结果，例如判定为“A and B”，条件覆盖只测试A真B假和A假B真，但判定结果均为假，未覆盖判定为真的情况。
```

```text
（3）条件覆盖
（4）条件判定组合覆盖

```

**解析**

```text
【核心考点】 白盒测试 逻辑覆盖 覆盖率
【题目解析】
本题考查白盒测试中逻辑覆盖方法的分类。逻辑覆盖是白盒测试的基础，通过设计测试用例来覆盖程序中的逻辑结构。题目要求列出8种覆盖方法，但需要注意的是，不同教材对覆盖方法的分类和命名可能略有差异，例如“多条件覆盖”有时也被称为“条件组合覆盖”。

7. 组合覆盖：通常指条件组合覆盖，与多条件覆盖类似。
8. 路径覆盖：程序中所有可能的路径至少执行一次。
【面试角度】
回答此类问题时，建议结合实际项目经历举例说明，例如“在关键模块的单元测试中，我们要求达到语句覆盖和判定覆盖，对核心算法则要求路径覆盖”，能有效提升答案深度。
【延伸知识】
```

## Q007169

- 题型：简答
- 难度：中等

**题目**

```text
采用白盒测试法设计测试用例时，常用的逻辑覆盖测试方法有哪几种？请简单描述各种方法的目的。
```

**答案**

```text
目前比较常用的逻辑覆盖测试方法有：
语句覆盖、判定覆盖（分支覆盖）、条件覆盖、判定/条件覆盖、组合覆盖和路径覆盖。
（1）语句覆盖的目的是选择足够多的测试用例，使程序中的每个可执行语句至少执行一次。
（2）判定覆盖的目的是通过执行足够的测试用例，使得程序中的每个判定至少都获得一次“真”值和“假”值，也就是使程序中的每个取“真”分支和取“假”分支至少均经历一次。
（3）条件覆盖的目的是设计若干测试用例，在执行被测程序以后，要使每个判定中每个条件的可能值至少满足一次。
（4）判定/条件覆盖的目的是设计足够的测试用例，使得判定中每个条件的所有取值（真/假）至少出现一次，并且每个判定本身的所有判定结果（真/假）也至少出现一次。
（5）组合覆盖的目的是通过执行足够的测试用例，使得每个判定中条件的各种可能都至少出现一次。 （6）路径覆盖的目的是设计足够多的测试用例，要求覆盖程序中所有可能的路径。
```

**解析**

```text
【核心考点】 白盒测试 逻辑覆盖
【题目解析】
白盒测试中的逻辑覆盖方法用于衡量测试用例对程序逻辑结构的覆盖程度，常见方法包括语句覆盖、判定覆盖、条件覆盖、判定/条件覆盖、组合覆盖和路径覆盖。
【参考答案要点】
1. 语句覆盖：使程序中每个可执行语句至少执行一次。
2. 判定覆盖（分支覆盖）：使每个判定的真值和假值至少各出现一次。
3. 条件覆盖：使每个判定中每个条件的可能取值（真/假）至少出现一次。
4. 判定/条件覆盖：同时满足判定覆盖和条件覆盖。
5. 组合覆盖：使每个判定中所有条件取值的组合至少出现一次。
```

## Q007112

- 题型：简答
- 难度：较难

**题目**

```text
分析归纳逻辑覆盖的各种策略，并比较每种覆盖的特点，分析在怎样的情况下采用何种覆盖方式。
```

**答案**

```text
语句覆盖是选择足够多的测试数据，使被测程序中每个语句至少执行一次。语句覆盖是最弱的逻辑覆盖标准。
判定覆盖又叫分支覆盖，它不仅每个语句必须至少执行一次，而且每个判定表达式的每种可能的结果都应该至少执行一次。
判定条件覆盖比语句覆盖强，但是对程序逻辑的覆盖程度仍然不高。 条件覆盖的含义是，使判定表达式中的每个条件都取到各种可能的结果。
条件覆盖通常比判定覆盖强，但是也可能有相反的情况：虽然每个条件都取到了两个不同的结果，判定表达式却始终只取一个值。
判定/条件覆盖的含义是，选取足够多的测试数据，使得判定表达式中的每个条件都取到各种可能的值，而且每个判定表达式也都取到各种可能的结果。
但有时判定/条件覆盖也并不比条件覆盖更强。 条件组合覆盖是更强的逻辑覆盖标准，它要求选取足够的测试数据，使得每个判定表达式中条件的各种可能组合都至少出现一次。
满足条件组合覆盖标准的测试数据，也一定满足判定覆盖、条件覆盖和判定/条件覆盖标准。因此，条件组合覆盖是前述几种覆盖标准中最强的。
但是，满足条件组合覆盖标准的测试数据并不一定能使程序中的每一条路径都执行到。 路径覆盖的定义是选取足够多测试数据，使程序的每一条可能路径都至少执行一次。
但在实际问题中，一个不太复杂的程序，其路径数都可能是一个庞大的数字，以致要在测试中覆盖所有的路径是不可能实现的。
即使对于路径数有限的程序做到了路径覆盖，也不能保证被测程序的正确性。
```

**解析**

```text
【核心考点】 逻辑覆盖 白盒测试
【参考答案要点】
1. 语句覆盖：每个语句至少执行一次。最弱覆盖，不能保证判定条件正确。
2. 判定覆盖（分支覆盖）：每个判定的真/假分支至少执行一次。比语句覆盖强，但可能遗漏条件组合。
3. 条件覆盖：每个条件取真和假至少一次。可能比判定覆盖强，但有时判定结果未覆盖全。
4. 判定/条件覆盖：同时满足判定覆盖和条件覆盖。但可能忽略条件组合。
5. 条件组合覆盖：所有条件组合至少一次。覆盖最强，但用例数指数增长。
6. 路径覆盖：所有可能路径至少一次。理论上最强，但实际不可行（循环导致无限路径）。
选择策略：
- 语句覆盖：用于快速冒烟测试。
- 判定覆盖：用于简单逻辑模块。
- 条件组合覆盖：用于关键安全系统，如航空、医疗。
- 路径覆盖：用于复杂算法，但需结合循环简化。
【面试角度】
回答时，建议结合实际项目案例说明覆盖选择，例如“在支付模块中，我们使用判定/条件覆盖确保所有分支正确”，能体现深度。
【延伸知识】
MC/DC（修改条件/判定覆盖）是航空标准DO-178C要求的覆盖，比条件组合覆盖更高效，常用于高安全性系统。
```
