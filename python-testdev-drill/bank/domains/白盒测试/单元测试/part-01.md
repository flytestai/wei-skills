
**答案**

```text

```

**解析**

```text
【核心考点】 单元测试 桩模块
【参考答案要点】
桩模块（Stub）是在进行单元测试时所设置的一种辅助测试模块，它用来模拟被测试模块工作过程中所调用的模块。桩模块由被测模块调用，它们一般只进行很少的数据处理，以便检验被测模块与其下级模块的接口。
```

## Q007194

- 题型：简答
- 难度：简单

**题目**

```text
单元测试环境由三部分构成？
```

**答案**

```text
所测模块和与它相关的驱动模块及桩模块共同构成了一个“测试环境”
```

**解析**

```text
【核心考点】 单元测试 测试环境
【题目解析】
本题考查单元测试环境的基本构成。单元测试是对软件最小可测试单元（如函数、方法）的验证，通常需要模拟被测模块的调用和被调用关系，因此需要驱动模块和桩模块来构建测试环境。
【参考答案要点】
单元测试环境由以下三部分构成：
1. 被测模块：即需要测试的单元本身，是测试的核心对象。
2. 驱动模块（Driver）：用于模拟被测模块的上级调用模块，负责调用被测模块并传递测试数据。
3. 桩模块（Stub）：用于模拟被测模块调用的下级模块，返回预设结果，以便隔离外部依赖。
三者共同构成一个完整的测试环境，确保被测模块在隔离状态下被正确验证。
【面试角度】
回答时建议结合实际项目经验，例如“在我们项目中，使用JUnit编写驱动模块，Mockito创建桩模块”，能体现对工具和方法的掌握。
【延伸知识】
驱动模块和桩模块是单元测试的核心概念，尤其在集成测试中也会用到。了解两者的区别（驱动是调用者，桩是被调用者）有助于应对面试中的深入提问。
```

## Q007209

- 题型：简答
- 难度：中等

**题目**

```text
如果开发时间紧迫，是否可以跳过单元测试而直接进行集成测试？为什么？
```

**答案**

```text
不可以。因为没有经过单元测试的模块会遗留大量的缺陷到集成测试阶段，而在集成测试阶段对这些缺陷定位困难，导致后续工作展开困难，修复缺陷成本成指数级增长。
```

**解析**

```text
【核心考点】 软件测试流程 单元测试 集成测试
【参考答案要点】
不可以。原因如下：
1. 缺陷遗留风险：未经过单元测试的模块会携带大量缺陷进入集成测试阶段，增加后续测试的复杂性和工作量。
2. 缺陷定位困难：在集成测试中，缺陷可能源于多个模块的交互，若未进行单元测试，缺陷定位将变得极其困难，需要花费大量时间排查。
3. 修复成本增加：缺陷发现得越晚，修复成本越高。跳过单元测试会导致缺陷在后期被发现，修复成本呈指数级增长。
【面试角度】
回答时，建议结合实际项目经验说明，例如“在我之前的项目中，曾因时间紧迫跳过单元测试，结果集成测试阶段发现大量接口问题，导致返工和延期”，这样能增强说服力。
【延伸知识】
在敏捷开发中，单元测试常与测试驱动开发（TDD）结合，强调先写测试后写代码，确保代码质量。即使时间紧张，也应优先保证核心模块的单元测试覆盖率。
```


## Q007217

- 题型：简答
- 难度：中等

**题目**

```text
简述驱动模块和桩模块的区别？
```

**答案**

```text
驱动模块：相当于被测模块的主程序，是用来代替被测单元的上层模块，它接收测试数据，把这些数据传送给被测模块，最后输出实测结果；
桩模块：用于代替被测模块调用的子模块，桩模块可以做少量的数据操作，不需要把子模块所有功能都带进来，但不允许什么事情也不做。
```

**解析**

```text
【核心考点】 单元测试 驱动模块 桩模块
【题目解析】
本题考查单元测试中驱动模块和桩模块的概念。驱动模块用于模拟被测模块的上层调用者，桩模块用于模拟被测模块调用的下层模块。两者都是测试替身，但角色相反。
【参考答案要点】
驱动模块（Driver）：相当于主程序，负责调用被测模块，传入测试数据并输出结果。常用于自底向上集成测试。
桩模块（Stub）：模拟被测模块调用的子模块，返回预设数据，不实现完整功能。常用于自顶向下集成测试。
【面试角度】
可结合集成测试策略说明何时使用驱动或桩，并提及Mock对象与桩的区别。
【易错提示】
驱动模块是调用者，桩模块是被调用者，两者方向相反，容易混淆。
```

```text
通常情况下，下列缺陷不能通过单元测试发现的是（）。

```


```text
D. 一个模块的功能是否会对另一个模块的功能产生不利的影响
```

```text
【核心考点】 单元测试 集成测试 测试阶段
【题目解析】
本题考查单元测试的局限性。单元测试聚焦于模块内部逻辑，如变量初始化、参数传递、错误处理等，而模块间的交互影响属于集成测试范畴。选项D描述的是模块间的耦合问题，无法通过单元测试发现。
```

## Q007222

- 题型：简答
- 难度：中等

**题目**

```text
阐述单元测试的终止的标准。
```

**答案**

```text
1.硬件资源不足或故障造成软件运行无法运行； 2.软件运行后无法正确显示； 3.所有功能测试均已经完成。
```

**解析**

```text
【核心考点】 单元测试 测试终止标准 测试过程
【题目解析】
本题考查单元测试的终止标准，即判断单元测试何时可以结束的条件。通常包括代码覆盖率达到要求、所有测试用例通过、关键缺陷已修复等。回答应体现测试过程的完整性和质量保证。
【参考答案要点】
1. 代码覆盖率达标：语句覆盖、分支覆盖、条件覆盖等达到预定阈值（如语句覆盖≥90%）。
2. 所有测试用例通过：无失败的测试用例，且测试结果符合预期。
3. 关键缺陷已修复：所有严重和致命缺陷已关闭，其余缺陷已评估并确认可接受。
4. 测试环境稳定：硬件资源充足，软件运行正常，无环境干扰。
5. 测试报告完成：输出测试总结报告，记录测试结果和遗留问题。
【面试角度】
面试官期望看到结合实际项目经验，例如“在我们项目中，单元测试终止标准还包括代码审查通过和性能基线达标”，能体现对质量管理的理解。
【易错提示】
常见错误：只强调测试用例通过而忽略覆盖率，或未考虑缺陷修复状态，导致测试不充分。
```
