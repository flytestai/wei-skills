## Q007247

- 题型：单选
- 难度：入门

**题目**

```text
代码评审员一般都是测试员担任。（）
```

**选项**

```text
A. 对
B. 错
```

**答案**

```text
B
```

**正确选项**

```text
B. 错
```

**解析**

```text
【核心考点】 代码评审 角色职责
【题目解析】
本题考查代码评审的参与角色。代码评审通常由开发人员主导，测试人员可参与但非必须。测试员的主要职责是测试执行和缺陷发现，而代码评审更侧重于代码质量、逻辑和设计，因此“一般由测试员担任”的说法是错误的。
【选项解析】
✗ A. 对 — 错误。代码评审通常由开发人员或技术负责人进行，测试员可参与但非主要角色。
✓ B. 错 — 正确。测试员主要负责测试，代码评审是开发过程的一部分。
【易错提示】
注意区分“代码评审”和“测试评审”，前者关注代码实现，后者关注测试用例和策略。
```

## Q007248

- 题型：简答
- 难度：简单

**题目**

```text
动态测试又包含哪些活动？
```

**答案**

```text
动态测试方法是指通过运行被测程序，检查运行结果与预期结果的差异，并分析运行效率和健壮性等性能，这种方法包括构造测试实例、执行程序、分析程序的输出结果。
所谓软件的动态测试，就是通过运行软件来检验软件的动态行为和运行结果的正确性。目前，动态测试也是公司的测试工作的主要方式。根据动态测试在软件开发过程中所处的阶段和作用，动态测试可分为如下几个步骤：单元测试、集成测试、系统测试、验收测试、回归测试。
```

**解析**

```text
【核心考点】 动态测试 测试阶段
【参考答案要点】
动态测试通过运行程序来检验行为，主要活动包括：
1. 单元测试：测试最小代码单元（函数、方法），通常由开发人员执行。
2. 集成测试：测试模块间的接口和交互，验证集成后的功能。
3. 系统测试：在完整系统上测试功能、性能、安全等，模拟真实环境。
4. 验收测试：由用户或客户执行，确认系统满足业务需求。
5. 回归测试：在修改后重新测试，确保未引入新缺陷。
【面试角度】
回答时强调各阶段的目标和参与者，例如“单元测试由开发人员完成，系统测试由测试团队负责”。
```

## Q007250

- 题型：单选
- 难度：简单

**题目**

```text
软件自动化测试工具有（）、功能测试工具、白盒测试工具、网络测试工具、测试管理工具和测试辅助工具。
```

**选项**

```text
A. 负载压力测试工具
B. 性能测试工具
C. 配置管理工具
D. 效率测试工具
```

**答案**

```text
A
```

**正确选项**

```text
A. 负载压力测试工具
```

**解析**

```text
【核心考点】 自动化测试工具分类
【题目解析】
本题考查软件测试工具的分类。题目中给出“软件自动化测试工具有（）、功能测试工具、白盒测试工具、网络测试工具、测试管理工具和测试辅助工具”，括号内应填入与功能测试工具并列的一类工具。负载压力测试工具属于性能测试范畴，但选项A和B易混淆。
【选项解析】
✓ A. 负载压力测试工具 — 正确。负载压力测试工具是自动化测试工具的一个子类，与功能测试工具并列，如JMeter、LoadRunner。
✗ B. 性能测试工具 — 错误。性能测试工具范围更广，包括负载压力测试，但题目中已有“负载压力测试工具”选项，且通常分类中“性能测试工具”可涵盖负载压力，但此处更具体。
✗ C. 配置管理工具 — 错误。配置管理工具属于管理类工具，如Git、SVN，不属于自动化测试工具。
✗ D. 效率测试工具 — 错误。效率测试工具并非标准分类，通常归入性能测试。
【易错提示】
注意区分“负载压力测试工具”和“性能测试工具”，前者是后者的子集。题目中已有“功能测试工具”作为参照，应选同类别的具体工具类型。
```

## Q007249

- 题型：单选
- 难度：中等

**题目**

```text
数据驱动测试也称（）
```

**选项**

```text
A. 单元测试
B. 白盒测试
C. 黑盒测试
D. 确认测试
```

**答案**

```text
C
```

**正确选项**

```text
C. 黑盒测试
```

**解析**

```text
【核心考点】 数据驱动测试 黑盒测试
【题目解析】
本题考察数据驱动测试的别名。数据驱动测试是一种自动化测试方法，通过外部数据源（如Excel、CSV、数据库）驱动测试脚本执行，测试逻辑与数据分离。它属于黑盒测试的一种实践，因为测试不关注内部代码，只关注输入输出。
【选项解析】
✗ A. 单元测试 — 错误。单元测试通常针对代码模块，与数据驱动无直接关联。
✗ B. 白盒测试 — 错误。白盒测试关注内部逻辑，数据驱动测试不依赖内部结构。
✓ C. 黑盒测试 — 正确。数据驱动测试是黑盒测试的一种形式，强调基于数据的测试。
✗ D. 确认测试 — 错误。确认测试是验证软件是否满足需求，与数据驱动概念不同。
【易错提示】
注意区分“数据驱动测试”与“关键字驱动测试”，前者是黑盒测试，后者可能涉及更多自动化框架概念。
```
