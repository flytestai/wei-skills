## Q004284

- 题型：简答
- 难度：简单

**题目**

```text
request如何传参的？如果是json形势怎么写？
```

**答案**

```text
requests库，对于所有的请求都是可以调用requests方法的，无论是get还是其它请求，常用是字典作为请求参数，是data形参。如果是json格式的，那么就使用json形参。
```

**解析**

```text
【核心考点】 Python requests库 参数传递
【参考答案要点】
1. 普通参数传递：使用data参数，通常传递字典格式。例如：requests.post(url, data={'key': 'value'})，适用于表单提交。
2. JSON格式传递：使用json参数，直接传递字典或列表，requests会自动序列化为JSON并设置Content-Type为application/json。例如：requests.post(url, json={'key': 'value'})。
3. 其他方式：GET请求使用params参数传递查询字符串，如requests.get(url, params={'key': 'value'})。
【面试角度】
面试官常考察data与json参数的区别：data默认编码为表单格式（application/x-www-form-urlencoded），而json自动处理为JSON格式。错误使用可能导致服务端解析失败。
【延伸知识】
对于复杂场景，可使用headers自定义Content-Type，或使用files参数上传文件。requests库还支持会话保持（Session）、超时设置等高级功能。
```

## Q004286

- 难度：简单

```text
什么时候进行接口自动化测试
```

**答案**

```text
1、接口自动化测试一般用于核心业务的回归测试
2、当项目核心业务业务稳定之后，就可以实施核心业务的接口自动化测试
```

**解析**

```text
【核心考点】 接口自动化测试 测试时机
【题目解析】
```

## Q004298

- 难度：简单

**题目**

```text
你知道断言是什么吗？怎么断言？
```

**答案**

```text
知道的，我们用的是Jemter的响应断言。请求下添加断言断言---响应断言---响应断言界面输入要检查比对的项，设置好断言后，执行接口测试如果是通过的，查看结果树不会有任何提示，如果断言失败，就会有红色报错。

```

**解析**

```text
【核心考点】 接口测试 断言 JMeter
【参考答案要点】
```

## Q004309

- 题型：简答
- 难度：简单

**题目**

```text
在接口自动化测试中，什么是状态码断言？为什么要进行状态码断言？
```

**答案**

```text
状态码断言是一种验证接口响应状态码是否符合预期的断言方式。在接口自动化测试中，通过断言接口返回的状态码，可以验证接口的执行是否成功、异常情况是否处理正确。状态码断言是保证接口测试准确性和可靠性的重要手段。
```

**解析**

```text
【核心考点】 接口自动化测试 状态码断言
【参考答案要点】
状态码断言是指在接口自动化测试中，验证接口返回的HTTP状态码是否符合预期的一种断言方式。例如，期望200表示成功，404表示未找到，500表示服务器错误等。
为什么要进行状态码断言？
1. 验证接口执行结果：状态码是接口响应的第一层信息，直接反映请求是否成功处理。
2. 确保异常处理正确：通过断言错误状态码（如400、401、403），验证系统对异常情况的处理是否符合设计。
3. 提高测试可靠性：状态码断言是接口测试的基础，能快速发现网络、权限、参数等层面的问题。
【面试角度】
面试中可能进一步问：状态码断言和响应体断言的关系？（状态码断言是前置条件，响应体断言验证具体数据，两者互补）如何设计状态码断言用例？（覆盖正常、异常、边界场景，如200、400、500等）。
【延伸知识】
常见的状态码分类：1xx（信息）、2xx（成功）、3xx（重定向）、4xx（客户端错误）、5xx（服务器错误）。在自动化测试中，建议对每个接口至少断言一次状态码，作为基础检查点。
```

```text
接口自动化上传下载文件用的什么库？
```

**答案**

```text
可以使用 requests 库完成上传和下载操作，
通过 files 参数直接上传文件，
可以通过响应对象 respose.content 获取文件数据
```

**解析**

```text
【核心考点】 接口自动化 文件上传下载 requests库
【题目解析】
本题考查Python接口自动化测试中，文件上传和下载的常用库及方法。requests库是Python中最流行的HTTP库，支持文件操作。
【参考答案要点】
1. 使用的库：通常使用Python的requests库。
2. 文件上传：通过requests的files参数，将文件以二进制模式打开并作为字典值传入。例如：files = {'file': open('test.txt', 'rb')}; response = requests.post(url, files=files)。
3. 文件下载：通过响应对象的content属性获取二进制数据，然后写入本地文件。例如：response = requests.get(url); with open('downloaded_file.zip', 'wb') as f: f.write(response.content)。
【易错提示】
上传文件时，注意使用rb模式打开文件，并确保文件路径正确。下载大文件时，建议使用stream=True参数和iter_content方法分块写入，避免内存溢出。
```

```text

【题目解析】
本题考察接口自动化测试中测试替身的概念。Mock和Stub都是模拟依赖项的技术，但侧重点不同：Stub提供预设的响应数据，用于替代真实依赖；Mock则更关注行为验证，检查是否按预期调用了方法。在接口测试中，它们用于解耦外部系统，提高测试的稳定性和可控性。
【参考答案要点】
1. Mock：模拟对象，可验证交互行为（如方法是否被调用、调用次数、参数等）。
2. Stub：占位符，提供预设的返回数据，不验证行为。
3. 作用：解决依赖项不可控、不稳定或未开发完成的问题，使测试独立运行。
【易错提示】
常见混淆：Mock和Stub常被混用，但面试中区分两者是加分项。Mock强调行为验证，Stub强调数据提供。
```

## Q004343

- 题型：简答
- 难度：中等

**题目**

```text
接口自动化时，使用request 模块发送请求的时候，怎么传递参数？
```

**答案**

```text
首先要确认一下接口的请求参数是什么类型的，如果接口需要的是查询字符串参数的话，那么就是 params 查；如果接口需要的是 json 型的参数的话，那么就直接使用 json 去查；

如果是 上传文件 的情况的话，那么可以通过 files 的参数来传递；

如果是 表单类型 的情况的话，那么可以使用 data 来传递，data 默认就是用来传递表单类型的参数；

那么当使用 data 传参的时候，也可以在那个请求头中，通过 content type 来指定这个请求参数的类型
```

**解析**

```text
【核心考点】 接口自动化测试 requests模块 参数传递
【题目解析】
本题考察在Python的requests库中，根据不同接口需求传递参数的方式。requests库提供了多种参数传递方式，包括params、json、data和files，分别对应查询字符串、JSON数据、表单数据和文件上传。正确选择参数传递方式对于接口自动化测试的准确性和效率至关重要。
【参考答案要点】
1. 查询字符串参数（params）：当接口需要查询字符串参数时，使用params参数传递，例如requests.get(url, params={'key': 'value'})。
2. JSON参数（json）：当接口需要JSON格式的请求体时，使用json参数传递，例如requests.post(url, json={'key': 'value'})。
3. 文件上传（files）：当接口需要上传文件时，使用files参数传递，例如requests.post(url, files={'file': open('test.txt', 'rb')})。
4. 表单数据（data）：当接口需要表单类型参数时，使用data参数传递，例如requests.post(url, data={'key': 'value'})。此时可通过Content-Type请求头指定具体格式，如application/x-www-form-urlencoded或multipart/form-data。
【面试角度】
回答时建议结合实际项目经验，例如“在测试登录接口时，使用json参数传递用户名和密码；在测试文件上传功能时，使用files参数”。同时，可补充说明data和json的区别：data默认发送表单数据，json自动设置Content-Type为application/json并序列化数据。
【易错提示】
容易混淆data和json的使用场景。如果接口要求JSON格式，使用data传递字典可能导致Content-Type错误，从而接口解析失败。务必根据接口文档选择正确的参数类型。
```

## Q004358

- 题型：简答
- 难度：较难

**题目**

```text
用过jmeter做接口测试，jmeter中跨线程调用token的方法是什么？
```

**答案**

```text
跨线程用调用token：
首先也是先登录并用后置处理器 -正则或者json提取器提取出来数据，复制给一个变量；然后使用函数助手选择__setProperty，通过BeanShell后置处理程序将值全局化；然后把BeanShell后置处理程序全局化的参数拿来调用，也要用到函数助手_P，添加我们从登录接口提取到的存储正则表达式的变量名，进行调用就可以了。
详细操作截图可以查看一下的博客：
相关技术文档
```

**解析**

```text
【核心考点】 JMeter跨线程组参数传递 BeanShell后置处理器 函数助手
【题目解析】
本题考察JMeter中跨线程组传递token的实战技术。在接口测试中，登录接口获取的token通常需要被其他线程组（如业务接口线程组）使用，但由于线程组间变量隔离，直接引用会失败。标准解决方案是通过__setProperty函数将变量设为JMeter全局属性，再通过__P函数在其他线程组中读取。
【参考答案要点】
步骤1：在登录线程组中，使用正则表达式提取器或JSON提取器从响应中提取token值，并赋值给一个变量（如token）。
步骤2：添加BeanShell后置处理器（或JSR223后置处理器），在其中调用__setProperty函数，将变量值设置为全局属性，例如：${__setProperty(global_token, ${token},)}。
步骤3：在目标线程组中，使用__P函数读取全局属性，例如：${__P(global_token,)}，即可在HTTP请求头或参数中引用该token。
【面试角度】
回答时建议强调实际项目中的应用场景，例如“在电商项目中，登录和下单分属不同线程组，通过此方法确保token共享”。同时可补充JSR223后置处理器的替代方案（使用Groovy语言），体现技术广度。
【易错提示】
注意区分跨线程组和同一线程组内的变量传递：同一线程组内直接使用变量名即可，无需全局化。另外，__setProperty需在BeanShell中调用，而非直接写在参数中。
```

```text
设计模式的选择需权衡复杂度与收益，过度设计反而降低可维护性。建议掌握常见模式及其适用场景。
```
