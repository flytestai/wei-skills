
**答案**

```text
在每一个功能层次中，通信双方共同尊守该层次的约定和规程。
```

**解析**

```text
【核心考点】 计算机网络 协议分层
【题目解析】
本题考察网络协议分层的基本概念。同层协议是指网络中不同节点上同一层次之间通信所遵循的规则和约定。例如，TCP/IP模型中，两台主机的传输层之间通过TCP或UDP协议通信，这些协议就是同层协议。
【参考答案要点】
同层协议是指在计算机网络分层体系结构中，不同节点上同一层次之间进行通信时所共同遵守的规则和约定。它定义了该层的数据格式、传输方式、错误处理等，确保对等实体能够正确交换信息。
【面试角度】

不要混淆“同层协议”与“相邻层接口”，前者是不同节点同一层之间的通信规则，后者是同一节点不同层之间的服务调用。
```

## Q004371

- 题型：简答
- 难度：简单

**题目**

```text
HTTP和HTTPS协议区别？
```

**答案**

```text
http是超文本传输协议，信息是明文传输

Https协议是由SSL+http协议构建的可进行加密传输、身份认证的网络协议，比http协议安全；
https协议需要到CA（Certificate Authority，证书颁发机构）申请证书，一般免费证书较少，因而需要一定费用；

http和https使用的是完全不同的连接方式，用的端口也不一样，前者是80，后者是443；
```

**解析**

```text
【核心考点】 网络协议 HTTP/HTTPS
【参考答案要点】
1. 安全性：HTTP是明文传输，数据易被窃听；HTTPS通过SSL/TLS加密，提供身份认证和数据完整性保护，更安全。
2. 证书：HTTPS需要向CA（证书颁发机构）申请SSL证书，通常需要费用；HTTP无需证书。
3. 端口：HTTP默认使用80端口，HTTPS默认使用443端口。
4. 性能：HTTPS因加密和解密过程，比HTTP稍慢，但现代优化（如会话复用）已大幅缩小差距。
【面试角度】
回答时建议从安全性、端口、证书和性能四个方面对比，并提及HTTPS在SEO中的优势（搜索引擎优先收录），以体现全面性。面试官可能进一步追问SSL握手过程。
【延伸知识】
HTTPS的SSL/TLS握手包括客户端问候、服务器证书验证、密钥交换等步骤，了解这些有助于应对深度面试问题。
```

## Q004372

- 题型：简答
- 难度：简单

**题目**

```text
JMeter中用户定义的变量（User Defined Variables）和用户参数（User Parameters）区别是什么？
```

**答案**

```text
用户定义的变量：在启动运行时获取一次值，在运行过程中，不在动态获取值 ，用户定义变量可以跨线程传参
用户参数： 在启动运行时获取一次值，在运行过程中，每次使用该参数都会动态获取一次值 ，用户参数不可以跨线程传递参数
```

**解析**

```text
【核心考点】 JMeter参数化 作用域
【参考答案要点】
用户定义的变量（User Defined Variables）：在启动运行时获取一次值，运行过程中不再动态获取；可以跨线程组传递参数。
用户参数（User Parameters）：在启动运行时获取一次值，但每次使用该参数时都会动态获取一次值；不可以跨线程组传递参数。
【题目解析】
本题考察JMeter中参数化机制的区别。用户定义的变量适用于全局常量，如服务器地址，在测试计划中配置后所有线程共享；用户参数适用于需要为不同用户或迭代动态赋值的场景，如模拟不同登录账号，但作用域仅限于当前线程组。
【易错提示】
易混淆点：用户定义的变量在运行中不变，但用户参数每次使用都会重新取值；用户定义的变量可跨线程组，用户参数不能。
【面试角度】
面试中常结合性能测试场景提问，例如“如何模拟100个不同用户登录？”应回答使用用户参数配合CSV数据文件。
```

## Q004381

- 题型：简答
- 难度：简单

**题目**

```text
Jmter做接口测试，什么时候建立线程组？线程组的默认三个参数是什么意思？
```

**答案**

```text
1、在接口测试的时候，打开Jmeter的测试计划下建立线程组，然后建立http请求。
2、设置并发用户数，并发时间，请求循环次数
```

**解析**

```text
【核心考点】 JMeter 线程组 性能测试
【题目解析】
本题考查JMeter线程组的创建时机和三个核心参数的含义。线程组是JMeter测试计划的基本组件，用于模拟并发用户。
【参考答案要点】
1. 建立线程组的时机：在接口测试开始时，首先在测试计划下添加线程组。线程组是执行测试的入口，所有请求和逻辑控制器都放在线程组下。
2. 三个默认参数含义：
- 线程数（Number of Threads）：模拟的并发用户数量。
- Ramp-Up Period（秒）：启动所有线程所需的时间。例如，10个线程，Ramp-Up为10秒，则每秒启动1个线程。
- 循环次数（Loop Count）：每个线程执行测试脚本的次数。勾选“永远”则持续运行直到手动停止。
【面试角度】
面试官可能追问：Ramp-Up Period如何设置？通常建议设置为线程数，使每秒启动一个线程，避免瞬间压力过大。另外，可补充“调度器”配置，用于控制测试持续时间。
【易错提示】
常见误解：认为线程数就是总请求数。实际上，线程数×循环次数=总请求数（每个线程发送一个请求）。另外，Ramp-Up时间过短可能导致服务器瞬间过载。
```

## Q004385

- 题型：简答
- 难度：简单

**题目**

```text
http与https有什么区别
```

**答案**

```text
1、http协议：是超文本传输协议，信息是明文传输。如果攻击者截取了Web浏览器和网站服务器之间的传输报文，就可以直接读懂其中的信息。
2、https协议：是具有安全性的ssl加密传输协议，为浏览器和服务器之间的通信加密，确保数据传输的安全。
3、http协议：http的连接很简单，是无状态的。
4、https协议：是由SSL＋HTTP协议构建的可进行加密传输、身份认证的网络协议。
```

**解析**

```text
【核心考点】 网络协议 HTTP与HTTPS区别
【参考答案要点】
1. 安全性：HTTP是明文传输，数据易被截获；HTTPS通过SSL/TLS加密传输，保证数据机密性和完整性。
2. 端口：HTTP默认使用80端口，HTTPS默认使用443端口。
3. 连接状态：HTTP是无状态协议；HTTPS通过SSL握手建立加密连接，可携带状态信息。
4. 证书：HTTPS需要CA证书验证服务器身份，HTTP无需证书。
【面试角度】
回答时建议结合实际项目中的HTTPS配置经验，例如证书部署、混合内容问题等，能体现深度。
【延伸知识】
HTTPS的SSL握手过程包括：客户端发送随机数→服务器返回证书和随机数→客户端验证证书并生成预主密钥→双方生成会话密钥。了解此过程有助于应对高级面试题。
```

## Q004383

- 题型：简答
- 难度：中等
- 解析：AI 补全（原数据缺失解析）

**题目**

```text
SOAP和REST的区别?
```

**答案**

```text
SOAP (Simple Object Access Protocol) 顾名思义，是一个严格定义的信息交换协议，用于在Web Service中把远程调用和返回封装成机器可读的格式化数据。
事实上SOAP数据使用XML数据格式，定义了一整套复杂的标签，以描述调用的远程过程、参数、返回值和出错信息等等。
REST (REpresentational State Transfort) 形式上应该表述为客户端通过申请资源来实现状态的转换。
REST只是一种架构风格，而不是协议或标准。
绝大多数SOAP是运行在HTTP上，使用URI标识服务，SOAP也仅仅使用POST方法发送请求，用一个唯一的URI标识服务的入口。
举一个图书馆在线查询管理系统为例，服务提供者必须为每一本书提供一个内部标识，然后可能定义一个listBooks操作来返回一系列图书，一个getBook操作来返回指定的图书，一个createBook操作来向数据库加入新增的图书，一个deleteBook操作来删除作废的图书，每个操作都有各自的参数，尤其是用内部标识来标识操作的图书。
这种设计被诟病之处，在于deleteBook操作也要用POST方法来发送，而其实HTTP协议有更和逻辑的DELETE方法可用。
REST正是这样设计的，REST为每一个资源（此处是图书）指定一个唯一的URI，而用HTTP的4种方法GET、POST、PUT、DELETE直观地表示获取、创建、更新和删除图书。同时图书集合也是和单本的图书不同的资源，如果用/books来代表图书列表，/books/ID来代表标识为ID的图书，那么对/books的GET操作就代表返回整个图书列表，对/books/ID的DELETE操作代表删除指定的图书，等等。
```

**解析**

```text
【核心考点】两种Web服务风格的差异。
【题目解析】SOAP是严格定义的协议，用XML描述调用、参数和返回值，通常只走POST，靠服务入口区分操作；REST是一种架构风格，用URI标识资源，用GET、POST、PUT、DELETE表达操作，更轻量。
【答题要点】
1. SOAP基于XML、协议严格、消息较重。
2. REST面向资源，使用标准HTTP方法，风格轻量。
3. REST不是标准协议，约束靠设计约定，测试时更关注资源与状态码。
【面试提示】可补充两者都常运行在HTTP上，区别在消息格式和设计理念。
```

## Q004386

```text
http和https的区别是什么？
```

```text
　　HTTPS和HTTP的区别主要如下：

　　
1、https协议需要到ca申请证书，一般免费证书较少，因而需要一定费用。

　　
2、http是超文本传输协议，信息是明文传输，https则是具有安全性的ssl加密传输协议。

　　
3、http和https使用的是完全不同的连接方式，用的端口也不一样，前者是80，后者是443。

　　
4、http的连接很简单，是无状态的；HTTPS协议是由SSL+HTTP协议构建的可进行加密传输、身份认证的网络协议，比http协议安全。
```

**解析**

```text
【核心考点】 HTTP与HTTPS协议 网络安全
【题目解析】
本题考查HTTP与HTTPS的核心区别，是网络基础知识中的高频面试题。HTTPS在HTTP基础上增加了SSL/TLS加密层，确保数据传输的机密性、完整性和身份认证。回答时需清晰对比两者的关键差异，并说明HTTPS的工作原理。
【参考答案要点】
1. 安全性：HTTP传输明文数据，易被窃听和篡改；HTTPS通过SSL/TLS加密，保证数据安全。
2. 证书：HTTPS需要向CA机构申请证书，通常需要费用；HTTP无需证书。
3. 端口：HTTP默认使用80端口，HTTPS默认使用443端口。
4. 性能：HTTPS因加密解密过程，速度略慢于HTTP，但现代硬件和优化已使差距缩小。
5. 工作原理：HTTPS = HTTP + SSL/TLS，通过握手过程协商加密算法和密钥，实现加密传输。
【面试角度】
回答时建议结合实际项目中的HTTPS配置经验，例如证书部署、混合内容问题等，能展示实践能力。同时可提及HTTPS对SEO的正面影响，体现知识广度。
【延伸知识】
HTTPS的SSL/TLS握手过程包括：客户端发送支持的加密套件列表→服务器选择并返回证书→客户端验证证书并生成会话密钥→双方使用会话密钥加密通信。了解TLS 1.3相比1.2的优化（减少握手次数）可提升答案深度。
```

## Q004408

- 题型：简答
- 难度：中等

**题目**

```text
列举几个主流协议，分别什么格式，有什么区别。
```

**答案**

```text
http：超文本传输协议（Hyper Text Transfer Protocol，HTTP）是一个简单的请求-响应协议，它通常运行在TCP之上。它指定了客户端可能发送给服务器什么样的消息以及得到什么样的响应。
rpc：远程调用协议 。RPC协议假定某些传输协议的存在，如TCP或UDP，为通信程序之间携带信息数据。在OSI网络通信模型中，RPC跨越了传输层和应用层。RPC使得开发包括网络分布式多程序在内的应用程序更加容易。
mqtt：MQTT是一个基于客户端-服务器的消息发布/订阅传输协议。MQTT协议是轻量、简单、开放和易于实现的，这些特点使它适用范围非常广泛。在很多情况下，包括受限的环境中，如：机器与机器（M2M）通信和物联网（IoT）。
```

**解析**

```text
【核心考点】 网络协议 HTTP RPC MQTT
【题目解析】
本题考查常见网络协议的基本概念、格式和区别。HTTP、RPC、MQTT分别适用于不同场景：HTTP用于Web通信，RPC用于远程服务调用，MQTT用于物联网消息传递。
【参考答案要点】
1. HTTP（超文本传输协议）：基于请求-响应模型，使用URL标识资源，格式为文本（如GET /index.html HTTP/1.1），无状态，适用于Web应用。
2. RPC（远程过程调用协议）：允许程序调用远程服务，格式通常为二进制（如gRPC使用Protobuf），支持多种传输协议，注重性能和服务治理。
3. MQTT（消息队列遥测传输）：发布/订阅模式，轻量级，二进制格式，支持QoS级别，适用于低带宽、高延迟的物联网场景。
区别：HTTP是文本协议，RPC和MQTT多为二进制；HTTP无状态，RPC可维护状态，MQTT基于主题；HTTP适用于请求-响应，RPC适用于服务间调用，MQTT适用于消息推送。
【易错提示】
易混淆RPC与HTTP，注意RPC通常封装了传输细节，而HTTP是应用层协议；MQTT与HTTP的区别在于模型和效率。
【面试角度】
面试中可能要求结合实际项目说明协议选择，例如微服务中为何用RPC而非HTTP，或物联网中MQTT的优势。
```

## Q004375


```text

然后在下一个线程组中，使用—property,将全局变量填入。生成函数并复制到下一个线程组的接口使用就可以了
```

```text
【核心考点】 JMeter接口关联 多线程组 参数传递
【题目解析】
本题考查JMeter中跨线程组传递参数的高级技巧，属于性能测试和接口测试中的难点。候选人需要理解JMeter的变量作用域，并掌握使用__setProperty()和__property()函数实现全局变量传递的方法。
【参考答案要点】
1. 提取变量：在第一个线程组中，使用正则表达式提取器或JSON提取器从响应中获取所需值（如token）。

【易错提示】
```

## Q004411

- 题型：简答
- 难度：较难

**题目**

```text
如何使用jmeter进行接口测试？
```

**答案**

```text
1、先分析接口需求，搞清楚接口请求、响应信息，以及业务关联。
2、Jmeter对应接口业务设计对应脚本：
2.1 不涉及关联的单接口执行，右键测试计划添加线程组，然后线程组下面添加HTTP请求，将接口的请求地址、请求方式，传参配置好；请求头在HTTP信息头管理器设置；最后添加监听器-查看结果树，用来记录测试结果
2.2 涉及关联的接口，例某个接口需要依赖到登录状态，在请求头需传递登录成功返回的token值，那么需用到后置处理器提取数据，像返回格式是json的可使用json提取器提取token值
2.3 涉及数据库获取数据，需添加jdbc连接配置，以及jdbc request进行数据库通过sql语句提取到数据后，在需要的接口进行引用，例如短信验证码的获取
2.4 脚本设计可能还需要用到参数化、断言实现；还有文件上传接口、参数加密等业务的处理；总之要依据实际业务场景设计脚本执行测试
3、执行中，通过断言判断是否符合预期；没那么好断言处理的，可以手动通过查看结果树的响应结果，数据库结果进行校验接口是否通过；出现bug及时提交缺陷管理平台并跟踪
以上就是如何做接口测试的大致过程。
```

**解析**

```text
【核心考点】 JMeter 接口测试 关联 数据库验证
【题目解析】
本题考查使用JMeter进行接口测试的完整流程，属于实践操作题。答案涵盖了单接口测试、关联处理、数据库验证三个关键场景，逻辑清晰，步骤完整，体现了对JMeter核心功能的掌握。
【参考答案要点】
1. 单接口测试： 添加线程组→配置HTTP请求（URL、方法、参数）→设置HTTP信息头管理器→添加查看结果树。
2. 关联处理： 使用JSON提取器或正则表达式提取器从响应中提取动态数据（如token），并通过${变量名}引用到后续请求中。
3. 数据库验证： 添加JDBC连接配置（数据库URL、驱动、用户名密码）→使用JDBC Request执行SQL查询→通过断言验证结果。
4. 参数化与断言： 使用CSV数据文件驱动测试数据，添加响应断言检查状态码或内容。
【面试角度】
面试官关注实际项目经验，建议结合具体案例说明，如“在XX项目中，我使用JMeter测试登录接口，通过JSON提取器获取token，并参数化多个用户账号进行并发测试”。同时可提及性能测试扩展，如添加聚合报告分析TPS和响应时间。
【延伸知识】
JMeter与Postman的对比：Postman适合手工调试和简单自动化，JMeter适合复杂场景和性能测试。在接口测试中，JMeter的线程组可模拟并发，而Postman的Collection Runner更适合顺序执行。了解工具差异有助于面试中展示技术广度。
```
