## Q004000

- 题型：简答
- 难度：入门

**题目**

```text
401状态码是啥？
```

**答案**

```text
请求要求身份验证。对于需要登录的网页，服务器可能返回此响应。
```

**解析**

```text
【核心考点】 HTTP状态码 401未授权
【参考答案要点】
401状态码表示“未授权”（Unauthorized），即请求要求身份验证。对于需要登录的网页，服务器可能返回此响应，提示客户端提供有效的认证凭证（如用户名密码或Token）。
【面试角度】
HTTP状态码是测试基础，面试中常与403（禁止访问）混淆。401表示未提供有效凭证，而403表示凭证有效但权限不足。建议结合API测试场景说明。
【延伸知识】
常见状态码：200（成功）、301（重定向）、404（未找到）、500（服务器错误）。在安全测试中，401的响应头通常包含WWW-Authenticate字段。
```

## Q004009

- 题型：简答
- 难度：入门

**题目**

```text
Post请求可以在url上放参数进行传参吗？
```

**答案**

```text
可以的。post请求在url或者是请求体里传参的。
```

**解析**

```text
【核心考点】 HTTP请求方法 POST传参方式
【参考答案要点】
可以。POST请求支持在URL上放置参数进行传参，但这不是标准做法。通常POST请求的参数放在请求体（Body）中，以表单格式（application/x-www-form-urlencoded）或JSON格式（application/json）传递。在URL上放参数虽然可行，但会暴露参数信息，降低安全性，且不符合RESTful API设计规范。
【面试角度】
回答时建议强调安全性和规范性，例如：在测试中应优先使用请求体传参，除非有特殊需求（如缓存、日志记录）。
【延伸知识】
GET请求参数只能放在URL上，有长度限制（约2048字符），而POST请求体无此限制，适合传输大量数据或敏感信息。
```

## Q004024

- 题型：简答
- 难度：入门

**题目**

```text
get请求这个有哪几种传参方式呢？
```

**答案**

```text
两种：url里传参、消息体里传参
```

**解析**

```text
【核心考点】 HTTP请求方法 GET传参
【题目解析】
本题考查HTTP GET请求的传参方式。GET请求通常用于获取资源，参数通过URL传递。
【参考答案要点】
两种主要传参方式：
1. URL查询字符串传参：在URL后添加?key1=value1&key2=value2，如http://example.com/api?name=test&age=20。
```

## Q004031

- 题型：简答
- 难度：入门

**题目**

```text
http请求需要传入什么参数？
```

**答案**

```text
请求头、请求体
```

**解析**

```text
【核心考点】 HTTP协议 请求结构
【参考答案要点】
HTTP请求主要包含以下参数部分：
请求头（Request Headers）：包含元数据，如Content-Type（指定请求体格式）、Authorization（认证信息）、User-Agent（客户端标识）等。
请求体（Request Body）：包含实际传输的数据，常见格式有JSON、表单数据（form-data）、URL编码（x-www-form-urlencoded）等。GET请求通常无请求体，参数放在URL中。
【面试角度】
此题为基础知识题，回答时需注意区分GET和POST请求的参数传递方式：GET参数在URL中（查询字符串），POST参数在请求体中。同时可补充说明请求行（方法、URL、协议版本）也是请求的一部分，但通常不称为“参数”。
【延伸知识】
HTTP请求还包括请求行（如GET /api/users HTTP/1.1），但面试中常问的“参数”主要指请求头和请求体。另外，RESTful接口中，路径参数（如/users/{id}）也属于URL的一部分，可单独提及。
```

## Q004032

- 题型：简答
- 难度：入门

**题目**

```text
http返回码400代表_____________500代表_____________
```

**答案**

```text
400
1、bad request 意思是 “错误的请求';
2、invalid hostname 意思是 '不存在的域名”。
500 内部服务器（HTTP-Internal Server Error）错误
```

**解析**

```text
【核心考点】 HTTP状态码 网络协议基础
【参考答案要点】
400 Bad Request：表示客户端发送的请求有语法错误或无法被服务器理解，常见于请求参数格式错误、缺少必要字段等。
500 Internal Server Error：表示服务器内部发生错误，无法完成请求，通常由服务器端代码异常、数据库连接失败等引起。
【面试角度】
这是HTTP协议的基础知识，面试中常结合实际调试场景提问，例如“你在测试中遇到400错误会如何排查？”建议回答时能区分客户端错误（4xx）和服务端错误（5xx），并举例说明常见原因。
【易错提示】
注意400和401（未授权）、403（禁止访问）的区别，以及500和502（网关错误）、503（服务不可用）的区别，这些是面试高频混淆点。
```

## Q004050

- 题型：简答
- 难度：入门

**题目**

```text
什么是cookie？
```

**答案**

```text
Cookie是由HTTP服务器设置的，保存在浏览器中，但HTTP协议是一种无状态协议，在数据交换完毕后，服务器端和客户端的链接就会关闭，每次交换数据都需要建立新的链接。
```

**解析**

```text
【核心考点】 Cookie HTTP协议
【题目解析】
本题考查Cookie的基本概念及其与HTTP协议的关系。Cookie是服务器发送到浏览器并保存在本地的小型文本文件，用于记录用户状态。由于HTTP是无状态协议，Cookie用于在多次请求间维持会话。
【参考答案要点】
1. 定义：Cookie是由HTTP服务器设置，保存在浏览器中的小型文本数据，用于存储用户信息或会话标识。
2. 作用：解决HTTP无状态问题，实现用户登录状态保持、个性化设置、跟踪用户行为等。
3. 特点：存储在客户端，大小有限制（通常4KB），可设置过期时间，存在安全风险（如XSS攻击窃取Cookie）。
4. 与Session区别：Session存储在服务器端，更安全但占用服务器资源。
【易错提示】
注意Cookie是存储在客户端而非服务器，且HTTP无状态特性是Cookie存在的基础。
【面试角度】
面试中常追问Cookie与Session的区别及安全措施，建议提前准备安全相关知识点，如HttpOnly属性、Secure标志等。
```

- 难度：入门

**题目**

```text
列出常见http响应状态码以及其代表的意义
```

**答案**

```text
200 请求成功
204 请求成功，不返回body
301 重定向
400 错误的请求，一般是参数错误
401 权限验证不通过
403 禁止访问
500 服务器故障
```

**解析**

```text
【核心考点】 HTTP协议 状态码
【题目解析】
本题考查HTTP状态码的分类和含义，是测试工程师必备的基础知识。状态码由三位数字组成，第一位数字表示响应类别。
【参考答案要点】
200 OK：请求成功，服务器正常返回数据。
204 No Content：请求成功，但响应不包含body内容。

【易错提示】
注意区分401和403：401表示未认证，403表示已认证但无权限，两者含义不同。
```

```text
Cookie实际上是一小段的文本信息。客户端请求服务器，如果服务器需要记录该用户状态，就使用response向客户端浏览器颁发一个Cookie。客户端浏览器会把Cookie保存起来。当浏览器再请求该网站时，浏览器把请求的网址连同该Cookie一同提交给服务器。服务器检查该Cookie，以此来辨认用户状态。服务器还可以根据需要修改Cookie的内容。
Cookie是客户端保存用户信息的一种机制，用来记录用户的一些信息，也是实现Session的一种方式。

Session代表服务器与浏览器的一次会话过程，这个过程是连续的，也可以时断时续的。Session是另一种记录客户状态的机制，不同的是Cookie保存在客户端浏览器中，而Session保存在服务器上。客户端浏览器访问服务器的时候，服务器把客户端信息以某种形式记录在服务器上。这就是Session。客户端浏览器再次访问时只需要从该Session中查找该客户的状态就可以了。
Session在用户第一次访问服务器的时候自动创建，并将通过特殊算法算出一个session的ID，用来标识该session对象，当浏览器下次（session继续有效时）请求别的资源的时候，浏览器会将sessionID放置到请求头中，服务器接收到请求后就得到该请求的sessionID，服务器找到该id的session返还给请求者（Servlet）使用。

如果Session内容过于复杂，当大量客户访问服务器时可能会导致内存溢出。为防止内存溢出，服务器会把长时间内没有活跃的Session从内存删除。这个时间就是Session的超时时间。如果超过了超时时间没访问过服务器，Session就自动失效了。

session技术是要使用到cookie的，之所以出现session技术，主要是为了安全。如果客户端的浏览器禁用了 Cookie 怎么办？一般这种情况下，会使用一种叫做URL重写的技术来进行会话跟踪，原理是将该用户Session的id信息重写到URL地址中。服务器能够解析重写后的URL获取Session的id。
```

**解析**

```text
【核心考点】 Web基础 会话管理
【题目解析】
本题考查Cookie和Session的概念及区别，是Web开发面试中的经典问题。Cookie是存储在客户端（浏览器）的小文本数据，用于记录用户信息；Session是存储在服务器端的会话数据，用于跟踪用户状态。两者常配合使用，Session ID通常通过Cookie传递。
【参考答案要点】
Cookie：由服务器生成，发送给客户端保存，每次请求时自动携带。大小有限（通常4KB），可设置过期时间。安全性较低，易被篡改。
Session：存储在服务器端，通常基于内存或数据库。安全性较高，但会占用服务器资源。Session ID通过Cookie或URL重写传递。
区别：存储位置不同（客户端 vs 服务器端）；安全性不同（Session更安全）；生命周期不同（Cookie可持久化，Session通常随浏览器关闭结束）。
【易错提示】
注意不要混淆Cookie和Session的存储位置，以及Session的依赖关系（Session通常依赖Cookie实现）。
```

## Q004030

- 题型：简答
- 难度：简单

**题目**

```text
http请求状态码从1到5分别代表什么？
```

**答案**

```text
1的请求表示服务器收到请求，需要请求者继续执行操作，这个请求接触的不多，
2的请求主要是服务器端成功处理这个请求并返回响应结果，但是不代表响应结果是正确的，
3的请求主要是一些系统的资源重定向，
4的请求主要是客户端这边出了问题，
5的请求主要是服务器端出现了问题
```

**解析**

```text
【核心考点】 HTTP协议 状态码
【题目解析】
本题考查HTTP协议中状态码的分类和基本含义。HTTP状态码由三位数字组成，第一位数字定义了响应的类别，从1xx到5xx分别代表信息性、成功、重定向、客户端错误和服务器错误。理解这些分类是排查网络问题的基础。
```

```text
socket超时有哪几种？有什么区别。
```

```text
读写超时：表示的是连接上了，但是读数据时超过了指定的时间范围，这就是读取超时。
```

**解析**

```text
【核心考点】 Socket超时 网络编程 异常处理
【题目解析】
本题考查Socket超时类型及其区别，属于网络编程和测试中的基础概念。面试中常考察候选人对网络通信异常的理解，以及在实际测试中如何模拟和处理超时场景。
【参考答案要点】
Socket超时主要有两种：
1. 连接超时（Connection Timeout）：从发送连接请求到成功连接目标主机的时间超过指定阈值。常见原因：网络不通、目标主机不可达、防火墙拦截等。

【面试角度】
回答时建议结合测试场景，例如“在弱网测试中，我们通过设置不同的连接超时和读写超时值，验证应用在超时后的重试机制和错误提示”，能体现应用能力。
【延伸知识】
在Java中，Socket类通过setSoTimeout()设置读写超时，而连接超时通过new Socket(host, port, timeout)或Socket.connect()方法设置。HTTP客户端如Apache HttpClient也支持类似超时配置。
```

## Q004045

- 题型：简答
- 难度：简单

**题目**

```text
什么情况下使用get请求，什么情况下使用post请求？
```

**答案**

```text
HTTP标准包含这两种方法是为了达到不同的目的。POST用于创建资源，资源的内容会被编入HTTP请示的内容中。例如，处理订货表单、在数据库中加入新数据行等。

当请求无副作用时（如进行搜索），便可使用GET方法；当请求有副作用时（如添加数据行），则用POST方法。一个比较实际的问题是：GET方法可能会产生很长的URL，或许会超过某些浏览器与服务器对URL长度的限制。

若符合下列任一情况，则用POST方法：

* 请求的结果有持续性的副作用，例如，数据库内添加新的数据行。
* 若使用GET方法，则表单上收集的数据可能让URL过长。
* 要传送的数据不是采用7位的ASCII编码。

若符合下列任一情况，则用GET方法：

* 请求是为了查找资源，HTML表单数据仅用来帮助搜索。
* 请求结果无持续性的副作用。
* 收集的数据及HTML表单内的输入字段名称的总长不超过1024个字符。
```

**解析**

```text
【核心考点】 HTTP协议 请求方法
【题目解析】
本题考查HTTP协议中GET和POST方法的适用场景，是Web开发和测试的基础知识。核心区别在于GET用于无副作用的请求（如查询），POST用于有副作用的请求（如创建资源）。
【参考答案要点】
使用GET的情况：请求无副作用（如搜索、查询），数据量小且为ASCII编码，URL长度在浏览器和服务器限制内。
使用POST的情况：请求有副作用（如添加数据行、修改状态），表单数据可能导致URL过长，或数据非7位ASCII编码。
【易错提示】
不要仅从安全性角度区分，GET和POST都不加密。实际开发中，GET请求参数暴露在URL中，不适合敏感信息；POST参数在请求体中，相对隐蔽。另外，RESTful API规范中，GET用于读取，POST用于创建，是更严格的区分。
```


**解析**

```text
【核心考点】 鉴权机制 Token 会话管理
【题目解析】
本题考查对Token鉴权机制的基本理解。Token是服务器生成的一串唯一字符串，用于无状态的身份验证。其核心原理是：用户登录后，服务器生成Token并与用户ID映射存储，客户端后续请求携带Token，服务器验证通过后即可识别用户身份。

- 服务器将Token返回给客户端，客户端保存（如本地存储或Cookie）。
```

## Q004122

- 题型：简答
- 难度：简单

**题目**

```text
简述同源策略?
```

**答案**

```text
浏览器为了内容的安全，只会允许同源的ajax请求，所谓的同源请求是指：协议相同，域名相同，端口相同的请求，其中一点不同就是非同源，即跨域。
例如:
http://www.example.com与https://www.example.com不同源
http://www.example.com与http://www.example.com:8000不同源
http://example.com与http:www.example.com不同源
```

**解析**

```text
【核心考点】 同源策略 跨域
【题目解析】
本题考查浏览器安全机制中的同源策略。同源策略是浏览器的一项核心安全策略，用于限制不同源之间的资源交互，防止恶意网站窃取数据。其核心定义是：协议、域名、端口三者完全一致才为同源，任一不同即为跨域。
【参考答案要点】
1. 定义：同源策略要求浏览器中的请求（如Ajax）必须与当前页面同源，即协议、域名、端口完全相同。
2. 跨域示例：http://www.example.com 与 https://www.example.com 不同源（协议不同）；http://www.example.com 与 http://www.example.com:8000 不同源（端口不同）；http://example.com 与 http://www.example.com 不同源（域名不同）。
```

## Q004137

- 题型：简答
- 难度：简单

**题目**

```text
请简单说一说get、post这 两种请求方法的区别?
```

**答案**

```text
GET与POST方法有以下区别：
（1） 在客户端，Get方式在通过URL提交数据，数据在URL中可以看到；POST方式，数据放置在HTML HEADER内提交。
（2） GET方式提交的数据最多只能有1024字节，而POST则没有此限制。
（3） 安全性问题。正如在（1）中提到，使用 Get 的时候，参数会显示在地址栏上，而 Post 不会。所以，如果这些数据是中文数据而且是非敏感数据，那么使用 get；如果用户输入的数据不是中文字符而且包含敏感数据，那么还是使用 post为好。
（4） 安全的和幂等的。所谓安全的意味着该操作用于获取信息而非修改信息。幂等的意味着对同一 URL 的多个请求应该返回同样的结果。完整的定义并不像看起来那样严格。换句话说，GET 请求一般不应产生副作用。从根本上讲，其目标是当用户打开一个链接时，她可以确信从自身的角度来看没有改变资源。比如，新闻站点的头版不断更新。虽然第二次请求会返回不同的一批新闻，该操作仍然被认为是安全的和幂等的，因为它总是返回当前的新闻。反之亦然。POST 请求就不那么轻松了。POST 表示可能改变服务器上的资源的请求。
```

**解析**

```text
【核心考点】 HTTP请求方法 GET与POST
【题目解析】
本题考查HTTP协议中GET和POST两种请求方法的区别，是Web开发和测试的基础知识。GET用于获取资源，参数在URL中可见；POST用于提交数据，参数在请求体中。两者在安全性、数据长度、幂等性等方面有显著差异。
【参考答案要点】
1. 数据传输方式：GET参数附加在URL后，可见；POST参数在请求体中，不可见。
2. 数据长度限制：GET受URL长度限制（通常1024字节），POST无限制。
3. 安全性：GET参数暴露在URL中，不适合敏感数据；POST相对安全。
4. 幂等性：GET是幂等的，多次请求结果相同；POST非幂等，可能产生副作用。
5. 缓存：GET请求可被缓存，POST通常不缓存。
【面试角度】
回答时建议结合实际项目场景，例如在API测试中如何选择GET和POST，以及如何验证其行为。面试官常追问RESTful API设计原则，可提前准备。
【易错提示】
不要混淆GET和POST的安全性与幂等性概念。GET是安全的（只读），POST不安全（可能修改数据）。另外，数据长度限制是浏览器和服务器共同决定的，并非HTTP协议本身限制。
```

## Q004138

- 题型：简答
- 难度：简单

**题目**

```text
请简单说一说get、post这两种请求方法的区别？
```

```text
参考

b.Get方式在传递参数的时候，一般都会把参数直接拼接在url上（例如:http://xxx?id=1&type=2）
c.Get请求方法可以传递的参数数据量是有限的（因为一般参数是拼接在url上，而浏览器对于url的长度是有限制的）
d.Get请求因为是直接将数据拼接在url上，所以安全性不如post强（相对），但是get的执行效率要快于post
Post：
a.一般往服务器提交数据的请求会设置为post方式
b.Post方式传递参数一般都会把参数放在请求体，而不会拼接在url
c.Post请求方法可以提交的数据量不受限制
Post请求传参相对于get要安全（相对不是绝对），但是post的执行效率不如get。
```

**解析**

```text
【核心考点】 HTTP请求方法 GET vs POST
【题目解析】
本题考察HTTP协议中GET和POST两种基本请求方法的区别，是Web开发和测试面试中的基础高频题。核心差异体现在：数据传输位置、数据量限制、安全性、幂等性及缓存行为等方面。
【参考答案要点】
1. 用途与语义：GET用于从服务器获取资源，POST用于向服务器提交数据（如创建/更新资源）。
2. 参数传递方式：GET参数拼接在URL中（如?id=1&type=2），POST参数放在请求体（body）中，URL不可见。
3. 数据量限制：GET受URL长度限制（浏览器通常限制2048字符），POST理论上无限制（受服务器配置影响）。
4. 安全性：GET参数暴露在URL中，易被缓存、记录，安全性较低；POST相对安全，但需配合HTTPS保障传输加密。
5. 幂等性：GET是幂等的（多次请求结果相同），POST非幂等（多次提交可能创建多个资源）。
6. 缓存：GET请求可被浏览器缓存，POST默认不缓存。
【面试角度】
面试时建议结合实际项目场景举例，如“查询用户信息用GET，登录提交用POST”，并补充RESTful API设计原则。同时可提及HTTPS对安全性的弥补作用，体现深度。
【易错提示】
不要混淆“GET比POST快”的原因：GET只需一次TCP连接（发送请求+接收响应），POST通常分两次（先发送请求头，服务器响应100 Continue后再发送body），但现代浏览器已优化，差异可忽略。
```

## Q004001

- 题型：简答
- 难度：中等

**题目**

```text
Cookie与Session区别
```

**答案**

```text
- Session是在服务端保存的一个数据结构，用来跟踪用户的状态，这个数据可以保存在集群、数据库、文件中

- Cookie是客户端保存用户信息的一种机制，用来记录用户的一些信息，也是实现Session的一种方式

- 区别

- session 在服务器端，cookie 在客户端（浏览器）

- session 默认被存在在服务器的一个文件里（不是内存）

- session 的运行依赖 session id，而通常情况下 session id 是存在 cookie 中的，也就是说，如果浏览器禁用了 cookie ，同时 session 也会失效（但是可以通过其它方式实现，比如在 url 中传递 session_id）
- session 可以放在 文件、数据库、或内存中都可以
- 用户验证这种场合一般会用 session
```

**解析**

```text
【核心考点】 Web 基础 会话管理 Cookie 与 Session
【题目解析】
本题考查 Web 开发中会话管理的核心概念。Session 和 Cookie 是维护用户状态的两大机制，理解其区别对于测试登录、购物车等场景至关重要。
【参考答案要点】
1. 存储位置：Session 数据存储在服务器端（文件、数据库或内存），Cookie 数据存储在客户端浏览器。
2. 安全性：Session 相对更安全，因为数据不直接暴露给客户端；Cookie 可被篡改或窃取，需加密敏感信息。
3. 生命周期：Session 默认在会话结束时销毁（或超时），Cookie 可设置过期时间实现持久化。
4. 容量限制：单个 Cookie 大小通常限制为 4KB，Session 无严格限制但受服务器资源影响。
5. 依赖关系：Session 通常依赖 Cookie 传递 Session ID（JSESSIONID），若禁用 Cookie 可通过 URL 重写或隐藏表单字段实现。
【易错提示】
常见误区：认为 Session 存储在内存中（实际可配置为文件或数据库）；忽略 Cookie 禁用对 Session 的影响。面试中常考察如何在不使用 Cookie 的情况下维持 Session。
```

## Q004002

- 题型：简答
- 难度：中等

**题目**

```text
GET，POST，PUT，DELETE 有什么区别？
```

**答案**

```text
1、GET：

GET请求会向数据库发送数据的请求，从而来获取信息，该请求就像数据库的select操作一样，只是用来查询数据，不会修改，增加数据，不会影响资源内容，即该请求不会产生副作用。无论进行多少次操作，结果都是一样的。

2、PUT：

PUT与GET不同的是，PUT请求是想服务器端发送数据的，从而改变信息，该请求就像数据库的update操作一样，用来修改数据的内容，但是不会增加数据的种类等，也就是说无论进行多少次PUT操作，其结果并没有不同。

3、POST：

POST请求同PUT请求类似，都是向服务器端发送数据的，但是该请求会改变数据的种类等资源，就像数据库的insert操作一样，会创建新的内容。几乎模前所有的提交操作都是用POST请求的。

4、DELETE：

DELETE求情顾名思义，就是用来删除某一行的，该请求就像数据库的delete操作一样。
```

**解析**

```text
【核心考点】 HTTP方法 RESTful API 幂等性
【题目解析】
本题考查HTTP协议中核心请求方法的语义区别，是Web开发和测试的必知基础。主要从幂等性、安全性和对服务器资源的影响三个维度区分。
【参考答案要点】
1. GET：用于获取资源，是安全且幂等的，不会改变服务器状态，参数通常放在URL中。
2. POST：用于创建新资源，非安全非幂等，每次请求可能产生不同结果（如重复提交订单），参数放在请求体中。
3. PUT：用于更新或替换资源，幂等，多次请求结果一致，通常需要指定资源ID。
4. DELETE：用于删除资源，幂等，删除后再次请求返回相同结果（如404）。
【面试角度】
面试中常结合幂等性场景提问，例如“为什么POST不安全而PUT安全？”或“如何设计幂等接口？”建议用支付接口举例说明幂等的重要性。
【易错提示】
容易混淆PUT和POST：PUT是幂等的，通常用于更新；POST用于创建，不幂等。另外，GET请求不应有副作用，但实际中可能因日志记录等产生轻微影响。
```

## Q004005

- 题型：简答
- 难度：中等

**题目**

```text
Http常见的响应状态码有哪些？
```

**答案**

```text
1XX --- 信息提示（表示临时的响应。客户端在收到常规响应之前，准备接收一个或多个1xx响应）
2XX --- 成功（表明服务器成功地接受了客户端请求）
3XX --- 重定向（客户端浏览器必须采取更多操作来实现请求。例如，浏览器可能不得不请求服务器上的不同的页面，或通过代理服务器重复该请求）
4XX --- 客户端错误（发送错误，客户端有问题。例如，客户端请求不存在的页面，客户端未提供有效的身份证验证信息）
5XX --- 服务器错误（服务器由于遇到错误而不能完成该请求）

常见的返回码有：
200 OK - [GET]：服务器成功返回用户请求的数据
201 CREATED - [POST/PUT/PATCH]：用户新建或修改数据成功
202 Aceepted - []：表示一个请求已经进入后台排队（异步任务）
204 NO CONTENT - [DELETE]：用户删除数据成功
400 INVALID REQUEST - [POST/PUT/PATCH]：用户发出的请求有错误，服务器没有进行新建或修改数据的操作
401 Unauthorized -[] ：表示用户没有权限（令牌、用户名、密码错误）
403 Forbidden -[] ：表示用户得到授权（与401错误相对），但是访问被禁止
404 NOT FOUND -[]：用户发出的请求针对得到是不存在的记录，服务器没有进行操作，该操作是幂等的
406 Not Acceptable - [GET]：用户请求的格式不可得（比如用户请求JSON格式，但是只有XML格式）
500 INTERNAL SERVER ERROR - [*]：服务器发生错误，用户将无法判断发出的请求是否成功
```

**解析**

```text
【核心考点】 HTTP状态码 网络协议
【参考答案要点】
1XX（信息提示）：表示请求已接收，继续处理。如 100 Continue。
2XX（成功）：请求成功被接收、理解、接受。常见：200 OK（GET请求成功）、201 Created（POST创建资源成功）、204 No Content（删除成功无返回体）。
3XX（重定向）：需要客户端进一步操作。常见：301 Moved Permanently（永久重定向）、302 Found（临时重定向）、304 Not Modified（缓存有效）。
4XX（客户端错误）：请求包含语法错误或无法完成。常见：400 Bad Request（参数错误）、401 Unauthorized（未认证）、403 Forbidden（无权限）、404 Not Found（资源不存在）、405 Method Not Allowed（请求方法不支持）。
5XX（服务器错误）：服务器处理请求出错。常见：500 Internal Server Error（服务器内部错误）、502 Bad Gateway（网关错误）、503 Service Unavailable（服务不可用）、504 Gateway Timeout（网关超时）。
【面试角度】
回答时建议结合实际调试经验，例如“遇到 502 时，我会先检查后端服务是否正常，再排查网关配置”，体现问题排查思路。
【延伸知识】
RESTful API 设计中，状态码的正确使用是重要规范，如用 201 表示创建成功，204 表示删除成功，避免滥用 200。
```

## Q004012

- 题型：简答
- 难度：中等

**题目**

```text
cookie和session什么意思，有什么区别？
```

**答案**

```text
cookie：是服务器发送到用户浏览器并保存在本地的一小块数据，它会在浏览器下次向同一服务器再发起请求时被携带并发送到服务器上。对于无状态的HTTP协议，它用于告知服务端两个请求是否来自同一浏览器，如保持用户的登录状态。
session：代表的是服务器与客户端的一次对话的过程，session对象储存用户的信息来保证登录状态，使得可以在页面之间相互跳转。可以通过以上的方法设计过滤器（当用户登录的时候将用户信息存储到session中，由此就可以实现，当session中没有用户信息时，拦截路径，返回到登录页面）。
cookie和session区别：
1、cookie它不是很安全，别人可以分析你存放在本地的cookie，进行这种欺骗，所以说考虑到这种安全性呢，我们最好使用session。
2、在一定时间之内，session它保存在服务器上，当访问越来越多，会比较占用服务器的资源性能，考虑到减轻服务器的资源性能方面，我们最好使用cookie。
3、单个cookie的保存数据是有限的，一般不会超过4K，很多浏览器都限制一个站点，最多保存20个cookie；而session呢它存在服务端，没有这种数据量的限制，可以保存更复杂的类型。
4、二者的生命周期有着明显的区别，cookie的生命周期它是累积的。而session的生命周期它是间隔的。
```

**解析**

```text
【核心考点】 HTTP协议 会话管理
【题目解析】
本题考查Cookie和Session的概念及区别。两者用于管理用户会话状态，但存储位置和安全性不同。Cookie存储在客户端，Session存储在服务器端。
【参考答案要点】
Cookie：服务器发送到浏览器并保存在本地的小数据块，用于标识用户，如保持登录状态。安全性较低，可被分析。
Session：服务器端存储的用户会话信息，通过Session ID关联，更安全。常用于页面间跳转的登录状态维护。
区别：
1. 存储位置：Cookie在客户端，Session在服务器端。
2. 安全性：Cookie不安全，Session相对安全。
3. 生命周期：Cookie可设置过期时间，Session通常随会话结束而失效。
4. 大小限制：Cookie有大小限制（通常4KB），Session无严格限制。
【面试角度】
回答时可结合实际应用，如“在登录功能中，使用Session存储用户信息，Cookie存储Session ID”。还可讨论安全措施，如设置HttpOnly属性防止XSS攻击。
【易错提示】
常见误解是认为Session完全替代Cookie，实际上两者常配合使用。另外，注意区分Session和Token，面试中可能延伸提问。
```

## Q004020

- 题型：简答
- 难度：中等

**题目**

```text
get和post区别是什么？
```

**答案**

```text
POST和GET都是向服务器提交数据，并且都会从服务器获取数据。
区别：
1）传送方式：get通过地址栏传输，post通过报文传输
2）传送长度：get参数有长度限制（受限于url长度），而post无限制
3）GET产生一个TCP数据包（对于GET方式的请求，浏览器会把http header和data一并发送出去，服务器响应200返回数据），POST产生两个TCP数据包（对于POST，浏览器先发送header，服务器响应100 continue，浏览器再发送data，服务器响应200 ok返回数据）
4）get请求参数会被完整保留在浏览历史记录里，而post中的参数不会被保留
5）在做数据查询时，建议用GET方式；而在做数据添加、修改或删除时，建议用post方式
```

**解析**

```text
【核心考点】 HTTP方法 GET与POST 网络基础
【参考答案要点】
1. 传送方式：GET通过URL参数传递数据，POST通过HTTP请求体（body）传递。
2. 传送长度：GET受URL长度限制（通常2048字符），POST理论上无限制。
3. 安全性：GET参数暴露在URL中，POST相对安全，但都不是加密协议。
4. 幂等性：GET是幂等的（多次请求结果相同），POST不幂等。
5. 缓存：GET请求可被浏览器缓存，POST默认不缓存。
6. 数据包数量：GET通常只产生一个TCP包（header+data一起发送），POST产生两个（先发header，服务器响应100 continue后再发data）。
【面试角度】
回答时建议结合实际应用场景，例如"查询操作用GET，提交表单用POST"，并提及RESTful API设计原则，能体现深度。
【延伸知识】
GET和POST在HTTP协议中本质都是TCP连接，区别主要由浏览器和服务器实现决定。HTTPS下数据加密，GET参数安全性有所提升但仍暴露在URL中。面试中常与RESTful API设计结合提问。
```

## Q004049

- 题型：简答
- 难度：中等

**题目**

```text
什么是Http协议?怎么解决HTTP协议无状态
```

**答案**

```text
无状态是指协议对于事务处理没有记忆能力，服务器不知道客户端是什么状态。即我们给服务器发送 HTTP 请求之后，服务器根据请求，会给我们发送数据过来，但是，发送完，不会记录任何信息。HTTP 是一个无状态协议，这意味着每个请求都是独立的，Keep-Alive 没能改变这个结果。缺少状态意味着如果后续处理需要前面的信息，则它必须重传，这样可能导致每次连接传送的数据量增大。另一方面，在服务器不需要先前信息时它的应答就较快。HTTP 协议这种特性有优点也有缺点，优点在于解放了服务器，每一次请求“点到为止”不会造成不必要连接占用，缺点在于每次请求会传输大量重复的内容信息。客户端与服务器进行动态交互的 Web 应用程序出现之后，HTTP 无状态的特性严重阻碍了这些应用程序的实现，毕竟交互是需要承前启后的，简单的购物车程序也要知道用户到底在之前选择了什么商品。于是，两种用于保持 HTTP 连接状态的技术就应运而生了，一个是 Cookie，而另一个则是 Session。
```

**解析**

```text
【核心考点】 HTTP协议 无状态 会话管理
【参考答案要点】
HTTP协议定义：HTTP（超文本传输协议）是应用层协议，用于客户端和服务器之间的通信。其特点是无状态，即服务器不保存客户端的状态信息，每个请求独立处理。
无状态的影响：优点：服务器无需维护状态，简化设计，提高并发能力；缺点：每次请求需携带完整上下文信息，导致重复传输，且无法实现会话保持（如购物车、登录状态）。
解决方案：
1. Cookie和Session：服务器生成Session ID，通过Cookie传递给客户端，后续请求携带Cookie，服务器根据Session ID识别用户。
2. Token机制：如JWT（JSON Web Token），客户端在登录后获取Token，后续请求在Header中携带Token，服务器验证Token有效性。
3. URL重写：在URL后附加会话标识，适用于Cookie被禁用的情况。
4. 隐藏表单域：在表单中嵌入会话信息，但安全性较低。
【面试角度】
回答时建议结合实际应用场景，例如“在电商项目中，我们使用Redis存储Session，实现分布式会话管理”，体现对方案选型的理解。
【延伸知识】
HTTP/2和HTTP/3在性能上有所改进，但无状态特性未变。RESTful API设计通常推荐无状态，以提升可伸缩性。
```

## Q004053

- 题型：简答
- 难度：中等

**题目**

```text
介绍一下http协议中的长链接
```

**答案**

```text
http/1.1协议中增加了长连接模型，它会保持连接去完成多次连续请求，减少了不断打开连接的时间。
```

**解析**

```text
【核心考点】 HTTP长连接 HTTP/1.1
【题目解析】
本题考查HTTP协议中长连接（Keep-Alive）的概念。HTTP/1.1默认使用长连接，允许在一个TCP连接上发送多个请求和响应，减少连接建立和关闭的开销，提升性能。
【参考答案要点】
1. 定义：HTTP长连接（持久连接）允许客户端和服务器在同一个TCP连接上连续发送多个HTTP请求和响应，无需每次重新建立连接。

注意区分HTTP长连接与WebSocket长连接：前者仍基于请求-响应模式，后者是全双工通信。另外，HTTP/1.1的长连接存在队头阻塞问题，HTTP/2通过多路复用解决。
```

```text
不要认为UI测试足够全面，接口测试能发现UI测试无法触及的后端逻辑缺陷，面试中常结合具体场景提问。
```

## Q004062

- 题型：简答
- 难度：中等

**题目**

```text
你做接口测试，测什么？
```

**答案**

```text
可用性测试
根据约定的协议、方法、格式内容，传输数据到接口经处理后返回期望的结果：
1、接口功能是否正确实现
2、返回值测试-返回值除了内容要正确，类型也要正确，保证调用方能够正确的解析
3、参数值边界值、等价类测试；错误和异常处理测试
4、输入异常值（空值、特殊字符、超长约定长度等），接口能正确处理，且按预期响应
5、输入错误的参数，接口能正常处理，按预期响应
6、多输入、少输入参数，接口能正常处理，按预期响应
7、错误传输数据格式（如json格式写成form格式）测试
安全性测试，主要指传输数据的安全性：
1、敏感数据（如密码、秘钥）等是否加密传输
2、返回数据是否含有敏感数据，如用户密码、完整的用户银行账号信息等
3、接口是否对传入的数据做安全校验，如身份ID加token类似校验
```

```text
在基本功能测试的基础上考虑输入输出的边界条件，这部分内容也会有重复的部分（比如业务规则的边界）。但是，前端的输入输出很多时候都是提供固守的值让用户选择（如下拉框），在这种情况下测试的边界范围就非常有限，但接口测试就不存在这方面的限制，相对来说接口可以覆盖的范围更广，同样的，接口出现问题的概率也更高。

3、性能测试：

这个比较容易区分，虽然都需要做性能测试，但关注点确大不相同。App端性能主要关注与手机相关的特性，如手机cpu、内存、流量、fps等。而接口性能主要关注接口响应时间、并发、服务端资源的使用情况等。两种测试时的策略和方法都有很大区别，所以这部分内容是需要分开单独进行测试的，理论上来说这也是不同的部分。
```

**解析**

```text
【核心考点】 接口测试 功能测试 边界分析 性能测试
【题目解析】
本题考察候选人对接口测试工作内容的全面理解。面试官希望了解候选人是否清楚接口测试的层次和重点，以及如何与前端测试区分。
【参考答案要点】
1. 基本功能测试：验证接口是否按预期处理请求和返回响应，包括正常和异常场景。2. 边界分析测试：测试输入参数的边界值，如最大值、最小值、空值等，接口测试可覆盖更广的边界条件。3. 性能测试：关注接口的响应时间、吞吐量、并发能力等，与App端性能（如CPU、内存）不同。4. 安全测试：鉴权、权限校验、SQL注入等。5. 异常测试：网络超时、服务端错误、参数非法等。
【易错提示】
容易遗漏安全测试和异常测试，或混淆接口性能测试与App性能测试。注意区分接口测试与前端测试的关注点。
【面试角度】
回答时建议结合实际项目经验，例如“在XX项目中，我们使用Postman进行功能测试，用JMeter做性能测试，并补充了安全测试用例”，展示全面性和实践能力。
```

## Q004124

- 题型：简答
- 难度：中等

**题目**

```text
讲一下get和post的区别
```

**答案**

```text
get和post的表象区分：
1、get获取资源 post提交数据
2、get参数是在url传输，post 请求体传输
3、get一般比post更不安全
4、get传参的长度限制 post没有

最根本区分：
get产生一个TCP数据包；post产生两个TCP数据包。
对于get方式的请求，浏览器会把http header和data一并发送出去，服务器响应200（返回数据）；
```

**解析**

```text
【核心考点】 HTTP协议 GET与POST
【题目解析】
GET和POST是HTTP最常用的两种请求方法，面试中常从表象和本质两个层面考察。表象区别包括参数位置、安全性、长度限制等；本质区别在于TCP数据包数量（GET一个，POST两个）及语义差异。
【参考答案要点】
表象区别：
1. GET用于获取资源，POST用于提交数据。
2. GET参数在URL中传输，POST在请求体中。
3. GET安全性较低（参数暴露），POST相对安全。

【面试角度】

【延伸知识】
现代浏览器和HTTP/2协议可能合并POST的TCP包，因此“两个包”的说法并非绝对，但仍是经典考点。
```

## Q004125

- 题型：简答
- 难度：中等

**题目**

```text
讲讲put和post的区别？？
```

**答案**

```text
Post:创建，不安全，不幂等。 Put：更新或创建，幂等
POST所对应的URI并非创建的资源本身，而是资源的接收者。
比如：POST 的语义是在http://www.forum.com/articles下创建一篇帖子，HTTP响应中应包含帖子的创建状态以及帖子的URI。两次相同的POST请求会在服务器端创建两份资源，它们具有不同的URI；所以，POST方法不具备幂等性。
而PUT所对应的URI是要创建或更新的资源本身。比如：PUT http://www.forum/articles/4231的语义是创建或更新ID为4231的帖子。对同一URI进行多次PUT的副作用和一次PUT是相同的；因此，PUT方法具有幂等性。
```

**解析**

```text
【核心考点】 HTTP方法 RESTful API
【题目解析】
本题考查 HTTP 方法 POST 和 PUT 的核心区别，主要在于幂等性和 URI 语义。POST 用于创建资源，不幂等；PUT 用于更新或创建资源，幂等。
【参考答案要点】
POST：用于创建资源，请求 URI 指向资源接收者（如集合），每次请求创建新资源，多次请求产生不同资源，因此不幂等。
PUT：用于更新或创建资源，请求 URI 指向具体资源（如特定 ID），多次请求结果相同，因此幂等。
【面试角度】
回答时建议结合实际 API 设计举例，例如“在用户注册接口中，POST /users 创建新用户，而 PUT /users/123 更新用户信息”，能加深理解。
【延伸知识】
PATCH 方法用于部分更新，与 PUT 不同，PATCH 不要求幂等性，但通常建议实现幂等。
```

## Q004139

- 难度：中等

**题目**

```text
请简述token， cookie 和session的区别
```

**答案**

```text
1、Session是在服务端保存的一个数据结构，用来跟踪用户的状态，这个数据可以保存在集群、数据库、文件中
2、Cookie是客户端保存用户信息的一种机制，用来记录用户的一些信息，也是实现Session的一种方式
3、token和session都属于服务端鉴权的一种方式
区别 ：
1、session 在服务器端，cookie 在客户端（浏览器）
2、session 默认被存在在服务器的一个文件里（不是内存）
3、session 的运行依赖 session id，而 session id 是存在 cookie 中的，也就是说，如果浏览器禁用了 cookie ，同时 session 也会失效（但是可以通过其它方式实现，比如在 url 中传递 session_id）
4、session 可以放在 文件、数据库、或内存中都可以。
5、用户验证这种场合一般会用 session
6、token是另一种鉴权实现方式
```

**解析**

```text

【参考答案要点】
1. Session：服务端保存的数据结构，用于跟踪用户状态，可存储在集群、数据库或文件中。依赖Session ID，通常存储在Cookie中。
2. Cookie：客户端（浏览器）保存用户信息的机制，用于记录用户信息，也是实现Session的一种方式。
3. Token：服务端鉴权的一种方式，通常用于无状态认证（如JWT），不依赖Cookie。
【区别】
存储位置：Session在服务端，Cookie在客户端（浏览器）。
存储方式：Session默认存储在服务器文件或内存中，Cookie存储在浏览器。
依赖关系：Session依赖Session ID，而Session ID通常存储在Cookie中，若浏览器禁用Cookie，Session可能失效。
【易错提示】
注意Token与Session的区别：Token是无状态的，通常不依赖服务端存储，而Session需要服务端维护状态。面试中常考察Token在分布式系统中的应用。
```
