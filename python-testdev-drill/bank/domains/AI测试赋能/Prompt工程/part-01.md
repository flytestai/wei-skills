## Q007084

- 题型：简答
- 难度：较难

**题目**

```text
你在测试平台中要求模型稳定输出结构化结果，但实际出现字段缺失和类型错乱。请给出你的提示模板与结构化输出验证方案。
```

**答案**

```text
我会先把问题拆成“模板设计”和“输出约束”两条线并行治理。第一步定义现象基线，统计字段缺失率、类型错误率、额外字段率和重试成功率，明确当前不稳定点。第二步提出假设：可能是提示模板层级不清、示例覆盖不足、约束语句位置错误，或者不同模型对格式遵从能力差异大。第三步做模板重构，固定角色、任务目标、输入边界、输出 Schema、失败处理和自检步骤，要求模型先校验再输出。第四步加入程序化校验，使用 JSON Schema 或 Pydantic 对响应做强校验，不合格结果触发自动重试与纠偏提示。第五步做对照实验，比较不同模板版本和不同模型在同一评测集上的通过率、平均修复轮次和总耗时。第六步形成持续回归，把失败样本沉淀为强对抗集，任何模板升级都需先过基线。这样结构化输出就从“靠提示词运气”升级为“模板+校验+回归”的稳定工程能力。
```

**解析**

```text
高分答案会讲到程序化校验和失败重试，不只停留在“多给几个示例”。面试官通常会追问如何平衡格式稳定性与响应速度。
```

## Q007085

- 题型：简答
- 难度：较难

**题目**

```text
在某AI测试平台中，你需要通过提示词让模型稳定生成可执行测试用例。现在产出经常出现字段缺失、边界条件不全。请描述你会怎样验证并迭代提示词，使结果更可控。
```

**答案**

```text
我会先把问题放进诊断链，而不是只靠经验改提示词。第一步梳理失败现象：字段缺失、格式不合法、场景覆盖不足、前后矛盾分别占比多少。第二步建立假设：可能是指令优先级不清、输出约束不强、示例不足，或者上下文输入质量不稳定。第三步收集证据：我会固定同一批需求文本，保存每轮提示词版本与输出，对每条结果按结构完整度、可执行性、边界覆盖率打分。第四步做A/B实验：分别测试角色定义、步骤模板、few-shot示例数量、约束语句位置对结果的影响，采用单变量控制避免互相干扰。第五步做结论与回归：把高分提示词封装成标准模板，同时把失败样例加入回归集，后续模型升级必须通过同一套门槛。这样我能把提示词优化从“个人技巧”变成“可度量、可复用、可交接”的工程能力。
```

**解析**

```text
面试中要体现提示词也需要版本化和回归，不只是“改几句文案”。易错点是没有统一评分标准，导致优化方向摇摆。可延伸说明如何把高分模板沉淀为团队规范，以及如何监控漂移。
```

## Q007086

- 题型：简答
- 难度：较难

**题目**

```text
如果团队已能写单条 Prompt，你会怎样把“Prompt链路”升级为可复用 Skill，并确保持续维护成本可控？
```

**答案**

```text
我会把升级路径拆成“标准化、模块化、运营化”。第一步标准化，把现有 Prompt 链路拆成固定节点：输入校验、任务分解、生成策略、结果校验、输出组装。每个节点定义参数契约和失败处理，避免依赖个人经验。第二步模块化，把高频能力抽象成可复用组件，例如需求解析器、用例生成器、断言补全器、报告摘要器，组件之间通过结构化 JSON 交互，降低耦合。第三步 Skill 封装，补齐元信息：适用场景、输入样例、禁用条件、质量门槛、调用成本。第四步质量控制，建立静态检查和动态回归。静态检查关注字段完整、格式合法、规则命中；动态回归关注采纳率、错误率、稳定性和执行耗时。第五步成本控制，用指标驱动维护优先级：若某 Skill 复用率低且维护成本高，应降级或淘汰；若高频高价值则持续投入。第六步版本治理，支持灰度发布、回滚和兼容策略，避免一次升级影响全量项目。第七步组织机制，设立 Skill 评审和复盘节奏，把失败样本反哺模板。这样做可以把“个人会写 Prompt”升级为“团队可复用能力库”，并通过数据化运营控制长期维护成本。
```

**解析**

```text
高质量回答应体现从一次性产出到可运营资产的转变，并给出明确淘汰和升级机制。
```

## Q007087

- 题型：简答
- 难度：较难

**题目**

```text
请你完整说明测试 Prompt 八大结构要素的设计逻辑，并解释每个要素缺失时可能导致的失败模式。
```

**答案**

```text
我会先给出设计原则：Prompt 八要素的目标是把“语言不确定性”压缩成“可验证输出”。推荐八要素为：任务目标、角色身份、业务上下文、输入约束、输出格式、评判标准、示例对齐、边界与异常。任务目标缺失会导致模型泛化，产出看似完整却偏题；角色身份缺失会导致语气和粒度漂移，影响可读与可执行性；业务上下文缺失会触发错误假设；输入约束缺失会出现字段遗漏和参数污染；输出格式缺失会让下游系统无法解析；评判标准缺失会导致“答得多但不命中”；示例缺失会让模型不知期望深度；边界缺失会引发越权建议或高风险动作。设计逻辑上，前四项约束“理解输入”，中两项约束“组织输出”，后两项约束“风险与一致性”。在测试场景中，我会增加一层可观测要求：每次输出要附理由、证据来源和置信度，便于评审。验证方式采用离线基准集+线上抽检双轨：离线看结构完整率、格式合规率、命中率；线上看采纳率、返工率和误导率。最后做版本管理，Prompt 模板变更必须记录动机、影响范围、回滚方案，避免团队多人并行时“模板漂移”。这样八要素就不是写作技巧，而是可评测、可迭代的工程规范。
```

**解析**

```text
重点看候选人是否能将八要素串成输入-输出-风险三段式方法，并讲清验证与版本治理。
```
