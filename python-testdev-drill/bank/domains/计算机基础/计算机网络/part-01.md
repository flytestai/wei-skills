```text
DNS是什么？
```

**选项**

```text
A. 域名解析
B. 环球网
C. 文件传输协议
D. 远程登录协议
```

**答案**

```text
A
```

**正确选项**

```text
A. 域名解析
```

**解析**

```text
【核心考点】 网络基础知识 DNS
【题目解析】
本题考查DNS（域名系统）的基本概念，属于计算机网络的基础知识。DNS用于将域名解析为IP地址，是互联网访问的关键服务。
```


**解析**

```text
【核心考点】 DNS 网络基础
【题目解析】
本题考查DNS（域名系统）的基本作用，属于计算机网络基础知识。DNS的核心功能是将人类易记的域名（如www.example.com）解析为机器可读的IP地址（如192.0.2.1），解决IP地址难以记忆的问题。
```

## Q005217

- 题型：简答
- 难度：入门

**题目**

```text
http和https的区别？？
```

**答案**

```text
http是明文传输的，https是加密传输的
两个的端口不不一样，http端口80，https端口443
两个的连接方式也不一样
https是要ca证书的，大多数是要收费的

https主要是多了ssl协议，主要是这上面的区别吧，还有安全上面的区别，其他的也没什么，

准确说是：CA机构颁发的SSL证书是收费的
```

**解析**

```text
【核心考点】 HTTP HTTPS 网络安全
【参考答案要点】
1. 传输方式：HTTP是明文传输，数据可被截获；HTTPS通过SSL/TLS协议加密传输，保证数据机密性和完整性。
2. 端口：HTTP默认端口80，HTTPS默认端口443。
3. 证书：HTTPS需要CA机构颁发的SSL证书（通常收费），用于身份验证；HTTP无此要求。
4. 连接方式：HTTPS在HTTP基础上增加了SSL握手过程，建立安全连接。
【面试角度】
面试时，除了列出区别，建议结合实际场景说明，例如“在支付接口测试中，必须使用HTTPS确保数据安全”。同时，了解HTTPS的握手过程（如非对称加密交换对称密钥）会加分。
【延伸知识】
HTTPS的SSL证书有DV（域名验证）、OV（组织验证）、EV（扩展验证）三种类型，安全性逐级递增。测试中需注意证书过期或无效导致的连接错误。
```

## Q005237

- 题型：简答
- 难度：入门

**题目**

```text
么是 IP 地址？
```

**答案**

```text
IP 地址是指互联网协议地址（英语：Internet Protocol Address，又译为网际协议地址），是 IP Address
的缩写。IP 地址是 IP 协议提供的一种统一的地址格式，它为互联网上的每一个网络和每一台主机分配一个逻
辑地址，以此来屏蔽物理地址的差异
```

**解析**

```text
【核心考点】 计算机网络基础 IP地址
【题目解析】
本题考查IP地址的基本概念。IP地址是网络通信的基础，面试中常作为基础知识题出现。回答应清晰定义IP地址的作用、分类和表示方法。
【参考答案要点】
1. 定义：IP地址（Internet Protocol Address）是互联网协议地址的简称，是分配给连接到互联网或局域网设备的数字标签，用于标识网络中的设备。
2. 作用：IP地址为网络中的每一台主机分配一个唯一的逻辑地址，用于数据包的路由和寻址，屏蔽底层物理地址的差异，实现不同网络间的通信。
3. 分类：
IPv4：32位二进制数，通常用点分十进制表示（如192.168.1.1），分为A、B、C、D、E五类，其中A、B、C为常用地址。
IPv6：128位二进制数，用冒号分隔的十六进制表示（如2001:0db8:85a3:0000:0000:8a2e:0370:7334），旨在解决IPv4地址枯竭问题。
4. 特殊地址：如127.0.0.1（本地回环地址）、192.168.x.x（私有地址）、0.0.0.0（默认路由）等。
【面试角度】
回答时建议结合测试场景，例如“在测试中，我们常通过ping 127.0.0.1检查本地网络协议栈是否正常”，或“使用私有地址进行局域网测试”。同时，可以提及IP地址与MAC地址的区别，展示更全面的知识储备。
【易错提示】
常见错误：混淆IP地址与MAC地址，或将IPv4的32位误写为64位。务必牢记IPv4是32位，IPv6是128位。
```

## Q005238

- 难度：入门

**题目**

```text
什么是 DNS？
```

**答案**

```text
DNS 是域名系统 (Domain Name System)，DNS 是用来做域名解析的,它会在你上网输入
网址后，把它转换成 IP，然后去访问对方服务器；
```

**解析**

```text
【核心考点】 DNS 域名解析 网络基础
【题目解析】
本题考察网络基础知识中的 DNS 概念。DNS 是互联网核心服务之一，负责将人类易记的域名（如 www.example.com）转换为机器可读的 IP 地址。
【参考答案要点】
DNS（Domain Name System，域名系统）是一种分布式数据库系统，主要功能是将域名解析为对应的 IP 地址。当用户在浏览器输入网址时，DNS 服务器会查询并返回目标服务器的 IP，从而建立连接。

【延伸知识】
DNS 解析过程：浏览器缓存 → 操作系统缓存 → 本地 DNS 服务器 → 根 DNS 服务器 → 顶级域服务器 → 权威 DNS 服务器，最终返回 IP 地址。
```


## Q005221

- 题型：简答
- 难度：简单

**题目**

```text
pop3和imap4什么区别？
```

**答案**

```text
POP3协议允许电子邮件客户端下载服务器上的邮件，但是在客户端的操作（如移动邮件、标记已读等），不会反馈到服务器上，比如通过客户端收取了邮箱中的3封邮件并移动到其他文件夹，邮箱服务器上的这些邮件是没有同时被移动的 。

而IMAP提供webmail 与电子邮件客户端之间的双向通信，客户端的操作都会反馈到服务器上，对邮件进行的操作，服务器上的邮件也会做相应的动作。

同时，IMAP像POP3那样提供了方便的邮件下载服务，让用户能进行离线阅读。IMAP提供的摘要浏览功能可以让你在阅读完所有的邮件到达时间、主题、发件人、大小等信息后才作出是否下载的决定。此外，IMAP 更好地支持了从多个不同设备中随时访问新邮件。
```

**解析**

```text
【核心考点】 邮件协议 POP3 IMAP4
【题目解析】
本题考查POP3和IMAP4两种电子邮件协议的核心区别。两者都是用于接收邮件的协议，但工作方式不同。
【参考答案要点】
POP3（Post Office Protocol 3）：
客户端将邮件从服务器下载到本地，服务器上的邮件通常会被删除（可配置保留）。客户端的操作（如移动、删除、标记已读）不会同步到服务器，因此不同设备间无法保持一致状态。
IMAP4（Internet Message Access Protocol 4）：
邮件保留在服务器上，客户端操作（如移动、删除、标记已读）会实时同步到服务器。支持多设备访问，状态一致。提供摘要浏览功能，可先查看邮件头信息再决定是否下载。
【面试角度】
回答时建议结合实际使用场景，例如：如果只用一台电脑收邮件，POP3足够；如果需要在手机、电脑、平板等多设备上同步邮件状态，则IMAP更合适。
【易错提示】
不要混淆POP3和SMTP（发送邮件协议），SMTP用于发送邮件，POP3/IMAP用于接收。
```

## Q005223

- 题型：简答
- 难度：简单

**题目**

```text
tcp三次握手过程
```

**答案**

```text
第一次握手: 客户端将标志位SYN置为1，随机产生一个值序列号seq=x，并将该数据包发送给服务端，客户端 进入SYN_SEND状态，等待服务端确认。

第二次握手: 服务端收到数据包后由标志位SYN=1知道客户端请求建立连接，服务端将标志位SYN和 ACK都置为1，然后ack=x+1,随机产生一个值seq=y，并将该数据包发送给客户端以确认连接请求，即SYN+ACK包，此时服务器进入SYN_RECV状态。

第三次握手: 客户端收到确认后检查,如果正确则将标志位ACK为1，ack=y+1，并将该数据包发送给服务端，此包发送完毕，服务端进行检查如果正确则连接建立成功，客户端和服务器进入ESTABLISHED状态，完成三次握手，随后客户端和服务端之间可以开始传输 数据了。
```

**解析**

```text
【核心考点】 TCP/IP协议 三次握手
【参考答案要点】
第一次握手：客户端发送SYN=1，seq=x，进入SYN_SEND状态。
第二次握手：服务端回复SYN=1，ACK=1，ack=x+1，seq=y，进入SYN_RECV状态。
第三次握手：客户端发送ACK=1，ack=y+1，进入ESTABLISHED状态，服务端收到后也进入ESTABLISHED。
【面试角度】
面试官常追问为什么需要三次握手而不是两次？核心原因是防止已失效的连接请求突然传到服务端，造成资源浪费。回答时强调“防止历史连接初始化”和“确保双方收发能力正常”。
【易错提示】
注意区分seq和ack的含义：seq是发送方自己的序列号，ack是期望对方下次发送的序列号。第三次握手可以携带数据，前两次不行。
```

```text
什么是ARQ？
```

```text
又称自动请示重发，是一种差错控制方法；要求接收方检测出差错时，就设法通知发送端重发，直到正确的数据收到为止。
```

**解析**

```text
【核心考点】 ARQ 差错控制 网络协议
【题目解析】
本题考察ARQ（自动重传请求）的基本概念，属于网络通信中的差错控制机制。ARQ的核心是接收方检测到错误后，请求发送方重传数据，直到正确接收为止。回答需简明扼要地说明其工作原理和常见类型。

【易错提示】
避免将ARQ与FEC（前向纠错）混淆，ARQ依赖重传，FEC通过冗余数据纠错。另外，注意超时重传是ARQ的一种实现方式。
```

## Q005241

- 题型：简答
- 难度：简单

**题目**

```text
什么是C/S，什么是B/S？
```

**答案**

```text
C/S （Client/Server）结构，即大家熟知的客户机和服务器结构。它是软件系统体系结构，通过它可以充分利用两端硬件环境的优势，将任务合理分配到Client端和Server端来实现，降低了系统的通讯开销。目前大多数应用软件系统都是Client/Server形式的两层结构，由于现在的软件应用系统正在向分布式的Web应用发展，Web和Client/Server 应用都可以进行同样的业务处理，应用不同的模块共享逻辑组件；因此，内部的和外部的用户都可以访问新的和现有的应用系统，通过现有应用系统中的逻辑可以扩展出新的应用系统。这也就是目前应用系统的发展方向。
B/S（Browser/Server）结构即浏览器和服务器结构。它是随着Internet技术的兴起，对C/S结构的一种变化或者改进的结构。在这种结构下，用户工作界面是通过WWW浏览器来实现，极少部分事务逻辑在前端（Browser）实现，但是主要事务逻辑在服务器端（Server）实现，形成所谓三层3-tier结构。这样就大大简化了客户端电脑载荷，减轻了系统维护与升级的成本和工作量，降低了用户的总体成本（TCO）。以目前的技术看，局域网建立B/S结构的网络应用，并通过Internet/Intranet模式下数据库应用，相对易于把握、成本也是较低的。它是一次性到位的开发，能实现不同的人员，从不同的地点，以不同的接入方式（比如LAN, WAN, Internet/Intranet等）访问和操作共同的数据库；它能有效地保护数据平台和管理访问权限，服务器数据库也很安全 。特别是在JAVA这样的跨平台语言出现之后，B/S架构管理软件更是方便、快捷、高效。
```

**解析**

```text
【核心考点】 软件架构 C/S与B/S
【参考答案要点】
C/S（Client/Server）结构：即客户机和服务器结构。它充分利用两端硬件环境的优势，将任务合理分配到Client端和Server端实现，降低系统通讯开销。通常为两层结构，客户端负责用户界面和部分业务逻辑，服务器端负责数据管理和核心业务处理。
B/S（Browser/Server）结构：即浏览器和服务器结构。用户通过浏览器访问Web服务器，服务器端集中处理业务逻辑和数据存储。B/S是三层或多层结构，客户端无需安装特定软件，维护和升级更方便。
【面试角度】
回答时建议结合实际项目经验，例如“在我参与的项目中，C/S结构用于内部管理系统，B/S结构用于面向客户的Web应用”，并对比两者的优缺点，如C/S响应快但维护成本高，B/S跨平台但依赖网络。
【延伸知识】
```

## Q005298

- 题型：简答
- 难度：简单

**题目**

```text
客户端使用 DHCP 获取 IP 的过程？
```

**答案**

```text
发现阶段：即 DHCP 客户端寻找 DHCP 服务器的阶段。
提供阶段：即 DHCP 服务器提供 IP 地址的阶段。
选择阶段：即 DHCP 客户端选择某台 DHCP 服务器提供的 IP 地址的阶段。
确认阶段：即 DHCP 服务器确认所提供的 IP 地址的阶段。
```

**解析**

```text
【核心考点】 DHCP协议 网络基础
【题目解析】
本题考查DHCP（动态主机配置协议）的基本工作流程，属于网络基础知识。DHCP通过四个阶段实现IP地址的自动分配：发现、提供、选择、确认，通常简称为DORA过程。
【参考答案要点】
1. 发现阶段（Discover）：DHCP客户端以广播方式发送DHCP Discover报文，寻找网络中的DHCP服务器。
2. 提供阶段（Offer）：DHCP服务器收到Discover报文后，从IP地址池中挑选一个未分配的IP地址，以广播方式回复DHCP Offer报文，包含IP地址、子网掩码、租期等信息。
3. 选择阶段（Select）：客户端可能收到多个Offer，选择其中一个（通常是第一个到达的），并以广播方式发送DHCP Request报文，告知所有服务器自己选择了哪个IP。
4. 确认阶段（Acknowledge）：被选中的服务器收到Request后，发送DHCP Ack报文确认分配，客户端即可使用该IP地址；其他服务器收回未选中的Offer。
【面试角度】
面试中常会追问DHCP租期续约和DHCP中继代理的概念，建议提前准备。此外，理解广播与单播的转换（如确认阶段可能使用单播）也能体现深度。
【易错提示】
注意：选择阶段客户端发送的是广播Request，而非单播，目的是通知所有服务器。另外，Offer阶段服务器也可能使用广播（取决于客户端标志位）。
```

## Q005302

- 题型：简答
- 难度：简单

**题目**

```text
常用路由协议有哪些
```

**答案**

```text
常用的Internet路由协议有RIP、OSPF、IS-IS、IGRP、EIGRP、BGP等
```

**解析**

```text
【核心考点】 网络协议 路由协议
【题目解析】
本题考查计算机网络基础知识，要求列举常用的Internet路由协议。路由协议用于路由器之间交换路由信息，决定数据包的最佳路径。
【参考答案要点】
常用的Internet路由协议包括：
1. RIP（路由信息协议）：基于距离向量算法，使用跳数作为度量，最大跳数为15，适用于小型网络。
2. OSPF（开放最短路径优先）：基于链路状态算法，计算最短路径，收敛速度快，适用于大型网络。
3. IS-IS（中间系统到中间系统）：类似OSPF，常用于ISP骨干网络。
4. IGRP（内部网关路由协议）：思科私有协议，基于距离向量，支持复合度量。
5. EIGRP（增强型内部网关路由协议）：思科私有协议，结合距离向量和链路状态特性，收敛快。
6. BGP（边界网关协议）：用于不同自治系统之间的路由，是Internet的核心路由协议。
【面试角度】
面试中常会追问RIP和OSPF的区别，以及BGP的工作原理，建议重点理解动态路由协议的分类（距离向量 vs 链路状态）和适用场景。
【易错提示】
容易混淆内部网关协议（如RIP、OSPF）和外部网关协议（如BGP），注意BGP主要用于自治系统间路由。
```

## Q005321

- 题型：简答
- 难度：简单

**题目**

```text
简述http与https的区别？
```

**答案**

```text
从安全性来说：http明文传输，易受攻击，无法确认双方身份，也无法保证数据的完整性；https使用ssl加密传输协议，信息是密文，可以认证双方身份，防止信息被截取篡改，安全性相比http要高
从端口来看：http默认端口80，https默认端口443
灵活性上：http简单快速，使用灵活；https技术门槛较高，多数个人或私人网站难以支撑
访问速度：http协议简单，http服务器的程序规模小，因而通信速度很快；https加重了服务端负担，需要更多的资源来支撑，降低了用户的访问速度
经济适用度：http没有额外的费用要求，https协议CA机构颁发的证书都是需年费的，此外对接https协议也需要额外的技术支持
```

**解析**

```text
【核心考点】 HTTP与HTTPS协议 网络安全
【题目解析】
本题考查HTTP与HTTPS协议的核心区别，包括安全性、端口、性能、成本等方面。HTTP是明文传输，HTTPS通过SSL/TLS加密，提供身份认证和数据完整性保护。
【参考答案要点】
1. 安全性：HTTP明文传输，易被窃听和篡改；HTTPS使用SSL/TLS加密，信息密文传输，可认证双方身份，防止中间人攻击。
2. 端口：HTTP默认端口80，HTTPS默认端口443。
3. 灵活性：HTTP简单快速，易于实现；HTTPS技术门槛较高，需配置证书，对个人网站不友好。
4. 访问速度：HTTP通信速度快，服务器负载小；HTTPS因加密解密过程增加延迟，需更多资源，速度较慢。
```

## Q005323

- 题型：简答
- 难度：简单

**题目**

```text
简述一下C/S架构和B/S架构的区别？
```

**答案**

```text
1.C/S又称Client/Server或客户/服务器模式。服务器通常采用高性能的PC、工作站或小型机，并采用大型数据库系统，如Oracle、Sybase、Informix或SQLServer。客户端需要安装专用的客户端软件。

B/S是Brower/Server的缩写，客户机上只要安装一个浏览器（Browser），如Netscape Navigator或Internet Explorer，服务器安装Oracle、Sybase、Informix或SQL Server等数据库。浏览器通过Web Server 同数据库进行数据交互。

2.Client/Server是建立在局域网的基础上的。

Browser/Server是建立在广域网的基础上的.

3．硬件环境不同:

C/S 一般建立在专用的网络上, 小范围里的网络环境, 局域网之间再通过专门服务器提供连接和数据交换服务.

B/S 建立在广域网之上的, 不必是专门的网络硬件环境,例与电话上网, 租用设备. 信息自己管理. 有比C/S更强的适应范围, 一般只要有操作系统和浏览器就行

4．对安全要求不同

C/S 一般面向相对固定的用户群, 对信息安全的控制能力很强.一般高度机密的信息系统采用C/S 结构适宜. 可以通过B/S发布部分可公开信息.

B/S 建立在广域网之上, 对安全的控制能力相对弱, 面向是不可知的用户群.

5．对程序架构不同

C/S 程序可以更加注重流程, 可以对权限多层次校验, 对系统运行速度可以较少考虑.

B/S 对安全以及访问速度的多重的考虑, 建立在需要更加优化的基础之上. 比C/S有更高的要求 B/S结构的程序架构是发展的趋势, 从MS的.Net系列的BizTalk 2000 Exchange 2000等, 全面支持网络的构件搭建的系统. SUN 和IBM推的JavaBean 构件技术等,使 B/S更加成熟.
```

**解析**

```text
【核心考点】 C/S架构 B/S架构 软件架构
【题目解析】
本题考查C/S（客户端/服务器）和B/S（浏览器/服务器）两种架构的区别，是软件测试和开发的基础知识。两者在部署、维护、性能、安全性等方面有显著差异。
【参考答案要点】
1. 架构定义：
- C/S：客户端需要安装专用软件，服务器端处理业务逻辑和数据。适用于局域网，响应速度快。
- B/S：客户端通过浏览器访问，服务器端处理所有逻辑。适用于广域网，部署和维护方便。
2. 主要区别：
- 部署与维护：C/S需更新客户端，B/S只需更新服务器。
- 性能：C/S通常更快，因为客户端分担部分计算；B/S依赖网络带宽。
- 安全性：C/S更安全，因为数据在局域网传输；B/S暴露在公网，需更多安全措施。
- 跨平台：B/S天然跨平台，C/S需为不同系统开发不同版本。
【面试角度】
回答时建议结合测试实践，例如“在测试B/S系统时，需要关注不同浏览器的兼容性；而C/S系统则需关注客户端安装和升级的测试”。
【延伸知识】
现代应用常采用混合架构，如移动端APP（C/S）配合Web管理后台（B/S）。了解RESTful API和微服务架构对测试的影响也会加分。
```

```text
C/S模式需要安装后才能使用, 即以软件的形式存在

优点:
1. 由于客户端实现与服务端的直接相连, 没有中间环节, 因此响应速度快
2. 操作界面漂亮, 形式多样, 可以充分满足客户自身的个性化要求

不需要安装客户端, 在网页上就可以访问, 即以浏览器为载体的形式呈现

优点:
1. 具有分布性特点, 可以随时随地进行查询, 浏览等业务处理
2. 业务扩展简单方便, 通过增加网页即可增加服务器功能.
3. 维护简单方便, 只需要改变网页, 即可实现所有用户的同步更新
4. 开发简单, 共享性强

缺点:
1. 个性化特点明显降低, 无法实现具有个性化的功能要求.
2. 操作是以鼠标为最基本的操作方式, 无法满足快速操作的要求.
3. 页面动态刷新, 响应速度明显降低.
4. 无法实现分页显示, 给数据库访问造成较大的压力
5. 功能弱化, 难以实现传统模式下的特殊功能要求
```

**解析**

```text
【核心考点】 软件架构 C/S模式 B/S模式
【题目解析】
本题考查C/S（客户端/服务器）和B/S（浏览器/服务器）两种软件架构模式的区别。这是软件测试面试中的基础概念题，理解两者的优缺点有助于测试策略的制定。
【参考答案要点】
C/S模式（客户端/服务器）：需要安装客户端软件，直接与服务器通信，响应速度快，界面可定制性强，但部署和升级较麻烦。适用于局域网环境或对交互要求高的应用（如游戏、办公软件）。
B/S模式（浏览器/服务器）：通过浏览器访问，无需安装客户端，维护方便，跨平台性强，但受网络影响较大，界面交互能力相对较弱。适用于互联网应用（如Web系统、电商平台）。
对比：C/S模式安全性较高，B/S模式更易扩展；C/S模式适合处理复杂业务，B/S模式适合轻量级应用。
【面试角度】
回答此类问题时，建议结合实际项目中的架构选择举例说明，例如“在测试P2P项目时，我们采用B/S架构，主要关注浏览器兼容性和网络延迟”，能体现应用能力。
【易错提示】
容易忽略的是C/S模式也支持离线操作，而B/S模式通常需要网络连接。另外，现代应用常采用混合架构，如使用B/S前端但后端有C/S组件。
```

```text
本题考查对OSI（开放系统互连）参考模型的基本概念理解。OSI模型是国际标准化组织（ISO）制定的一个概念性框架，用于标准化网络通信，使不同厂商的计算机系统能够互连。其核心思想是将复杂的网络通信过程分解为七个层次，每一层负责特定的功能，并为上层提供服务。
【参考答案要点】
1. 定义：OSI（Open System Interconnection）模型，即开放系统互连参考模型，是一种将计算机网络通信划分为七个层次的概念模型。
2. 主要功能：实现不同网络系统、不同主机之间的可靠通信，通过分层结构降低网络设计的复杂性。
3. 七层结构（从下到上）：
物理层：负责传输原始比特流，定义物理接口的机械、电气、功能和规程特性。
数据链路层：将比特流封装成帧，提供节点到节点的可靠传输，处理差错控制和流量控制。
网络层：负责数据包的路由选择和转发，实现端到端的通信，核心协议是IP。
传输层：提供端到端的可靠或不可靠数据传输，核心协议是TCP和UDP。
会话层：管理会话的建立、维护和终止，控制对话的同步。
表示层：处理数据的表示、加密、压缩和格式转换，确保不同系统间的数据语义一致。
应用层：为应用程序提供网络服务接口，如HTTP、FTP、SMTP等。
【面试角度】
回答时建议结合TCP/IP模型进行对比，说明OSI模型是理论模型，而TCP/IP是事实标准。同时，可以举例说明每一层的典型协议（如HTTP属于应用层，TCP属于传输层），展示对网络分层思想的深入理解。
【易错提示】
常见错误是混淆OSI模型与TCP/IP模型的层次对应关系，例如将IP协议归为传输层。务必牢记：IP是网络层协议，TCP/UDP是传输层协议。
```

```text
【易错提示】
容易混淆IP与TCP的层次，或误认为UDP也提供可靠性保证。
```

## Q005188

- 题型：简答
- 难度：中等

**题目**

```text
NAT是什么，有什么好处，能带来什么问题？
```

**答案**

```text
1、 NAT，Network Address Translation，网络地址转换协议，当在专用网内部的一些主机本来已经分配到了本地IP地址，但现在又想和因特网上的主机通信（并不需要加密）时，可使用NAT方法进行地址的转化。所有使用本地地址的主机在和外界通信时，都要用NAT其本地地址转换成全球IP地址，才能和因特网连接。
好处：
1、这种通过使用少量的公有IP 地址代表较多的私有IP 地址的方式，将有助于减缓可用的IP地址空间的枯竭。
2、NAT 增强了与公有网络连接的灵活性。为了确保可靠的公有网络连接，可以实施多池、备用池和负载均衡池。
3、NAT 提供了网络安全性。由于私有网络在实施 NAT 时不会通告其地址或内部拓扑，因此在实现受控外部访问的同时能确保安全。
带来的问题：
1、影响性能。转换数据包报头内的每个 IP 地址需要时间，因此 NAT 会增加交换延迟；
2、端到端 IP 可追溯性也会丧失。由于经过多个 NAT 地址转换点，数据包地址已改变很多次，因此追溯数据包将更加困难，排除故障也更具挑战性。
3、使用 NAT 也会使隧道协议(例如 IPsec)更加复杂，因为 NAT 会修改报头中的值，从而干扰 IPsec 和其它隧道协议执行的完整性检查。
```

**解析**

```text
【核心考点】 网络协议 NAT
【题目解析】
本题考察网络地址转换（NAT）的基本概念、优点和潜在问题。NAT是解决IPv4地址短缺的关键技术，但也会带来一些副作用。
【参考答案要点】
1. NAT定义：NAT（Network Address Translation）将私有IP地址转换为公有IP地址，使内网主机能访问互联网。它通常部署在路由器或防火墙上。
2. 好处：
- 缓解IP地址枯竭：多个私有IP共享一个公有IP，节省地址资源。
- 增强灵活性：支持多池、备用池和负载均衡池，确保可靠连接。
- 提供安全性：隐藏内部网络结构，外部无法直接访问内网主机，增加攻击难度。
3. 带来的问题：
- 端到端连通性破坏：NAT打破了IP端到端模型，某些协议（如P2P、VoIP）需要额外处理（如STUN、TURN）。
- 性能开销：NAT转换增加延迟和CPU负载。
- 日志和追踪困难：多个内网主机共享一个IP，导致审计和故障排查复杂。
【面试角度】
面试官可能关注NAT在实际网络中的影响，例如“如何解决NAT导致的P2P连接问题”。建议提及NAT穿透技术（如UDP打洞）。
【延伸知识】
NAT类型包括静态NAT、动态NAT和端口地址转换（PAT）。IPv6普及后，NAT需求将减少，但过渡期仍重要。
```

## Q005201

```text
TCP和UDP有什么区别?
```

**答案**

```text

3、UDP具有较好的实时性，工作效率比TCP高，适用于对高速传输和实时性有较高的通信或广播通信。

4.每一条TCP连接只能是点到点的;UDP支持一对一，一对多，多对一和多对多的交互通信
```

```text
2. 可靠性：TCP提供可靠传输（无差错、不丢失、按序到达），UDP尽最大努力交付，不保证可靠。
3. 实时性：UDP实时性更好，效率高，适用于高速传输和广播。

【易错提示】
```

## Q005206

- 题型：简答
- 难度：中等

**题目**

```text
cookie,session的区别?
```

**答案**

```text
相似点：都是存储器用户的信息。
不同点：
1、cookie是存储在我们的客户端，而session是存储在我们的服务器上面
2、cookie不是很安全，别人可以分析存放在本地的COOKIE并进行COOKIE欺骗,如果主要考虑到安全应当使用session
3、session会在一定时间内保存在服务器上。当访问增多，会比较占用你服务器的性能，如果主要考虑到减轻服务器性能方面，应当使用COOKIE

4、单个cookie在客户端的限制是3K，就是说一个站点在客户端存放的COOKIE不能3K。
5、所以：将登陆信息等重要信息存放为SESSION;其他信息如果需要保留，可以放在COOKIE中
```

**解析**

```text
【核心考点】 Web基础 会话管理 安全测试
【题目解析】
本题考查Cookie和Session的核心区别，是Web开发和测试面试中的高频题。两者都是用于存储用户会话信息，但存储位置、安全性、性能影响和容量限制有显著差异。
【参考答案要点】
1. 存储位置：Cookie存储在客户端（浏览器），Session存储在服务器端。
2. 安全性：Cookie不安全，易被篡改或伪造（Cookie欺骗）；Session相对安全，敏感信息应放在Session中。
3. 性能影响：Session存储在服务器，访问量大会占用服务器内存；Cookie存储在客户端，对服务器性能影响小。
4. 容量限制：单个Cookie大小限制约3KB（不同浏览器略有差异），Session无此限制。
5. 使用建议：登录信息等重要数据用Session；非敏感、需持久化的数据（如用户偏好）可用Cookie。
【易错提示】
不要混淆Cookie和Session的存储位置，这是最常考的点。另外，注意Cookie的容量限制和安全性问题是面试追问的重点。
```

## Q005211

- 题型：简答
- 难度：中等

**题目**

```text
https加密过程是怎样的？
```

**答案**

```text
1. 服务器把自己的公开密钥登录至数字证书认证机构。
2. 数字证书认证机构用自己的私有密钥向服务器的公开密码署数字签名并颁发公钥证书。
3. 客户端拿到服务器的公钥证书后，使用数字签名认证机构的公开密钥，向数字证书认证机构验证公钥证书上的数字签名，以确认服务器的公开密钥的真实性。
4. 使用服务器的公开密钥对报文加密后发送。
5. 服务器用私有密钥对报文解密。
```

**解析**

```text
【核心考点】 HTTPS协议 加密过程 数字证书
【题目解析】
本题考查HTTPS加密通信的完整流程，涉及非对称加密、数字签名和证书认证机制。HTTPS通过SSL/TLS协议在HTTP基础上增加加密层，确保数据传输的机密性和完整性。核心步骤包括：服务器向CA申请证书、客户端验证证书、协商对称密钥、加密通信。
【参考答案要点】
1. 服务器申请证书：服务器将自己的公开密钥提交给数字证书认证机构（CA）。
2. CA颁发证书：CA使用自己的私有密钥对服务器的公开密钥进行数字签名，生成公钥证书（包含服务器公钥、CA签名等信息）。
3. 客户端验证证书：客户端使用CA的公开密钥验证证书上的数字签名，确认服务器公钥的真实性和有效性（如未过期、未被篡改）。
4. 加密通信：客户端使用服务器的公开密钥加密报文（或协商的对称密钥）后发送。
5. 服务器解密：服务器使用自己的私有密钥解密报文，获取原始数据。
【面试角度】
回答时建议补充对称加密与非对称加密的结合使用细节，例如：实际通信中，客户端会用服务器公钥加密一个临时生成的对称密钥，后续通信使用该对称密钥进行高效加密。这体现了HTTPS的性能与安全平衡。
【易错提示】
易混淆点：客户端验证证书时，使用的是CA的公钥（预装在浏览器/操作系统中），而非服务器的公钥。另外，数字签名是CA用私钥对服务器公钥的哈希值加密，而非直接加密公钥本身。
```


**答案**

```text
什么是Http协议无状态：
因为HTTP的每个请求都是完全独立的，每个请求包含了处理这个请求所需的完整的数据，发送请求不涉及到状态变更。

怎么解决 Http 协议无状态协议：
可以使用cookie，token，session，JWT进行鉴权解决无状态的问题
```

**解析**

```text
【核心考点】 HTTP协议 无状态 鉴权机制
【题目解析】
本题考查HTTP协议的核心特性——无状态，以及如何解决由此带来的问题。无状态意味着每个请求独立，服务器不保存客户端状态，这简化了协议但增加了鉴权复杂度。
【参考答案要点】
1. 无状态的含义：每个HTTP请求包含完整信息，服务器不保留上下文。优点是易于扩展，缺点是需要额外机制维护会话。

【延伸知识】
HTTP/2和HTTP/3并未改变无状态特性，但通过多路复用等机制提升了性能。在测试中，需关注鉴权机制对接口测试的影响，如Token过期处理。
```

## Q005281

- 题型：简答
- 难度：中等

**题目**

```text
写出ISO模型，tcp/udp在那层？他们有什么区别
```

**答案**

```text
1、ISO模型：ISO于1978年开发的一套标准架构ISO模型，被引用来说明数据通信协议的结构和功能。

OSI在功能上可以划分为两组：

网络群组：物理层、数据链路层、网络层

使用者群组：传输层、会话层、表示层、应用层
2、tcp /udp属于运输层
3、区别：

(1)对数据可靠性的要求。tcp适用于可靠性高的场合，udp适用于可靠性低的场合

(2)应用的实时性。tcp有延时较大，udp演示较小

(3)网络的可靠性。网络不好的情况下使用tcp，网络条件好的情况下，使用udp
```

**解析**

```text
【核心考点】 OSI模型 TCP/UDP 网络协议
【参考答案要点】
1. OSI模型：国际标准化组织（ISO）于1978年开发的网络通信参考模型，共7层：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。功能上可分为网络群组（物理层、数据链路层、网络层）和使用者群组（传输层、会话层、表示层、应用层）。
2. TCP/UDP所在层：TCP和UDP均属于传输层（第4层）。
3. 区别：
✓ TCP（传输控制协议）：面向连接、可靠传输、有确认重传机制，适用于对数据可靠性要求高的场景（如文件传输、网页浏览），但延迟较大。
✓ UDP（用户数据报协议）：无连接、不可靠传输、无确认机制，适用于实时性要求高、网络条件好的场景（如视频直播、在线游戏），延迟较小。
【面试角度】
回答时建议结合实际网络应用场景举例，如“在测试视频流传输时，我们选择UDP以降低延迟”，能体现对协议特性的理解深度。
【延伸知识】
OSI模型是理论模型，实际互联网采用TCP/IP四层模型（应用层、传输层、网络层、网络接口层），了解两者对应关系有助于应对网络协议类面试题。
```
