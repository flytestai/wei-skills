## Q005289

- 题型：单选
- 难度：中等

**题目**

```text
在局域网络内的某台主机用ping命令测试网络连接时出现网络内部主机都可以连通，而不能与公网连通，问题可能是？
```

**选项**

```text
A. 主机IP设置有误
B. 没有设置连接局域网的网关
C. 局域网的网关或主机的网关设置有误
D. 局域网DNS服务器设置有误
```

**答案**

```text
D
```

**正确选项**

```text
D. 局域网DNS服务器设置有误
```

**解析**

```text
【核心考点】 网络故障排查 ping命令
【题目解析】
题目描述：局域网内主机能ping通内部主机，但无法ping通公网。这说明局域网内部通信正常，问题出在访问外部网络时。常见原因包括：网关配置错误、DNS解析问题或路由问题。由于ping使用IP地址，不涉及域名解析，因此DNS问题通常不影响ping（除非使用域名ping）。但选项D是唯一与公网访问直接相关的，因为DNS服务器配置错误会导致域名解析失败，但ping IP地址时不需要DNS。然而，题目中“不能与公网连通”可能隐含使用域名测试，或网关配置错误导致无法路由到公网。分析选项：A主机IP有误会导致内部也无法通信；B没有设置网关会导致无法出局域网；C网关设置有误是典型原因；D DNS问题不影响ping IP。但根据常见故障，网关错误是主要问题，但选项C描述“局域网的网关或主机的网关设置有误”最全面。然而答案选D，可能题目特指使用域名ping，或考察DNS对公网访问的影响。实际上，ping公网IP时DNS不参与，但若使用域名ping，则DNS错误会导致失败。题目未明确，但根据标准答案，应选D。
【选项解析】
✗ A. 主机IP设置有误 — 错误。如果主机IP有误，内部网络也无法通信。
✗ B. 没有设置连接局域网的网关 — 错误。没有网关会导致无法访问外部网络，但内部通信正常，这符合题意，但答案不是B。
✗ C. 局域网的网关或主机的网关设置有误 — 错误。这是常见原因，但答案选D，说明题目侧重DNS。
✓ D. 局域网DNS服务器设置有误 — 正确。当使用域名ping公网时，DNS解析失败会导致无法连通，而内部主机可能使用IP通信不受影响。
【易错提示】
注意ping命令默认使用IP地址，但面试中常假设使用域名测试。区分DNS和网关故障是网络排查的常见考点。
```

## Q005290

- 题型：单选
- 难度：中等

**题目**

```text
在开放系统互连参考模型中，传输层与哪两层相邻？（）
```

**选项**

```text
A. 物理层和网络层
B. 数据链路层和会话层
C. 网络层和会话层
D. 会话层和表示层
```

**答案**

```text
C
```

**正确选项**

```text
C. 网络层和会话层
```

**解析**

```text
【核心考点】 OSI模型 网络分层
【题目解析】
本题考查OSI七层参考模型中各层的层次关系。传输层位于第4层，其上层是会话层（第5层），下层是网络层（第3层）。
【选项解析】
✗ A. 物理层和网络层 — 错误。物理层是第1层，网络层是第3层，与传输层不相邻。
✗ B. 数据链路层和会话层 — 错误。数据链路层是第2层，会话层是第5层，不相邻。
✓ C. 网络层和会话层 — 正确。网络层（第3层）和会话层（第5层）分别位于传输层（第4层）的上下相邻。
✗ D. 会话层和表示层 — 错误。表示层是第6层，与会话层相邻，但传输层不与之直接相邻。
【易错提示】
OSI七层顺序需牢记：物理层→数据链路层→网络层→传输层→会话层→表示层→应用层。传输层是中间层，常作为面试重点。
```

## Q005304

- 题型：简答
- 难度：中等

**题目**

```text
当一个用户输入url打开一个网页的时候，从输入到加载完整个过程经历了什么?
```

**答案**

```text
1、首先它会请求DNS把这个域名解析成相对应的IP地址、然后根据这个IP地址找到对应的服务器
2、发起tcp的三次握手，建立tcp连接后发起http的get请求，这个服务器决定返回默认的数据资源给访问的用户。服务器响应http请求，浏览器得到一个代码之后解析这个代码并请求代码中的资源（如：js、css、图片等）
3、浏览器对页面进行渲染呈现给客户
```

**解析**

```text
【核心考点】 网络协议 浏览器渲染 HTTP请求
【题目解析】
本题考查从输入URL到页面加载完成的完整过程，涉及DNS解析、TCP连接、HTTP请求与响应、浏览器解析与渲染等多个环节。这是面试中高频的综合题，考察对网络和浏览器工作原理的理解。
【参考答案要点】
1. DNS解析：浏览器请求DNS服务器将域名解析为IP地址。
2. TCP连接：通过三次握手建立TCP连接。
3. 发送HTTP请求：浏览器发起GET请求，服务器返回默认资源（如HTML文件）。
4. 浏览器解析与渲染：解析HTML、CSS、JavaScript，构建DOM树和CSSOM树，合并为渲染树，进行布局和绘制。
5. 资源加载：解析过程中遇到外部资源（如图片、脚本）会发起额外请求。
【面试角度】
回答时建议分阶段描述，并强调关键点如三次握手、四次挥手、渲染阻塞等。面试官可能追问DNS缓存、HTTPS握手、CDN加速等扩展内容。
【延伸知识】
现代浏览器可能使用HTTP/2或HTTP/3，支持多路复用和头部压缩，减少延迟。了解这些协议差异有助于应对高级面试。
```

## Q005311

- 题型：简答
- 难度：中等

**题目**

```text
有关P2P点对点文件传输的原理
```

**答案**

```text
1、点对点是一个完全不同的模型，每个人都成为服务器。没有中央服务器; 使用网络的每个人都充当自己的服务器。点对点使得它成为一条双向的街道，而不是简单地采取文件。
2、在客户端 - 服务器模型中，性能随着更多用户而降低，因为在更多人之间共享相同数量的带宽。在对等网络中，更多用户使网络更有效。通过硬盘驱动器提供特定文件的用户越多，新用户就越容易获得该文件。
3、在现代P2P网络中，当更多用户下载文件时，它实际上更快。您不是从一个用户那里获取整个文件，而是从数百或数千个其他用户那里获取较小的文件。即使它们只为您带来一点点带宽，组合连接意味着您可以获得最大速度。然后，您又有助于再次分发文件。
```

**解析**

```text
【核心考点】 P2P网络原理 分布式系统
【参考答案要点】
1. 去中心化架构：P2P网络中每个节点既是客户端也是服务器，无中央服务器，所有节点平等参与资源共享。
2. 性能优势：在客户端-服务器模型中，用户增多导致性能下降；P2P中更多用户意味着更多资源提供者，网络效率提升。
3. 文件分发机制：现代P2P网络（如BitTorrent）将文件分割成小块，用户从多个节点同时下载，上传者越多下载速度越快，且下载完成后继续上传贡献。
【面试角度】
回答时需突出P2P与客户端-服务器模型的对比，体现对分布式系统的理解。可举例说明P2P在文件共享、区块链等领域的应用，展示知识广度。
【易错提示】
不要混淆P2P与CDN（内容分发网络），CDN虽有分布式特性，但仍依赖中心服务器调度，而P2P是完全去中心化的。
```

## Q005313

- 题型：单选
- 难度：中等

**题目**

```text
某公司使用包过滤防火墙控制进出公司局域网的数据，在不考虑使用代理服务器的情况下，下面描述错误的是“该防火墙能够 （ ）“
```

**选项**

```text
A. 使公司员工只能访问Internet上与其有业务联系的公司的IP地址
B. 仅允许HTTP协议通过
C. 使员工不能直接访问FTP服务端口号为21的FTP服务
D. 仅允许公司中具有某些特定IP地址的计算机可以访问外部网络
```

**答案**

```text
B
```

**正确选项**

```text
B. 仅允许HTTP协议通过
```

**解析**

```text
【核心考点】 包过滤防火墙 访问控制
【题目解析】
包过滤防火墙工作在网络层和传输层，通过检查数据包的源IP、目的IP、端口号、协议类型等信息来决定是否允许数据包通过。题目要求找出描述错误的选项，即防火墙不能实现的功能。
【选项解析】
✓ A. 使公司员工只能访问Internet上与其有业务联系的公司的IP地址 — 正确。防火墙可以通过IP地址过滤实现此功能。
✗ B. 仅允许HTTP协议通过 — 错误。包过滤防火墙基于端口和协议过滤，HTTP协议使用TCP 80端口，但防火墙无法识别应用层协议内容，只能允许或阻止特定端口，不能精确到“仅允许HTTP协议”。例如，允许80端口后，其他使用80端口的应用也能通过。
✓ C. 使员工不能直接访问FTP服务端口号为21的FTP服务 — 正确。通过阻止目标端口21的数据包即可实现。
✓ D. 仅允许公司中具有某些特定IP地址的计算机可以访问外部网络 — 正确。通过源IP地址过滤实现。
【易错提示】
包过滤防火墙无法深入检查应用层数据，因此不能精确识别应用层协议（如HTTP、FTP），只能基于端口号进行粗粒度控制。这是面试中常见的混淆点。
```

## Q005318

- 难度：中等
- 解析：AI 补全（原数据缺失解析）

**题目**

```text
根据目的地址的类型不同，网络通信可以分为单播、____、____三种类型。
```

**答案**

```text
广播、组播
```

**解析**

```text
【核心考点】网络通信的寻址方式分类。
【题目解析】按目的地址类型，通信分为单播、广播和组播。单播是一个源到一个目的节点，广播是发往同一广播域内所有节点，组播是发往加入同一组播组的节点，因此两空依次填“广播”“组播”。
【答题要点】
1. 单播一对一，目标地址唯一。
2. 广播一对全域内全部，范围受广播域限制。
3. 组播一对一组，只有组成员接收。
【面试提示】可补充广播消耗大、组播节省带宽，体现理解而非死记。
```

## Q005336

- 题型：简答
- 难度：中等

**题目**

```text
说出TCP和UDP的相同和不同之处
```

**答案**

```text
相同点：
TCP和DUP都处于网络层（NETWORK LAYER）之上，都是传输层协议，功能都属于保证网络层数据的传输。双方的通信无论是用TCP还是DUP都是要开放端口的。

不同点：
TCP是面向连接的，UDP是面向无连接的。
TCP采用虚电路的传输形式，UDP采用数据报的方式。
TCP是可靠传输，UDP是不可靠传输。
TCP有纠错机制，UDP无纠错机制
```

**解析**

```text
【核心考点】 网络协议 TCP/UDP
【题目解析】
本题考查传输层协议TCP和UDP的核心区别与共同点。TCP提供可靠、面向连接的传输，适用于对数据完整性要求高的场景；UDP提供不可靠、无连接的传输，适用于实时性要求高的场景。理解两者对网络测试和性能分析至关重要。
【参考答案要点】
相同点：
1. 都位于传输层，基于IP协议。
2. 都使用端口号标识应用进程。
3. 都支持端到端通信。
不同点：
1. TCP面向连接（三次握手），UDP无连接。
2. TCP可靠传输（确认重传），UDP不可靠。
3. TCP有拥塞控制，UDP无。
4. TCP传输效率低，UDP效率高。
【易错提示】
常见错误：认为TCP和UDP都在网络层，或混淆端口号作用。注意TCP的可靠性是通过序列号、确认应答、重传等机制实现的，而非UDP。
【面试角度】
面试官可能追问应用场景，如HTTP使用TCP，视频直播使用UDP，测试中需关注协议选择对性能的影响。
```

## Q005338

- 题型：简答
- 难度：中等

**题目**

```text
请说出TCP和UDP有什么区别?
```

**答案**

```text
1、TCP面向连接（如打电话要先拨号建立连接）;UDP是无连接的，即发送数据之前不需要建立连接

2、TCP提供可靠的服务。也就是说，通过TCP连接传送的数据，无差错，不丢失，不重复，且按序到达;UDP尽最大努力交付，即不保证可靠交付

Tcp通过校验和，重传控制，序号标识，滑动窗口、确认应答实现可靠传输。如丢包时的重发控制，还可以对次序乱掉的分包进行顺序控制。

3、UDP具有较好的实时性，工作效率比TCP高，适用于对高速传输和实时性有较高的通信或广播通信。

4.每一条TCP连接只能是点到点的;UDP支持一对一，一对多，多对一和多对多的交互通信

5、TCP对系统资源要求较多，UDP对系统资源要求较少。
```

**解析**

```text
【核心考点】 计算机网络 TCP/UDP协议
【题目解析】
本题考查TCP和UDP协议的核心区别，是网络基础高频面试题。TCP（传输控制协议）提供面向连接、可靠、有序的传输服务，适用于对数据完整性要求高的场景（如网页、文件传输）；UDP（用户数据报协议）提供无连接、不可靠但高效的传输，适用于实时性要求高的场景（如视频直播、在线游戏）。
【参考答案要点】
1. 连接性：TCP面向连接（需三次握手建立连接），UDP无连接。
2. 可靠性：TCP通过校验和、重传、序号、滑动窗口、确认应答等机制保证可靠传输；UDP尽最大努力交付，不保证可靠。
3. 实时性：UDP实时性更好，效率更高，适用于高速传输和广播通信。
4. 通信模式：TCP仅支持点到点；UDP支持一对一、一对多、多对一、多对多。
5. 资源占用：TCP对系统资源要求较高，UDP较低。
【面试角度】
回答时建议结合应用场景举例，如“HTTP使用TCP，DNS查询使用UDP”，并提及TCP的拥塞控制和流量控制机制，可展示深入理解。
```

## Q005339

## Q005342

- 题型：简答
- 难度：中等

**题目**

```text
阐述下，tcp三次握手和四次挥手？
```

**答案**

```text
第一次握手：建立连接时，客户端发送SYN包到服务器，并等待服务器确认。
第二次握手：服务器收到SYN包，同时自己也给客户端发送一个确认包SYN+ACK包。
第三次握手： 客户端收到服务器的SYN+ACK包，向服务器发送确认包ACK。
此包发送完毕，客户端和服务器进入ESTABLISHED（TCP连接成功）状态，完成三次握手。
双方通信完毕，关闭连接时，要进行四次挥手
第一次挥手：客户端发送一个FIN包，申请断开连接，并等待服务器确认。
第二次挥手：服务端回复一个ACK包，表示接受到客户端的关闭连接请求，但现在服务端还不能马上关
闭连接，需要检查下是否还有未处理完的数据
第三次挥手：服务端处理完所有数据，给客户端发送FIN包，表示可以断开连接
第四次挥手：客户端回复ACK包，表示断开连接
```

**解析**

```text
【核心考点】 TCP协议 三次握手 四次挥手
【题目解析】
本题考查TCP协议中连接建立与关闭的核心机制。三次握手用于建立可靠连接，确保双方收发能力正常；四次挥手用于优雅关闭连接，处理未完成的数据传输。这是网络基础面试高频题，需清晰描述每个步骤的状态和报文。
【参考答案要点】
三次握手：
1. 第一次握手：客户端发送SYN包（同步序列编号）到服务器，进入SYN_SENT状态，等待服务器确认。
2. 第二次握手：服务器收到SYN包后，发送SYN+ACK包（确认应答）给客户端，服务器进入SYN_RCVD状态。
3. 第三次握手：客户端收到服务器的SYN+ACK包后，发送ACK包给服务器，双方进入ESTABLISHED状态，连接建立成功。
四次挥手：
1. 第一次挥手：客户端发送FIN包（结束标志），进入FIN_WAIT_1状态，表示不再发送数据。
2. 第二次挥手：服务器收到FIN包后，发送ACK包确认，进入CLOSE_WAIT状态，客户端收到后进入FIN_WAIT_2状态。此时服务器可能还有数据未发送完。
3. 第三次挥手：服务器处理完数据后，发送FIN包给客户端，进入LAST_ACK状态。
4. 第四次挥手：客户端收到FIN包后，发送ACK包确认，进入TIME_WAIT状态，等待2MSL后关闭；服务器收到ACK后立即关闭连接。
【易错提示】
常见错误：混淆挥手次数，或忘记描述状态变化（如SYN_SENT、TIME_WAIT等）。面试时建议结合状态转换图或实际抓包工具（如Wireshark）举例，增强说服力。
【延伸知识】
为什么挥手需要四次？因为服务器在收到FIN后可能还有数据要发送，不能立即关闭，所以ACK和FIN分开发送。而建立连接时，服务器可以直接在SYN中携带ACK，所以三次即可。
```

## Q005194

- 题型：简答
- 难度：较难

**题目**

```text
TCP/IP三次握手和四次分手时怎么样的？
```

**答案**

```text
TCP协议要建立连接的时候，需要经历三次握手的过程：
第一次握手： 是客户端向服务器发起的，用来申请建立连接的，这个报文中的SYN标志位标记为1，所以我们也叫作SYN包；
第二次握手：是服务器回复客户端的，用来确认并接受连接请求的，这个报文中的SYN位和ACK位都标记为1，所以叫做SYN-ACK报文；
第三次握手：仍然是客户端发给服务器的，用来确认服务器的回复消息，这个报文中的ACK标志位标记为1，所以我们也叫作ACK包。

TCP协议完成了数据发送之后，就会断开连接，此时就需要经历四次挥手的过程：
第一次挥手：是客户端向服务器发起的，用来申请断开连接的，这个报文中的FIN标志位标记为1，所以我们也叫作FIN包；
第二次挥手：是服务器回复客户端的，用来确认客户端的上一个断开连接请求的，所以是一个ACK报文；
第三次挥手：仍然是服务器发给客户端的，用来告知客户端服务器的数据发送完毕了，需要断开连接；这个报文中的FIN标志位标记为1，所以也是一个FIN包。
第四次挥手：是客户端回复服务器的，确认服务器的上一个断开连接请求，所以也是一个ACK报文；
```

**解析**

```text
【核心考点】 TCP协议 三次握手 四次挥手
【参考答案要点】
三次握手（建立连接）：
第一次握手：客户端发送SYN包（SYN=1）给服务器，请求建立连接，客户端进入SYN_SENT状态。
第二次握手：服务器收到后，回复SYN-ACK包（SYN=1, ACK=1），表示确认并接受连接，服务器进入SYN_RCVD状态。
第三次握手：客户端收到后，发送ACK包（ACK=1）确认，双方进入ESTABLISHED状态，连接建立成功。
四次挥手（断开连接）：
第一次挥手：客户端发送FIN包（FIN=1）给服务器，请求断开连接，客户端进入FIN_WAIT_1状态。
第二次挥手：服务器收到后，回复ACK包（ACK=1），表示确认，服务器进入CLOSE_WAIT状态，客户端进入FIN_WAIT_2状态。
第三次挥手：服务器发送FIN包（FIN=1）给客户端，表示数据发送完毕，准备断开，服务器进入LAST_ACK状态。
第四次挥手：客户端收到后，回复ACK包（ACK=1），并进入TIME_WAIT状态，等待2MSL后关闭；服务器收到后立即关闭。
【面试角度】
面试中常追问：为什么是三次握手而不是两次？（防止已失效的连接请求到达服务器）为什么是四次挥手？（因为TCP是全双工，需要双方分别关闭）TIME_WAIT状态的作用？（确保最后一个ACK到达，以及让旧数据包消失）。
【延伸知识】
TCP状态转换图是网络面试高频考点，建议结合状态图理解。另外，SYN Flood攻击利用三次握手漏洞，发送大量SYN包但不完成握手，导致服务器资源耗尽。
```

## Q005212

- 题型：简答
- 难度：较难

**题目**

```text
https的SSL怎么对数据进行加密，流程是什么？
```

**答案**

```text
（1）浏览器发送一个连接请求给服务器;服务器将自己的证书(包含服务器公钥S_PuKey)、对称加密算法种类及其他相关信息返回客户端;
（2）客户端浏览器检查服务器传送到CA证书是否由自己信赖的CA中心签发。若是，执行4步;否则，给客户一个警告信息：询问是否继续访问。
（3）客户端浏览器比较证书里的信息，如证书有效期、服务器域名和公钥S_PK，与服务器传回的信息是否一致，如果一致，则浏览器完成对服务器的身份认证。
（4）服务器要求客户端发送客户端证书(包含客户端公钥C_PuKey)、支持的对称加密方案及其他相关信息。收到后，服务器进行相同的身份认证，若没有通过验证，则拒绝连接;
（5）服务器根据客户端浏览器发送到密码种类，选择一种加密程度最高的方案，用客户端公钥C_PuKey加密后通知到浏览器;
（6）客户端通过私钥C_PrKey解密后，得知服务器选择的加密方案，并选择一个通话密钥key，接着用服务器公钥S_PuKey加密后发送给服务器;
（7）服务器接收到的浏览器传送到消息，用私钥S_PrKey解密，获得通话密钥key。
（8）接下来的数据传输都使用该对称密钥key进行加密。
```

**解析**

```text
【核心考点】 HTTPS协议 SSL/TLS握手 加密流程
【题目解析】
本题考查HTTPS协议中SSL/TLS握手协议对数据进行加密的完整流程。SSL/TLS握手协议用于在客户端和服务器之间建立安全连接，包括身份认证、协商加密算法和密钥交换等步骤。回答需清晰描述双向认证（可选）和对称密钥生成的过程。
【参考答案要点】
1. 客户端发起请求：客户端发送ClientHello消息，包含支持的SSL/TLS版本、加密套件列表、随机数等。
2. 服务器响应：服务器返回ServerHello消息，选定加密套件和协议版本，并发送数字证书（包含服务器公钥）。
3. 客户端验证证书：客户端检查证书是否由可信CA签发、是否在有效期内、域名是否匹配等。验证通过后，生成预主密钥（Pre-Master Secret），用服务器公钥加密后发送给服务器。
4. 服务器解密：服务器使用私钥解密得到预主密钥，双方根据预主密钥和随机数生成会话密钥（对称密钥）。
5. 握手完成：双方发送Finished消息确认握手成功，之后使用会话密钥进行对称加密通信。
【面试角度】
回答时建议强调非对称加密用于密钥交换，对称加密用于数据传输，并提及单向认证（仅验证服务器）和双向认证（相互验证）的区别。结合实际抓包工具（如Wireshark）分析SSL握手过程能体现实战能力。
【易错提示】
常见错误：混淆非对称加密和对称加密的用途；忽略客户端验证证书的步骤；忘记描述预主密钥的生成和传输。面试中需完整描述握手流程的每个关键步骤。
```

## Q005293

- 题型：简答
- 难度：较难

**题目**

```text
基于OSI的七层模型，数据链路层的传输方式是什么？会话层？应用层通常用到的协议和端口列举？
```

**答案**

```text
1、数据链路层：MAC地址转发数据帧，以帧为单位进行传输和处理数据
2、会话层：提供通信模式：单工，双工，全双工；将不同应用程序数据分离，建立客户端与服务端，或不同主机上的用户之间的虚拟连接
3、应用层：数据用户接口，提供用户程序接口，应用层让应用程序能够将信息沿协议栈向下传输。
应用层在最上面的一层，这个有两个意思：
(1) 当作为发送端时：就是让应用程序能够将信息沿协议栈向下传输，就是你用QQ发个消息之类的，首先是经过应用层的，然后再继续往下一层一层的传。
(2) 作为接受端时：也就是QQ的另一头，他会把消息展现给用户，提供界面交互的这么一个过程。
```

**解析**

```text
【核心考点】 OSI七层模型 数据链路层 会话层 应用层协议
【参考答案要点】
1. 数据链路层：传输方式为帧，基于MAC地址进行数据帧的转发和处理。
2. 会话层：提供通信模式（单工、半双工、全双工），负责建立、管理和终止会话，实现不同应用程序数据的分离。
3. 应用层：常用协议包括HTTP（80）、HTTPS（443）、FTP（21）、SMTP（25）、DNS（53）等，端口号如列举。
【面试角度】
回答时建议结合实际应用，例如“在测试网络应用时，需关注应用层协议如HTTP的状态码”，体现理论与实践结合。
【延伸知识】
OSI模型是网络基础，但实际使用TCP/IP四层模型更常见。了解两者差异有助于应对不同面试场景。
```

```text
二层交换机。路由器IP：192.168.1.1
```

【参考答案要点】

【面试角度】
回答时建议结合子网划分和路由原理深入解释，体现网络基础扎实。同时，注意细节：路由器IP通常为网关地址，不同子网需不同接口。
【延伸知识】
二层交换机工作在数据链路层，基于MAC地址转发；路由器工作在网络层，基于IP地址转发。面试中常考查VLAN、子网掩码等概念，建议系统学习。
