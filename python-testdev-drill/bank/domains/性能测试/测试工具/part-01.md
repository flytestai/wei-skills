## Q005522

- 题型：单选
- 难度：入门

**题目**

```text
Jmeter聚合报告中响应时间的单位是
```

**选项**

```text
A. s秒
B. ms 毫秒
C. ss 微妙
D. m 分钟
```

**答案**

```text
B
```

**正确选项**

```text
B. ms 毫秒
```

**解析**

```text
【核心考点】 JMeter聚合报告 响应时间单位
【题目解析】
本题考查JMeter工具的基础知识。聚合报告（Aggregate Report）是JMeter中常用的监听器，用于统计请求的响应时间、吞吐量等指标。响应时间的默认单位是毫秒（ms）。
【选项解析】
✗ A. s秒 — 错误。秒是较大单位，JMeter聚合报告默认以毫秒显示。

✗ C. ss微妙 — 错误。微秒单位过小，JMeter不使用此单位。
✗ D. m分钟 — 错误。分钟用于长时间统计，但非响应时间单位。
【易错提示】

```


```text

【题目解析】
本题考查JMeter的目录结构及第三方插件存放位置。JMeter的插件（如自定义监听器、函数等）通常放置在lib/ext目录下，该目录是JMeter自动加载扩展组件的默认路径。而lib目录存放核心依赖库，bin目录存放启动脚本和配置文件，%JAVA_HOME%\lib是Java运行环境目录，与JMeter无关。

✗ D. %JAVA_HOME%\lib — 错误。这是Java运行时库目录，与JMeter无关。
【易错提示】
注意区分lib和lib\ext：lib存放JMeter自身依赖，lib\ext存放用户自定义插件。面试中常混淆这两个路径。
```

## Q005507

- 题型：简答
- 难度：中等

**题目**

```text
JMeter中vars与props的差异？
```

**答案**

```text
主要差异：vars只在当前线程组中能使用；props则可以跨线程组使用；另外vars只能是String或Object类型
```

**解析**

```text
【核心考点】 JMeter vars props 变量作用域
【题目解析】
本题考查JMeter中vars和props变量的核心差异。两者都是JMeter中存储和传递数据的对象，但作用域和类型限制不同，理解这些差异对编写复杂测试脚本至关重要。
【参考答案要点】
1. 作用域不同：vars（JMeterVariables）仅在当前线程组内可见，不同线程组之间无法共享；props（JMeterProperties）是全局属性，可在所有线程组之间共享。
2. 数据类型：vars只能存储String或Object类型；props可以存储任意类型，但通常用于配置属性。
3. 使用场景：vars用于线程内临时数据传递；props用于跨线程组共享配置或全局变量。
【面试角度】
面试官可能追问实际应用场景，例如“在分布式压测中，如何用props传递全局参数？”或“vars和props的线程安全性”。建议结合JMeter函数（如__P、__V）举例，展示深入理解。
【易错提示】
注意vars不是线程安全的，而props是全局共享的，多线程修改props时需谨慎。面试中常误认为vars可以跨线程组使用，需明确区分。
```

## Q005525

- 题型：简答
- 难度：中等

**题目**

```text
LaodRunner 脚本中 action()和 init、end() 除了迭代的区别还有其他吗？
```

**答案**

```text
集合点只能插入到Action	部分， vuser_init和 vuser_end 中不能插入集合点。

action()	和 init、 end() 都可以插入事务点。
```

**解析**

```text
【核心考点】 LoadRunner脚本结构 集合点 事务点
【参考答案要点】
1. 集合点（Rendezvous）：只能插入在Action部分，不能插入在vuser_init和vuser_end中。集合点用于控制虚拟用户同时执行某个操作，模拟高并发场景。
2. 事务点（Transaction）：可以插入在Action、vuser_init和vuser_end中。事务点用于测量某个操作的响应时间，可嵌套使用。
3. 其他区别：vuser_init和vuser_end只执行一次（迭代次数为1），而Action部分可以按设置的迭代次数重复执行。此外，vuser_init和vuser_end中不能使用参数化迭代。
【面试角度】
回答时建议结合实际性能测试场景说明，例如“在登录操作中，将登录脚本放在vuser_init中，业务操作放在Action中，以模拟真实用户行为”，能体现对工具特性的深入理解。
【延伸知识】
LoadRunner的脚本结构设计遵循了性能测试的最佳实践：初始化操作放在vuser_init，业务操作放在Action，清理操作放在vuser_end，这样能更准确地模拟用户行为并减少资源消耗。
```

## Q005549

- 题型：简答
- 难度：中等

**题目**

```text
jmeter的长链接、短链接、原件执行原理？
```

**答案**

```text
短连接的操作步骤是：建立连接——数据传输——关闭连接...建立连接——数据传输——关闭连接。
长连接的操作步骤是：建立连接——数据传输...（保持连接）...数据传输——关闭连接。
长连接多用于操作频繁，点对点的通讯，而且连接数不能太多情况，。每个TCP连接都需要三步握手，这需要时间，如果每个操作都是先连接，再操作的话那么处理速度会降低很多，所以每个操作完后都不断开，次处理时直接发送数据包就OK了，不用建立TCP连接。例如：数据库的连接用长连接， 如果用短连接频繁的通信会造成socket错误，而且频繁的socket 创建也是对资源的浪费。

而像WEB网站的http服务一般都用短链接，因为长连接对于服务端来说会耗费一定的资源，而像WEB网站这么频繁的成千上万甚至上亿客户端的连接用短连接会更省一些资源，如果用长连接，而且同时有成千上万的用户，如果每个用户都占用一个连接的话，那可想而知吧。所以并发量大，但每个用户无需频繁操作情况下需用短连好。
Jmeter使用的原理？------模拟客户端发送请求到服务器，服务器处理请求并返回响应结果，jmeter接收响应结果
```

**解析**

```text
【核心考点】 HTTP协议 连接管理 JMeter原理
【题目解析】
本题考察JMeter中长连接与短连接的概念及其执行原理，以及JMeter各元件的执行顺序。短连接每次请求都建立新连接，完成后立即关闭；长连接则复用同一连接进行多次请求。JMeter通过线程组、取样器、监听器等元件按作用域和顺序执行测试。
【参考答案要点】
1. 短连接原理：每次HTTP请求都经历三次握手建立连接→数据传输→四次挥手关闭连接。适用于请求频率低、连接数多的场景，如Web网站。
2. 长连接原理：建立连接后保持打开状态，多次数据传输后关闭。适用于频繁交互、点对点通信，如数据库连接，减少握手开销。
3. JMeter元件执行原理：测试计划按配置元件→前置处理器→定时器→取样器→后置处理器→断言→监听器的顺序执行，且遵循作用域规则（父级元件影响子级）。
【面试角度】
回答时需结合实际性能测试场景，例如“在接口测试中，长连接可减少连接建立时间，但需注意连接池管理”。面试官关注对协议底层原理的理解和JMeter工具的实际应用能力。
【易错提示】
常见错误是混淆长连接与Keep-Alive机制，或忽略JMeter元件执行顺序对测试结果的影响。务必明确长连接≠持久连接，且元件顺序影响断言和监听器数据。
```

```text
注意：集合点经常和事务结合起来使用，常放在事务的前面，集合点只能插入到	Action部 分 ， vuser_init	和	vuser_end	中 不 能 插 入 集 合 点 。

lr_rendezvous(	“SubmitData ”)
```

```text
【核心考点】 性能测试 LoadRunner 集合点
【题目解析】
本题考查性能测试工具LoadRunner中集合点的概念与使用。集合点是性能测试中实现并发访问的关键机制，常用于模拟高并发场景。
【参考答案要点】
1. 集合点定义：集合点（Rendezvous Point）是LoadRunner中用于控制虚拟用户同步执行的一个点。当多个虚拟用户运行到集合点时，会等待直到达到预设的用户数，然后同时执行后续操作，从而模拟真实的并发访问。

3. 设置集合点的函数：在LoadRunner中使用 lr_rendezvous("集合点名"); 函数。该函数通常插入在事务开始之前，以确保并发操作在事务内被测量。
【面试角度】

【易错提示】
常见错误是混淆集合点与事务。集合点只控制并发时机，不测量性能；事务用于测量响应时间。另外，集合点只能插入到Action部分，不能放在vuser_init或vuser_end中。
```

## Q005617

- 题型：简答
- 难度：中等

**题目**

```text
进行参数化的目的是什么？
```

**答案**

```text
在性能测试的过程中，我们要使用多用户并发，使用多用户进行性能测试时，如果使用同一个数据，那么，每次返回的结果都是可能相同，可能被缓存，从而导致不能准确反应服务器性能，如果使用不同的数据，那么被缓存的概率就会低很多，就能更加真实的反应服务器的性能，而要使用不同的数据，就需要对数据进行参数化，需要时，调用参数，获取数据。
```

**解析**

```text
【核心考点】 性能测试 参数化
【题目解析】
本题考查性能测试中参数化的目的。参数化是用变量代替固定值，在并发测试中为每个虚拟用户提供不同的输入数据，以模拟真实用户行为。
【参考答案要点】
```

```text
【参考答案要点】
```

```text
1. 数据分段：根据并发用户个数，将参数池中某个连续的范围分段。每个用户使用其中的一段数据，互不重叠。

【延伸知识】
Unique参数化在分布式测试中需注意数据池的全局唯一性，避免不同负载生成器间的数据冲突。LoadRunner还支持“Unique+Each iteration”等组合模式，进一步控制数据分配粒度。
```

## Q005616

- 题型：简答
- 难度：较难

**题目**

```text
请阐述LR中进程和线程的含义，以及优劣势?
```

**答案**

```text
进程和线程都是由操作系统所体会的程序运行的基本单元，系统利用该基本单元实现系统对应用的并发性。
进程和线程的区别在于：
简而言之,一个程序至少有一个进程,一个进程至少有一个线程. 线程的划分尺度小于进程，使得多线程程序的并发性高。
另外，进程在执行过程中拥有独立的内存单元，而多个线程共享内存，从而极大地提高了程序的运行效率。
线程在执行过程中与进程还是有区别的。每个独立的线程有一个程序运行的入口、顺序执行序列和程序的出口。但是线程不能够独立执行，必须依存在应用程序中，由应用程序提供多个线程执行控制。
从逻辑角度来看，多线程的意义在于一个应用程序中，有多个执行部分可以同时执行。但操作系统并没有将多个线程看做多个独立的应用，来实现进程的调度和管理以及资源分配。这就是进程和线程的重要区别。

进程是具有一定独立功能的程序关于某个数据集合上的一次运行活动,进程是系统进行资源分配和调度的一个独立单位. 线程是进程的一个实体,是CPU调度和分派的基本单位,它是比进程更小的能独立运行的基本单位.线程自己基本上不拥有系统资源,只拥有一点在运行中必不可少的资源(如程序计数器,一组寄存器和栈),但是它可与同属一个进程的其他的线程共享进程所拥有的全部资源. 一个线程可以创建和撤销另一个线程;同一个进程中的多个线程之间可以并发执行.

优劣势：
如果选择按照进程方式运行， 每个用户都将启动一个mmdrv进程，多个mmdrv进程会占用大量内存及其他系统资源，这就限制了可以在任一负载生成器上运行的并发用户数的数量，因为负载机的资源（内存及其他系统资源）是有限的。

如果选择按照线程方式运行，在默认情况下，controller为每50个用户仅启动一个mmdrv进程，而每个用户都按线程方式来运行，这些线程用户将共享父进程的内存段，这就节省了大量内存空间，从而可以在一个负载生成器上运行更多的用户。（如果选择线程方式来运行用户，每个进程中会多出几个线程，例如是53个，多出来的进程可能是用于维护进程之间的运行的）

选择线程方式虽然可以减少启动的mmdrv进程数，减少了内存的占用，但是也容易出现一个问题，例如，同一个测试场景，用线程并发就会出现超时失败或报错，而用进程并发就没错。为什么呢？因为线程的资源是从进程资源中分配出来的，因此同一个进程中的多个线程会有共享的内存空间，假设a线程要用资源就必须 等待b线程释放，而b线程也在等待其他资源释放才能继续，这样就会出现这个问题。
```

**解析**

```text
【核心考点】 进程与线程 LR性能测试
【参考答案要点】
进程：操作系统资源分配的基本单位，拥有独立的内存空间，进程间相互隔离，通信开销大。
线程：CPU调度的基本单位，属于进程的一部分，共享进程的内存空间，线程间通信高效。
优势：
- 进程：稳定性高，一个进程崩溃不影响其他进程；适合CPU密集型任务。
- 线程：创建和切换开销小，资源共享方便，适合I/O密集型任务。
劣势：
- 进程：创建和切换开销大，资源占用多，进程间通信复杂。
- 线程：共享内存可能导致数据竞争和死锁，一个线程崩溃可能影响整个进程。
【面试角度】
在LR（LoadRunner）性能测试中，理解进程和线程的区别至关重要：LR的虚拟用户（Vuser）可以以进程或线程方式运行，线程模式更节省资源，适合大规模并发测试。
【延伸知识】
现代操作系统如Linux中，线程常被视为轻量级进程（LWP），Python的GIL限制了多线程并行，但多进程可绕过此限制。
```

- 难度：未标注
- 解析：AI 补全（原数据缺失解析）

**题目**

```text
Jmeter怎么获取动态时间？
```

**答案**

```text
使用__timeShift函数：

•
在JMeter中，你可以使用__timeShift函数来获取当前时间，并进行时间偏移。该函数的语法如下：

${__timeShift(yyyy-MM-dd HH:mm:ss,${__time(,)},-600)}
• ${__timeShift(format, time, shift)}

• format：日期时间格式，比如yyyy-MM-dd HH:mm:ss。
• time：参考时间，一般使用${__time(,)}来表示当前时间。
• shift：时间偏移量，以秒为单位。可以使用正数表示未来时间，使用负数表示过去时间。

•
例如，如果你想获取当前时间的前10分钟，可以使用以下表达式：

${__timeShift(yyyy-MM-dd HH:mm:ss,${__time(,)},-600)}
```

**解析**

```text
【核心考点】性能脚本中动态时间的生成。
【题目解析】用 __timeShift 函数可以生成动态时间。它接收格式、参考时间和偏移量三个参数：格式如 yyyy-MM-dd HH:mm:ss，参考时间常写 ${__time(,)} 表示当前时间，偏移量以秒为单位，负数表示过去。例如偏移 -600 秒即当前时间前十分钟。
【答题要点】
1. 格式串决定输出样式。
2. 参考时间缺省时也要按参数位置补齐逗号。
3. 偏移量注意单位是秒，正负决定前后。
```
