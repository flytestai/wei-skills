## Q006882

- 题型：简答
- 难度：简单

**题目**

```text
APP冷启动和热启动的区别？
```

**答案**

```text
冷启动：指 app 被后台杀死后，在这个状态打开 app，这种启动方式叫做冷启动
热启动：指 app 没有被后台杀死，仍然在后台运行（如按home键），通常我们再次去打开这个 app，
这种启动方式叫热启动。
热启动比冷启动速度更快。
```

**解析**

```text
【核心考点】 APP启动方式 冷启动 热启动
【题目解析】
本题考查移动APP测试中的基础概念。冷启动和热启动是衡量APP启动性能的重要指标，两者的区别在于进程是否在后台存活。
【参考答案要点】
1. 冷启动：APP进程被系统完全杀死后，用户重新打开APP。此时需要重新加载应用资源、初始化数据、执行启动流程，速度较慢。
2. 热启动：APP仍在后台运行（如按Home键），用户再次切换回前台。此时进程和部分数据仍在内存中，启动速度更快。
3. 区别：热启动比冷启动速度快，因为省去了进程创建、资源加载等步骤。测试中需分别关注两种场景的启动时间。
【面试角度】
面试时建议结合性能测试指标，如“我们使用冷启动时间作为APP性能基准，热启动时间反映用户体验”。也可补充“首次安装启动”作为第三种场景。
【易错提示】
冷启动不等于首次安装启动，首次安装还需处理权限申请等额外步骤。热启动中若系统内存不足，可能部分资源被回收，导致启动速度介于两者之间。
```

5. 发布流程：APP需通过应用商店审核；小程序通过微信等平台审核，流程相对简单。

## Q006884

- 题型：简答
- 难度：中等

**题目**

```text
H5架构和原生的区别？
```

**答案**

```text
1、原生的页面运行速度快，比较流畅。H5页面相对原生的运行性能低，特别是一些动画效果有明显卡顿。

2、H5页面的很多交互都没有原生的好，比如弹层、输入时候的页面滑动 等。H5的效果相对比较low，没有原生的好看，也没有原生默认的动画等效果。
3、原生APP修改页面要重新发布，等待审核（现在iOS的审核速度已经提高到1天到2天）。H5页面的修改 可以随时上线，不用等待审核。

4、H5跨平台，iOS和android需要各自开发。相对原生，H5开发成本低。

5、原生APP能很好的使用设备底层功能，如摄像头、方向传感器、重力传感器等。H5有所限制。比如android里的H5对摄像头和方向传感器就需要再多做一些处理。再比如你不想用系统默认的手机相册样式，就要用原生来开发了。

6、H5过度依赖于网络，网络不好的时候卡到不行，并且刚打开看到的都是一个空白页面。默认的H5页面每次打开都会重新请求页面（可以做缓存，不过基本很少有做的）。
H5比原生更费流量，H5除了加载html还要加载js、css这些资源文件，相比原生网络加载速度慢。
```

**解析**

```text
【核心考点】 移动端测试 H5与原生对比
【题目解析】
本题考察对移动端两种主流架构的理解，包括性能、交互、开发成本、发布流程和设备能力等方面。回答需从性能、交互、发布、跨平台、设备能力五个维度对比。
【参考答案要点】
1. 性能与流畅度
原生APP：运行速度快，动画流畅，适合复杂交互。H5：性能较低，尤其在动画和页面切换时可能出现卡顿。
2. 交互体验
原生APP：支持原生UI组件，交互自然（如滑动、弹层、手势）。H5：交互效果相对粗糙，部分操作（如输入时页面滑动）体验不佳。
3. 发布与更新
原生APP：修改需重新发布，等待应用商店审核（iOS审核通常1-2天）。H5：修改可随时上线，无需审核，迭代速度快。
4. 跨平台与开发成本
原生APP：iOS和Android需分别开发，成本高。H5：一套代码跨平台，开发成本低，维护简单。
5. 设备能力调用
原生APP：可调用摄像头、传感器、GPS等底层功能。H5：对设备功能调用受限，如Android H5对摄像头支持不完善。
【易错提示】
常见错误：仅列出差异，未结合测试场景说明。例如，H5页面需重点测试网络切换、缓存机制；原生APP需关注不同系统版本兼容性。
【面试角度】
面试官可能追问“混合架构（Hybrid）的测试要点”，建议补充JSBridge通信、WebView性能、离线缓存等知识点。
```

## Q006886

- 题型：简答
- 难度：中等

**题目**

```text
Hybrid应用是什么意思？怎么判断？
```

**答案**

```text
(Hybrid)混合应用程序，在应用程序中嵌入了webview，通过webview访问网页，webview是一个基于webkit引擎，展现web页面的控件
作用： 显示和渲染web界面 直接使用html文件（网络或Apk资源包assets中）作布局 可和JavaScript交互调用
优点： 开发成本较低,可以跨平台,调试方便 维护成本低,功能可复用 功能更加完善,性能和体验要比起web app好太多 更新较为自由
缺点： 相比原生,性能仍然有较大损耗 不适用于交互性较强的app
可以使用开发者选项->显示布局边界进行判断
```

**解析**

```text
【核心考点】 移动测试 Hybrid应用
【题目解析】
本题考查Hybrid（混合）应用的概念及识别方法。Hybrid应用结合原生壳与WebView，兼具跨平台和部分原生性能。判断方法包括查看布局边界或检查WebView组件。
【参考答案要点】
Hybrid应用定义：在原生应用中嵌入WebView，通过加载HTML/JS实现界面，可调用原生API。
优点：开发成本低、跨平台、更新灵活；缺点：性能逊于原生，交互体验受限。
判断方法：开启开发者选项中的“显示布局边界”，若界面显示为WebView区域，则为Hybrid；或通过抓包工具检查网络请求中的HTML内容。
【易错提示】
混淆Hybrid与Web App。Hybrid有原生壳，可访问设备功能；Web App完全基于浏览器，无原生能力。面试中常要求举例说明，如微信小程序属于Hybrid变体。
```

## Q006887

- 题型：简答
- 难度：中等

**题目**

```text
app测试上的H5和原生页面怎么区分？
```

**答案**

```text
1）断开网络，显示404或则错误页面的是H5

2）查看页面布局，a.在手机设置、开发者选项中开启显示布局边界功能；b.进入应用查看布局边界；c.原生应用可以看到各个控件的布局边界，H5只有整个页面的一个边界

3）长按页面，出现特殊标记、放大镜，复制，粘贴等等，甚至手机震动（Android），则表示是H5

4）打开新页面导航栏下面有一条加载的线的话，这个页面就是H5页面

5）APP顶部导航栏当中出现了关闭按钮或者有关闭的图标，那么当前是H5页面

6）下拉页面的时候显示网址提供方的是H5页面
```

**解析**

```text
【核心考点】 APP测试 H5页面 原生页面
【参考答案要点】
1. 网络断开测试：断开网络，显示404或错误页面的是H5。
2. 布局边界查看：在手机设置、开发者选项中开启显示布局边界功能；进入应用查看布局边界；原生应用可以看到各个控件的布局边界，H5只有整个页面的一个边界。
3. 长按操作：长按页面，出现特殊标记、放大镜、复制、粘贴等，甚至手机震动（Android），则表示是H5。
4. 加载进度条：打开新页面导航栏下面有一条加载的线的话，这个页面就是H5页面。
5. 关闭按钮：APP顶部导航栏当中出现了关闭按钮或者有关闭的图标，那么当前是H5页面。
6. 下拉显示网址：下拉页面的时候显示网址提供方的是H5页面。
【面试角度】
回答此类问题时，建议结合实际项目经验举例说明，例如“在项目中我们通过布局边界快速定位H5页面”，能有效提升答案深度。
【延伸知识】
H5页面与原生页面在性能、交互体验和开发成本上各有优劣。面试中可进一步讨论混合开发框架（如React Native、Flutter）的测试策略。
```

## Q006888

- 题型：简答
- 难度：中等

**题目**

```text
你说一下小程序怎么测的？
```

**答案**

```text
小程序的测试业务功能跟web、APP测试一样的，先分析需求，提炼测试点，使用等价类边界值、场景法等方法设计用例；然后执行测试；
另外，小程序还有自己的一些专项测试点；比如小程序的入口测试、跟微信的兼容性测试，登录权限的测试等，以及还要覆盖不同的网络类型进行，以及弱网测试，还有中断测试等。
```

**解析**

```text
【核心考点】 小程序测试 专项测试
【题目解析】
本题考查小程序测试的完整流程和专项测试点。小程序测试既包含传统Web/APP测试的通用方法（如需求分析、用例设计、执行），又需关注其特有的入口、兼容性、网络等专项测试。
【参考答案要点】
1. 业务功能测试：与Web/APP测试一致，先分析需求，提炼测试点，使用等价类、边界值、场景法等方法设计用例，然后执行测试。
2. 专项测试：
- 入口测试：验证小程序从微信聊天、搜索、扫码等不同入口进入时的表现。
- 兼容性测试：测试与微信不同版本、不同手机型号的兼容性。
- 登录权限测试：测试微信授权登录、用户信息获取等权限流程。
- 网络测试：覆盖Wi-Fi、4G/5G、弱网及无网络场景。
- 中断测试：测试电话、短信、微信消息等中断对小程序的影响。
【面试角度】
回答时建议结合实际项目经验，例如“在测试某电商小程序时，我们重点验证了从朋友圈分享入口进入的流程”，能体现对专项测试的深入理解。
【易错提示】
不要只回答业务功能测试，忽略专项测试点，这是面试官考察的重点。
```

## Q006889

- 题型：简答
- 难度：中等

**题目**

```text
实时视频怎么写测试点？
```

**答案**

```text
音视频实时性（延时）、流畅性（测试视频卡顿率、渲染帧率）、主观画质（接收端的画面质量，质量等级越高，画面质量越好）、首帧出图（从进入会议到看到对端画面的时间，单位：ms，首帧出图越快越好）、音画同步（音画同步反映视频和音频的同步程度），还有就是弱网、兼容性、性能测试；
```

**解析**

```text
【核心考点】 实时视频测试 音视频质量
【题目解析】
本题考查实时视频通信场景下的测试点设计，属于音视频测试领域的核心内容。实时视频测试需覆盖用户体验的关键指标：延时、流畅性、画质、首帧出图、音画同步，以及弱网、兼容性和性能测试。
【参考答案要点】
1. 音视频实时性（延时）：测试端到端延迟，包括采集、编码、传输、解码、渲染各环节耗时，通常要求2. 流畅性：测试视频卡顿率、渲染帧率，确保帧率稳定（如30fps），无频繁卡顿。
3. 主观画质：接收端画面质量等级评估，使用MOS分或主观评价，关注清晰度、色彩、噪声等。
4. 首帧出图：从进入会议到看到对端画面的时间，单位ms，越快越好，通常要求5. 音画同步：测试视频和音频的同步程度，偏差应6. 弱网测试：模拟丢包、延迟、抖动、带宽限制等场景，验证抗丢包算法和自适应码率。
7. 兼容性测试：覆盖不同操作系统、浏览器、移动设备、摄像头等。
8. 性能测试：CPU、内存、网络带宽占用，长时间稳定性测试。
【面试角度】
回答时建议结合实际项目经验，例如“在视频会议项目中，我们使用WebRTC工具分析延时，通过模拟弱网环境测试卡顿率”，能体现实践能力。
【易错提示】
易遗漏弱网和兼容性测试，仅关注功能指标。面试中需强调用户体验，如首帧出图对用户感知的影响。
```

## Q006890

- 题型：简答
- 难度：中等

**题目**

```text
小程序怎么和微信交互的？
```

**答案**

```text
小程序要跟微信交互 主要是登录授权 和 微信的钱包卡包支付 以及跟小程序使用 过程中，微信消息等正常使用；
比如登录授权的交互：就是小程序需要先去获取微信的登录凭证，得到微信的授权后，再用微信的账号发送到自己的服务器里保存成业务会话；后面就直接用这个微信账号进行登录了；
```

**解析**

```text
【核心考点】 小程序开发 微信交互 登录授权
【题目解析】
本题考查小程序与微信生态的交互机制，核心是登录授权流程。小程序通过wx.login获取临时code，发送到开发者服务器，服务器通过code向微信服务器换取session_key和openid，从而建立用户会话。此外，还涉及支付、卡包、消息模板等交互。
【参考答案要点】
1. 登录授权流程：小程序调用wx.login获取code → 发送到开发者服务器 → 服务器调用auth.code2Session接口获取openid和session_key → 服务器生成自定义登录态返回给小程序。
2. 支付交互：小程序调用wx.requestPayment，传入支付参数（由服务器统一下单生成）。
3. 消息交互：通过模板消息或订阅消息向用户发送通知。
【面试角度】
回答时建议强调安全性，如code仅能使用一次、session_key不应传给客户端等，体现对微信安全规范的了解。
【易错提示】
容易混淆前端和后端职责，如误以为前端直接获取openid。实际openid必须由后端通过code换取，保证安全性。
```

【核心考点】 H5测试 移动端测试

本题考察候选人对H5页面测试的实践经验。面试官期望了解候选人是否具备H5测试的独立方法，而不仅仅是依赖APP整体测试。回答应体现对H5特性（如兼容性、性能、离线存储等）的测试意识。

## Q006885

- 题型：简答
- 难度：较难

**题目**

```text
H5测试是怎么做的？
```

**答案**

```text
我们平时说的H5测试就是HTML5，就是：移动端WEB页面。
我们以往的APP是使用原生系统内核的，相当于直接在系统上操作，是我们传统意义上的软件，更加稳定。H5的APP先得调用系统的浏览器内核，相当于是在网页中进行操作，较原生APP稳定性稍差。h5最大的优点是可以跨平台，开发容易。APP的话需要用ANDROID的语言和IOS的语言各自写，H5只要开发一套 。
简单的说：H5是基于web，native基于客户端。
H5测试应该从哪些方面考虑？

1、业务逻辑相关
除基本的功能测试之外，H5页面的测试，需要关注以下几点：

1.1 登陆
目前H5与native各个客户端都做了互通，所以在测试的时候要注意两点：

A、若客户端已登录，那么进入H5后仍然是登录状态。

B、若客户端未登录，进入H5，点击对应按钮OR链接，如果需要登录，须拉起native登录。若取消登录，是否可再次拉起登录，或者停留在的页面是否有对应的登录提示。

1.2 翻页
遇到翻页加载的页面，需要注意内容为1页或者多页的情况。

A、数据分页加载时，注意后续页面请求数据的正确。
ps：这个需要注意在快速操作场景中，请求页数是不是依次递增，快速操作
（如第一页尚未loading出来的时候仍然继续上拉操作）时是否发出去对应的请求了。

1.3 刷新与返回

A、下拉刷新是否仍然处于当前页面。

B、用户主动点击刷新按钮是否仍然处于当前页面。

C、点击返回与back键，回退页面是否是期望页面

1.4 数据的请求与返回：

A:提交了数据，数据是否正确的整理到后台管理系统

B:发送了请求，是否正确返回你要求的数据：比如我们常见的结婚请帖，是否有收到回执？

2、H5适配相关
H5的适配其实比客户端的相对来说，要少一些，手机品牌之间的差异不大，所以不用太多关注，最容易出现问题的是android2.3系统，这个要特别关注下：

A、大屏（如720*1280，重点关注页面背景是否完全撑开页面，刷新是否有抖动）、小屏手机（如320*480，重点关注下弹框样式和文案折行）

B、android2.3、android4.X随机找一个即可。

C、ios5、ios6、ios7。

D、浏览器上也要能够进行完美展示。

3、安全相关

3.1 明确投放渠道都有哪些
如独客、主客、wap，是否对未投放渠道做了限制，直接通过url请求是否拦截等

3.2 是否需要接入支付宝实名认证涉及到金钱相关，如天猫积分，红包等，为了防刷，一般都需要判断是否支付宝实名认证。

4、体验相关

4.1 资源相关

A、页面中有图片的话，淘宝那边建议图片一般不大于50kb，本着一个原则，尽量缩小图片。

B、资源是否压缩、是否通过CDN加载。---CDN是什么？---就近地区访问，服务速度会更快。

C、如何保证二次发布后有效更新。

D、对于类似公司名称、offer名称长度的问题，在手机上最好能根据屏幕大小自适应而不是截断，因为手机上是不会有tips可以看的。截断导致大屏幕下也只能显示几个字，交互不好

4.2 流量

A、对于一些不会变化的图片，如游戏动画效果相关图片，不需要每次都请求的东西，做本地缓存。

B、数据较多时是否做了分页加载。

4.3 页面展现时间

A、关注页面首屏加载时间。

4.4 页面提示

A、弱网络下，数据加载较慢，是否有对应的loading提示。

B、接口获取异常时，提示是否友好。

C、刷新页面或者加载新内容时页面是否有抖动。

4.5 手机操作相关

A、锁屏之后展示页面。

B、回退到后台之后，重新呼出在前台展示。
</
```

**解析**

【参考答案要点】

## Q006891

- 题型：简答
- 难度：较难

**题目**

```text
建立视频通讯的过程是怎么实现的？
```

**答案**

```text
直播的话，业界用的比较多的是rtmp协议，主播端推流到rtmp服务器，观众端从服务器拉视频流播放；视频会议中，国内用的比较多的是webrtc，各端进入会议后，各端相互直接通信且各端与webrtc服务器同时进行通信；短视频中，一般是用户拍摄的视频直接放到视频服务器上，观众端通过http从服务器获取视频数据进行播放。
```

**解析**

```text
【核心考点】 视频通讯 流媒体协议 RTMP WebRTC
【题目解析】
本题考查视频通讯的实现原理，涉及不同场景下的协议选择。直播场景常用RTMP协议实现推流和拉流；视频会议场景常用WebRTC实现点对点通信；短视频场景则通过HTTP协议进行文件传输。每种协议有其适用场景和优缺点。
【参考答案要点】
1. 直播场景：主播端使用RTMP协议推流到流媒体服务器，观众端通过RTMP或HLS从服务器拉流播放。
2. 视频会议场景：基于WebRTC，各端建立P2P连接，同时与信令服务器和TURN/STUN服务器交互，实现NAT穿透和媒体协商。
3. 短视频场景：用户上传视频到服务器，观众通过HTTP请求下载视频文件进行播放。
【面试角度】
建议结合实际项目经验说明协议选型原因，如“在直播项目中，我们选择RTMP是因为其低延迟特性，适合实时互动”。
【延伸知识】
WebRTC使用ICE框架进行连接建立，包括STUN（获取公网地址）和TURN（中继转发）服务器，确保在各种网络环境下可用。
```
