## Q006723

- 难度：入门

**题目**

```text
怎么判断手机上的应用是否安装成功？
```

**答案**

```text
app安装完后，手机屏幕上会出现该app的图标，点击后可以正常打开并使用该程序，即为应用程序安装成功
```

**解析**

```text
【核心考点】 移动应用测试 安装测试
【参考答案要点】
判断手机应用是否安装成功，通常从以下两个方面验证：
1. 图标显示：安装完成后，手机桌面或应用列表中应出现该应用的图标。

【面试角度】

【延伸知识】
安装测试还应关注：安装过程中是否提示权限请求、安装后是否生成正确的桌面快捷方式、卸载后是否残留文件等细节。
```

## Q006679

- 题型：简答
- 难度：简单

**题目**

```text
APP如何用工具弱网测试？
```

**答案**

```text
1）打开Charles-》Throttle settings
2）设置网络：设置2/3G网络环境，设置上下行带宽

3) 把手机网络设置代理为配置了Charles的电脑IP和对应的端口；
```

**解析**

```text
【核心考点】 弱网测试 Charles工具
【题目解析】
本题考查APP测试中弱网环境的模拟方法，属于移动测试基础技能。使用Charles工具进行弱网测试的步骤包括：打开Charles的Throttle Settings，设置网络类型（如2G/3G）及上下行带宽，然后将手机代理指向配置了Charles的电脑IP和端口，即可模拟弱网环境。
【参考答案要点】
1. 打开Charles：点击Proxy菜单，选择Throttle Settings。
2. 配置网络参数：勾选Enable Throttling，选择预设网络类型（如3G），或自定义带宽、延迟等参数。
3. 设置手机代理：将手机WiFi代理设置为电脑IP和Charles默认端口（8888）。
4. 开始测试：在手机上操作APP，观察弱网下的行为。
【易错提示】
注意手机和电脑必须在同一局域网内，且Charles需要开启SSL Proxying以捕获HTTPS请求。
```

```text
OA项目商店下载不了，内部是怎么下载的（包括安卓和iOS）
```

**答案**

```text
android 是通过开发提供APK包进行安装的；iOS的话 我们是给开发UDID的编号，让开发帮忙添加到开发者账号，然后就是可以安装开发提供的测试版本了。
```

**解析**

```text
【核心考点】 移动端测试 应用安装方式
【题目解析】
本题考察移动应用测试中，Android和iOS平台内部测试版本的分发与安装机制。Android通过APK包直接安装，iOS则依赖UDID授权和开发者签名。
【参考答案要点】
Android：开发提供APK包，测试人员通过USB、邮件、内测平台（如蒲公英）等方式下载并安装，需开启“允许未知来源”权限。

【易错提示】
```

```text
【延伸知识】
除了本地和服务器环境，App测试还可能涉及网络环境（如WiFi、4G/5G）、硬件环境（不同分辨率、操作系统版本）等，面试中可补充说明以展示广度。
```

## Q006707

- 题型：简答
- 难度：简单

**题目**

```text
什么是PIN PIN2 PUK码？
```

**答案**

```text
PIN码(PIN1)就是 SIM卡的 个人识别密码。
PUK码(PUK1)由8位数字组成，这是用户无法更改，只有补换 SIM卡后PUK码才会变更。
PIN2（Personal Identification Number 2）码是在进入某种特殊功能时（如设置固定号码，设置通话计费等）所要输入的个人识别码。
```

**解析**

```text
【核心考点】 SIM卡安全 移动通信基础
【题目解析】
本题考查SIM卡相关的安全码概念，属于移动通信基础知识。PIN码、PUK码是保护SIM卡安全的重要机制，在手机测试中常涉及。
【参考答案要点】
1. PIN码（PIN1）：SIM卡的个人识别密码，默认一般为1234或0000，用户可修改。输入错误3次后SIM卡被锁定。
2. PUK码（PUK1）：由8位数字组成，用于解锁被PIN码锁定的SIM卡。用户无法更改，只有补换SIM卡时才会变更。输入错误10次后SIM卡永久损坏。
3. PIN2码：进入特殊功能（如设置固定号码、通话计费等）时所需的个人识别码，通常不常用。
【易错提示】
注意区分PIN码和PUK码：PIN码是用户设置的保护码，PUK码是运营商提供的解锁码。另外，PIN2码与PIN1码不同，功能更局限。
```

```text
APP 测试和 web 测试有什么区别？
```

```text
(2) 客户端性能方面：Web 端可能只会关注响应时间；App 则还要关心流量、电量、cpu、
等；
(3) 兼容方面：Web 是基于浏览器的，所以更倾向于浏览器（IE、Chrome、firefox）和电脑
硬件，电脑系统方向的兼容；App 测试则必须依赖于手机或者 pad，不仅要看分辨率、频目
尺寸、重要看设备系统。
```

```text
【核心考点】 移动端测试 Web端测试 测试区别
【参考答案要点】
1. 系统架构：Web端是B/S架构，更新服务器后客户端自动同步；App端是C/S架构，服务端更新后需回归测试客户端所有核心版本。

3. 兼容性：Web端侧重浏览器（IE、Chrome、Firefox）和操作系统兼容；App端侧重设备型号、操作系统版本、屏幕分辨率等。
4. 网络环境：App测试需考虑不同网络（2G/3G/4G/5G/WiFi）和弱网场景，Web端通常假设网络稳定。
5. 安装卸载：App需测试安装、升级、卸载、覆盖安装等；Web端无此过程。
【面试角度】
建议结合实际项目经验举例，例如“在App测试中，我们使用Charles模拟弱网环境，而Web测试则用LoadRunner做性能测试”。

移动端测试还包括手势操作、推送通知、后台运行等特有场景，面试中可进一步展开。
```

## Q006714

- 题型：简答
- 难度：中等

**题目**

```text
埋点测试怎么测试？
```

**答案**

```text
埋点测试是指对移动应用程序中埋入的统计代码进行测试，以确保收集的数据正确、完整和准确。埋点测试通常包括以下步骤：
1、埋点设计审核：在应用程序开发过程中，需要对埋点设计进行审核，包括埋点名称、埋点位置、埋点参数等。审核的目的是确保埋点设计符合产品需求和业务规则，并避免不必要的冗余数据。
2、埋点代码集成测试：在应用程序开发过程中，需要对埋点代码进行集成测试，以确保代码可以正确地收集数据，并将数据发送到统计服务端。集成测试的目的是确保埋点代码的正确性和稳定性。
3、埋点数据验证测试：在应用程序发布前或发布后，需要对埋点数据进行验证测试，以确保收集的数据正确、完整和准确。验证测试的目的是发现数据收集中的问题，并及时修复。
下面是具体的步骤：
1、确定需求和业务规则：在进行埋点测试前，需要明确应用程序的需求和业务规则，确定需要收集的数据类型和数量。
2、设计测试用例：根据需求和业务规则，设计测试用例，包括测试场景、测试步骤和预期结果。
```

## Q006726

- 题型：简答
- 难度：中等

**题目**

```text
手机APP更新测试，说下测试点？
```

**答案**

```text
移动端版本更新升级是一个比较重要的功能点，主要分为强制更新和非强制更新。
1. 强制更新需要测试的点有：
a> 强制升级是否可以升级成功，功能是否正常
b> 升级后的数据是否正常
c> 强制升级的弹窗是否可以关闭
d> 强制更新的提示，包括未更新和已更新
e> 版本号对比等等
2. 非强制更新的测试点有：
1> 提示弹框的显示，是否可以选择暂不更新和立即更新；是否可以关闭弹框不显示
2> 选择暂不更新后，老版本是否可以正常使用
3> 选择立即更新后，更新能否成功，新版本号是否是最新版本；功能是否是最新的
4> 非强制更新弹框的提示频率，是每天一次还是每周一次，根据需求来测
5> APP设置里的版本更新，是否也能触发非强制更新
6> 用户选择继续使用老版本后，使用某些新版本才有的功能时，是否还有更新提示
7> 版本号对比等等

总结：强制升级一般用于版本改动较大，业务较重要，功能模块存在风险的情况；非强制更新适用于版本改动不是很大，对业务影响不大，不存在风险问题的。
```

**解析**

```text
【核心考点】 移动端测试 版本更新
【题目解析】
本题考察移动端APP版本更新功能的测试点设计。版本更新分为强制更新和非强制更新，测试需覆盖更新流程、数据兼容性、用户交互和版本号管理。
```

## Q006700

- 题型：简答
- 难度：较难

**题目**

```text
app测试和web测试的区别?
```

**答案**

```text
单纯从功能测试的层面上来讲的话，APP测试、web测试在流程和功能测试上是没有区别的。
根据两者载体不一样，则区别如下：
1、系统结构方面
web项目，b/s架构，基于浏览器的；web测试只要更新了服务器端，客户端就会同步会更新。
app项目，c/s结构的，必须要有客户端；app 修改了服务端，则客户端用户所有核心版本都需要进行回归测试一遍。
2、性能方面
web项目 需监测 响应时间、CPU、Memory
app项目 除了监测 响应时间、CPU、Memory外，还需监测 流量、电量等
3、兼容方面
（1）web项目：
1. 浏览器（火狐、谷歌、IE等）
2. 操作系统（Windows7、Windows10、Linux等）
（2）app项目：
1. 设备系统:iOS（ipad、iphone）、Android（三星、华为、联想等） 、Windows（Win7、Win8）、OSX（Mac）
2. 手机设备可根据 手机型号、分辨率不同
4、相对于 Web 项目，APP有专项测试
1. 干扰测试：中断，来电，短信，关机，重启等
2. 弱网络测试（模拟2g、3g、4g，wifi网络状态以及丢包情况）；网络切换测试（网络断开后重连、3g切换到4g/wifi 等）
3. 安装、更新、卸载
安装：需考虑安装时的中断、弱网、安装后删除安装文件等情况
卸载：需考虑 卸载后是否删除app相关的文件
更新：分强制更新、非强制更新、增量包更新、断点续传、弱网状态下更新
4. 界面操作：关于手机端测试，需注意手势，横竖屏切换，多点触控，前后台切换
5. 安全测试：安装包是否可反编译代码、安装包是否签名、权限设置，例如访问通讯录等
6. 边界测试：可用存储空间少、没有SD卡/双SD卡、飞行模式、系统时间有误、第三方依赖（QQ、微信登录）等
7. 权限测试：设置某个App是否可以获取该权限，例如是否可访问通讯录、相册、照相机等
5、测试工具方面
自动化工具：APP 一般使用 Appium; Web 一般使用 Selenium
性能测试工具：APP 一般使用 JMeter; Web 一般使用 LR、JMeter
```

**解析**

```text
【核心考点】 移动测试 Web测试 测试对比
【参考答案要点】
APP测试和Web测试在功能测试流程上基本一致，但存在以下主要区别：
1. 系统结构方面：Web项目基于B/S架构，更新服务端后客户端自动同步；APP项目基于C/S架构，需客户端更新，且需回归测试所有核心版本。
2. 性能方面：Web测试关注响应时间、CPU、内存；APP测试还需监测流量、电量、温度等移动特有指标。
3. 兼容性方面：Web测试需考虑浏览器（Chrome、Firefox、IE等）和操作系统（Windows、macOS）；APP测试需考虑设备型号、屏幕分辨率、操作系统版本（Android/iOS）等。

【面试角度】
回答时建议结合实际项目经验，例如“在APP测试中，我们曾遇到不同机型电量消耗差异大的问题，需专项测试”，并提及自动化测试工具差异（如Web常用Selenium，APP常用Appium），提升答案专业度。
【延伸知识】
移动测试还包括手势操作测试（滑动、多点触控）、推送测试、弱网测试等，这些是Web测试不具备的。
```

## Q006727

- 题型：简答
- 难度：较难

**题目**

```text
手机上语音测试怎么测 如Siri 今天天气怎么样 怎么判断这句话是对的？
```

**答案**

```text
语音识别技术是让机器通过识别把语音信号转变为文本。评价指标是识别率，在实际工作中，一般识别率的直接指标是“WER（词错误率，Word Error Rate）”。先对一段语音进行标注，然后与程序识别结果进行对比，得出词错误率
```

**解析**

```text
【核心考点】 语音识别测试 WER指标 测试方法
【参考答案要点】
1. 测试方法：语音识别测试需模拟真实场景，包括不同口音、语速、噪声环境等，输入语音后对比识别结果与预期文本。
2. 评价指标：常用WER（词错误率），计算公式为 (插入词数+删除词数+替换词数) / 总词数。WER越低，识别准确率越高。
3. 判断正确性：对测试语音进行人工标注，得到标准文本，然后与识别结果对齐，计算WER。例如，问“今天天气怎么样”，若识别为“今天天气怎么样”则正确，若为“今天天气怎么”则计算错误。
【题目解析】
本题考察语音识别测试的实践方法。语音测试不同于传统功能测试，需要关注识别准确率、响应时间、鲁棒性等。WER是行业标准指标，通过对比标注文本和识别结果来量化。测试时需覆盖多种场景，如安静环境、嘈杂环境、不同方言等。
【延伸知识】
除了WER，还有CER（字符错误率）和SER（句子错误率）。面试中可补充测试数据集的构建，如使用开源语音库或自建语料，以及如何评估多轮对话的语义理解。
```

```text
12.在安装中点击取消或杀掉进程，是否还能重新安装
```

**解析**

```text

【题目解析】
本题考察候选人对App安装测试的全面思考能力。安装测试是App测试的基础环节，需要覆盖正常安装、版本升级、回退、异常情况、兼容性等多个维度。面试官期望看到系统化的测试点设计，而非零散罗列。
【参考答案要点】
1. 正常安装测试：验证安装过程是否顺利，安装后应用能否正常启动和运行。
2. 版本覆盖测试：测试低版本覆盖高版本（如1.0→1.1）、高版本覆盖低版本（如1.1→1.0）是否正常，数据是否保留。
3. 版本回退测试：安装高版本后回退到低版本，检查是否允许回退及数据兼容性。
4. 内存不足测试：在设备存储空间不足时安装，验证是否有明确提示。
5. 异常中断测试：安装过程中断电、断网、来电、短信、切换应用等，检查安装状态是否正常恢复或提示。
6. 兼容性测试：在不同品牌、型号、系统版本（Android/iOS）、屏幕尺寸、分辨率上安装测试。
7. 安装后影响测试：重启手机后应用能否正常启动；是否影响其他应用运行；杀毒软件是否误报。
8. 权限测试：安装时是否提示所需权限，拒绝权限后应用是否正常降级运行。
9. 安装包完整性：损坏或篡改的APK/IPA文件安装时是否提示错误。
10. 多用户测试：在支持多用户的设备上，不同用户安装是否互不影响。
【面试角度】
回答时建议按分类组织（如正常、异常、兼容性等），体现结构化思维。可结合实际项目经验举例，如“在测试中曾发现低版本覆盖高版本导致数据丢失的bug”。
【易错提示】
常见遗漏：版本回退测试、权限测试、多用户场景。避免只列出3-4个点，应尽量全面覆盖。
```

## Q006728

- 题型：简答
- 难度：未标注
- 解析：AI 补全（原数据缺失解析）

**题目**

```text
手机测试主要分为哪几个领域
```

**答案**

```text
手机软件测试大致分为下列测试。
1、功能测试：手机软件的基本功能。
2、稳定性测试：大多数手机应用需要保证能够稳定运行一定时间，而且在应用的运行状态发生切换后需要继续保持当前的状态，不出现闪退。
3、性能测试：这部分分为两个方面，一是后台服务的性能测试，二是应用自身的性能情况。
4、安全测试：应用有没有做混淆，敏感数据是否存在内存卡上等。
5、地理位置定位测试：大多数业务软件都支持获取用户的地理位置信息，方便本地业务的定制。
6、应用升级兼容性测试：需要保证应用能够在升级或跨版本升级后一些关键数据得以保留，而不必用户重新设置。
7、设备兼容性测试：随着安卓设备的快速分化以及iOS设备的缓慢分化，应用需要适配在不同配置的硬件平台上。
8、耦合应用测试：大多数应用需要跟其他应用进行交互，从而达到“社交化”或“分享”以及“支付”的功能。
```

**解析**

```text
【核心考点】手机测试的主要领域划分。
【题目解析】手机测试通常覆盖功能、稳定性、性能、安全、定位、升级兼容、设备兼容和耦合应用等方面。功能验证基本业务；稳定性看长时间运行和状态切换；性能分后台服务与应用自身；安全关注混淆和敏感数据；兼容性覆盖机型、系统和版本；耦合应用关注分享、支付等跨应用交互。
【答题要点】
1. 功能与稳定性是基础。
2. 性能和安全决定体验与风险。
3. 兼容性、升级和跨应用交互易被遗漏。
【面试提示】按“功能、非功能、兼容、交互”归类记忆，比逐条背诵更自然。
```
