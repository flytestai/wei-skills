## Q006844

- 题型：简答
- 难度：中等

**题目**

```text
ANR有哪些类型?
```

**答案**

```text
1：KeyDispatchTimeout(5 seconds) –主要类型
按键或触摸事件在特定时间内无响应

2：BroadcastTimeout(10 seconds)
BroadcastReceiver在特定时间内无法处理完成，此处指的是前台广播，后台广播为60秒

3：ServiceTimeout(20 seconds) –小概率类型
Service在特定的时间内无法处理完成，此处通常指前台Service，后台Service为200秒

4:contentprovider的publish在10秒内没进行完，这个比较陌生和少见
```

**解析**

```text
【核心考点】 ANR类型 Android性能
【题目解析】
本题考察Android ANR（Application Not Responding）的类型，属于Android开发与测试的进阶知识。ANR是Android系统检测到应用主线程阻塞超时后触发的机制，常见类型包括输入事件超时、广播超时、服务超时和ContentProvider超时。面试中常以此考察候选人对Android系统机制的熟悉程度。
【参考答案要点】
1. KeyDispatchTimeout（5秒）：按键或触摸事件在5秒内无响应，最常见类型，通常由主线程执行耗时操作（如网络请求、数据库读写）导致。
2. BroadcastTimeout（前台10秒，后台60秒）：BroadcastReceiver的onReceive方法在指定时间内未执行完毕，前台广播超时10秒，后台广播超时60秒。
3. ServiceTimeout（前台20秒，后台200秒）：Service的onCreate、onStartCommand等生命周期方法在指定时间内未完成，前台服务超时20秒，后台服务超时200秒。
4. ContentProviderTimeout（10秒）：ContentProvider的publish过程在10秒内未完成，较为少见，通常与Provider初始化耗时有关。
【面试角度】
回答时可补充ANR定位与解决方法，例如使用StrictMode检测主线程耗时操作、通过Traceview分析卡顿点、将耗时任务移至子线程等，体现实战能力。
【易错提示】
注意区分前台和后台服务的超时时间不同，避免混淆；ContentProvider超时较冷门但需了解。
```

## Q006848

- 题型：简答
- 难度：中等

**题目**

```text
APP耗电量特别快会有什么原因导致
```

**答案**

```text
cpu：复杂的运算逻辑、死循环等会直接导致CPU负载过高，会导致耗电；
wakelock（保持唤醒锁）：只要有应用程序拿到wakelock这个锁，系统就无法进入睡眠状态。频繁wakelock或者申请了wakelock没有释放，会导致耗电；
wifiscan和wifilock：wifiscan和wifilock也会导致手机的wifi模块处于激活状态，频繁的wifiscan或者wifilock不释放，会导致耗电；
sensor：传感器打开后会导致系统持续监听设备外围环境的数据变化，使用后不及时关闭，会导致耗电；
network：大量的数据传输，或者长时间的移动网络数据传输导致radio长期处于活跃状态，会导致耗电；
gps：gps也是一种传感器，定位中没有及时关闭，会导致耗电。
```

**解析**

```text
【核心考点】 APP性能测试 耗电分析
【参考答案要点】
1. CPU负载过高：复杂运算、死循环等导致CPU持续高负荷运行，增加功耗。
2. Wakelock（保持唤醒锁）：应用申请wakelock后阻止系统休眠，若未及时释放，会导致系统无法进入低功耗状态。
3. WiFi扫描和WiFi锁：频繁WiFi扫描或持有WiFi锁不释放，使WiFi模块持续活跃。
4. 传感器使用：如GPS、加速度计等传感器开启后持续监听环境数据，使用后未关闭会增加耗电。
5. 网络数据传输：大量数据传输或长时间移动网络连接，使Radio模块处于高功耗状态。
【面试角度】
回答时建议结合实际项目经验，例如“在测试中，我们使用Battery Historian工具分析耗电情况，发现某个后台服务频繁唤醒CPU，通过优化后功耗降低30%”。同时可提及耗电测试方法，如使用adb命令模拟不同场景，展现实践能力。
【延伸知识】
耗电优化策略包括：减少后台任务、使用JobScheduler替代定时器、优化网络请求合并、及时释放资源等。面试中可能进一步考察如何定位耗电问题，如使用dumpsys batterystats或第三方工具。
```

```text
5、设计不合理，1个接口，拉取的数据量太大，请求结果会很慢，且占用大量内存，APP会闪退（比如，我们现在做的记录仪，进入相册列表时候，要拉取所有图片，拉取太慢了，就闪退了）。
```

## Q006871

- 题型：简答
- 难度：中等

**题目**

```text
出现崩溃和无响应是一般在什么情况出现？
```

**答案**

```text
崩溃：
1.内存管理错误：可能是可用内存过低，app所需的内存超过设备的限制，app跑不起来导致App crash。 或是内存泄露，程序运行的时间越长，所占用的内存越大，最终用尽全部内存，导致整个系统崩溃。 亦或非授权的内存位置的使用也可能会导致App crash。

2.程序逻辑错误：数组越界、堆栈溢出、并发操作、逻辑错误。 e.g. app新添加一个未经测试的新功能，调用了一个已释放的指针，运行的时候就会crash。
3.设备兼容：由于设备多样性，app在不同的设备上可能会有不同的表现。
```

## Q006849

- 题型：简答
- 难度：较难

**题目**

```text
Android APP 内存不足时， 系统如何结束进程获得内存？
```

**答案**

```text
系统优先结束被挂起（暂停）的进程，释放内存
1.先回收与其他Activity或Service/Intent Receiver无关的进程（即优先回收独立的Activity）
2.再回收处于“Stopped”状态的其他类型Activity（在背景等待的Activity）。很久没有使用的Activity优先回收（比较官方的说法是“根据LRU算法...”）
3.还不够？回收service进程
4.快不行啦，关掉可见的Activity进程
5.关闭当前的Activity
```

**解析**

```text
【核心考点】 Android内存管理 进程优先级 LRU算法
【参考答案要点】
Android 系统在内存不足时，根据进程优先级从低到高依次回收：
1. 空进程：优先回收与任何 Activity/Service/Intent Receiver 无关的独立进程。
2. 后台 Activity 进程：回收处于“Stopped”状态、在后台等待的 Activity，按 LRU（最近最少使用）算法优先回收长时间未使用的。
3. Service 进程：回收正在运行的后台 Service。
4. 可见 Activity 进程：回收当前可见但非前台的 Activity（如被对话框部分遮挡）。
5. 前台 Activity 进程：最后回收当前与用户交互的 Activity。
【面试角度】
面试官常考察 进程优先级与回收顺序，建议结合 实际项目中的内存优化 举例，如“在低端设备上测试时，发现后台 Service 被频繁回收，导致功能异常，通过调整进程优先级或使用前台 Service 解决”。
【延伸知识】
Android 系统使用 Low Memory Killer 机制，基于 oom_adj 值决定回收顺序。了解 Activity 生命周期 和 进程保活 策略有助于深入回答。
```

```text
app出现ANR，是什么原因导致的？
```

**答案**

```text
那么导致ANR的根本原因是什么呢？
简单的总结有以下两点：
1.主线程执行了耗时操作，比如数据库操作或网络编程
2.其他进程（就是其他程序）占用CPU导致本进程得不到CPU时间片，比如其他进程的频繁读写操作可能会导致这个问题。
细分的话，导致ANR的原因有如下几点：
1.耗时的网络访问
2.大量的数据读写
3.数据库操作
4.硬件操作（比如camera)
5.调用thread的join()方法、sleep()方法、wait()方法或者等待线程锁的时候
6.service binder的数量达到上限
7.system server中发生WatchDog ANR
8.service忙导致超时无响应
9.其他线程持有锁，导致主线程等待超时
10.其它线程终止或崩溃导致主线程一直等待。
```

**解析**

```text
【核心考点】 ANR原因分析 Android性能测试
【题目解析】
本题考查Android中ANR（Application Not Responding）的常见原因。ANR本质上是主线程（UI线程）被阻塞超过一定时间（如5秒），导致系统弹出无响应对话框。原因可分为主线程耗时操作和系统资源竞争两大类。
【参考答案要点】
1. 主线程耗时操作：在主线程中执行网络请求、数据库操作、文件读写、Bitmap解码等耗时任务，会阻塞UI更新。
2. 线程同步问题：主线程等待其他线程释放锁（如synchronized块），或调用Thread.join()、sleep()、wait()等方法导致长时间阻塞。
3. 系统资源竞争：其他进程频繁占用CPU或I/O资源，导致本进程无法获得时间片。
4. 系统服务超时：Service或BroadcastReceiver执行时间过长（如Service超时20秒），或binder调用达到上限。
5. 硬件操作：Camera、传感器等硬件操作在主线程中执行。
【面试角度】
面试中，建议结合实际项目中的ANR排查案例，例如“在测试某社交应用时，发现图片加载导致ANR，原因是主线程直接解码大图，后改为使用异步线程和Glide库解决”。同时可提及使用Traceview或Systrace工具分析ANR日志。
【易错提示】
常见错误：仅关注主线程耗时操作而忽略系统资源竞争；混淆ANR与OOM（内存溢出）的区别；未考虑低端设备性能差异。
```

## Q006878

- 题型：简答
- 难度：较难

**题目**

```text
请描述android中ANR的现象并列举发生ANR的原因？
```

**答案**

```text
粗略的来分会有两种情况导致ANR：

第一类：dispatchTimeout 输入事件分发超时，一般是由于主线程在5秒之内没有响应输入事件。

第二类：BroadcastReceiver没有在系统设定的时间内完成并返回。
再细分的话ANR可能是由主线程导致也可能是由非主线程导致：

由于主线程导致的情况：

1.耗时网络访问

2.当有大量数据读写操作时再请求数据读写

3.数据库操作(比如其他大数据量应用访问数据库导致数据库负载过重时)

4.硬件操作(比如Camera)

5.调用thread_join() / Sleep() / Wait() 或者等待locker的时候

6.Service binder数量达到上限

7.在system_server中发生WatchDog ANR

8.Service忙导致超时无响应

由于非主线程导致的情况：

1.非主线程持有lock，导致主线程等待lock超时

2.非主线程终止或者崩溃导致主线程一直等待
```

**解析**

```text
【核心考点】 Android ANR 性能问题
【题目解析】
ANR（Application Not Responding）是Android应用无响应的现象，通常表现为弹窗提示用户等待或关闭应用。面试官考察对ANR机制的深入理解。
【参考答案要点】
1. 现象：系统弹出ANR对话框，提示“应用无响应”，用户可选择等待或关闭。
2. 主要原因：
输入事件超时：主线程5秒内未处理完输入事件（如触摸、按键）。
广播超时：BroadcastReceiver在10秒内未执行完毕。
服务超时：Service在20秒内未完成启动。
3. 常见原因：
主线程执行耗时操作（网络请求、大文件读写、数据库操作）、死锁、CPU负载过高、内存不足导致频繁GC等。
【面试角度】
回答时可结合实际调试经验，例如“在项目中通过分析trace文件定位到主线程中的数据库操作导致ANR”。
【延伸知识】
ANR的排查工具：Logcat查看ANR日志、/data/anr/traces.txt文件、Systrace等。
```
