## Q007431

- 题型：简答
- 难度：简单

**题目**

```text
XSS 的分类
```

**答案**

```text
反射型
存储型
DOM 型
```

**解析**

```text
【核心考点】 XSS攻击 Web安全
【题目解析】
本题考查XSS（跨站脚本攻击）的基本分类，是Web安全的基础知识。XSS主要分为三类：反射型、存储型和DOM型。
【参考答案要点】
1. 反射型XSS：攻击脚本通过URL参数传递，服务器反射到响应页面，需要用户点击恶意链接触发。
2. 存储型XSS：攻击脚本存储在服务器端（如数据库），当用户访问受影响页面时自动执行，危害更大。
3. DOM型XSS：攻击脚本通过修改页面DOM环境执行，不经过服务器，完全在客户端发生。
【面试角度】
回答时建议补充防御措施，如输入输出过滤、使用CSP（内容安全策略）等，体现对安全的全面理解。
【易错提示】
不要遗漏DOM型XSS，初学者常只记得反射型和存储型。
```

## Q007428

- 题型：简答
- 难度：中等

**题目**

```text
CSRF与XSS 的区别
```

**答案**

```text
CSRF:本质是攻击者利用/借用用户的 cookie
XSS:本质是攻击者偷用户的 cookie
```

**解析**

```text
【核心考点】 安全测试 CSRF XSS
【题目解析】
本题考查两种常见Web安全攻击的区别。CSRF（跨站请求伪造）和XSS（跨站脚本攻击）都涉及用户浏览器，但攻击原理和目标不同。理解其本质差异对安全测试至关重要。
【参考答案要点】
1. CSRF（跨站请求伪造）：攻击者利用用户已登录的cookie，伪造请求发送到目标网站，执行非用户意愿的操作（如转账、改密码）。本质是借用用户的cookie，利用身份认证漏洞。
2. XSS（跨站脚本攻击）：攻击者向网页注入恶意脚本，当用户浏览时执行，窃取cookie、会话令牌或进行其他恶意操作。本质是偷取用户的cookie，利用输入验证漏洞。
3. 主要区别：CSRF是攻击者利用用户身份执行操作，XSS是攻击者窃取用户信息。CSRF通常需要用户已登录，XSS则不需要。防御方式也不同：CSRF使用令牌（Token）验证，XSS使用输入过滤和输出编码。
【易错提示】
不要混淆两者的攻击目标。CSRF是操作型攻击，XSS是信息窃取型攻击。面试中常要求举例说明，建议结合具体场景（如银行转账CSRF、评论框XSS）加深理解。
```

## Q007430

- 题型：简答
- 难度：中等

**题目**

```text
SQL 注入与 XSS 的区别？
```

**答案**

```text
SQL 注入：就是通过把 SQL 命令插入到 Web 表单递交或输入域名或页面请求的查询字符
串，最终达到欺骗服务器执行恶意的 SQL 命令。简单来说就是用户恶意输入 sql 命令，导致
最终数据库查询的结果并不是按照常理出现的结果；
XSS 攻击：指的是恶意攻击者往 Web 页面里插入恶意 html 代码，当用户浏览该页之时，嵌
入其中 Web 里面的 html 代码会被执行，从而达到恶意用户的特殊目的
```

**解析**

```text
【核心考点】 安全测试 SQL注入 XSS攻击
【题目解析】
本题考查两种常见Web安全漏洞的区别。SQL注入和XSS攻击都是通过用户输入注入恶意代码，但攻击目标、注入方式和影响范围不同。SQL注入针对数据库，XSS针对浏览器用户。
【参考答案要点】
1. 攻击目标不同：SQL注入攻击数据库，窃取或篡改数据；XSS攻击浏览器，窃取用户信息或执行恶意操作。
2. 注入方式不同：SQL注入通过构造SQL语句（如' OR 1=1 --）；XSS通过插入HTML/JavaScript代码（如<script>alert('xss')</script>）。
3. 影响范围不同：SQL注入直接影响服务器端数据库；XSS影响客户端用户，可能导致会话劫持、钓鱼等。
【面试角度】
回答时建议结合实际案例，例如“在测试登录功能时，我们通过输入' OR '1'='1测试SQL注入，通过输入<script>alert(1)</script>测试XSS”。同时，可以补充防御措施（如参数化查询、输出编码），体现深度。
【延伸知识】
还有CSRF（跨站请求伪造）、SSRF（服务端请求伪造）等常见安全漏洞，了解它们之间的区别有助于全面应对安全测试面试。
```


**答案**

```text
注入攻击的本质，是把用户输入的数据当做代码执行。
```

**解析**

```text
【核心考点】 SQL注入 安全测试
【题目解析】
本题考查SQL注入攻击的基本原理。SQL注入是一种常见的Web安全漏洞，其本质在于应用程序未对用户输入进行充分过滤或转义，导致攻击者可以将恶意SQL代码拼接到数据库查询语句中，从而执行非预期的数据库操作。核心是用户输入被当作代码执行，而非单纯的数据。

3. 防御：使用参数化查询（PreparedStatement）、输入验证、最小权限原则等。
【面试角度】
回答时，建议结合实际案例说明，例如“在登录接口中，如果直接拼接用户名和密码，攻击者输入' OR '1'='1' 即可绕过验证”。同时，强调防御措施比单纯描述原理更能体现深度。
【延伸知识】
SQL注入不仅限于GET/POST参数，还可能出现在Cookie、HTTP头等位置。测试时需关注所有用户可控的输入点。
```

```text
什么是CSRF攻击？
```

**答案**

```text
CSRF 攻击（Cross Site Request Forgery，跨站请求伪造）是攻击者通过跨站请求，以合法的用户身
份进行非法操作（如转账或发帖等）。
CSRF 的原理是利用浏览器的 Cookie 或服务器的 Session，盗取用
户身份，其原理如下图所示。防范 CSRF 的主要手段是识别请求者的身份，主要有以下几种方式：
（1）在表单中添加令牌（token）；
（2）验证码；
（3）检查请求头中的 Referer（前面提到防图片盗链接也是用的这种方式）。
```

**解析**

```text
【核心考点】 安全测试 CSRF攻击
【参考答案要点】
CSRF（Cross Site Request Forgery，跨站请求伪造）是一种攻击方式，攻击者通过伪造请求，以合法用户身份执行非法操作（如转账、发帖等）。其原理是利用浏览器自动携带Cookie或Session的特性，诱使用户点击恶意链接或访问恶意页面，从而在用户不知情的情况下发起请求。
防范措施：
1. 添加令牌（Token）：在表单或请求头中加入随机生成的Token，服务端验证Token有效性。
2. 验证码：关键操作（如支付、修改密码）要求用户输入验证码，增加攻击难度。
3. 检查Referer头：验证请求来源是否合法，拒绝非白名单来源的请求。
【面试角度】
回答时建议结合实际案例，如“在项目中，我们为所有敏感接口添加了Token校验，并定期更换密钥”，体现安全意识和实践能力。
【延伸知识】
与CSRF类似的概念还有XSS（跨站脚本攻击），两者常被混淆。XSS通过注入恶意脚本窃取用户信息，而CSRF利用用户身份执行操作，面试中需清晰区分。
```

```text
什么是XSS攻击？
```

```text
反射型攻击（诱使用户点击一个嵌入恶意脚本的链接以达到攻击的目标，目前有很多攻击者利用论坛、微博发布含有恶意脚本的 URL 就属于这种方式）
持久型攻击（将恶意脚本提交到被攻击网站的数据库中，用户浏览网页时，恶意脚本从数据库中被加载到页面执行，
```

**解析**

```text
【核心考点】 Web安全 XSS攻击 安全测试
【题目解析】
本题考查Web安全领域的常见攻击方式——跨站脚本攻击（XSS）。XSS攻击通过向网页注入恶意脚本，在用户浏览器中执行，可窃取用户数据、会话令牌或进行钓鱼攻击。理解XSS的类型和防御措施是安全测试的基础。
【参考答案要点】
1. 定义：XSS（Cross Site Scripting，跨站脚本攻击）是攻击者向网页中注入恶意脚本，当用户浏览该网页时，脚本在用户浏览器中执行，从而窃取信息或进行其他恶意操作。
2. 主要类型：
反射型XSS：恶意脚本嵌入在URL中，用户点击链接后，服务器将脚本反射到页面执行。例如：攻击者在论坛发布含有恶意脚本的链接，诱导用户点击。
持久型XSS：恶意脚本被提交到服务器数据库，当用户访问包含该脚本的页面时，脚本从数据库加载并执行。例如：在评论区提交恶意脚本，所有访问该页面的用户都会受影响。
3. 防御措施：输入验证与过滤（如HTML实体编码）、输出转义、使用HTTPOnly Cookie、内容安全策略（CSP）等。
【面试角度】

【延伸知识】
XSS与CSRF（跨站请求伪造）常被混淆：XSS利用用户对网站的信任执行脚本，CSRF利用网站对用户的信任伪造请求。两者结合可能造成更严重的攻击，面试中能区分并说明关联性可加分。
```

```text
找传参点--判断闭合符--判断列数--判断显示位--查找数据库--查表--查数据
```

**解析**

```text
【核心考点】 SQL注入 联合查询注入
【参考答案要点】
联合注入（UNION注入）是利用SQL中UNION操作符将攻击者构造的查询结果与原始查询结果合并，从而获取额外数据。标准步骤如下：
1. 找传参点：识别存在SQL注入漏洞的输入参数（如URL、表单等）。
2. 判断闭合符：通过输入单引号、双引号等测试，确定SQL语句的闭合方式（如单引号、双引号加括号等）。
3. 判断列数：使用ORDER BY或UNION SELECT NULL语句逐步增加列数，直到不报错，确定原查询的列数。
4. 判断显示位：使用UNION SELECT 1,2,3...（列数匹配）确定哪些列的数据会显示在页面上。
5. 查找数据库：利用显示位查询数据库名（如SELECT database()）。
6. 查表：查询指定数据库中的表名（如SELECT table_name FROM information_schema.tables）。
7. 查数据：查询目标表中的字段和数据。

【延伸知识】
联合注入是SQL注入的基础技术，但实际中常需要绕过过滤（如使用注释符、编码、大小写混淆等）。此外，盲注（布尔盲注、时间盲注）在无显示位时更为常用，了解这些变种有助于应对复杂面试题。
```

## Q007445

- 题型：简答
- 难度：困难

**题目**

```text
发现 demo.jsp?uid=110 注入点，你有哪几种思路获取 webshell，哪种是优选？
```

**答案**

```text
有写入权限的，构造联合查询语句使用using INTO OUTFILE，可以将查询的输出重定向到系统的文件中，这样去写入 WebShell
使用 sqlmap –os-shell 原理和上面一种相同，来直接获得一个 Shell，这样效率更高，通过构造联合查询语句得到网站管理员的账户和密码，然后扫后台登录后台，再在后台通过改包上传等方法上传 Shell
```

**解析**

```text
【核心考点】 SQL注入 WebShell 渗透测试
【参考答案要点】
发现demo.jsp?uid=110注入点后，获取WebShell的常见思路如下：
1. 利用INTO OUTFILE写入WebShell（优选）：若数据库有写入权限，构造联合查询语句使用INTO OUTFILE将查询结果写入Web目录，例如：union select 1,2,'<?php @eval($_POST[cmd]);?>' into outfile '/var/www/html/shell.php'。此方法直接高效，但需知道Web路径。
2. 使用sqlmap的--os-shell：sqlmap自动检测并利用INTO OUTFILE或INTO DUMPFILE功能，直接获取Shell。这是自动化首选，效率高且稳定。
3. 通过后台登录上传Shell：先通过注入获取管理员账号密码，登录后台，利用文件上传功能（如修改包、绕过限制）上传WebShell。此方法路径较长，但适用于无写入权限的场景。
4. 其他方法：如利用日志文件写入、利用MySQL的general_log功能等，但条件较苛刻。
【面试角度】
此题考察安全测试的实战能力，面试官希望看到候选人对SQL注入利用的深入理解。优选方案是INTO OUTFILE或sqlmap --os-shell，因为直接、高效。回答时需强调前提条件（如数据库权限、Web路径可写），并说明不同场景下的选择。
【延伸知识】
安全测试中，SQL注入获取WebShell是常见攻击手法，但防御方应禁用INTO OUTFILE、限制数据库用户权限、使用WAF等。面试中可补充防御建议以体现全面性。
```

```text
1. 利用分号分隔多条 SQL 语句。
2. 前提是数据库和驱动允许批量执行。
3. 危害包括数据泄露、篡改和删除。
```
