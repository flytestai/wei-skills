## Q007460

- 题型：简答
- 难度：中等

**题目**

```text
CSRF、SSRF和重放攻击有什么区别？
```

**答案**

```text
CSRF是跨站请求伪造攻击，由客户端发起
SSRF是服务器端请求伪造，由服务器发起
重放攻击是将截获的数据包进行重放，达到身份认证等目的
```

**解析**

```text
【核心考点】 安全测试 攻击类型
【题目解析】
本题考查三种常见网络攻击的区别：CSRF（跨站请求伪造）、SSRF（服务器端请求伪造）和重放攻击。CSRF利用用户已登录的身份，在用户不知情下发起恶意请求；SSRF则是攻击者利用服务器端漏洞，让服务器发起恶意请求；重放攻击是截获合法数据包后重复发送以欺骗系统。三者核心区别在于攻击发起方和攻击目标不同。
【参考答案要点】
1. CSRF（跨站请求伪造）：攻击者诱导用户点击链接或访问页面，利用用户已登录的会话状态，向目标网站发送恶意请求（如转账、改密），由客户端（用户浏览器）发起。
2. SSRF（服务器端请求伪造）：攻击者利用服务器端漏洞，构造恶意请求让服务器内部发起网络请求，绕过防火墙访问内网资源或执行未授权操作，由服务器端发起。
3. 重放攻击：攻击者截获通信数据包（如认证令牌、交易请求），稍后重新发送该数据包以欺骗接收方，达到身份认证或重复交易等目的，由攻击者客户端发起。
【面试角度】
回答时建议结合实际项目中的防御措施举例，如CSRF使用Token或Referer验证，SSRF限制URL白名单，重放攻击使用时间戳和随机数（Nonce）。
【易错提示】
易混淆CSRF和SSRF：CSRF是客户端发起，SSRF是服务器端发起；重放攻击与CSRF不同，重放不依赖用户会话，而是直接重放截获数据。
```

## Q007462

- 题型：简答
- 难度：中等

**题目**

```text
一次典型的网络攻击划分哪几个阶段，每个阶段采用什么技术手段
```

**答案**

```text
一般来说，网络攻击分为四个阶段：

第一阶段：信息收集，通常采用端口扫描、系统指纹识别、路由跟踪、Banner收集等技术手段。

第二阶段：漏洞利用，通常采用漏洞利用、暴力破解、恶意代码注入等技术手段。

第三阶段：持续控制，通常采用后门控制、僵尸网络控制等技术手段。

第四阶段：数据清除，通常采用日志清除、数据篡改等技术手段。
```

**解析**

```text
【核心考点】 网络安全 攻击生命周期
【参考答案要点】
第一阶段：信息收集 — 技术手段：端口扫描（如Nmap）、系统指纹识别、路由跟踪、Banner收集。
第二阶段：漏洞利用 — 技术手段：漏洞利用（如SQL注入、缓冲区溢出）、暴力破解、恶意代码注入。
第三阶段：持续控制 — 技术手段：后门控制、僵尸网络控制、权限提升。
第四阶段：数据清除 — 技术手段：日志清除、数据篡改、痕迹擦除。
【面试角度】
回答时建议结合安全测试实践，如“在渗透测试中，我们模拟攻击者的信息收集阶段，使用Nmap扫描开放端口，然后针对发现的漏洞进行利用测试”。
【延伸知识】
现代攻击模型如Cyber Kill Chain（网络杀伤链）将攻击分为7个阶段，包括侦察、武器化、投递、利用、安装、指挥与控制、目标行动。了解不同模型有助于全面理解攻击流程。
```

## Q007463

- 题型：简答
- 难度：中等

**题目**

```text
什么 csrf 攻击原理？如何解决？
```

**答案**

```text
（1）csrf 攻击原理
简单来说就是: 你访问了信任网站 A，然后 A 会用保存你的个人信息并返回给你的浏
览器一个 cookie，然后呢，在 cookie 的过期时间之内，你去访问了恶意网站 B，它给你返
回一些恶意请求代码，要求你去访问网站 A，而你的浏览器在收到这个恶意请求之后，在
你不知情的情况下，会带上保存在本地浏览器的 cookie 信息去访问网站 A，然后网站 A 误
以为是用户本身的操作，导致来自恶意网站 C 的攻击代码会被执行，比如发邮件，发消息，
修改你的密码，购物，转账，偷窥你的个人信息，导致私人信息泄漏和账户财产安全受到威
胁。

（2）常见解决方案
Cookies Hashing：每一个表单请求中都加入随机的 Cookie，由于网站中存在 XSS 漏洞而
被偷窃的危险。
HTTP refer：可以对服务器获得的请求来路进行欺骗以使得他们看起来合法，这种方法
不能够有效防止攻击
```

**解析**

```text
【核心考点】 安全测试 CSRF攻击 Web安全
【参考答案要点】
1. 攻击原理：用户登录信任网站A后，浏览器保存了A的cookie。用户访问恶意网站B，B返回恶意请求代码（如图片、链接）让用户浏览器自动请求A。由于cookie有效，A误认为请求来自用户，执行恶意操作（如转账、改密码）。
2. 常见解决方案：
- 使用CSRF Token：在表单中嵌入随机token，服务器验证token有效性。
- 检查Referer头：验证请求来源是否合法。
- 设置SameSite Cookie属性：限制cookie在跨站请求中发送。
- 使用验证码：关键操作要求用户输入验证码。
【面试角度】
回答时，结合实际项目中的防御措施，如如何在API中实现Token验证，能体现安全测试的实战经验。
【易错提示】
CSRF与XSS攻击的区别：CSRF利用用户身份，XSS注入恶意脚本，两者常混淆。
```

```text
说出你知道的网络攻击手段以及特点
```

```text
1. 拒绝服务攻击（DoS）：是指攻击者通过大量构造无效请求，来消耗系统资源以致使系统崩溃或无效，从而影响系统正常服务的一种攻击手段。

2. 分布式拒绝服</sp
```

**解析**

```text
【核心考点】 网络安全 攻击类型
【参考答案要点】
1. 拒绝服务攻击（DoS）：攻击者通过大量构造无效请求，消耗系统资源，导致系统崩溃或无法正常服务。
```

## Q007465

- 题型：简答
- 难度：中等

**题目**

```text
请简述什么是DDos攻击，什么是SQL注入
```

**答案**

```text
1. 分布式拒绝服务攻击(英文意思是Distributed Denial of Service，简称DDoS)是指处于不同位置的多个攻击者同时向一个或数个目标发动攻击，或者一个攻击者控制了位于不同位置的多台机器并利用这些机器对受害者同时实施攻击。它利用网络协议和操作系统的一些缺陷，采用欺骗和伪装的策略来进行网络攻击，使网站服务器充斥大量要求回复的信息，消耗网络带宽或系统资源，导致网络或系统不胜负荷以至于瘫痪而停止提供正常的网络服务。
2.SQL注入即是指web应用程序对用户输入数据的合法性没有判断或过滤不严，攻击者可以在web应用程序中事先定义好的查询语句的结尾上添加额外的SQL语句，在管理员不知情的情况下实现非法操作，以此来实现欺骗数据库服务器执行非授权的任意查询，从而进一步得到相应的数据信息。
```

**解析**

```text
【核心考点】 网络安全 DDoS攻击 SQL注入
【参考答案要点】
1. DDoS攻击：分布式拒绝服务攻击，攻击者控制多台机器同时向目标发送大量请求，耗尽系统资源，导致正常服务不可用。
2. SQL注入：攻击者通过输入恶意SQL语句，利用程序对输入过滤不严的漏洞，执行非授权数据库操作，如获取、篡改数据。
【面试角度】
回答时建议结合实际案例，如描述一次DDoS防御策略或SQL注入修复过程，能体现实战经验。同时可补充防御措施：DDoS常用CDN、限流；SQL注入常用参数化查询、输入验证。
【易错提示】
注意区分DDoS与DoS（单源拒绝服务），SQL注入与XSS（跨站脚本）的区别，面试中常被混淆。
```

## Q007461

- 题型：简答
- 难度：较难

**题目**

```text
dos 攻击类型，防御措施，连接耗尽攻击，cc攻击,二者的区别
```

**答案**

```text
**DoS 攻击**

DoS 攻击（Denial of Service）是指利用特定的网络服务或者资源，使网络服务器或计算机系统无法响应正常的请求而达到拒绝服务（Denial of Service）的目的</s
```

**解析**

```text
【核心考点】 网络安全 DoS攻击 CC攻击
【参考答案要点】
1. DoS攻击类型：包括带宽耗尽攻击（如ICMP Flood）、资源耗尽攻击（如SYN Flood）、应用层攻击（如HTTP Flood/CC攻击）等。
2. 防御措施：使用防火墙和入侵检测系统（IDS）、限制连接速率、启用SYN Cookie、部署CDN和负载均衡、使用WAF（Web应用防火墙）过滤恶意请求。
3. 连接耗尽攻击：通过大量半连接或全连接耗尽服务器资源，使正常连接无法建立。典型如SYN Flood攻击。
4. CC攻击（Challenge Collapsar）：属于应用层DoS攻击，通过大量看似合法的HTTP请求（如GET/POST）消耗服务器资源，模拟正常用户行为，更难防御。
5. 二者区别：连接耗尽攻击主要针对网络层和传输层，利用协议漏洞；CC攻击针对应用层，模拟真实请求，更隐蔽且难以区分。
【面试角度】
回答时建议结合实际项目经验，例如“在项目中曾遇到CC攻击，通过配置WAF的速率限制和IP黑名单缓解”，能体现实战能力。同时，区分不同攻击层次是面试高频点。
【延伸知识】
DDoS（分布式拒绝服务）是DoS的升级版，利用僵尸网络发起大规模攻击。防御需结合云防护服务（如阿里云盾、Cloudflare）和本地设备协同。
```
