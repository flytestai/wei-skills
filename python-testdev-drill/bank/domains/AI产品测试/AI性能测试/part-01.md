## Q007467

- 题型：简答
- 难度：中等

**题目**

```text
AI模型或AI工具的运行通常依赖计算资源（如CPU、GPU、内存）。如何测试其资源消耗情况？
```

**答案**

```text
测试AI模型的资源消耗情况需要使用监控工具在模型运行时监控CPU、GPU、内存的使用率，记录不同负载下的资源消耗情况。
```

**解析**

```text
【核心考点】 CPU GPU 内存 负载关联
【题目解析】
使用 top、htop、nvidia-smi 等监控工具，在单请求、并发请求、长稳运行场景下记录资源占用。重点观察资源是否随并发线性增长、是否存在内存泄漏，以及单位请求成本是否可接受。
【易错提示】
忽略长稳运行后的内存趋势，可能漏掉泄漏和性能衰减问题。
```

## Q007468

- 题型：简答
- 难度：中等

**题目**

```text
如何测试AI模型在长时间运行或高负载下的稳定性？可能出现哪些问题（如内存泄漏、性能衰减）？
```

**答案**

```text
测试AI模型的稳定性需要进行压力测试和耐久性测试，可能出现的问题包括内存泄漏、性能衰减和崩溃或异常。
```

**解析**

```text
【核心考点】 高负载 长时间运行 内存泄漏 性能衰减
【题目解析】
稳定性测试包括短时高压和长时耐久两类。关注内存是否持续增长、响应是否变慢、是否出现随机崩溃。对线上服务，应结合监控告警和自动恢复机制一起验证。
【易错提示】
把功能通过误认为可以上线。AI 服务常见问题往往在持续运行或高峰流量后才暴露。
```

## Q007469

- 题型：简答
- 难度：中等

**题目**

```text
如何测试AI模型的响应时间、吞吐量等性能指标？对于大模型，如何评估其在不同并发场景下的表现？
```

**答案**

```text
测试AI模型的性能指标需要发送请求并记录响应时间和处理数量，对于大模型，需要测试不同并发数下的表现。
```

**解析**

```text
【核心考点】 延迟统计 QPS/TPS 并发梯度 错误率
【题目解析】
通过压测工具发送请求，统计平均/最大/分位延迟和吞吐；对大模型还需做并发梯度测试（如 10/50/100），观察响应时间和错误率如何随并发上升，评估容量上限和降级策略。
【易错提示】
不要只看单次请求耗时。生产环境关心的是高并发下的稳定性与尾延迟。
```
