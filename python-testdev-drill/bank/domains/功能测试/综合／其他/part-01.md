## Q001613

- 题型：单选
- 难度：入门

**题目**

```text
2018年和2019年至今的测试市场中，市场份额最高的是？（）
```

**选项**

```text
A. Web测试
B. Mobile App测试
C. 桌面程序的测试
D. 接口测试
```

**答案**

```text
A
```

**正确选项**

```text
A. Web测试
```

**解析**

```text
【核心考点】 测试市场趋势 行业认知
【题目解析】
本题考查对软件测试行业市场份额的基本认知。根据行业报告，Web测试在2018年和2019年至今的测试市场中占据最高份额，因为Web应用仍然是企业级系统和互联网服务的主要形式，其测试需求持续旺盛。
【选项解析】
✓ A. Web测试 — 正确。Web应用覆盖电商、金融、教育等多个领域，测试需求最大。
✗ B. Mobile App测试 — 错误。虽然移动端增长迅速，但整体市场份额仍低于Web测试。
✗ C. 桌面程序的测试 — 错误。桌面程序市场趋于稳定，份额相对较小。
✗ D. 接口测试 — 错误。接口测试是重要组成部分，但通常作为Web或移动测试的一部分，单独市场份额不高。
【易错提示】
注意区分“市场份额”与“增长趋势”，移动测试增长快但基数小，Web测试仍是主流。
```

**题目**

```text
什么是用户测试？
```

**答案**

```text
用户测试又称“Beta测试”，使用户在真实的应用环境，通过运行和实用软件，检测与核查软件是否符合自己预期的要求。
```

**解析**

```text
【核心考点】 软件测试类型 用户测试
【题目解析】
本题考查软件测试中用户测试（Beta测试）的基本概念。用户测试是软件发布前由真实用户在真实环境中进行的测试，目的是验证软件是否符合用户预期。它是验收测试的一种形式，强调用户视角的验证。
【参考答案要点】
用户测试又称“Beta测试”，使用户在真实的应用环境，通过运行和实用软件，检测与核查软件是否符合自己预期的要求。
【面试角度】
回答时，可以补充Alpha测试与Beta测试的区别：Alpha测试由内部人员在模拟环境中进行，Beta测试由外部用户在真实环境中进行。这能展示对测试类型的深入理解。
【延伸知识】
用户测试是验收测试的一部分，通常与Alpha测试、Gamma测试（最终用户测试）等概念相关。了解这些测试的适用场景和目的，有助于在面试中展现系统性知识。
```

## Q001659

- 题型：简答
- 难度：入门

**题目**

```text
什么是黑盒测试?
```

**答案**

```text
黑盒测试，它是通过测试来检测每个功能是否都能正常使用。在测试中，把程序看作一个不能打开的黑盒子，在完全不考虑程序内部结构和内部特性的情况下，在程序接口进行测试，它只检查程序功能是否按照需求规格说明书的规定正常使用，程序是否能适当地接收输入数据而产生正确的输出信息。黑盒测试着眼于程序外部结构，不考虑内部逻辑结构，主要针对软件界面和软件功能进行测试。
```

**解析**

```text
【核心考点】 黑盒测试 测试方法
【参考答案要点】
黑盒测试是一种软件测试方法，将程序视为一个不透明的黑盒子，完全不考虑内部结构和逻辑，仅通过输入和输出来验证功能是否符合需求规格说明书。它主要关注软件界面和功能，确保程序能正确接收输入并产生预期输出。
【面试角度】
回答时建议补充黑盒测试的常用技术，如等价类划分、边界值分析、决策表等，以展示知识广度。同时可提及黑盒测试的局限性，如无法覆盖内部逻辑错误。
【延伸知识】
黑盒测试与白盒测试常结合使用，形成灰盒测试。面试中可能进一步询问黑盒测试用例设计方法的具体应用。
```


```text
【核心考点】 回归测试 测试策略
【参考答案要点】
1. 定义：回归测试是在软件修改后，重新执行已有测试用例，以验证修改未引入新缺陷或副作用的过程。
2. 目的：确保代码变更（如修复缺陷、新增功能）不会破坏现有功能，保证系统稳定性。
3. 范围：通常选择受影响模块的测试用例，以及核心功能的测试用例进行回归。

【延伸知识】
回归测试策略包括：完全回归（所有用例）、选择性回归（基于影响分析）和冒烟回归（核心功能）。在CI/CD环境中，回归测试通常集成到流水线中自动触发。
```

## Q001660

- 题型：简答
- 难度：简单

**题目**


**答案**

```text
①黑盒测试指把测试对象看成一个黑盒子，测试人员完全不考虑程序的内部结构和处理过程，只在软件的接口处进行测试，依据需求规格说明书，检查程序是否满足功能要求，又称为功能测试或数据驱动测试。
②白盒测试指把测试对象看成一个打开的盒子，测试人员需了解程序的内部结构和处理过程，以检查处理过程的细节为基础，对程序中尽可能多的逻辑路径进行测试，检验内部控制结构和数据结构是否有错，实际的运行状态与预期的状态是否一致。
③白盒测试适应的测试有单元测试、逻辑覆盖（按逻辑覆盖程度不同，有语句覆盖、判定覆盖、条件覆盖、判定/条件覆盖、条件组合覆盖和路径覆盖。）、循环覆盖（限制循环次数，有单循环和嵌套循环）和基本路径测试。
④黑盒测试适应的测试有：确认测试、等价类划分、边界值分析、错误推测和因果图。
```

**解析**

```text
【核心考点】 黑盒测试 白盒测试 测试分类
【参考答案要点】
1. 黑盒测试：将测试对象视为黑盒子，不考虑内部结构和处理过程，仅在软件接口处进行测试，依据需求规格说明书检查功能是否满足要求，也称为功能测试或数据驱动测试。
2. 白盒测试：将测试对象视为打开的盒子，测试人员需了解内部结构和处理过程，检查逻辑路径、控制结构和数据结构，验证实际运行状态与预期是否一致。
3. 白盒测试适用场景：单元测试、逻辑覆盖（包括语句覆盖、判定覆盖、条件覆盖、判定/条件覆盖、条件组合覆盖和路径覆盖）、循环覆盖（单循环和嵌套循环）和基本路径测试。
```

```text
什么是黑盒测试？什么白盒测试？二者有什么区别？
```

**答案**

```text
黑盒测试：是指在测试过程中只关注输入和输出，如果输入一个测试数据，输出的结果是正确的，我们就认为这个功能是正确的。也叫数据驱动测试

1-黑盒测试主要关注输入和输出结果是否正确，白盒测试更关心内部代码逻辑是否正确；
2-黑盒测试主要使用等价类、边界值、场景法等方法来设计用例；
白盒测试则主要使用代码走查、代码审查、逻辑覆盖（语句覆盖、判定覆盖、条件覆盖、判定条件覆盖、条件组合覆盖、路径覆盖）等方法来进行测试
```

```text
【核心考点】 黑盒测试 白盒测试
【题目解析】
本题考查软件测试的基础概念——黑盒测试与白盒测试的定义及区别。黑盒测试关注功能正确性，不关心内部实现；白盒测试关注代码逻辑和结构。两者是互补的测试策略，在实际项目中常结合使用。
【参考答案要点】
1. 黑盒测试：又称数据驱动测试，只关注输入和输出，验证功能是否符合需求。常用方法包括等价类划分、边界值分析、场景法等。
2. 白盒测试：基于代码内部结构和逻辑的测试方法，关注程序执行路径和条件。常用方法包括语句覆盖、判定覆盖、条件覆盖等。
3. 区别：
- 关注点不同：黑盒关注功能结果，白盒关注代码逻辑。
- 测试方法不同：黑盒使用等价类、边界值等，白盒使用逻辑覆盖。

【面试角度】
回答时建议结合实际项目案例说明，例如“在项目中，单元测试采用白盒方法，集成测试采用黑盒方法”。

灰盒测试介于两者之间，既关注输入输出也关注部分内部逻辑，常用于集成测试。
```

## Q001672

- 题型：简答
- 难度：简单

**题目**

```text
你所熟悉的软件测试类型有哪些?
```

**答案**

```text
测试类型有：功能测试、性能测试、界面测试

　
功能测试在测试工作中占有比例最大，功能测试也叫黑盒测试。

　
性能测试是通过自动化的测试工具模拟多种正常、峰值以及异常负载条件来对系统的各项性能指标进行测试。
负载测试和压力测试都属于性能测试，两者可以结合进行。

　
界面测试，界面是软件与用户交互的最直接的层，界面的好坏决定用户对软件的第一印象。

　
区别在于:
1、功能测试关注产品的所有功能，要考虑到每个细节功能，每个可能存在的功能问题。
2、性能测试主要关注产品整体的多用户并发下的稳定性和健壮性。
3、界面测试则关注与用户体验相关内容，用户使用该产品的时候是否已用，是否易懂，是否规范(用户无意输入无效的数据，当然考虑到体验性，不能太粗鲁的弹出警告)。做某个性能测试的时候，首先它可能是个功能点，首先要保证她的功能是没有问题的，然后再考虑性能的问题。
```

**解析**

```text
【核心考点】 软件测试类型 测试分类
【题目解析】
本题考查对常见软件测试类型的理解及区分。软件测试按不同维度可分为多种类型，如按测试阶段（单元测试、集成测试、系统测试）、按是否执行代码（黑盒测试、白盒测试）、按测试目的（功能测试、性能测试、安全测试）等。本题要求列举并说明区别，属于基础概念题。
【参考答案要点】
1. 功能测试：验证软件功能是否符合需求，通常采用黑盒测试方法，关注输入输出，不关心内部实现。
2. 性能测试：评估系统在不同负载下的响应时间、吞吐量、资源利用率等指标，包括负载测试、压力测试、稳定性测试等。
3. 界面测试：检查用户界面的易用性、美观性、一致性，确保用户操作流畅、反馈正确。
4. 区别：功能测试侧重“功能正确性”，性能测试侧重“系统效率与稳定性”，界面测试侧重“用户体验”。三者测试目标、方法和关注点不同。
【面试角度】
回答时建议结合实际项目经验，例如“在电商项目中，功能测试覆盖下单流程，性能测试关注高并发下的响应时间，界面测试确保支付按钮易点击”，这样能体现理解深度。
【易错提示】
常见错误：混淆功能测试与黑盒测试（功能测试是黑盒测试的一种应用，但黑盒测试还包括其他类型如边界值分析）；忽略性能测试中的细分类型（如负载测试与压力测试的区别）。
```

```text
【核心考点】 功能测试定义 黑盒测试
```

```text
功能测试在测试工作中占有比例最大，功能测试也叫黑盒测试。
性能测试是通过自动化的测试工具模拟多种正常、峰值以及异常负载条件来对系统的各项性能指标进行测试。负载测试和压力测试都属于性能测试，两者可以结合进行。

区别在于，功能测试关注产品的所有功能，要考虑到每个细节功能，每个可能存在的功能问题。性能测试主要关注产品整体的多用户并发下的稳定性和健壮性。界面测试则关注与用户体验相关内容，用户使用该产品的时候是否已用，是否易懂，是否规范(用户无意输入无效的数据，当然考虑到体验性，不能太粗鲁的弹出警告)。做某个性能测试的时候，首先它可能是个功能点，首先要保证她的功能是没有问题的，然后再考虑性能的问题。
```

**解析**

```text
【核心考点】 软件测试类型 测试分类
【参考答案要点】
常见的软件测试类型包括：
1. 功能测试：验证软件功能是否符合需求，通常采用黑盒测试方法。
2. 性能测试：评估系统在不同负载下的响应时间、吞吐量等指标，包括负载测试、压力测试、稳定性测试等。
3. 界面测试：检查用户界面的易用性、一致性、美观性等。
4. 安全测试：发现系统安全漏洞，如SQL注入、XSS等。
5. 兼容性测试：验证软件在不同环境（浏览器、操作系统、设备）下的表现。
【面试角度】
回答时建议结合具体项目举例，例如“在电商项目中，功能测试覆盖了购物车、支付流程；性能测试则针对双11大促进行了压力测试”。同时注意区分负载测试和压力测试：负载测试是逐步增加负载观察性能，压力测试是超过极限看系统如何崩溃。
【易错提示】
```

- 难度：简单

**题目**

```text
软件验收测试包括什么？
```

**答案**

```text
正式验收测试，alpha测试，beta测试
```

**解析**

```text
【核心考点】 软件验收测试 测试阶段
【参考答案要点】
软件验收测试主要包括：正式验收测试、Alpha测试和Beta测试。
1. 正式验收测试：由客户或用户代表在开发环境下执行，验证系统是否符合合同或需求规格说明，通常有明确的测试计划和用例。
2. Alpha测试：由内部用户或测试人员在开发环境下进行，模拟真实使用场景，发现缺陷并反馈，通常在Beta测试之前。
3. Beta测试：由实际用户在实际使用环境中进行，收集用户反馈和缺陷，测试系统在真实场景下的表现，通常不控制测试过程。
【面试角度】
回答时建议结合实际项目经验，例如“在我们项目中，Alpha测试由QA和产品经理共同执行，Beta测试则邀请部分种子用户参与”，可体现对验收测试流程的深入理解。
【延伸知识】
验收测试是软件交付前的最后阶段，除上述三种外，还有合同验收测试、法规验收测试等变体，面试中常与系统测试对比考查。
```

## Q001816

- 题型：简答
- 难度：简单

**题目**

```text
集成测试的两种方法？
```

**答案**

```text
非增量式集成测试、增量式集成测试
```

**解析**

```text
【核心考点】 集成测试 测试策略
【题目解析】
本题考查集成测试的两种基本方法。集成测试是将各个模块组合起来进行测试，以验证模块间的交互。根据模块组合的方式，分为非增量式集成测试和增量式集成测试。
【参考答案要点】
1. 非增量式集成测试：也称为大爆炸集成，将所有模块一次性组合后进行测试。优点是简单、适合小型系统；缺点是问题定位困难，风险高。
2. 增量式集成测试：逐步将模块加入进行测试，包括自顶向下、自底向上和混合方式。优点是问题定位容易，风险较低；缺点是测试周期较长。
【面试角度】
回答此类问题时，建议结合实际项目经历举例说明，例如“在项目中，我们采用自底向上的增量集成方式，先测试底层模块，再逐步集成上层模块”，能有效提升答案深度。
【延伸知识】
增量式集成测试还包括三明治集成（混合方式），结合自顶向下和自底向上的优点。了解不同集成策略的适用场景有助于应对面试中的深入追问。
```

## Q001826

- 题型：简答
- 难度：简单

**题目**

```text
黑盒测试和白盒测试的定义与区别？
```

**答案**

```text
白盒测试：
是一种测试用例设计方法，在这里盒子指的是被测试的软件。白盒，顾名思义即盒子是可视的，你可以清楚盒子内部的东西以及里面是如何运作的，因此白盒测试需要你对系统内部的结构和工作原理有一个清楚的了解，并且基于这个知识来设计你的用例。
黑盒测试 - 又叫功能测试
这是因为在黑盒测试中主要关注被测软件的功能实现，而不是内部逻辑。
在黑盒测试中，被测对象的内部结构，运作情况对测试人员是不可见的，测试人员对被测产品的验证主要是根据其规格，验证其与规格的一致性。
在绝大多数没有用户参与的黑盒测试中，最常见的测试有：功能性测试、容量测试、安全性测试、负载测试、恢复性测试、标杆测试、稳定性测试、可靠性测试等。
1、测试方式不同
（1）黑盒测试：功能测试，是通过测试来检测每个功能是否能正常使用
（2）白盒测试：俗称：结构测试\透明盒测试\逻辑驱动测试\基于代码的测试
2、测试目的不同
（1）黑盒测试：把程序看作一个不能打开的黑盒子，在完全不考虑程序内部结构盒特性的情况下，在程序接口进行测试，只检查程序功能是否按照需求规格说明书的规定正常使用，程序是否能适当地接收输入数据而产生正确的输出信息
（2）白盒测试：通过检查软件内部的逻辑结构，对软件中的逻辑路径进行覆盖测试。在程序不同地方设立监测点，检查程序的状态，以确定实际运行状态与预期状态是否一致。
3、测试原则不同
（1）黑盒测试：以用户角度，从输入数据与输出数据的对应关系出发进行测试的。很明显，如果外部特性本身设计有问题或规格说明的规定有误，用黑盒测试方法是发现不了的。
（2）白盒测试：一个模块种的所有独立路径至少被测一次。所有逻辑值均需测试true和false两种情况
```

**解析**

```text
【核心考点】 白盒测试 黑盒测试 测试分类
【参考答案要点】
1. 定义：
白盒测试：又称结构测试或逻辑驱动测试，测试人员基于程序内部结构和逻辑设计用例，关注代码路径、分支和条件覆盖。
黑盒测试：又称功能测试或数据驱动测试，测试人员基于软件规格说明，验证功能是否符合需求，不关心内部实现。
2. 区别：
测试依据：白盒测试依据源代码和设计文档；黑盒测试依据需求规格说明书。
测试对象：白盒测试关注内部逻辑；黑盒测试关注外部功能。
测试方法：白盒测试包括语句覆盖、判定覆盖、条件覆盖等；黑盒测试包括等价类划分、边界值分析、决策表等。
适用阶段：白盒测试通常在单元测试阶段；黑盒测试在集成测试和系统测试阶段。
【面试角度】
回答时建议结合实际项目经验举例，例如“在单元测试中，我们使用白盒测试覆盖关键路径；在系统测试中，使用黑盒测试验证用户场景”，能体现对测试策略的理解。
【延伸知识】
灰盒测试介于两者之间，既关注内部逻辑又关注外部功能，常用于集成测试和渗透测试。
```

## Q001628

- 题型：简答
- 难度：中等

**题目**

```text
jmeter和postman有哪方面的区别
```

**答案**

```text
1. 用例组织方式

Jmeter的组织方式相对比较扁平，它首先没有WorkSpace的概念，直接是TestPlan，TestPlan下创建的Threads Group就相当于TestCase，并没有TestSuite的层级。

Postman功能上更简单，组织方式也更轻量级，它主要针对的就是单个的HTTP请求。Collection就相当于是Project，而Collection中可以创建不定层级的Folders，可以自己组织TestSuite。
2. 支持的接口类型与测试类型

从功能上Jmeter最为强大，可以测试各种类型的接口，不支持的也可以通过网上或自己编写的插件进行扩展。

Postman更是轻量级，定位也不同，可用来测试Rest接口。
3. 配置不同接口类型

Jmeter可以在线程组里添加HTTP、TCP或WebSocket的Sampler。

Postman仅支持Rest接口。

4. 自定义变量以及变量的作用域

除以下表格中所列的变量之外，每个工具都有系统变量，未列在内。
6. 流程控制

Jmeter：由Switch控制器、If控制器、随机控制器等一系列控制器实现流程控制，以及Beanshell脚本

Postman：通过JavaScript脚本控制

7. 断言

Jmeter：TestPlan、Threads Group、Sampler均可添加断言

Postman：请求的Tests中可添加断言

8. 脚本扩展能力

Jmeter：Bean shell（Java）

Postman：JavaScript

9. 团队协作

Jmeter：一个TestPlan也是一个jmx（xml）文件，无法分割，但Jmeter有一个合并的功能，允许将多个文件合并在一起。只能每个团队成员自己建立一个TestPlan，分功能块进行测试。最后整理合并。

Postman：有团队协作的功能，需要付费。
```

**解析**

```text
【核心考点】 接口测试工具对比 JMeter Postman
【题目解析】
本题考查对主流接口测试工具JMeter和Postman的理解。两者定位不同：JMeter侧重性能测试和复杂场景，Postman侧重API调试和功能测试。
【参考答案要点】
1. 用例组织方式：JMeter基于TestPlan和Threads Group，结构扁平，无TestSuite层级；Postman使用Collection和Folder，支持多层嵌套，更灵活。
2. 支持的接口类型：JMeter支持HTTP、HTTPS、JDBC、JMS等多种协议，可通过插件扩展；Postman主要针对HTTP/HTTPS，功能相对单一。
3. 测试类型：JMeter擅长性能测试（负载、压力、并发），Postman更适合功能测试和调试。
4. 其他差异：JMeter是开源Java工具，Postman有桌面版和Web版；JMeter脚本编写较复杂，Postman界面友好易上手。
【面试角度】
回答时建议结合实际使用场景，例如“在项目中，我使用Postman进行接口调试和冒烟测试，用JMeter做性能测试”，能体现工具选型能力。
【延伸知识】
其他接口测试工具如SoapUI（支持WebService）、Rest-Assured（Java库）也可提及，展示知识广度。
```
