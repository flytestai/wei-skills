## Q002211

- 题型：单选
- 难度：入门

**题目**

```text
WEB应用中一般采用架构的是（）
```

**选项**

```text
A. C/S结构
B. B/S结构
C. 集群结构
D. 服务器互备份
```

**答案**

```text
B
```

**正确选项**

```text
B. B/S结构
```

**解析**

```text
【核心考点】 软件架构 B/S与C/S
【题目解析】
本题考查Web应用的基本架构。Web应用（即浏览器访问的应用）通常采用B/S（Browser/Server）架构，客户端通过浏览器访问服务器，无需安装专用软件；而C/S（Client/Server）架构需要安装客户端程序，如桌面应用。
【选项解析】
✗ A. C/S结构 — 错误。C/S结构需要安装客户端，不适用于Web应用。
✓ B. B/S结构 — 正确。Web应用通过浏览器访问服务器，是典型的B/S架构。
✗ C. 集群结构 — 错误。集群是一种部署方式，用于提高可用性和性能，不是Web应用的基本架构。
✗ D. 服务器互备份 — 错误。这是容灾或高可用方案，不是架构类型。
【易错提示】
注意区分B/S和C/S：B/S无需安装客户端，C/S需安装；Web应用默认是B/S架构。
```

## Q002210

- 题型：简答
- 难度：简单

**题目**

```text
B/S 和 C/S 的区别
```

**答案**

```text
b/s 代表浏览器和服务器架构；c/s 代表客户端和服务器架构
网络环境不同（c/s 建立在专用的局域网上，b/s 建立在广域网上）
安全要求不同（c/s 必须安装客户端，安全度较高；b/s 安全度较低）
系统维护不同（c/s 升级困难，需要重新安装最新客户端；b/s 无缝升级）
对系统要求不同（c/s 对系统要求较高；b/s 对系统要求较低）
```

**解析**

```text
【核心考点】 B/S与C/S架构 软件架构对比
【参考答案要点】
1. 定义：B/S（Browser/Server）即浏览器/服务器架构；C/S（Client/Server）即客户端/服务器架构。
2. 网络环境：C/S建立在专用局域网，B/S建立在广域网（如Internet）。
3. 安全要求：C/S需安装客户端，安全度较高；B/S通过浏览器访问，安全度较低。
4. 系统维护：C/S升级困难，需重新安装最新客户端；B/S可无缝升级，只需更新服务器。
5. 系统要求：C/S对客户端系统要求较高；B/S对客户端要求较低，主要依赖服务器性能。
【面试角度】
回答时建议结合实际项目经验举例，如“在之前的电商项目中，后台管理系统采用B/S架构，而收银客户端采用C/S架构”，能体现对架构选择的深入理解。
【延伸知识】
现代架构中，B/S和C/S界限逐渐模糊，如混合架构（Hybrid App）结合两者优势。面试中可补充PWA（渐进式Web应用）等趋势。
```

## Q002212

- 题型：简答
- 难度：简单

**题目**

```text
Web 系统测试通常包括哪些?
```

**答案**

```text
功能测试、界面测试、易用性测试、帮助文档测试、兼容性测试、安全测试、性能测试
```

**解析**

```text
【核心考点】 Web测试类型 测试覆盖范围
【参考答案要点】
Web系统测试通常包括以下方面：
1. 功能测试：验证所有功能是否按需求规格说明正确实现，包括链接测试、表单测试、数据库测试等。
2. 界面测试：检查页面布局、字体、颜色、图片等是否符合设计规范，确保用户界面友好、一致。
3. 易用性测试：评估系统的易学性、操作效率、用户满意度，如导航是否清晰、提示是否明确。
4. 帮助文档测试：验证帮助系统、用户手册、在线文档的准确性和完整性。
5. 兼容性测试：测试系统在不同浏览器（Chrome、Firefox、Edge等）、操作系统（Windows、macOS、Linux）、设备（PC、手机、平板）上的表现是否一致。
6. 安全测试：检查系统是否存在SQL注入、XSS、CSRF等安全漏洞，验证身份认证、权限控制、数据加密等机制。
7. 性能测试：评估系统在不同负载下的响应时间、吞吐量、并发用户数等指标，包括负载测试、压力测试、稳定性测试。
【面试角度】
回答时建议结合实际项目经验，例如“在之前的电商项目中，我们重点做了功能测试和性能测试，因为高并发场景是核心风险点”，能体现测试策略的针对性。同时可补充非功能测试的重要性，如可访问性测试（WCAG标准）和国际化测试。
【易错提示】
不要遗漏兼容性测试和安全测试，这两个是Web系统区别于传统桌面应用的关键测试领域。另外，性能测试常被误认为只包含负载测试，实际上还应包括压力测试、耐久性测试和容量测试。
```

```text
兼容性测试常与配置测试混淆，兼容性侧重不同环境下的功能表现，配置测试侧重不同硬件/软件组合下的系统行为。
```

## Q002218

- 题型：简答
- 难度：简单

**题目**

```text
你们公司产品主要是支持哪些浏览器？
```

**答案**

```text
--- 我们在为甲方做项目时，首先考虑支持甲方指定的浏览器，其次再考虑市场的主流浏览器的兼容性测试
--- 我们公司是自研产品，基于市场的考虑，会做几款市场主流的浏览器来做兼容性测试
```

**解析**

```text
【核心考点】 兼容性测试 浏览器支持
【题目解析】
本题考察软件测试中浏览器兼容性测试的策略。不同项目类型（如甲方项目、自研产品）对浏览器支持的要求不同。回答时应体现对项目背景的考虑，展示测试策略的灵活性。
【参考答案要点】
1. 甲方项目：优先支持甲方指定的浏览器，通常是企业内部标准浏览器（如IE、Chrome特定版本），其次考虑市场主流浏览器（如Chrome、Firefox、Edge、Safari）。
2. 自研产品：基于市场调研，选择主流浏览器进行兼容性测试，通常包括Chrome、Firefox、Safari、Edge等，并关注用户群体常用的浏览器。
3. 测试方法：使用真实浏览器或云测试平台（如BrowserStack）进行测试，确保核心功能在不同浏览器上表现一致。
【面试角度】
回答时建议结合实际项目经验，例如“在金融项目中，客户要求支持IE11，我们重点测试了IE11的兼容性，并针对其CSS兼容性问题进行了修复”。同时，可提及响应式设计和渐进增强策略，以提升跨浏览器兼容性。
【易错提示】
不要只回答“支持所有浏览器”，这不符合实际。应强调根据项目需求制定兼容性测试范围，并说明如何确定优先级。
```

## Q002224

- 题型：简答
- 难度：简单

**题目**

```text
商品数据来源于哪里？商城和后台权限是怎么划分的？
```

**答案**

```text
1）商品的数据来源于后台配置的；

2）在后台用管理员登录后可以去添加商品、商品分类、优惠券、秒杀产品、团购产品等；然后在商城前台就可以显示商品、商品分类等，也可以去领取优惠券、参与秒杀、团购等活动。商城前台的账号是自己注册的，只能商城前台的权限，主要用来进行登录、购物、支付、订单跟踪等。
```

**解析**

```text
【核心考点】 电商系统架构 权限管理 数据来源
【参考答案要点】
1. 商品数据来源：商品数据通常由后台管理系统配置生成。管理员登录后台后，可添加商品、分类、优惠券、秒杀/团购活动等，前台商城则展示这些数据。
2. 权限划分：
后台管理：面向管理员，拥有商品管理、订单处理、用户管理、营销设置等高级权限，通常通过独立的管理员账号登录。
商城前台：面向普通用户，用户自行注册账号，主要进行浏览商品、下单、支付、查看订单等操作，权限受限，不能修改后台数据。
【面试角度】
回答时可结合测试场景，例如测试后台配置商品后前台是否正确显示，或验证普通用户无法访问后台接口，体现对权限安全的理解。
【易错提示】
注意区分后台和前台的数据流，商品数据是单向流动（后台→前台），前台用户无法直接修改商品数据。面试中可能追问权限校验的实现方式，如RBAC模型。
```

## Q002241

- 题型：简答
- 难度：简单

**题目**

```text
请详细说明Web功能测试的方法主要包括的内容。
```

**答案**

```text
W.eb功能测试通常又称为网站（网页）测试。测试的方法主要有如下几点：
1.页面链接检查：每一个链接都要有对应的页面，并且页面之间切要正确。
2.相关性检查：检查删除/增加其中每一项是否会对其他项产生影响，如果产生影响，这些影响是否都正确。
3.检查按钮的功能是否正确，如Add，delete，save，update功能键.
4.字符串长度检查：输入超出所要求的字符串长度的内容，看系统检查字符串长度时会不会出错。
5.字符类型检查：在应该输入指定类型的地方输入其他类型的内容，例如在应该输入浮点型的地方输入其他字符类型，看系统是否检查字符类型时是否报错。
6.标点符号检查：输入内容包括各种标点符号，特别是逗号、句号、空格、回车键、回格键。看系统处理是否正确。
7.中文字符处理：在可以输入中文的地方输入中文，看是否出现乱码或出现错误。
8.检查带出信息的完整性：在查看信息和更新信息时，查看所填写的信息是否全部带出以及带出和添加的信息是否一致。
9.信息重复：在一些需要命名并且名字是唯一的信息中输入重复的名字，看系统是否处理、报错；重名包括是否区分大小写；以及在输入内容的前后输入空格，系统是否作出正确处理。
10.检查删除功能：在一些可以一次删除多个信息的地方，不选择任何信息，按“delete”键，看系统如何处理，是否出错；然后选择一个和多个信息，进行删除，看是否正确处理。
11.检查添加和修改是否一致：检查添加和修改信息的要求是否一致，例如添加要求必填的项，修改也应该必填；添加规定为浮点型的项，修改也必须为浮点型。
12.检查修改重名：修改时把不能重名的项改为已存在的内容，看能否处理、报错。同时也要注意，会不会报和自己重名的错。
13.重复提交表单：一条已经成功提交的纪录，回格后再提交，看看系统是否做了处理。
14.检查多次使用回格键的情况：在有回格的地方回格，回到原来页面，再回格，重复多次，看会否出错。
15.Search检查：在有search功能的地方输入系统存在和不存在的内容，看搜索结果是否正确。如果可以输入多个搜索条件，可以同时添加合理和不合理的条件，看系统处理是否正确。
16.输入信息位置：注意在光标停留的地方输入信息时，光标和所输入的信息会否会跳动。
17.上传下载文件检查：上传下载文件的功能是否实现，上传文件能否打开。对上传文件的格式有何规定，系统是否有解释信息，并检查系统能否做到。
18.必填项检查：应该填写的项没有填写时系统是否都做了处理，对必填项是否有提示信息。
19.快捷键检查：是否支持常用快捷键，如Ctrl+C ，Ctrl+V等，对一些不允许输入信息的字段，如选人，选日期对快捷方式是否也做了限制。
20.回车键检查：在输入结束后直接按回车键，看系统处理如何，是否报错。
```

**解析**

```text

【题目解析】
```

## Q002214

- 题型：简答
- 难度：中等

**题目**

```text
web方面的 ：cookies的在浏览器中是怎样工作的？
```

**答案**

```text
1、创建Cookie

当用户第一次浏览某个使用Cookie的网站时，该网站的服务器就进行如下工作：

①该用户生成一个唯一的识别码（Cookie id），创建一个Cookie对象；

②默认情况下它是一个会话级别的cookie，存储在浏览器的内存中，用户退出浏览器之后被删除。如果网站希望浏览器将该Cookie存储在磁盘上，则需要设置最大时效（maxAge），并给出一个以秒为单位的时间（将最大时效设为0则是命令浏览器删除该Cookie）；

③将Cookie放入到HTTP响应报头，将Cookie插入到一个 Set-Cookie HTTP请求报头中。

④发送该HTTP响应报文。

2、设置存储Cookie

浏览器收到该响应报文之后，根据报文头里的Set-Cookied特殊的指示，生成相应的Cookie，保存在客户端。该Cookie里面记录着用户当前的信息。

3、发送Cookie

当用户再次访问该网站时，浏览器首先检查所有存储的Cookies，如果某个存在该网站的Cookie（即该Cookie所声明的作用范围大于等于将要请求的资源），则把该cookie附在请求资源的HTTP请求头上发送给服务器。

4、读取Cookie

服务器接收到用户的HTTP请求报文之后，从报文头获取到该用户的Cookie，从里面找到所需要的东西。
```

**解析**

```text
【核心考点】 Cookie机制 HTTP协议 Web会话管理
【题目解析】
本题考察Cookie在浏览器中的工作原理。Cookie是服务器存储在客户端的小型文本文件，用于记录用户状态、偏好等信息。其工作流程涉及服务器生成Cookie、浏览器存储和发送Cookie等步骤。
【参考答案要点】
Cookie在浏览器中的工作流程：
1. 服务器生成Cookie：当用户首次访问网站时，服务器为该用户生成一个唯一的标识（如Cookie ID），并创建一个Cookie对象。
2. 设置Cookie属性：默认情况下，Cookie是会话级别的，存储在浏览器内存中，关闭浏览器后删除。若需持久化，服务器设置Max-Age（以秒为单位）或Expires属性。设置Max-Age=0可删除Cookie。
3. 服务器发送Cookie：服务器将Cookie放入HTTP响应头中的Set-Cookie字段，发送给浏览器。
4. 浏览器存储Cookie：浏览器收到响应后，根据Cookie属性（如域、路径、有效期）将Cookie存储在内存或磁盘中。
5. 浏览器发送Cookie：后续每次请求该域下的资源时，浏览器自动在HTTP请求头中添加Cookie字段，携带相关Cookie发送给服务器。
6. 服务器读取Cookie：服务器解析请求头中的Cookie，识别用户身份或状态。
【面试角度】
回答时，可以对比Cookie与Session的区别，说明Cookie存储在客户端，Session存储在服务器端。同时，提及Cookie的安全属性（如HttpOnly、Secure、SameSite），展示对Web安全的理解。另外，可以补充Cookie的大小限制（通常4KB）和数量限制（每个域约50个）。
【易错提示】
容易混淆Cookie和Session，Cookie是客户端机制，Session是服务器端机制。另外，注意Cookie的域和路径属性决定了哪些请求会携带Cookie，跨域请求默认不发送Cookie（除非设置withCredentials）。
```

```text
1.布局是否合理，2个testbox 和一个按钮是否对齐
2.testbox和按钮的长度，高度是否复合要求
3. 界面的设计风格是否与UI的设计风格统一
4. 界面中的文字简洁易懂，没有错别字。
性能测试(performance test)
1.打开登录页面，需要几秒
2.输入正确的用户名和密码后，登录成功跳转到新页面，不超过5秒
安全性测试(Security test)
1.登录成功后生成的Cookie，是否是httponly (否则容易被脚本盗取)
2.用户名和密码是否通过加密的方式，发送给Web服务器
3.用户名和密码的验证，应该是用服务器端验证， 而不能单单是在客户端用javascript验证
4.用户名和密码的输入框，应该屏蔽SQL 注入攻击
5.用户名和密码的的输入框，应该禁止输入脚本 （防止XSS攻击）

7. 考虑是否支持多用户在同一机器上登录；
8. 考虑一用户在多台机器上登录
可用性测试(Usability Test)
1. 是否可以全用键盘操作，是否有快捷键
2. 输入用户名，密码后按回车，是否可以登陆
3. 输入框能否可以以Tab键切换
兼容性测试（Compatibility Test）
1.主流的浏览器下能否显示正常已经功能正常（IE,6,7,8,9, Firefox, Chrome, Safari,等）
2.不同的平台是否能正常工作，比如Windows, Mac
3.移动设备上是否正常工作，比如Iphone, Andriod
4.不同的分辨率
本地化测试 （Localization test）
1. 不同语言环境下，页面的显示是否正确。
软件辅助性测试 （Accessibility test）
软件辅助功能测试是指测试软件是否向残疾用户提供足够的辅助功能
1. 高对比度下能否显示正常 （视力不好的人使用）
```

**解析**

```text
【核心考点】 测试用例设计 Web测试 等价类划分 边界值分析
【题目解析】
这是一道综合性的开放设计题，考察面试者的测试思维广度、深度以及实际Web测试经验。题目要求设计30个以上测试用例，需要从功能、UI、安全、性能、兼容性等多个维度展开。
【参考答案要点】
1. 需求澄清：首先明确登录界面的具体需求，如用户名长度限制、密码强度要求（大小写、数字、特殊字符）、是否支持记住密码、验证码等。
2. 功能测试用例：
— 正常登录：输入有效用户名和密码，点击登录，验证跳转。
— 无效用户名：输入不存在的用户名，验证错误提示。
— 无效密码：输入正确用户名但错误密码，验证提示。
— 空用户名/密码：点击登录，验证必填提示。
— 用户名和密码边界值：如最小长度、最大长度、特殊字符、空格等。
— 密码显示/隐藏功能（如有）。
3. UI测试用例：
— 界面布局、对齐、字体一致性。
— 不同分辨率下的显示效果。
— 错误提示的样式和位置。
4. 安全测试用例：
— SQL注入：输入' OR '1'='1等。
— XSS攻击：输入<script>alert('xss')</script>。
— 暴力破解：连续多次失败登录，验证锁定机制。
— 密码传输是否加密（HTTPS）。
5. 性能测试用例：
— 大量用户并发登录。
— 弱网环境下的响应时间。
6. 兼容性测试用例：
— 不同浏览器（Chrome、Firefox、Safari、Edge）。
— 不同操作系统（Windows、macOS、移动端）。
7. 异常场景：
— 网络中断后点击登录。
— 浏览器后退/刷新按钮。
— 多标签页同时登录同一账号。
【易错提示】
常见错误是只关注功能测试，忽略安全、性能、兼容性等维度。面试官期望看到系统性的测试思维，建议按测试类型分类组织答案。
【面试角度】
回答时建议结合实际项目经验，例如“在我们项目中，曾发现一个边界值bug，用户名超过20字符导致数据库截断”，能有效提升答案深度。
```

**题目**

```text
web测试主要包括哪几方面的测试？
```

**答案**

```text
功能、UI、兼容性、易用性、安全、性能
```

**解析**

```text
【核心考点】Web 测试的整体框架。
【题目解析】Web 测试覆盖功能、界面、兼容性、易用性、安全和性能等方面。功能验证业务是否正确，界面关注布局与交互，兼容性覆盖浏览器与设备，易用性看用户操作体验，安全关注权限与数据保护，性能关注响应和承载能力。
【答题要点】
1. 功能测试：业务流程、表单、链接。
2. 界面与兼容性：布局、多浏览器多分辨率。
3. 易用性、安全、性能：体验、防护和承载。
【面试提示】按维度展开回答，比只罗列名词更有说服力。
```
