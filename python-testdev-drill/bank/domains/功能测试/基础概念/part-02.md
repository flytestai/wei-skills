```text
你原来公司用的是那种语言，你是做黑盒还是白盒测试的？
```

```text
用 Python 语言， 做黑盒测试。
```

**解析**

```text
【核心考点】 测试类型 编程语言
【题目解析】
这是一道开放式问题，考察候选人是否具备测试类型的基本概念以及编程语言的实际应用经验。面试官通过询问公司使用的语言和测试类型，旨在了解候选人的技术栈和测试方法偏好。
【参考答案要点】

避免回答“只做黑盒”或“只做白盒”，因为现代测试常需结合两者。同时，不要对不熟悉的语言或框架夸大其词，诚实更能赢得信任。
```

```text
B. 决定软件质量的关键因素是人员和过程
C. 软件过程的优劣决定了软件质量的高低
```

## Q000482

- 题型：单选
- 难度：简单

**题目**

```text
关于软件测试与软件开发的认识，不正确的是（）
```

**选项**

```text
A. 软件生命周期各个阶段都可能产生错误
B. 软件测试是独立于软件开发的一个工作
C. 软件开发的需求分析和设计阶段就应开始测试工作
D. 测试越早进行，越有助于提高被测软件的质量
```

**答案**

```text
B
```

**正确选项**

```text
B. 软件测试是独立于软件开发的一个工作
```

**解析**

```text
【核心考点】 软件测试基本原则 测试与开发关系
【题目解析】
本题考查软件测试的基本概念，特别是测试与开发的关系。软件测试是开发过程中的重要环节，并非独立于开发之外的工作，测试活动应贯穿整个软件生命周期。
【选项解析】
✓ A. 软件生命周期各个阶段都可能产生错误 — 正确。错误可能发生在需求、设计、编码等任何阶段，这是测试要尽早介入的原因之一。
✗ B. 软件测试是独立于软件开发的一个工作 — 错误。测试与开发紧密协作，测试活动（如静态测试）在开发过程中同步进行，并非完全独立。
✗ C. 软件开发的需求分析和设计阶段就应开始测试工作 — 正确。这是“测试左移”理念，通过评审、静态分析等手段尽早发现缺陷。
✗ D. 测试越早进行，越有助于提高被测软件的质量 — 正确。早期发现缺陷修复成本低，能有效提升质量。
【易错提示】
注意题干问的是“不正确的”，容易误选A或C。B选项描述测试与开发完全独立，违背了测试与开发协作的基本原则，是错误选项。
```

## Q000483

- 题型：单选
- 难度：简单

**题目**

```text
关于软件测试对软件质量的意义，有如下说法： （1）度量和评估软件质量； （2）保证软件质量； （3）有利于改进软件开发过程； （4）发现软件错误。则其中正确的是（）。
```

**选项**

```text
A. （1）、（2）、（3）
B. （1）、（2）、（4）
C. （1）、（3）、（4）
D. （1）、（2）、（3）、（4）
```

**答案**

```text
C
```

**正确选项**

```text
C. （1）、（3）、（4）
```

**解析**

```text
【核心考点】 软件测试目的
【题目解析】
本题考查软件测试对软件质量的意义。测试的主要目的是发现错误，但也能度量和评估质量，并反馈改进开发过程。但测试本身不能“保证”软件质量，质量是设计和开发出来的。
【选项解析】
✗ A. （1）、（2）、（3） — 错误。包含（2）保证软件质量，不正确。
✗ B. （1）、（2）、（4） — 错误。同样包含（2）。
✓ C. （1）、（3）、（4） — 正确。测试可以度量和评估质量，发现错误，并有利于改进开发过程。
✗ D. （1）、（2）、（3）、（4） — 错误。包含（2）。
【易错提示】
常见误区：认为测试能保证质量。实际上，测试只能验证质量，不能保证。质量保证是过程管理活动。
```

## Q000485

- 题型：单选
- 难度：简单

**题目**

```text
关于软件测试，下列叙述有关错误的是（）。
```

**选项**

```text
A. 测试只能证明缺陷，不能证明缺陷不存在
B. 开发人员测试自己的程序后，可作为该程序已经通过测试的依据
C. 80%的缺陷聚集在20%的模块中，经常出错的模块改错后还会经常出错
```

**答案**

```text
B
```

**正确选项**

```text
B. 开发人员测试自己的程序后，可作为该程序已经通过测试的依据
```

**解析**

```text
【核心考点】 软件测试原则 测试局限性
【题目解析】
本题考查软件测试的基本原理。测试只能证明缺陷存在，不能证明缺陷不存在，这是测试的不可穷尽性。同时，测试中存在缺陷聚集性（Pareto原则），即80%的缺陷集中在20%的模块中。开发人员测试自己的程序存在偏见，不能作为通过测试的依据。
【选项解析】
✓ A. 测试只能证明缺陷，不能证明缺陷不存在 — 正确。这是测试的基本原则之一，测试无法证明程序无缺陷。
✗ B. 开发人员测试自己的程序后，可作为该程序已经通过测试的依据 — 错误。开发人员测试自己的程序存在主观偏见，容易遗漏缺陷，不能作为通过测试的依据。
✓ C. 80%的缺陷聚集在20%的模块中，经常出错的模块改错后还会经常出错 — 正确。这是缺陷聚集性原则，也是测试中需要重点关注高风险模块的原因。
【易错提示】
注意题干问的是“错误的是”，选项B明显违背测试独立性原则，是常见错误理解。
```

## Q000488

- 题型：简答
- 难度：简单

**题目**

```text
写出你对软件测试的认识，尽量详细。
```

**答案**

```text
定义：软件测试(英语:software

testing)，描述一种用来促进鉴定软件的正确性、完整性、安全性和质量的过程。换句话说，软件测试是一种实际输出与预期输出间的审核或者比较过程。软件测试的经典定义是:在规定的条件下对程序进行操作，以发现程序错误，衡量软件质量，并对其是否能满足设计要求进行评估的过程。

测试原则：

一，测试应该尽早进行，最好在需求阶段就开始介入，因为最严重的错误不外乎是系统不能满足用户的需求。

二，程序员应该避免检查自己的程序，软件测试应该由第三方来负责。

三，设计测试用例时应考虑到合法的输入和不合法的输入以及各种边界条件，特殊情况下不要制造极端状态和意外状态。

四，应该充分注意测试中的群集现象。

五，对策就错误结果进行地一个确认过程。一般由A测试出来的错误，一定要由B来确认。严重的错误可以召开评审会议进行讨论和分析，对测试结果要进行严格的确认，是否真的存在这个问题以及严重程度等。

六，制定严格的测试计划。一定要制定测试计划，并且要有指导性。测试时间安排尽量宽松，不要希望在极短的时间内完成也有一个高水平的测试。

七，妥善保存测试计划、测试用例、出错统计和最终分析报告，为维护提供方便。
```

**解析**

```text
【核心考点】 软件测试定义 测试原则
【题目解析】
本题考查对软件测试的总体认识，包括定义和基本原则。这是一道开放性的简答题，要求考生展示对测试核心概念的理解。答案应涵盖测试的目的、过程以及关键原则。
【参考答案要点】
定义：软件测试是在规定的条件下对程序进行操作，以发现程序错误，衡量软件质量，并评估其是否满足设计要求的过程。它涉及实际输出与预期输出的比较。
测试原则：
1. 尽早测试：测试应尽早介入，最好从需求阶段开始，以尽早发现缺陷，降低修复成本。
2. 避免自我检查：程序员应避免测试自己的代码，由独立的第三方进行测试更客观。
3. 全面考虑输入：测试用例应覆盖合法输入、非法输入以及边界条件，避免极端或意外状态。
4. 缺陷集群性：缺陷往往集中在某些模块，测试应重点关注高风险区域。
5. 测试无终点：测试只能证明缺陷存在，不能证明缺陷不存在，需根据风险确定测试充分性。
【面试角度】
回答时建议结合实际项目案例，例如“在项目中，我们坚持尽早测试，在需求评审时就参与，发现了很多逻辑漏洞”，并提及测试原则如何指导日常工作，以体现深度。
【延伸知识】
ISTQB 定义了七项测试原则，包括“穷尽测试不可能”、“缺陷集群性”等，了解这些有助于应对更深入的面试问题。
```

- 难度：简单

```text
目前的社会更新换代很快，我们需要多的接触、学习，新的测试理论、测试方法、测试工具，提高自己的知识水平及知识体系，才能更好的工作，让自己有一个更加美好的未来。我反思了一下，自身作为一名测试人员，目前所掌握的测试数据准备方法还是太少，仍然需要不断学习新知识，才能提高自身测试水平，为提高测试效率打下良好基础。
```

```text

本题为开放性简答题，考察面试者对软件测试的整体理解。回答应体现对测试重要性的认识、测试工程师的角色分类、以及软件开发生命周期中测试的位置。参考答案已给出基本框架，建议进一步补充个人见解。

2. 测试角色：包括业务功能测试、自动化测试、测试工具开发三类，各有侧重。
3. 软件生命周期：规划、需求分析、设计、编码、测试、运行维护六个阶段，测试贯穿始终。
```

## Q000491

- 题型：简答
- 难度：简单

**题目**

```text
功能测试的基本概念是什么？请简述之。
```

**答案**

```text
功能测试就是对产品的各功能进行验证，根据功能测试用例，逐项测试，检查产品是否达到用户要求的功能。 功能测试一般须在完成单元测试后集成测试前进行，而且是针对应用系统进行各功能测试。一般应用系统有多个功能（子系统），功能测试是基于产品功能说明书，是在已知产品所应具有的功能，从用户角度来进行功能验证，以确认每个功能是否都能正常使用、是否实现了产品规格说明书的要求、是否能适当地接收输入数锯而产生正确的输出结果等。功能测试，包括用户界面测试、各种操作的测试、不同的数据输入、逻辑思路、数据输出和存储等的测试。对于功能测试，针对不同的应用系统，其测试内容的差异很大，但一般都可归为界面、数据、操作、逻辑、接口等几个方面。
```

**解析**

```text
【核心考点】 功能测试 黑盒测试
【参考答案要点】
1. 定义：功能测试是验证软件系统是否满足用户需求的功能性测试，基于功能规格说明书，从用户角度检查每个功能是否正常。
2. 测试内容：包括用户界面测试、数据输入验证、操作流程测试、逻辑处理测试、数据输出和存储测试等。
```

## Q000596

- 题型：简答
- 难度：简单

```text
简述软件测试中的“80-20原则”
```

**答案**

```text
80-20原则是指在软件测试中，80%的测试用例可以涵盖20%的功能，即可以使用更少的测试用例来覆盖系统的大部分功能，而不必涵盖所有功能。这个原则提醒我们要重点测试系统的重要功能，而不必消耗过多的时间和资源去测试所有功能。
```

**解析**

```text
【核心考点】 测试原则 帕累托法则
【题目解析】
本题考查对软件测试中“80-20原则”的理解。该原则源自帕累托法则，强调在测试中应优先关注核心功能，以有限的资源获得最大的测试效果。
【参考答案要点】
80-20原则指：80%的缺陷往往集中在20%的核心功能中。因此，测试资源应优先分配给高风险、高使用频率的功能模块，而非平均分配。这有助于提高测试效率，快速发现关键问题。
【面试角度】
回答时建议结合实际项目经验，例如："在电商项目中，我们重点测试支付和购物车模块，因为这些功能承载了80%的用户操作"，能体现对原则的灵活应用。
【延伸知识】
80-20原则也适用于缺陷分布，即80%的缺陷由20%的模块引起。测试中可结合风险分析，对高风险模块进行更深入的测试。
```

## Q000619

- 题型：简答
- 难度：简单

**题目**

```text
调试是一个测试活动，测试是一个开发活动。这句话对吗？
```

**答案**

```text
错误。虽然调试和测试两者之间有一定的重叠，但是它们是不同的活动并且具有不同的职责。测试通常被认为是一个独立的活动，旨在确保软件的质量和符合用户要求，测试工程师通常是负责完成测试活动的人员。而调试是一个开发活动，主要用于检测和修复代码中的缺陷和错误，并由开发人员完成。换句话说，测试旨在发现问题，在软件发布之前识别和纠正缺陷，而调试旨在解决问题，在代码编写期间发现和消除错误。
```

**解析**

```text
【核心考点】 测试与调试的区别 软件测试基础
【题目解析】
本题考查对测试和调试这两个关键概念的理解。题目中的说法是错误的，测试和调试虽然相关，但属于不同的活动，具有不同的目标和执行者。测试是验证软件是否符合需求、发现缺陷的过程，通常由测试工程师负责；而调试是开发人员定位并修复代码缺陷的过程，属于开发活动。简单来说，测试是“找问题”，调试是“修问题”。
【参考答案要点】
1. 定义不同：测试是验证软件质量、发现缺陷的过程；调试是定位和修复代码错误的过程。
2. 执行者不同：测试通常由测试工程师执行；调试由开发人员执行。
3. 目的不同：测试旨在发现缺陷；调试旨在修复缺陷。
4. 阶段不同：测试贯穿整个软件生命周期；调试主要在开发阶段进行。
【易错提示】
容易混淆测试和调试的职责，误以为测试包含修复工作。面试中常以此考察对软件工程基本概念的理解，需明确区分。
```

## Q000643

- 题型：简答
- 难度：简单

**题目**

```text
软件测试分哪些阶段？各阶段的含义
```

**答案**

```text
大体上来说可分为单元测试、集成测试、系统测试、验收测试;每个阶段又分为确定测试计划,测试设计,设计测试用例,实施测试,进行测试报告五个步骤:。
1)单元测试对软件中的基本组成单位进行的测试,如一个模块、一个过程等等。它是软件动态测试的最基本的部分,也是最重要的部分之一,其目的是检验软件基本组成单位的正确性。
2)集成测试软件系统集成过程中所进行的测试,其主要目的是检查软件单位之间的接口是否正确。
3)系统测试,系统测试是对已经集成好的软件系统进行彻底的测试,以验证软件系统的正确性和性能等满足其规约所指定的要求,检查软件的行为和输出是否正确并非一项简单的任务,它被称为测试的“先知者问题”。
4)验收测试,在向软件的购买者展示该软件系统满足其用户的需求。它的测试数据通常是系统测试的测试数据的子集.
5)回归测试,回归测试是在软件维护阶段,对软件进行修改之后进行的测试。其目的是检验对软件进行的修改是否正确。
```

**解析**

```text
【核心考点】 软件测试阶段 测试生命周期
【题目解析】
本题考查软件测试的基本阶段划分及其含义，是软件测试的基础知识。题目要求回答测试阶段及各阶段的含义，属于简答题。答案应清晰列出主要阶段，并简要说明每个阶段的目标和活动。
【参考答案要点】
1. 单元测试：对软件的最小组成单元（如模块、函数）进行测试，验证其正确性。
2. 集成测试：在单元测试之后，将各单元逐步集成，检查模块间的接口和交互是否正确。
3. 系统测试：对已集成的完整系统进行测试，验证系统是否满足需求规格说明，包括功能、性能、安全等方面。
4. 验收测试：由用户或客户执行，确认系统是否满足业务需求和用户期望，通常包括Alpha测试和Beta测试。
【面试角度】
回答时建议结合实际项目经验，例如“在项目中，单元测试由开发人员完成，集成测试由测试人员主导”，并提及每个阶段的典型活动（如测试计划、用例设计、执行、报告），以展示对测试流程的全面理解。
【易错提示】
常见错误是混淆阶段顺序或遗漏验收测试。注意：系统测试和验收测试是不同的阶段，前者侧重技术验证，后者侧重用户确认。
```

```text
设计：完成测试方案，从技术层面上对测试进行规划；

执行：根据前期完成的计划、方案、用例、规程等文档，执行测试用例。
```

## Q000428

- 题型：简答
- 难度：中等

**题目**

```text
为什么说软件测试必须有预期结果呢？
```

**答案**

```text
没有预期结果的测试是不可理喻的。软件缺陷是经过对比而得出来的。这正如没有标准无法进行度量一样。如果我们事先不知道或是无法肯定预期的结果，我们必然无法了解测试正确性。这很容易然人感觉如盲人摸象一般，不少测试人员常常凭借自身的感觉去评判软件缺陷的发生，其结果往往是把似是而非的东西作为正确的结果来判断，因此常常出现误测的现象。
```

**解析**

```text
【核心考点】 软件测试基础 预期结果 缺陷定义
【题目解析】
本题考查软件测试中预期结果的重要性。测试的核心是比较实际结果与预期结果，没有预期结果就无法判断测试是否通过，也无法识别缺陷。
【参考答案要点】
1. 缺陷定义依赖对比：软件缺陷是通过实际结果与预期结果的对比得出的，没有预期结果就无法判断是否存在缺陷。
2. 测试可执行性：预期结果是测试用例的必备要素，确保测试有明确的目标和判断标准。
3. 避免主观判断：没有预期结果，测试人员容易凭感觉判断，导致误测或漏测。
【面试角度】
回答时建议结合实际项目中的案例，例如“在测试登录功能时，预期结果是输入正确账号密码后跳转到主页，否则提示错误信息，这样就能明确判断功能是否正常”，能提升答案深度。
【延伸知识】
预期结果应基于需求文档或设计文档，对于模糊需求，测试人员需要与产品经理确认，避免歧义。
```

```text
网络重发
消息重发
系统间重试
所以说保证接口的幂等性是非常重要的。

测试幂等的手段：前端幂等测试，注意按钮的多次快速点击；

响应。
```

```text
2. 常见场景：用户重复提交、网络重发、消息重发、系统间重试等。
3. 测试手段：
前端幂等测试：注意按钮的多次快速点击，观察是否重复提交。

【延伸知识】
```

## Q000456

- 题型：简答
- 难度：中等

**题目**

```text
什么是软件质量?
```

**答案**

```text
概括地说，软件质量就是“软件与明确的和隐含的定义的需求相一致的程度”。具体地说，软件质量是软件符合明确叙述的功能和性能需求、文档中明确描述 的开发标准、以及所有专业开发的软件都应具有的隐含特征的程度。 影响软件质量的主要因素，这些因素是从管理角度对软件质量的度量。可划分为三组，分别反应用户在使用软件产品时的三种观点。正确性、健壮性、效率、完整性、可用性、风险(产品运行);可理解性、可维修性、灵活性、可测试性(产品修改);可移植性、可再用性、互运行性(产品转移)。
```

**解析**

```text
【核心考点】 软件质量 质量模型
【题目解析】
本题考查软件质量的定义及其影响因素。软件质量是一个多维度的概念，不仅包括显性需求（功能、性能），还涉及隐性需求（可维护性、可移植性等）。
【参考答案要点】
1. 定义：软件质量是“软件与明确的和隐含的定义的需求相一致的程度”，即软件符合功能、性能、文档标准以及专业软件应具有的隐含特征的程度。
2. 影响因素（按McCall质量模型分类）：
（1）产品运行：正确性、健壮性、效率、完整性、可用性、风险。
（2）产品修改：可理解性、可维修性、灵活性、可测试性。
（3）产品转移：可移植性、可再用性、互运行性。
【面试角度】
回答时建议结合ISO/IEC 25010质量模型进行补充，该模型将质量分为功能性、可靠性、易用性、效率、维护性、可移植性等8个特性，是当前国际标准。
【易错提示】
注意区分软件质量与软件测试的关系：测试是保证质量的手段之一，但质量贯穿于整个开发过程，包括需求、设计、编码等环节。
```

```text
4.测试总结阶段：项目测试结束，负责人输出测试报告，对整个测试过程和版本质量做一个详细评估，确认是否可以上线；
```

```text
1. 测试计划设计阶段：需求分析、评审、业务评级、绘制流程图，制定测试计划（范围、资源、时间表）。
```

```text
【参考答案要点】
需求评审常见问题：
1. 需求不明确：描述模糊，导致理解偏差。
2. 需求冲突：不同模块或用户需求矛盾。
3. 需求遗漏：未覆盖边界条件或异常场景。
4. 优先级不明：未区分核心功能与次要功能。
用例评审常见问题：
1. 场景覆盖不足：遗漏关键业务路径或异常流程。
2. 用例重复：不同用例覆盖相同场景，浪费资源。
3. 数据设计不合理：测试数据未覆盖等价类或边界值。
4. 预期结果不明确：缺少具体验证点，导致执行时无法判断。
【面试角度】
建议结合具体案例说明，例如“在一次需求评审中，发现用户登录功能未定义密码错误次数限制，导致后续测试遗漏”。同时可提及如何改进评审流程，如引入检查清单或增加跨角色参与。
【易错提示】
避免泛泛而谈“需求不清晰”，应给出具体类型和影响。另外，注意区分需求评审与用例评审的侧重点：前者关注业务正确性，后者关注测试充分性。
```

## Q000474

- 题型：简答
- 难度：中等

**题目**

```text
你怎么定义是不是bug?
```

**答案**

```text
1、功能是否符合需求说明书
2、站在使用者的角度，功能是否易操作、易理解
3、系统压力指标是否达到质量要求
```

**解析**

```text
【核心考点】 缺陷定义 测试思维
【参考答案要点】
1. 功能偏差：实际结果与需求说明书不一致，即功能未按预期实现。
2. 用户体验问题：从用户视角看，功能不易操作、不易理解，如界面混乱、流程繁琐。
3. 质量指标不达标：系统性能、可靠性等非功能指标未达到要求，如响应时间过长、并发失败。
【面试角度】
回答时建议结合具体项目案例，例如“我曾发现一个支付按钮点击后无反馈，虽符合需求但用户易误操作，最终被认定为bug”。这能体现测试的全面性和用户导向思维。
【延伸知识】
业界对bug的定义包括：缺陷（Defect）、错误（Error）、失败（Failure）。测试中应区分“不符合需求”与“不符合用户期望”，后者常被忽略但很重要。
```

## Q000476

- 题型：简答
- 难度：中等

**题目**

```text
你觉得开发解决问题的思路和测试的测试思路有哪些区别？
```

**答案**

```text
1、测试的思维很大程度上就是黑白测试的思想，总体思路都是实际结果和预期结果比对。
2、测试思维是发散的，属于横向思维；开发思维是纵的。测试工程师的确可以从开发的角度和测试角度回到源头。但是最重要的是，测试第一步就是为了取得预期结果。如果没有明确的预期结果，那么测试将无法进行，或者做得不好。
3、开发的思维就是怎么做，测试的思维就是做得怎么样。正是由于测试的思维是考虑预期结果，而预期结果其实在用户那里，所以测试要从用户的角度来考虑，而开发是不需要考虑这些的。只管实现才是第一位的.
```

**解析**

```text
【核心考点】 测试思维 开发思维 思维差异
【题目解析】
本题考查测试人员与开发人员在解决问题时的思维差异。开发思维聚焦于如何实现功能，是纵向的、构建性的；测试思维则关注功能是否满足预期，是横向的、批判性的。理解这种差异有助于跨团队协作和提升测试有效性。
【参考答案要点】
1. 目标不同：开发思维关注“如何做”，即实现功能；测试思维关注“做得怎么样”，即验证结果是否符合预期。
2. 视角不同：开发思维是纵向的，专注于代码实现；测试思维是横向的，从用户角度出发，考虑各种场景和边界。
3. 方法不同：开发使用正向推理，构建系统；测试使用逆向思维，寻找缺陷和异常。
4. 预期结果：测试的第一步是明确预期结果，否则无法有效验证；开发则更注重实现过程。
【面试角度】
回答时建议结合实际案例，例如“在XX项目中，开发关注功能实现，而测试则从用户角度发现易用性问题”。同时可提及测试左移和测试右移，体现思维融合。
【易错提示】
避免将测试思维简单等同于“找bug”，而应强调其系统性、用户导向和预期结果验证的特点。
```

## Q000478

- 题型：简答
- 难度：中等

**题目**

```text
你认为软件测试应该注意什么？
```

**答案**

```text
1、边界测试，测试用户输入框中的数值的最大数和最小数，以及为空时的情况。

　　2、非法测试，例如在输入数字的地方输入字母。

　　3、跟踪测试，跟踪一条数据的流程，保证数据的正确性。

　　4、在开始测试时应保证数据的正确性，然后在从系统中找出各种BUG。

　　5、接口测试，程序往往在接口的地方很容易发生错误，要在此模块测试勿掉以轻心。

　　6、代码重用测试，在开发过程中有些模块功能几乎相同，程序员在重用代码时可能忘记在原有代码上修改或修改不全面，而造成的错误。

　　7、突发事件测试，服务器上可能发生意外情况的测试。

　　8、外界环境测试，有些系统在开发时依赖于另外一个系统，当另外一个系统发生错误时， 这个系统所受到的影响的情况。

　　9、缺陷验证：在程序员刚修复Bug之后的地方，一定要在次验证、测试，往往程序员只修复报告出来的缺陷而不去考虑别的功能在修改时可能会重新造成错误。

　　10、做好BUG管理工作，认真做好测试记录，在做完一天的测试记录之后，第二天再根据第一天的测试记录重复测试你会发现有未修正的错误。

　　11、错字、错词测试，如果在系统中有用词不当的地方，我想这是不应该的。

　　12、系统兼容测试，例如有些程序在IE6能运行正常，到IE5下不能运行。有些程序在WIN2000下能运行，而到WIN98却不能运行。像一些很特别的用户去使用系统，你很有可能发现BUG。

　　13、用户的易用性测试，往往用户的需求是不断的变化的，而其中一部份变化的原因，是由用户操作上不方便引起的
```

**解析**

```text
【核心考点】 测试关注点 测试策略
【参考答案要点】
1. 边界测试：测试输入框数值的最大、最小及为空情况。
2. 非法测试：在数字输入处输入字母等非法字符。
3. 跟踪测试：跟踪一条数据的完整流程，确保数据正确性。
4. 数据正确性：开始测试时保证数据正确，再从中发现BUG。
5. 接口测试：程序接口易出错，需重点测试。
6. 代码重用测试：检查重用代码是否修改全面。
7. 突发事件测试：模拟服务器意外情况。
8. 外界环境测试：测试依赖系统故障时的影响。
【面试角度】
回答此类开放性问题时，建议结合实际项目经验举例，如“在电商项目中，我们特别关注边界测试和接口测试，因为价格计算和订单流转容易出错”。同时可补充安全性测试、性能测试等，体现全面性。
【延伸知识】
测试关注点应基于风险分析，优先测试高风险区域。ISTQB建议测试策略包括功能、非功能、结构测试等。
```

## Q000484

- 题型：单选
- 难度：中等

**题目**

```text
关于软件测试有如下做法：（1）公司甲规定在概要设计阶段开始软件测试工作；（2）测试员乙声称他对自己所测的软件进行了充分、完全的测试；（3）公司丙的测试工作由专门的测试部负责，而不是由开发部直接负责；（4）测试员丁在平时测试中注意关注缺陷的修复，重点测试已修复的缺陷及相关模块。则以上做法中正确的是（）。
```

**选项**

```text
A. （1）（2）
B. （2）（3）
C. （3）（4）
D. （1）（4）
```

**答案**

```text
C
```

**正确选项**

```text
C. C、（3）（4）
```

**解析**

```text
【核心考点】 软件测试原则 测试过程管理
【题目解析】
本题考查软件测试基本实践原则。需逐一分析每个做法的正确性。
【选项解析】
✗ (1) 公司甲规定在概要设计阶段开始软件测试工作 — 错误。测试应尽早介入，通常从需求分析阶段开始，概要设计阶段已偏晚。

✓ (3) 公司丙的测试工作由专门的测试部负责，而不是由开发部直接负责 — 正确。测试与开发分离，保证独立性和客观性。
✓ (4) 测试员丁在平时测试中注意关注缺陷的修复，重点测试已修复的缺陷及相关模块 — 正确。回归测试是重要环节，确保缺陷修复且不引入新问题。
【正确答案】 C. (3)(4)
【易错提示】
注意(1)中“概要设计阶段”开始测试是错误做法，正确做法是需求阶段介入；完全测试不可能，这是经典陷阱。
```

## Q000486

- 题型：单选
- 难度：中等

**题目**

```text
关于软件质量的描述，正确的是【 】
```

**选项**

```text
A. 软件质量是指软件满足规定用户需求的能力
B. 软件质量特性是指软件的功能性、可靠性、易用性、效率、可维护性
C. 软件质量保证过程就是软件测试过程
D. 以上描述都不对
```

**答案**

```text
B
```

**正确选项**

```text
B. 软件质量特性是指软件的功能性、可靠性、易用性、效率、可维护性
```

**解析**

```text
【核心考点】 软件质量 质量特性
【题目解析】
本题考查软件质量的基本概念。软件质量包括功能性、可靠性、易用性、效率、可维护性等特性，选项B正确描述了这些特性。
【选项解析】
✗ A. 软件质量是指软件满足规定用户需求的能力 — 错误。软件质量不仅包括满足用户需求，还包括符合标准、无缺陷等更广泛的含义。
✓ B. 软件质量特性是指软件的功能性、可靠性、易用性、效率、可维护性 — 正确。这是ISO/IEC 9126质量模型中的核心特性。
✗ C. 软件质量保证过程就是软件测试过程 — 错误。质量保证（QA）是预防性活动，包括过程改进、审计等，而测试是质量控制（QC）的一部分，两者不同。
✗ D. 以上描述都不对 — 错误。选项B正确。
【易错提示】
注意区分质量保证（QA）和质量控制（QC），QA关注过程，QC关注产品，测试属于QC范畴。
```
