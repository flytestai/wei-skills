## Q002861

- 题型：简答
- 难度：入门

**题目**

```text
写自动化用例的一个简单步骤
```

**答案**

```text
a:声明 driver 对象（也就是你将要启动什么浏览器）

b:driver 去打开浏览器，并输入你要测试的网页地址（使用 get 方法打开测试站点）

c:找到你要操作的元素（利用 WebElement 声明元素对象）

d:对元素进行输入，点击，断言

e:关闭浏览器，释放资源
```

**解析**

```text
【核心考点】 自动化测试流程 Selenium基础
【题目解析】
本题考查自动化测试用例的基本编写步骤。以Selenium WebDriver为例，典型流程包括：初始化驱动、打开页面、定位元素、执行操作、断言验证、清理资源。这是自动化测试的入门知识。
【参考答案要点】
1. 声明驱动对象：如WebDriver driver = new ChromeDriver()，指定浏览器类型。
2. 打开测试页面：使用driver.get(url)方法。
3. 定位元素：通过findElement方法，使用ID、XPath等定位器。
4. 执行操作：如click()、sendKeys()，并添加断言验证结果。
5. 关闭浏览器：调用driver.quit()释放资源。
【易错提示】
常见错误是忘记关闭驱动或未处理异常，导致资源泄漏。建议使用try-finally或@After方法确保清理。
```

## Q002723

- 题型：简答
- 难度：简单

**题目**

```text
PageObject是什么
```

**答案**

```text
参考：
PageOjbect是页面对象，是ui自动化中一种设计模式，一般称为po模式，简单来说就是将页面封装成类，定义页面属性，功能。在测试代码中调用它，从而达到测试逻辑和页面逻辑解耦的效果，提高代码复用性，扩展性，便于维护。
```

**解析**

```text
【核心考点】 UI自动化 设计模式 PageObject
【参考答案要点】
PageObject（PO模式）是UI自动化测试中一种常用的设计模式。核心思想是将每个页面封装成一个类，类中定义页面的元素定位和操作方法。测试代码通过调用这些类的方法来操作页面，从而实现测试逻辑与页面逻辑的解耦。
优点：
1. 提高代码复用性：页面元素变化时只需修改对应类，无需修改测试用例。
2. 增强可维护性：页面结构变化对测试影响最小化。
3. 提升可读性：测试用例更接近业务描述，易于理解。
【面试角度】
面试官常问PO模式的实现细节，例如如何管理页面对象、如何处理页面跳转、如何与数据驱动结合。建议在回答时提及实际项目中的使用经验。
【延伸知识】
PO模式通常与测试框架（如Selenium、Appium）结合使用，还可扩展为Page Factory模式，进一步简化元素初始化。
```

## Q002730

- 难度：简单

**题目**

```text
Selenium中的硬断言和软断言有什么区别？
```

**答案**

```text
硬断言：
当断言语句失败时，硬断言会立即抛出AssertException，测试套件将继续执行下一个@Test。
如果断言条件失败，则将方法标记为失败，方法内部的其它语句将被终止。
软断言：
软断言在@Test执行期间收集错误，当然断言失败是，软断言不会抛出异常，并且会继续执行Assert语句后面的语句。
```

**解析**

```text
【核心考点】 Selenium 断言 硬断言 软断言
【题目解析】
本题考查Selenium自动化测试中断言的使用，属于基础概念。硬断言（Hard Assert）在断言失败时立即抛出异常并终止当前测试方法，后续代码不执行；软断言（Soft Assert）在断言失败时不会抛出异常，而是收集所有错误，测试方法继续执行，最后在测试结束时统一报告所有失败。
【参考答案要点】
硬断言：断言失败时立即抛出AssertException，测试方法被标记为失败，方法内后续语句终止执行，测试套件继续执行下一个@Test。
软断言：断言失败时不抛出异常，测试方法继续执行，所有断言错误被收集，在测试方法结束时统一报告。
【易错提示】
注意软断言不会立即终止测试，而是收集错误，适合需要验证多个条件且不希望因一个失败而中断的场景。
【面试角度】
回答时建议结合实际测试场景，例如“在页面元素验证中，使用软断言可以一次性检查多个元素，提高测试效率”，体现对断言策略的理解。
```

## Q002742

- 题型：简答
- 难度：简单

**题目**

```text
WinRunner可以用录制的方式快速建立自动测试脚本，请问WinRunner提供了哪几种可用的录制模式？
```

**答案**

```text
请描述各种录制模式的特点。
WinRunner提供了两种录制模式：环境判断模式和模拟模式。
环境判断模式：这种模式根据用户选取的GUI对象（如窗体、列表、按钮等）将用户对软件的操作动作录制来，并忽略这些对象在屏幕上的物理位置。每一次对被测软件进行操作。回放测试脚本的过程，就是WinRunner模拟一个用户鼠标选取对象、用键盘输入数据的操作过程。
模拟模式：这种模式记录鼠标点击、键盘输入和鼠标在二维平面上（x轴、y轴）的精确运动轨迹。执行测试时，WinRunner让鼠标根据轨迹运动。模拟模式对于那些需要追踪鼠标运动的测试非常有用，例如画图软件。
```

**解析**

```text
【核心考点】 WinRunner 录制模式
【题目解析】
本题考查WinRunner工具中两种录制模式的概念和区别。WinRunner是经典的GUI自动化测试工具，其录制模式分为环境判断模式和模拟模式，分别适用于不同的测试场景。
【参考答案要点】
1. 环境判断模式（Context Sensitive Mode）：基于GUI对象（如按钮、文本框）录制操作，忽略屏幕物理位置。回放时通过识别对象属性来模拟用户交互，适用于大多数功能测试。
2. 模拟模式（Analog Mode）：记录鼠标和键盘的精确物理轨迹（坐标、按键序列）。回放时完全复制操作轨迹，适用于需要精确鼠标移动的测试，如绘图或拖拽操作。
【面试角度】
虽然WinRunner已较少使用，但录制模式的概念在现代工具（如UFT、Selenium IDE）中依然存在。面试时能对比两种模式的适用场景，体现对自动化测试原理的理解。
【易错提示】
环境判断模式并非不记录坐标，而是以对象为中心；模拟模式不依赖对象识别，因此对界面变化更敏感。
```

## Q002793

- 题型：简答
- 难度：简单

**题目**

```text
什么是断言？什么是验证命令？两者有什么区别？
```

**答案**

```text
断言和验证命令是测试中常用的两种验证技术。它们之间的区别在于它们的行为和用途。
1、断言是一种验证技术，用于在测试过程中检查预期结果是否与实际结果匹配。如果断言失败，测试将立即停止并标记为失败。断言用于验证测试的关键点，并确保应用程序的行为符合预期。
2、验证命令是一种验证技术，用于在测试过程中检查预期结果是否与实际结果匹配，但与断言不同的是，如果验证命令失败，测试将继续执行并生成一条警告。验证命令用于验证测试的次要点，即使出现验证失败，测试也可以继续执行并生成详细的测试结果报告。
3、总结来说，断言用于验证测试的关键点，如果断言失败，测试将停止并标记为失败；而验证命令用于验证测试的次要点，即使验证失败，测试也会继续执行并生成警告。这使得验证命令在需要验证多个条件的情况下更为有用，因为它可以收集更多的测试结果信息。
```

**解析**

```text
【核心考点】 自动化测试 断言 验证命令
【题目解析】
本题考察自动化测试中两种验证机制的概念和区别。断言和验证命令都用于检查预期与实际结果，但失败时的行为不同。
【参考答案要点】
1. 断言：用于验证关键点，如果失败则测试立即停止并标记为失败。
2. 验证命令：用于验证次要点，如果失败测试继续执行，仅生成警告。
3. 区别：断言是硬性检查，失败即终止；验证命令是软性检查，失败不影响后续执行。
【面试角度】
面试中可结合Selenium或TestNG等框架举例，如TestNG中的assert与softAssert，展示对工具的理解。
【易错提示】
不要混淆断言和验证命令，断言失败会中断测试，而验证命令允许继续，适用于非关键检查。
```

- 难度：简单

```text
手工测试和自动化测试的区别是什么？
```

```text
1、由于较高可能性的人为错误，手工测试具有较低的准确性，而自动化测试则具有更高的准确性，因为计算机测试消除了错误的机会
2、手工测试在大规模的测试时需要更多的时间，而自动化测试可以轻松的以最高的效率执行大规模的测试
3、手工测试需要更多的时间来完成一个测试周期，因此周转时间更高，自动化测试可以在可控时间内完成一个测试周期，因此周转时间更短
4、手工测试应该用于执行探索性测试、可用性测试和其他特别的测试，以显示最好的结果，自动化测试应该用于执行回归测试、负载测试、性能测试和重复测试，以获得最佳的结果。
5、从长远来看，手工测试的初始投资和ROI低于自动化测试，而自动化测试的初始投资更高，但从长远来看ROI更好。
```

```text
【核心考点】 手工测试 自动化测试 测试策略
【题目解析】
本题考查手工测试与自动化测试的核心区别，涉及准确性、效率、适用场景和成本等方面。两者互补，而非替代。
【参考答案要点】
1. 准确性：手工测试易受人为错误影响，准确性较低；自动化测试由计算机执行，准确性高，减少人为失误。
2. 效率：手工测试在大规模或重复测试时耗时较长；自动化测试可快速执行大量用例，效率高，周转时间短。
3. 适用场景：手工测试适合探索性测试、可用性测试等需要人类判断的场景；自动化测试适合回归测试、负载测试、性能测试等重复性任务。
4. 成本与ROI：手工测试初始投资低，但长期成本高；自动化测试初始投资高（工具、脚本），但长期ROI高，尤其适合频繁回归。
【面试角度】
回答时建议结合项目实例，如“在项目中，我们对手工测试进行探索性测试发现UI问题，而自动化测试用于CI/CD中的回归测试”，体现实际应用。
【易错提示】
常见错误：认为自动化测试完全替代手工测试，或忽略成本因素。面试中强调两者互补关系更佳。
```

- 难度：简单

**题目**

```text
请解释什么是Page Object模型？
```

**答案**

```text
Page Object模型是一种设计模式。
它将页面的每个元素抽象成一个对象，这个对象封装了与该元素相关的所有操作。它提高了测试脚本的可维护性和可重用性。
```

**解析**

```text
【核心考点】 Page Object模型 设计模式 测试可维护性
【题目解析】
Page Object模型是UI自动化测试中经典的设计模式，核心思想是将每个页面抽象为一个类，类中封装页面元素定位和操作方法。它通过分离页面逻辑和测试逻辑，显著提升脚本的可维护性和可重用性，减少因UI变更导致的脚本修改成本。
【参考答案要点】
1. 定义：Page Object是一种设计模式，将每个Web页面或组件抽象为一个对象，该对象包含页面元素（如按钮、输入框）的定位信息和相关操作（如点击、输入）。
2. 优点：
- 可维护性：页面元素变更时只需修改对应Page类，无需修改测试用例。
- 可重用性：多个测试用例可共享同一Page类的操作方法。
- 可读性：测试用例更贴近业务逻辑，如loginPage.inputUsername()。
3. 示例：以登录页面为例，创建LoginPage类，包含usernameInput、passwordInput和loginButton元素，以及login(username, password)方法。
【面试角度】
回答时可结合实际项目经验，例如“在Selenium+Python项目中，我们为每个页面创建Page类，并配合PageFactory简化元素初始化”。同时可提及与PO模式相关的其他模式（如Page Element、Business Flow），展现深度。
【易错提示】
注意Page Object并非框架，而是一种设计模式，常与Selenium、Appium等工具结合使用。不要混淆为具体工具或库。
```

```text
第一个原则是，公共方法表示页面提供的一个服务，比如我们可以把 登录封装成一个 logo 的方法，把搜索方法封装成一个设施方法，把注册操作封装成一个 register 的方法；
第二个原则是，尽量不要暴露页面的内部；比如说一个HTML的页面还有一个页面的上下结构；
第三个原则是，在 PO 当中一般不做断言，会做到页面逻辑和测试逻辑的分离
第四个原则是，PO 一般里面的方法返回 self 或者是其他的 Page Object 也可以是一个元素属性
第五个原则是，整个 PO 你不需要封装整个页面的行为，用到什么逻辑就封装什么
第六个原则是，对于统一操作，如果出现不同的结果，可以把用不同的方法来表示，比如说登录成功有跳转，登录失败有报错，
```

```text

【参考答案要点】

2. 隐藏页面内部细节：不暴露HTML结构或元素定位方式，提高可维护性。
3. 不做断言：PO层只负责操作和返回结果，断言放在测试层，实现逻辑分离。
```


**答案**

```text
目的：
提高复用率，可读性和编写效率。
测试代码与被测页面对象代码分离，降低页面变化带来的维护成本。
```

**解析**

```text
【核心考点】 Page Object 模式 UI 自动化测试 设计模式
【参考答案要点】
PO（Page Object）模型是一种设计模式，将面向过程的测试脚本转变为面向对象的方式，以页面为单位进行管理。其核心思想是分层，将每个页面的元素定位和操作封装在一个 Page 类中。
具体做法：
1. 创建 Page 类：为每个页面创建一个类，类中定义该页面的所有元素定位（如通过 @FindBy 注解）和操作方法（如点击、输入文本）。
2. 测试用例调用：在测试类中实例化 Page 对象，通过调用其方法完成操作，不直接操作元素。
3. 维护性提升：当页面元素变化时，只需修改对应的 Page 类，测试代码无需改动。
目的：提高代码复用率、可读性和编写效率，降低页面变化带来的维护成本。
【面试角度】

【延伸知识】
PO 模式常与数据驱动测试（DDT）和测试框架（如 Selenium、Appium）结合使用。高级用法还包括页面工厂（PageFactory）和组件化设计，以应对复杂页面结构。
```

```text
unittest 和 pytest 的区别
```

```text
（2）测试类必须继承 unittest.TestCase

2.pytest 提供了模块级、函数级、类级、方法级的 setup/teardown，比 unittest 的

五、失败重跑
1.unittest 无此功能。
2.pytest 支持用例执行失败重跑，pytest-rerunfailures 插件。
六、参数化
1.unittest 需依赖 ddt 库，
2.pytest 直接使用@pytest.mark.parametrize 装饰器。
七、用例分类执行
1、unittest 默认执行全部用例，也可以通过加载 testsuit，执行部分用例。
```

## Q002786

- 题型：简答
- 难度：中等

**题目**

```text
什么是庄模式和数据驱动模式？
```

**答案**

```text
庄模式是一种测试开发中的设计模式，也称为Page Object模式。它将页面抽象为对象，将页面中的元素和操作封装成方法，以提高测试代码的可维护性和可重用性。
在庄模式中，每个页面都有一个对应的Page Object类，该类包含了页面上的元素和与之关联的操作方法。

在软件测试中，庄模式常常与数据驱动模式结合使用。通过庄模式可以实现对页面元素和操作进行封装并提供良好的界面访问方式，而通过数据驱动模式可以更加灵活有效地管理和使用大量的测试数据。
自动化测试中常用 Page Object 模式和数据驱动模式，以提高代码质量和可维护性。
```

**解析**

```text
【核心考点】 Page Object模式 数据驱动模式 自动化测试设计模式
【参考答案要点】
1. 庄模式（Page Object Pattern）：将每个页面抽象为一个类，封装页面元素定位和操作方法。测试用例通过调用 Page Object 的方法来执行操作，而不直接操作元素。优点包括：
• 提高代码复用性，减少重复代码。
• 当页面元素变化时，只需修改对应 Page Object 类，不影响测试用例。
• 增强可读性和可维护性。

2. 数据驱动模式（Data-Driven Testing）：将测试数据与测试脚本分离，通过外部数据源（如 Excel、CSV、JSON、数据库）驱动测试执行。同一测试脚本可针对多组数据重复运行，提高测试覆盖率。优点包括：
• 减少脚本数量，降低维护成本。
• 便于非技术人员管理测试数据。
• 支持大规模参数化测试。

【面试角度】
回答时建议结合实际项目中的实现细节，例如“在电商项目中，我们为每个页面创建 Page Object 类，如 LoginPage、ProductPage，并在测试用例中调用其方法。同时使用数据驱动模式，将用户账号、商品信息等数据存储在 Excel 中，通过循环读取执行多组测试”。
【易错提示】
注意：庄模式并非必须与数据驱动模式结合使用，但两者常搭配以提升测试框架的灵活性和可维护性。另外，庄模式中的“庄”是“Page Object”的音译，并非标准术语，面试中建议使用“Page Object 模式”或“页面对象模式”。
```
