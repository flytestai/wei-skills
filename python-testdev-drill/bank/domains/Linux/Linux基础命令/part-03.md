## Q004688

- 题型：简答
- 难度：中等

**题目**

```text
根据题目要求写出具体linux操作命令\n1、进入/wls/applogs/CDTSServer/目录\n2、显示该目录下所有文件详细信息\n3、在后台运行该目录下的C001-listen.sh程序\n4、查看当前运行的所有包含“C001\"名称的进程信息\n5、停止进程号为25601的进程\n显示该目录下所有文件名包含cdts.log的文件信息
```

**答案**

```text
find . -name *cdts.log*
```

**解析**

```text
【核心考点】 Linux命令 文件操作 进程管理
【参考答案要点】
1. 进入目录：cd /wls/applogs/CDTSServer/
2. 显示所有文件详细信息：ls -la 或 ll
3. 后台运行C001-listen.sh程序：nohup ./C001-listen.sh &
4. 查看包含“C001”名称的进程信息：ps -ef | grep C001
5. 停止进程号为25601的进程：kill -9 25601
6. 显示文件名包含cdts.log的文件信息：find . -name "*cdts.log*"
【面试角度】
此类题目考察Linux基础操作能力，面试官通常期望候选人能熟练使用常用命令。建议在回答时注意命令的参数含义，例如ps -ef显示所有进程，grep用于过滤，kill -9强制终止。若项目中使用过类似场景，可举例说明。
【易错提示】
第6题要求“显示该目录下所有文件名包含cdts.log的文件信息”，注意find命令的-name参数需使用通配符，且路径为当前目录.。另外，ls命令不能递归查找子目录，而find可以。
```

## Q004703

- 题型：简答
- 难度：中等

**题目**

```text
端口冲突怎么解决
```

**答案**

```text
利用netstat -apn | grep 端口，查看端口占用情况，比如tomcat用8080端口，假如这时候发现被占用了，先通过命令查
询占用情况
如果正在用的是无关紧要的程序，那么杀掉对应进程，
如果对方进程是必须的，则可以通过修改tomcat默认的使用端口来解决问题，在tomcat/conf/server.xml 修改
```

**解析**

```text
【核心考点】 Linux端口管理 Tomcat配置
【题目解析】
本题考查Linux环境下端口冲突的排查与解决能力，是运维和测试工程师的常见问题。核心思路是：先定位占用端口的进程，再根据进程重要性决定是终止进程还是修改应用端口。
【参考答案要点】
1. 定位占用进程：使用netstat -apn | grep 端口号命令，查看占用该端口的PID和进程名。
2. 判断进程重要性：如果进程无关紧要，使用kill -9 PID终止进程；如果进程必须保留，则修改应用端口。
3. 修改Tomcat端口：编辑tomcat/conf/server.xml文件，找到<Connector port="8080" ...>，将8080改为其他未占用端口，然后重启Tomcat。
【面试角度】
回答时建议补充实际案例，例如“某次部署时发现8080被Jenkins占用，通过修改Tomcat端口解决”，并提及lsof -i :端口作为替代命令，体现知识广度。
【易错提示】
注意netstat命令的权限问题，部分系统需加sudo；另外修改端口后需确保防火墙放行新端口。
```

## Q004729

- 题型：简答
- 难度：中等

**题目**

```text
请问当⽤户反馈⽹站访问慢，你会如何处理？
```

**答案**

```text
网站比较慢：

1、服务器出口带宽不够用
本身服务器购买的出口带宽比较小。一旦并发量大的话，就会造成分给每个用户的出口带宽就小，访问速度自然就会慢。

2、服务器负载过大，导致响应不过来
可以从两个方面入手分析：
分析系统负载，使用 w 命令或者 uptime 命令查看系统负载。如果负载很高，则使用 top 命令查看 CPU ，MEM 等占用情况，要么是 CPU 繁忙，要么是内存不够。
如果这二者都正常，再去使用 sar 命令分析网卡流量，分析是不是遭到了攻击。一旦分析出问题的原因，采取对应的措施解决，如决定要不要杀死一些进程，或者禁止一些访问等。

3、数据库瓶颈
如果慢查询比较多。那么就要开发人员或 DBA 协助进行 SQL 语句的优化。
如果数据库响应慢，考虑可以加一个数据库缓存，如 Redis 等。然后，也可以搭建 MySQL 主从，一台 MySQL 服务器负责写，其他几台从数据库负责读。

4、网站开发代码没有优化好
```

**解析**

```text
【核心考点】 性能测试 问题排查 Linux命令
【参考答案要点】
1. 确认问题范围：先询问用户是否所有页面都慢，还是特定功能；是否特定时间段；是否特定浏览器或网络环境。
2. 检查网络层面：使用ping、traceroute检查网络延迟和丢包；查看服务器带宽使用情况（如sar -n DEV）。
3. 检查服务器资源：使用top/htop查看CPU和内存占用；使用free -m查看内存；使用df -h查看磁盘I/O。
4. 检查应用层面：查看Web服务器日志（如Nginx/Apache access log），分析慢请求；检查数据库慢查询日志（slow query log）。
5. 使用性能工具：如使用ab或JMeter模拟并发请求，定位瓶颈；使用strace跟踪系统调用。
【面试角度】
面试官期望看到系统化的排查思路，从用户端到服务器端层层递进。建议回答时强调“先定位再解决”，并举例说明使用过的工具和命令。
【易错提示】
不要直接跳到数据库优化，应先排除网络和服务器负载问题。常见错误是忽略前端因素（如JS/CSS加载慢）。
```

## Q004629

```text
如何查看某进程所占用的各种开销(如CPU、物理内存、虚拟内存、SOCKET句柄，网络流量，SOCKET状态等)，请列出你所知道的尽可能多的命令或者通过哪个文件看。
```

**答案**

```text
查看CPU：
cat /proc/cpuinfo
查看内存：
cat /proc/meminfo

查看网络流量：
sar命令
```

**解析**

```text
【核心考点】 Linux系统监控 性能分析
【题目解析】
本题考查Linux环境下进程资源监控的常用命令和文件接口。这是测试工程师进行性能分析和问题定位的重要技能，需要熟悉多种工具和系统文件。
【参考答案要点】
CPU使用：top -p <pid>、ps -p <pid> -o %cpu、/proc/<pid>/stat
物理内存：top -p <pid>、ps -p <pid> -o %mem,rss、/proc/<pid>/status（VmRSS字段）
虚拟内存：/proc/<pid>/status（VmSize字段）、pmap <pid>
网络流量：sar -n DEV 1 5（查看系统级）、nethogs（按进程）、/proc/<pid>/net/dev
Socket句柄/状态：lsof -p <pid>、ss -p、/proc/<pid>/fd、/proc/<pid>/net/tcp
【面试角度】
面试官期望看到多工具组合使用的能力，例如用top快速定位问题进程，再用strace跟踪系统调用。建议提及性能瓶颈分析思路，如CPU高用perf，内存泄漏用valgrind。
【易错提示】
注意区分/proc/cpuinfo（CPU硬件信息）和/proc/<pid>/stat（进程CPU使用）。题目要求“某进程”，应聚焦进程级命令，避免答成系统级命令。
```

```text

【延伸知识】
若日志格式复杂，建议使用awk进行更精确的时间过滤，例如：awk '$0 ~ /2022-02-24/ && $0 ~ /00:00:*/'。
```

## Q004634

- 题型：简答
- 难度：未标注
- 解析：AI 补全（原数据缺失解析）

**题目**

```text
如果再执行一条命令的时候突然卡死了，如何操作才能退出来？
```

**答案**

```text
ctrl + c
```

**解析**

```text
【核心考点】前台进程的中断方式。
【题目解析】命令卡死时通常按Ctrl+C发送中断信号，终止当前前台进程并回到命令行。若是需要退出的交互式程序，也可用Ctrl+D发送结束输入；进程无响应时可在其他终端查进程号后终止。
【答题要点】
1. Ctrl+C发送中断信号，终止当前前台命令。
2. Ctrl+D表示输入结束，适合交互式程序退出。
3. 仍无响应时用进程查看命令找到进程再强制终止。
【面试提示】先判断是命令在等待输入还是真的卡死，避免误杀正常任务。
```
