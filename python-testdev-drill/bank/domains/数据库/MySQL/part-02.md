## Q006542

- 题型：简答
- 难度：中等

**题目**

```text
数据库的存储过程与触发器的区别？
```

**答案**

```text
数据库中的 存储过程 和 触发器 都是用于封装和执行业务逻辑的数据库对象，但它们在用途、触发方式和执行方式上有显著区别。以下是它们的简单介绍和主要区别：
1. 存储过程（Stored Procedure）
• 定义：
存储过程是一组预编译的 SQL 语句，存储在数据库中，可以通过名称调用执行。
• 用途：• 封装复杂的业务逻辑。
• 提高代码复用性和维护性。
• 减少网络传输（客户端只需调用存储过程，而不是发送多条 SQL 语句）。

• 触发方式：
存储过程需要 显式调用，例如通过 CALL 语句或应用程序代码调用。
• 执行方式：• 可以接收输入参数，并返回输出参数或结果集。
• 支持条件判断、循环等逻辑控制。

• 示例：sql

CREATE PROCEDURE GetEmployee(IN emp_id INT)
BEGIN
SELECT * FROM employees WHERE id = emp_id;
END;

调用：sql

CALL GetEmployee(1);

2. 触发器（Trigger）
• 定义：
触发器是一种特殊的存储过程，它在特定事件（如 INSERT、UPDATE、DELETE）发生时 自动执行。
• 用途：• 数据完整性约束（如检查或修改数据）。
• 审计日志记录（如记录数据变更）。
• 自动化业务逻辑（如更新相关表）。

• 触发方式：
触发器是 隐式触发 的，当指定的事件发生时自动执行，无需手动调用。
• 执行方式：• 不能接收参数，也不能直接返回结果。
• 通常用于对触发事件的数据进行验证或修改。

• 示例：sql

CREATE TRIGGER before_employee_insert
BEFORE INSERT ON employees
FOR EACH ROW
BEGIN
IF NEW.salary < 0 THEN
SET NEW.salary = 0;
END IF;
END;

当插入新员工记录时，触发器会自动检查并修正薪资值。

3. 主要区别
特性	存储过程	触发器
触发方式	显式调用（如 CALL 或应用程序调用）	隐式触发（事件发生时自动执行）
执行时机	由用户或应用程序控制	在特定事件（如 INSERT、UPDATE）发生时
参数支持 支持输入和输出参数	不支持参数
返回值 可以返回结果集或输出参数	不能直接返回值
用途 封装复杂业务逻辑，提高代码复用性	数据完整性约束、审计日志、自动化逻辑
调用频率 按需调用	每次触发事件时自动执行

4. 使用场景
• 存储过程：• 需要手动调用的复杂业务逻辑。
• 需要返回结果集或输出参数的场景。

• 触发器：• 需要自动执行的逻辑（如数据校验、日志记录）。
• 需要确保数据一致性或业务规则的场景。

5. 注意事项
• 触发器应尽量简单，避免复杂的逻辑，以免影响性能。
• 存储过程适合封装复杂逻辑，但过度使用可能导致数据库与业务逻辑耦合过紧。

通过合理使用存储过程和触发器，可以有效地管理数据库逻辑并提高系统的可维护性和性能。
```

**解析**

```text
【核心考点】 存储过程 触发器 数据库对象
【参考答案要点】
1. 定义：存储过程是预编译的SQL语句集合，通过名称调用；触发器是特殊类型的存储过程，自动在特定事件（如INSERT、UPDATE、DELETE）发生时执行。
2. 触发方式：存储过程需要显式调用（如CALL语句）；触发器由数据库事件隐式触发，无需手动调用。
3. 参数：存储过程可以接受输入参数并返回输出参数；触发器通常不接受参数，但可以访问被修改的行数据（如NEW和OLD伪行）。
4. 用途：存储过程用于封装业务逻辑、提高复用性；触发器常用于实现数据完整性、审计日志或级联操作。
【面试角度】
回答时建议结合实际项目场景，例如“在订单系统中，使用存储过程处理复杂的订单计算，使用触发器记录库存变更日志”，能体现对两者适用场景的理解。
【延伸知识】
触发器可能引发性能问题或递归调用，需谨慎使用。存储过程在分布式系统中可能增加数据库负载，现代架构中部分逻辑会迁移到应用层。
```

## Q006543

- 题型：简答
- 难度：中等

**题目**

```text
数据库的存储过程与触发器的区别？
```

**答案**

```text
触发器与存储过程非常相似，触发器也是SQL语句集，两者唯一的区别是触发器不能用EXECUTE语句调用，而是在用户执行Transact-SQL语句时自动触发（激活）执行。
触发器是在一个修改了指定表中的数据时执行的存储过程。
触发器不同于存储过程，触发器主要是通过事件执行触发而被执行的，而存储过程可以通过存储过程名称名字而直接调用。
当对某一表进行诸如UPDATE、INSERT、DELETE这些操作时，SQLSERVER就会自动执行触发器所定义的SQL语句，从而确保对数据的处理必须符合这些SQL语句所定义的规则。
```

**解析**

```text
【核心考点】 存储过程 触发器 数据库对象
【参考答案要点】
1. 定义与调用方式：存储过程是一组预编译的SQL语句，通过EXECUTE或CALL显式调用；触发器是特殊的存储过程，由数据操作（INSERT、UPDATE、DELETE）自动触发，不能直接调用。2. 执行时机：存储过程在调用时执行；触发器在事件发生时自动执行，常用于数据完整性约束。3. 参数：存储过程支持输入输出参数；触发器通常无参数，但可访问INSERTED和DELETED临时表。4. 用途：存储过程用于封装业务逻辑；触发器用于审计、级联更新或强制复杂约束。
【面试角度】
回答时建议结合实际项目场景，例如“在订单系统中，使用触发器自动更新库存”，并说明触发器的潜在性能问题，避免过度使用。
【易错提示】
易混淆点：触发器本质是存储过程，但调用方式不同。面试中常问触发器的递归调用和嵌套限制。
```

**解析**

```text
【核心考点】 数据库 存储过程
【题目解析】
本题考察对数据库存储过程的基本概念和优势的理解。存储过程是一组预编译的SQL语句集合，存储在数据库中，可被重复调用。它在处理复杂业务逻辑、提高性能、增强安全性方面有重要作用。面试中常作为数据库基础知识的考察点。
```

## Q006549

- 题型：简答
- 难度：中等

**题目**

```text
数据库索引有哪两种实现方式 分别对应的数据结构是什么？
```

**答案**

```text
mysql索引主要有两种结构：b+tree索引和hash索引.

1.hash索引
mysql中，只有memory(memory表只存在内存中，断电会消失，适用于临时表)存储引擎显示支持hash索引，是memory表的默认索引类型，尽管memory表也可以使用b+tree索引。hsah索引把数据的索引以hash形式组织起来，因此当查找某一条记录的时候,速度非常快。当时因为是hash结构，每个键只对应一个值，而且是散列的方式分布。所以他并不支持范围查找和排序等功能。

2.b+树索引
b+tree是mysql使用最频繁的一个索引数据结构，是inodb和myisam存储引擎模式的索引类型。相对hash索引，b+树在查找单条记录的速度比不上hash索引，但是因为更适合排序等操作，所以他更受用户的欢迎。毕竟不可能只对进行单条记录的操作。
```

**解析**

```text
【核心考点】 数据库索引 B+树索引 Hash索引
【题目解析】
本题考查数据库索引的底层实现方式，是数据库面试高频题。MySQL中主要支持B+树索引和Hash索引，两者在存储引擎支持、查询性能和应用场景上有显著差异。
【参考答案要点】
1. Hash索引：仅Memory存储引擎默认支持，基于哈希表实现，等值查询速度极快（O(1)），但不支持范围查询、排序和部分索引匹配，因为哈希值无序。
2. B+树索引：InnoDB和MyISAM存储引擎默认使用，数据按顺序存储，支持范围查询、排序和高效的多列索引，是MySQL最常用的索引结构。
【面试角度】
回答时可补充实际应用场景，例如“在电商系统中，订单表常用B+树索引支持时间范围查询”，并提及B+树与B树的区别（如非叶子节点不存数据、链表结构优化范围扫描），展现深度。
【易错提示】
常见错误：误认为所有存储引擎都支持Hash索引，或混淆Hash索引与自适应Hash索引（InnoDB的优化特性）。
【延伸知识】
MySQL 8.0还支持倒排索引（全文索引）和空间索引（R树），面试中可提及以展示知识广度。
```

```text
日常工作中，sql性能优化，你是怎么做的？
```

```text

【易错提示】
不要只回答“加索引”，需强调索引是否被正确使用（如最左前缀原则），以及避免索引失效的场景。
```

## Q006560

```text
有如下两张数据表：
```

```text
select * from base_user t1 left join account as t2 on t1.id = t2.id;
分析：
从此结果来看，此题目考察面试人员对left join的掌握情况。
因为结果中A表的数据都有，不满足查询“on t1.id = t2.id”的右表数据均以NULL值显示的。
```

**解析**

```text
【核心考点】 SQL连接查询 LEFT JOIN
【题目解析】
本题考察SQL中LEFT JOIN的使用，要求根据两张表（base_user和account）编写查询语句，确保左表（base_user）所有记录都保留，右表（account）匹配不上的字段显示为NULL。题目中给出的答案正确，但需要注意表别名的使用和字段选择。
【参考答案要点】
标准答案：SELECT * FROM base_user t1 LEFT JOIN account t2 ON t1.id = t2.id;

【面试角度】
回答时建议结合实际项目场景，例如“在用户信息查询中，使用LEFT JOIN确保所有用户都能被列出，即使其账户信息缺失”。同时，可补充INNER JOIN和RIGHT JOIN的区别，展示对连接类型的全面理解。
【易错提示】
常见错误包括：混淆LEFT JOIN和INNER JOIN；忘记使用别名导致语法错误；或未指定连接条件导致笛卡尔积。面试中建议强调连接条件的准确性和表别名的规范性。
```

## Q006561

- 题型：简答
- 难度：中等

**题目**

```text
有如下表和数据：
学生表：Sid：学号，Sname：学生姓名，Sage：学生年龄，Ssex：学生性别
课程表：Cid：课程编号，Cname：课程名称，Tid：教师编号
成绩表：Sid：学号，Cid：课程编号，Score：成绩
教师表：Tid：教师编号，Tname：教师名字

1）请查出所有成绩大于88分的学生学号以及姓名；
2）查出数学成绩比物理成绩高的学生姓名；
3）查出只修了一门课程的学生姓名、课程名字以及分数；
4）查询学过\"徐明长\"老师课程的学生学号，姓名，课程名字，分数
```

**答案**

```text
1. 查出所有成绩大于 88 分的学生学号以及姓名
sql

SELECT s.Sid, s.Sname
FROM Student s
JOIN Score sc ON s.Sid = sc.Sid
WHERE sc.score > 88;

2. 查出数学成绩比物理成绩高的学生姓名
sql

SELECT s.Sname
FROM Student s
JOIN Score sc1 ON s.Sid = sc1.Sid
JOIN Course c1 ON sc1.Cid = c1.Cid AND c1.Cname = '数学'
JOIN Score sc2 ON s.Sid = sc2.Sid
JOIN Course c2 ON sc2.Cid = c2.Cid AND c2.Cname = '物理'
WHERE sc1.score > sc2.score;
```

## Q006564

- 题型：简答
- 难度：中等

**题目**

```text
条件后面where和having的区别是什么？
```

**答案**

```text
1、用的地方不一样
where 可以用于 select、update、delete 和 insert 语句中。 having 只能用于 select 语句中
2、执行的顺序不一样
where 的搜索条件是在执行语句进行分组之前应用
having 的搜索条件是在分组条件后执行的
即如果 where 和 having 一起用时，where 会先执行，having 后执行
3、子句有区别
where 子句中的条件表达式 having 都可以跟，而 having 子句中的有些表达式 where 不可以跟；
having 子句可以用聚合函数（sum、count、avg、max 和 min），而 where 子句不可以。
```

**解析**

```text
【核心考点】 SQL查询 WHERE子句 HAVING子句
【题目解析】
本题考查SQL中WHERE和HAVING子句的区别，这是数据库查询中的基础但重要知识点。两者都用于过滤数据，但应用阶段和功能不同。WHERE在分组前过滤行，HAVING在分组后过滤组，且HAVING可使用聚合函数。
【参考答案要点】
1. 使用位置不同：WHERE可用于SELECT、UPDATE、DELETE和INSERT语句；HAVING仅用于SELECT语句。
2. 执行顺序不同：WHERE在分组前过滤行；HAVING在分组后过滤组，若同时使用，WHERE先执行。
3. 子句条件不同：WHERE不能包含聚合函数（如SUM、COUNT、AVG等），而HAVING可以；HAVING中的条件表达式WHERE不一定支持。
【面试角度】
回答时建议结合实际SQL查询场景举例，例如“查询每个部门平均工资大于5000的部门”，需先用WHERE过滤员工，再用HAVING过滤部门，能体现理解深度。
【易错提示】
常见错误：认为HAVING可替代WHERE，或混淆两者执行顺序。记住：WHERE过滤行，HAVING过滤组，聚合函数只能在HAVING中使用。
```

## Q006581

- 题型：简答
- 难度：中等

**题目**

```text
简单说说SQL语句的执行顺序？
```

**答案**

```text
SQL语法结构与执行顺序解析
一、SQL基本语法结构
SQL语句通常由以下几个关键部分组成（以SELECT语句为例）：
sql
SELECT [DISTINCT] 列名1, 列名2, 聚合函数(列名) -- 5.最终选择要返回的列
FROM 表名 -- 1.确定数据来源
[JOIN 表名 ON 连接条件] -- 2.表连接
[WHERE 条件] -- 3.行级过滤
[GROUP BY 分组列] -- 4.分组
[HAVING 分组后条件] -- 4.5 分组后过滤
[ORDER BY 排序列 [ASC|DESC]] -- 6.排序
[LIMIT 数量] -- 7.限制返回行数

二、SQL语句执行顺序（逻辑处理顺序）
虽然SQL的书写顺序如上所示，但数据库引擎实际执行顺序却是：
• FROM + JOIN
首先确定数据来源，执行表连接操作

• WHERE
对FROM和JOIN后的结果集进行行级过滤

• GROUP BY
按照指定列对数据进行分组

• HAVING
对分组后的结果进行筛选（注意：WHERE在分组前，HAVING在分组后）

• SELECT
选择最终要返回的列（此时才计算SELECT中的表达式和聚合函数）

• DISTINCT
去除重复行（如果有DISTINCT关键字）

• ORDER BY
对结果集进行排序

• LIMIT/OFFSET
限制返回的行数

三、执行顺序示例说明
假设有以下SQL：
sql
SELECT user_id, COUNT(*) as order_count
FROM orders
WHERE status = 'completed'
GROUP BY user_id
HAVING COUNT(*) > 5
ORDER BY order_count DESC
LIMIT 10;

实际执行步骤：
• 从orders表获取数据（FROM）
• 筛选status = 'completed'的记录（WHERE）
• 按user_id分组（GROUP BY）
• 筛选订单数>5的分组（HAVING）
• 选择user_id和计算每个用户的订单数（SELECT）
• 按order_count降序排序（ORDER BY）
• 只返回前10条记录（LIMIT）

四、重要注意事项
• WHERE vs HAVING：
• WHERE在分组前过滤，不能使用聚合函数
• HAVING在分组后过滤，可以使用聚合函数

• 别名使用：
• SELECT阶段定义的别名，只能在ORDER BY和HAVING中使用
• 不能在WHERE或GROUP BY中使用SELECT定义的别名

• 性能影响：
• WHERE条件应尽量先过滤掉不需要的数据
• 合理的执行顺序理解有助于编写高性能SQL

五、测试工程师应用场景
理解SQL执行顺序可以帮助测试工程师：
• 更准确地设计测试用例
• 分析查询性能瓶颈
• 验证复杂SQL的结果正确性
• 优化测试数据准备语句

例如测试一个报表查询时，可以按照执行顺序逐步验证中间结果的正确性，而不是只检查最终输出。
这种理解对于编写高效的测试SQL和定位数据问题非常有价值。
```

**解析**

```text
【核心考点】 SQL语法 执行顺序
【题目解析】
本题考查SQL语句的语法结构和执行顺序，这是数据库基础面试中的高频考点。SQL语句的书写顺序和执行顺序不同，理解这一点对于编写高效、正确的查询至关重要。
【参考答案要点】
1. SQL基本语法结构：以SELECT语句为例，包括SELECT、FROM、JOIN、WHERE、GROUP BY、HAVING、ORDER BY、LIMIT等子句。
2. 执行顺序：FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT。注意：WHERE在GROUP BY之前执行，HAVING在GROUP BY之后；SELECT在ORDER BY之前执行。
3. 关键点：WHERE不能使用聚合函数，HAVING可以；ORDER BY可以使用别名，因为它在SELECT之后执行。
【面试角度】
建议结合实际SQL优化案例说明，例如“在项目中，通过调整WHERE和HAVING的顺序，减少了分组前的数据量，提升了查询性能”。
【延伸知识】
不同数据库（如MySQL、Oracle）对SQL执行顺序的优化略有差异，但逻辑顺序一致。了解执行顺序有助于避免常见错误，如WHERE中使用别名。
```

```text
CREATE TRIGGER check_order_amount

• 自动执行关联表的更新
• 示例：删除用户时同步删除其订单sql
CREATE TRIGGER delete_user_orders
AFTER DELETE ON users
FOR EACH ROW
BEGIN

• 自动记录数据变更历史
• 示例：记录员工薪资变更sql
CREATE TRIGGER log_salary_change
AFTER UPDATE ON employees
FOR EACH ROW
BEGIN

END;

• 自动计算派生数据
• 示例：更新库存数量sql
CREATE TRIGGER update_inventory

BEGIN

• BEFORE：在操作执行前触发

• INSERT：插入数据时触发
• UPDATE：更新数据时触发
• DELETE：删除数据时触发

优缺点
优点：
• 提高数据完整性
• 简化应用层代码
• 自动执行业务规则

缺点：
• 隐性执行，调试困难
• 可能导致意外的连锁反应
• 增加数据库负担

使用建议
• 避免过度使用触发器
• 保持触发器逻辑简单
• 注意性能影响
• 做好文档记录
```

## Q006593

- 题型：简答
- 难度：中等

**题目**

```text
说一下数据库的索引的工作原理及其种类。
```

**答案**

```text
1）数据库索引: 是数据库管理系统中一个排序的数据结构，以协助快速查询、更新数据库表中数据。在数据之外，数据库系统还维护着满足特定查找算法的数据结构，这种数据结构，就是索引。
为表设置索引要付出代价的：
一是增加了数据库的存储空间，
二是在插入和修改数据时要花费较多的时间(因为索引也要随之变动)。

2）根据数据库的功能，可以在数据库设计器中创建三种索引：唯一索引、主键索引和聚集索引。
a. 唯一索引是不允许其中任何两行具有相同索引值的索引。
b. 主键索引 :数据库表经常有一列或列组合，其值唯一标识表中的每一行。该列称为表的主键。 在数据库关系图中为表定义主键将自动创建主键索引，主键索引是唯一索引的特定类型。
c. 聚集索引 :在聚集索引中，表中行的物理顺序与键值的逻辑（索引）顺序相同。一个表只能包含一个聚集索引。聚集索引和非聚集索引的根本区别是表记录的排列顺序和与索引的排列顺序是否一致，聚集索引表优点是查询速度快，缺点是对表进行修改速度较慢
```

**解析**

```text
【核心考点】 数据库索引 性能优化
【参考答案要点】
索引工作原理：索引是数据库维护的一种排序数据结构（如B+树、哈希表），用于快速定位数据行。通过索引，数据库可以避免全表扫描，直接通过索引键找到对应记录的位置，从而大幅提升查询效率。
索引种类：
1. 唯一索引：确保索引列的值唯一，允许空值但只能有一个空值。
2. 主键索引：一种特殊的唯一索引，不允许空值，每个表只能有一个主键索引。
3. 聚集索引：表中数据行的物理顺序与索引键顺序相同，每个表只能有一个聚集索引。
4. 非聚集索引：索引顺序与数据物理顺序不同，通过指针指向数据行，一个表可有多个非聚集索引。
代价：索引会占用额外存储空间，并降低插入、更新、删除操作的性能（因为索引需同步维护）。
【面试角度】
面试中常结合查询优化提问，如“如何选择合适的索引列？”可回答：选择查询频繁、区分度高的列，避免对频繁更新的列建索引。
【易错提示】
注意区分聚集索引与非聚集索引：聚集索引决定数据存储顺序，非聚集索引只存储键值和指针。
```

```text
• INNER JOIN：只返回两个表中共有的数据行，即交集部分。
• LEFT JOIN：返回左表中所有数据行，以及右表中与左表匹配的数据行，右表中未匹配的数据行用NULL填充。
• RIGHT JOIN：返回右表中所有数据行，以及左表中与右表匹配的数据行，左表中未匹配的数据行用NULL填充。
• FULL OUTER JOIN：返回左表和右表中所有数据行，左表和右表未匹配的数据行用NULL填充。

示例：
假设有两个表格，一个是用户表user，包含字段id和name；另一个是订单表order，包含字段id和user_id。
我们想要查询每个订单所对应的用户名称，可以使用如下的SQL语句：
SELECT order.id, user.name
FROM order
INNER JOIN user
ON order.user_id = user.id;
这条SQL语句使用了INNER JOIN来连接order和user两个表，并根据user_id和id这两个字段进行匹配，返回结果包含order表中的id字段和user表中的name字段。
```

```text
【核心考点】 MySQL多表查询 JOIN
【参考答案要点】
MySQL多表查询通过JOIN实现，常见类型：
INNER JOIN：返回两表匹配的行（交集）。

【面试角度】

【延伸知识】
MySQL不支持FULL OUTER JOIN，但可通过LEFT JOIN UNION RIGHT JOIN实现相同效果。此外，多表查询时注意索引优化，避免全表扫描。
```

## Q006604

- 题型：简答
- 难度：中等

**题目**

```text
请简单说说mysql的事务隔离级别
```

**答案**

```text
MySQL 的事务隔离级别定义了事务之间的可见性和并发控制规则。MySQL 支持四种事务隔离级别，从低到高分别是：
• Read Uncommitted（读未提交）
• Read Committed（读已提交）
• Repeatable Read（可重复读）
• Serializable（串行化）

以下是对每种隔离级别的简单说明和案例。
1. Read Uncommitted（读未提交）
• 描述：事务可以读取其他事务未提交的数据（“脏读”）。
• 问题：可能导致脏读、不可重复读和幻读。
• 案例：• 事务 A 更新一条记录但未提交。
• 事务 B 读取了事务 A 未提交的数据。
• 如果事务 A 回滚，事务 B 读取的数据就是无效的。

sql

-- 设置隔离级别为 Read Uncommitted
SET SESSION TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;

-- 事务 A
START TRANSACTION;
UPDATE users SET balance = 200 WHERE id = 1; -- 未提交

-- 事务 B
START TRANSACTION;
SELECT balance FROM users WHERE id = 1; -- 可能读到 200（脏读）

2. Read Committed（读已提交）
• 描述：事务只能读取其他事务已提交的数据。
• 问题：可能导致不可重复读和幻读。
• 案例：• 事务 A 读取一条记录。
• 事务 B 更新并提交了这条记录。
• 事务 A 再次读取时，发现数据已改变（不可重复读）。

sql

-- 设置隔离级别为 Read Committed
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 事务 A
START TRANSACTION;
SELECT balance FROM users WHERE id = 1; -- 读到 100

-- 事务 B
START TRANSACTION;
UPDATE users SET balance = 200 WHERE id = 1;
COMMIT;

-- 事务 A
SELECT balance FROM users WHERE id = 1; -- 读到 200（不可重复读）

3. Repeatable Read（可重复读）
• 描述：事务在执行期间多次读取同一数据时，结果一致（MySQL 默认隔离级别）。
• 问题：可能导致幻读。
• 案例：• 事务 A 读取一组记录。
• 事务 B 插入或删除记录并提交。
• 事务 A 再次读取时，发现记录数量变化（幻读）。

sql

-- 设置隔离级别为 Repeatable Read
SET SESSION TRANSACTION ISOLATION LEVEL REPEATABLE READ;

-- 事务 A
START TRANSACTION;
SELECT COUNT(*) FROM users; -- 读到 10

-- 事务 B
START TRANSACTION;
INSERT INTO users (id, name) VALUES (11, 'John');
COMMIT;

-- 事务 A
SELECT COUNT(*) FROM users; -- 仍然读到 10（可重复读）

4. Serializable（串行化）
• 描述：事务完全串行执行，避免脏读、不可重复读和幻读。
• 问题：性能最低，因为所有事务必须按顺序执行。
• 案例：• 事务 A 读取一组记录。
• 事务 B 尝试更新或插入记录时会被阻塞，直到事务 A 完成。

sql

-- 设置隔离级别为 Serializable
SET SESSION TRANSACTION ISOLATION LEVEL SERIALIZABLE;

-- 事务 A
START TRANSACTION;
SELECT * FROM users;

-- 事务 B
START TRANSACTION;
INSERT INTO users (id, name) VALUES (11, 'John'); -- 被阻塞，直到事务 A 提交或回滚

总结

• 脏读：读到未提交的数据。
• 不可重复读：同一事务内多次读取同一数据，结果不一致。
• 幻读：同一事务内多次读取同一范围的数据，记录数量不一致。
• 性能：隔离级别越高，并发性能越低。
```

**解析**

```text
【核心考点】 MySQL事务隔离级别 并发控制
【题目解析】
本题考察MySQL事务隔离级别的理解和应用。MySQL支持四种隔离级别：Read Uncommitted（读未提交）、Read Committed（读已提交）、Repeatable Read（可重复读）、Serializable（串行化）。每种级别解决不同并发问题（脏读、不可重复读、幻读），级别越高，数据一致性越强，但性能越低。示例回答中，候选人解释了Read Uncommitted可能导致脏读，并给出了案例，但回答不完整，缺少其他级别的说明。
【参考答案要点】
1. Read Uncommitted：允许脏读，事务可读取未提交数据，并发性最高但一致性最差。
2. Read Committed：避免脏读，但可能出现不可重复读（同一事务内两次读取结果不同）。
3. Repeatable Read：MySQL默认级别，避免脏读和不可重复读，但可能出现幻读（插入新行导致结果集变化）。
4. Serializable：最高级别，完全串行化执行，避免所有并发问题，但性能最低。
【面试角度】
面试官常要求结合案例说明，例如“在银行转账场景中，使用Repeatable Read确保余额一致”。建议补充MySQL的MVCC机制（多版本并发控制）如何实现Repeatable Read，以展示深度。
【易错提示】
注意区分“不可重复读”和“幻读”：不可重复读针对同一行数据变化，幻读针对新增行。MySQL的Repeatable Read通过间隙锁（Gap Lock）部分解决幻读。
```

## Q006606

- 题型：简答
- 难度：中等

**题目**

```text
请说一下数据库事务的几个特性
```

**答案**

```text
1、原子性(Atomicity)：事务中的全部操作在数据库中是不可分割的，要么全部完成，要么均不执行。
2、一致性(Consistency)：几个并行执行的事务，其执行结果必须与按某一顺序串行执行的结果相一致。
3、隔离性(Isolation)：事务的执行不受其他事务的干扰，事务执行的中间结果对其他事务必须是透明的。
4、持久性(Durability)：对于任意已提交事务，系统必须保证该事务对数据库的改变不被丢失，即使数据库出现故障
```

**解析**

```text
【核心考点】 数据库事务 ACID特性
【题目解析】
本题考查数据库事务的四个基本特性，即ACID。这是数据库领域的核心概念，也是面试中的高频考点。事务是数据库操作的基本单位，保证数据的一致性和完整性。
【参考答案要点】
1. 原子性（Atomicity）：事务中的所有操作要么全部成功，要么全部失败回滚，不可分割。
2. 一致性（Consistency）：事务执行前后，数据库的完整性约束必须保持一致，即从一个一致状态转换到另一个一致状态。
3. 隔离性（Isolation）：并发执行的事务之间互不干扰，每个事务都感觉不到其他事务的存在。
4. 持久性（Durability）：一旦事务提交成功，其对数据库的修改是永久性的，即使系统崩溃也不会丢失。
【易错提示】
注意区分一致性和隔离性：一致性是事务执行的结果正确，隔离性是并发控制的手段。另外，持久性通常通过日志机制实现，面试时提及这一点会加分。
```

## Q006412

- 题型：简答
- 难度：较难

**题目**

```text
MySQL数据库索引，为什么是B+树，而不是B树、二叉树这些？
```

**答案**

```text
二叉树，是一种特殊链表，数据在树的两边，如果数据越多，树的层级就会越深，查找数据时的IO就会很高，性能就比较差；
B树，是平衡二叉树，就是树的两边数据相等，相对来说速度会快一点，但是，树的每个节点只存储了一个键值和数据，查询的IO还是很高。
而B+树，叶子节点上只存储键值，这样，叶子上能存储的键值就越多，能存储的数据量就越多，相对B数，查询数据时的IO次数就可以更少，效率也就更快了。
```

**解析**

```text
【核心考点】 MySQL索引 B+树 数据结构
【题目解析】
MySQL的InnoDB存储引擎使用B+树作为索引结构，主要因为B+树在磁盘I/O、范围查询和稳定性方面优于B树和二叉树。二叉树在数据量大时层级深，导致I/O次数多；B树每个节点存储键值和数据，节点大小有限，导致树高度较高；而B+树只有叶子节点存储数据，非叶子节点只存键值，因此每个节点能存储更多键值，树高度更低，I/O次数更少。
【参考答案要点】
1. 二叉树：每个节点最多两个子节点，数据量增大时树高度线性增长，导致查询时磁盘I/O次数多，性能差。
2. B树：平衡多路搜索树，每个节点存储键值和数据，节点大小固定（通常为页大小），因此每个节点能存储的键值数量有限，树高度仍较高，I/O次数较多。
3. B+树：非叶子节点只存储键值，不存储数据，因此每个节点能存储更多键值，树高度更低（通常3-4层），查询时I/O次数少；叶子节点形成有序链表，支持高效的范围查询和排序。
【面试角度】

```

```text
1、写流程：先删除缓存，再写数据库
2.、读流程：先读缓存，如果命中就返回，如果miss就读取数据库，然后将数据存入缓存，再返回数据
```

**解析**

```text
【核心考点】 缓存一致性 Redis与数据库同步
【题目解析】
本题考察Redis与数据库（如MySQL）之间的数据同步策略，核心是解决缓存与数据库双写时的数据一致性问题。常见的方案包括：先更新数据库再删除缓存、先删除缓存再更新数据库、以及延迟双删等。面试中常要求解释为何不能先更新缓存，以及如何处理并发场景下的不一致。
【参考答案要点】
1. 写流程：先删除缓存，再写数据库。这样即使后续读请求在写数据库前读到旧缓存，也会因缓存被删而重新从数据库加载，保证最终一致性。
2. 读流程：先读缓存，命中则直接返回；未命中则读取数据库，将数据写入缓存后再返回。注意需设置过期时间，防止缓存与数据库长期不一致。
3. 补充方案：延迟双删（先删缓存→写数据库→延迟再次删缓存）可进一步降低并发写读导致的不一致概率。
【面试角度】
回答时建议结合实际项目中的并发场景，例如高并发下单时如何保证库存数据一致，并提及可能出现的脏读问题及解决方案（如消息队列异步同步）。
【易错提示】
避免回答“先更新数据库再更新缓存”，这会导致缓存与数据库数据不一致（如写库成功但缓存更新失败）。正确做法是删除缓存而非更新，因为删除操作幂等且简单。
```

## Q006519

- 题型：简答
- 难度：较难

**题目**

```text
当数据表中A、B字段做了组合索引，那么单独使用A或单独使用B会有索引效果吗？（使用like查询如何有索引效果）
```

**答案**

```text
在 MySQL 中，如果对 A 和 B 字段创建了组合索引（复合索引），单独使用 A 或 B 字段的查询是否有效，取决于组合索引的顺序以及查询条件。以下是详细说明和案例。
1. 组合索引的基本规则
• 组合索引的字段顺序非常重要。
• 如果组合索引是 (A, B)，则：• 查询条件中只使用 A 时，索引有效。
• 查询条件中只使用 B 时，索引无效。
• 查询条件中同时使用 A 和 B 时，索引有效。

• 如果查询条件中使用了 LIKE，则需要遵循最左前缀原则，且 LIKE 的模式不能以通配符开头。

2. 案例演示
创建表和组合索引
sql

CREATE TABLE users (
id INT PRIMARY KEY,
first_name VARCHAR(50),
last_name VARCHAR(50),
age INT
);

CREATE INDEX idx_name ON users (first_name, last_name);

插入测试数据
sql

INSERT INTO users (id, first_name, last_name, age) VALUES
(1, 'John', 'Doe', 25),
(2, 'Jane', 'Smith', 30),
(3, 'Alice', 'Johnson', 22),
(4, 'Bob', 'Brown', 28);

3. 查询是否使用索引
查询 1：单独使用 A（first_name）
sql

EXPLAIN SELECT * FROM users WHERE first_name = 'John';

结果：
• 使用了 idx_name 索引。
• 因为 first_name 是组合索引的最左字段。

查询 2：单独使用 B（last_name）
sql

EXPLAIN SELECT * FROM users WHERE last_name = 'Doe';

结果：
• 未使用 idx_name 索引。
• 因为 last_name 不是组合索引的最左字段。

查询 3：同时使用 A 和 B
sql

EXPLAIN SELECT * FROM users WHERE first_name = 'John' AND last_name = 'Doe';

结果：
• 使用了 idx_name 索引。
• 因为查询条件中包含了组合索引的最左字段 first_name。

4. 使用 LIKE 查询
查询 4：LIKE 以通配符开头
sql

EXPLAIN SELECT * FROM users WHERE first_name LIKE '%oh%';

结果：
• 未使用 idx_name 索引。
• 因为 LIKE 的模式以通配符开头，无法利用索引。

查询 5：LIKE 不以通配符开头
sql

EXPLAIN SELECT * FROM users WHERE first_name LIKE 'Jo%';

结果：
• 使用了 idx_name 索引。
• 因为 LIKE 的模式不以通配符开头，且 first_name 是组合索引的最左字段。

5. 如何优化单独使用 B 字段的查询？
如果经常需要单独使用 last_name 字段查询，可以单独为 last_name 创建一个索引：
sql

CREATE INDEX idx_last_name ON users (last_name);

然后执行以下查询：
sql

EXPLAIN SELECT * FROM users WHERE last_name = 'Doe';

结果：
• 使用了 idx_last_name 索引。

总结
• 组合索引的最左前缀原则：• 如果组合索引是 (A, B)，查询条件中必须包含 A 才能使用索引。
• 单独使用 B 时，索引无效。

• **LIKE 查询的索引使用**：• 如果 LIKE 的模式以通配符开头（如 %abc），索引无效。
• 如果 LIKE 的模式不以通配符开头（如 abc%），且符合最左前缀原则，索引有效。

• 优化建议：• 根据查询需求合理设计组合索引。
• 如果经常需要单独查询某个字段，可以为该字段单独创建索引。
```

**解析**

```text
【核心考点】 MySQL索引 组合索引 最左前缀原则
【题目解析】
本题考查MySQL组合索引的最左前缀原则。组合索引 (A, B) 中，查询条件必须从最左列开始才能使用索引。单独使用A有效，单独使用B无效。对于LIKE查询，需避免以通配符开头才能利用索引。
【参考答案要点】
1. 单独使用A：有效，因为满足最左前缀原则，索引可用于查找A值。
2. 单独使用B：无效，因为B不是最左列，索引无法直接使用，会导致全表扫描。
3. LIKE查询：要使索引有效，LIKE模式不能以通配符开头，例如 LIKE 'abc%' 可使用索引，而 LIKE '%abc' 则不能。
【面试角度】
回答时建议结合实际项目经验，例如“在电商系统中，对用户ID和订单时间创建组合索引，单独查询用户ID时索引生效，但单独查时间则需额外优化”。
【延伸知识】
MySQL 8.0支持索引跳跃扫描（Index Skip Scan），可部分缓解单独使用非最左列的问题，但仍有性能限制。
```

## Q006594

- 题型：简答
- 难度：较难

**题目**

```text
说一下数据库的索引的工作原理及其种类。
```

**答案**

```text
1. 索引的工作原理
• 索引 是一种数据结构，用于快速查找数据库表中的数据。
• 类似于书籍的目录，索引通过维护一个指向数据行的指针，减少查询时需要扫描的数据量。
• 当执行查询时，数据库会先检查索引，找到符合条件的行，然后直接定位到这些行，而不是扫描整个表。

2. 索引的种类
（1）按数据结构分类
• B-Tree 索引：• 最常见的索引类型，适用于等值查询和范围查询。
• 数据按平衡树（B-Tree）结构组织，支持快速查找、插入和删除。

• 哈希索引：• 基于哈希表实现，适用于等值查询。
• 查询速度非常快，但不支持范围查询。

• 全文索引：• 用于文本数据的全文搜索，支持关键词匹配。

• R-Tree 索引：• 用于空间数据（如地理坐标），支持范围查询和多维数据。

（2）按功能分类
• 主键索引（Primary Key Index）：• 唯一标识表中的每一行，不允许重复和 NULL 值。

• 唯一索引（Unique Index）：• 确保索引列的值唯一，允许 NULL 值。

• 普通索引（Normal Index）：• 最基本的索引类型，没有唯一性约束。

• 复合索引（Composite Index）：• 基于多个列创建的索引，支持多列查询。

（3）按存储方式分类
• 聚集索引（Clustered Index）：• 数据行的物理存储顺序与索引顺序一致，一个表只能有一个聚集索引。

• 非聚集索引（Non-Clustered Index）：• 索引和数据行的存储是分开的，一个表可以有多个非聚集索引。

3. 索引的优点
• 加快查询速度：通过减少扫描的数据量，提高查询效率。
• 保证数据唯一性：通过主键索引或唯一索引，确保数据唯一。
• 优化排序和分组：索引可以加速 ORDER BY 和 GROUP BY 操作。

4. 索引的缺点
• 占用存储空间：索引需要额外的存储空间。
• 影响写操作性能：插入、更新和删除操作需要维护索引，可能降低性能。
• 维护成本：索引需要定期维护，否则可能失效。

5. 适用场景
• 频繁查询的列：如 WHERE 条件中经常使用的列。
• 需要排序或分组的列：如 ORDER BY 或 GROUP BY 中的列。
• 需要保证唯一性的列：如主键或唯一约束列。

6. 总结
索引是数据库优化的重要手段，通过合理使用索引，可以显著提高查询性能。但需要根据实际需求选择合适的索引类型，并注意维护成本。
```

**答案**

```text
查询 1：查询所有学生的学号，姓名，选课数，平均成绩
sql

SELECT s.sid, s.sname, COUNT(sc.cid) AS 选课数, AVG(sc.score) AS 平均成绩
FROM student s
LEFT JOIN score sc ON s.sid = sc.sid
GROUP BY s.sid, s.sname;

查询结果：

解析：
• 使用 LEFT JOIN 连接学生表和成绩表，确保没有选课的学生也能被查询到。
• 使用 COUNT 统计选课数，AVG 计算平均成绩。

查询 2：查询各科成绩最高分和最低分以及此学生学号、姓名
sql

SELECT c.cid, c.cname, MAX(sc.score) AS 最高分, MIN(sc.score) AS 最低分,
MAX(CASE WHEN sc.score = t.max_score THEN sc.sid END) AS 最高分学生学号,
MAX(CASE WHEN sc.score = t.min_score THEN sc.sid END) AS 最低分学生学号
FROM course c
JOIN score sc ON c.cid = sc.cid
JOIN (
SELECT cid, MAX(score) AS max_score, MIN(score) AS min_score
FROM score
GROUP BY cid
) t ON c.cid = t.cid
GROUP BY c.cid, c.cname;

查询结果：

解析：
• 使用子查询计算每门课程的最高分和最低分。
• 使用 CASE 语句找到对应最高分和最低分的学生学号。

SELECT s.sid, s.sname, AVG(sc.score) AS 平均成绩
FROM student s
JOIN score sc ON s.sid = sc.sid
GROUP BY s.sid, s.sname
HAVING AVG(sc.score) > 60;

查询结果：

解析：
• 使用 GROUP BY 和 HAVING 过滤出平均成绩大于60分的学生。

查询 4：查询每门课程被选修的学生数
sql

SELECT c.cid, c.cname, COUNT(DISTINCT sc.sid) AS 学生数
FROM course c
LEFT JOIN score sc ON c.cid = sc.cid
GROUP BY c.cid, c.cname;

查询结果：

解析：
• 使用 LEFT JOIN 确保没有学生选修的课程也能被查询到。

查询 5：查询没有学过叶平老师课程的学生学号以及姓名
sql

SELECT s.sid, s.sname
FROM student s
WHERE s.sid NOT IN (
SELECT sc.sid
FROM score sc
JOIN course c ON sc.cid = c.cid
JOIN teacher t ON c.tid = t.tid
WHERE t.tname = '叶平'

查询结果：

• 使用子查询找到学过叶平老师课程的学生，然后通过 NOT IN 排除这些学生。

查询 6：查询学过叶平老师所有课程的学生学号和姓名

SELECT s.sid, s.sname
FROM student s
WHERE NOT EXISTS (
SELECT c.cid
FROM course c
JOIN teacher t ON c.tid = t.tid
WHERE t.tname = '叶平'
AND c.cid NOT IN (
SELECT sc.cid
FROM score sc
WHERE sc.sid = s.sid
)
);

查询结果：

解析：
• 使用 NOT EXISTS 确保学生选修了叶平老师的所有课程。

查询 7：查询同时学过1，2号课程的学生学号和姓名
sql

SELECT s.sid, s.sname
FROM student s
WHERE EXISTS (
SELECT 1
FROM score sc
WHERE sc.sid = s.sid AND sc.cid = 1

SELECT 1
FROM score sc
WHERE sc.sid = s.sid AND sc.cid = 2

查询结果：

解析：
• 使用 EXISTS 确保学生同时选修了1和2号课程。

总结
• 查询 1：统计每个学生的选课数和平均成绩。
• 查询 2：找到每门课程的最高分和最低分及其对应的学生。
• 查询 3：筛选出平均成绩大于60分的学生。
• 查询 4：统计每门课程被选修的学生数。
• 查询 5：排除学过叶平老师课程的学生。
• 查询 6：筛选出学过叶平老师所有课程的学生。
```

```text
低SQL语句的执行顺序？
```

```text
2、where语句是对条件加以限定；
```

**解析**

```text
【核心考点】SQL 查询的逻辑执行顺序。
【题目解析】SQL 书写顺序与执行顺序不同。执行时先确定数据源，即 FROM 及连接；再用 WHERE 过滤行；随后 GROUP BY 分组、HAVING 过滤分组；然后执行聚合与 SELECT 投影；最后 ORDER BY 排序。因此不能按书写顺序理解执行过程。
【答题要点】
1. FROM 和连接先确定数据集。
2. WHERE 在分组前过滤，HAVING 在分组后过滤。
3. SELECT 在分组聚合之后计算，ORDER BY 最后排序。
【面试提示】补充 LIMIT 在排序后执行，能体现对执行链路的完整理解。
```
