## Q003932

- 题型：简答
- 难度：入门

**题目**

```text
CSS中常用的选择器有哪些？
```

**答案**

```text
常用的有：类选择器、标签选择器、ID选择器、分组选择器等
```

**解析**

```text
【核心考点】 CSS基础 选择器
【参考答案要点】
1. 类选择器（Class Selector）：以点号（.）开头，选择具有特定class属性的元素，如 .myClass。
2. 标签选择器（Type Selector）：直接使用HTML标签名，选择所有该标签的元素，如 div。
3. ID选择器（ID Selector）：以井号（#）开头，选择具有特定id属性的唯一元素，如 #myId。
4. 分组选择器（Grouping Selector）：用逗号分隔多个选择器，同时应用相同样式，如 h1, h2, p。
5. 其他常用选择器：包括后代选择器（空格）、子选择器（>）、相邻兄弟选择器（+）、属性选择器（[attr]）、伪类选择器（:hover）和伪元素选择器（::before）等。
【面试角度】
回答时建议列举至少4种基础选择器，并简要说明其优先级规则（ID > 类 > 标签），以展示对CSS层叠机制的理解。若结合实际项目中的选择器使用场景（如避免过度使用ID选择器以提升复用性），可提升答案深度。
【延伸知识】
CSS3引入了更多选择器，如:nth-child()和:not()，了解这些有助于应对高级面试问题。
```

```text
在Docker容器操作中，如果要进入容器，要使用哪个指令？
```


**答案**

```text

```

**正确选项**


**解析**

```text
【核心考点】 Docker容器操作 常用命令
【题目解析】
本题考查Docker容器操作中进入容器的命令。Docker提供了多个命令用于与容器交互，其中docker exec用于在运行中的容器内执行命令，包括进入容器的交互式shell。
```

```text
CSS中按照样式的位置，一般分为几种？
```

```text
行内样式：一般在标签类使用style属性定义；内部样式：一般定义在head部分；外部样式：一般在网页外部，以单独的.css文件存在。
```

**解析**

```text
【核心考点】 CSS样式分类
【参考答案要点】
CSS中按照样式的位置，一般分为三种：
1. 行内样式：直接在HTML标签的style属性中定义，如<p style="color:red;">。优先级最高，但不利于复用和维护。
2. 内部样式：在HTML文档的<head>部分使用<style>标签定义，作用于当前页面，适合单页面样式。
3. 外部样式：以单独的.css文件存在，通过<link>标签引入，可被多个页面共享，是推荐的最佳实践。
【面试角度】
回答时建议补充优先级规则：行内样式 > 内部样式 > 外部样式，且相同优先级下后定义的覆盖先定义的。同时可提及!important的例外情况，展示对CSS层叠机制的深入理解。
【延伸知识】
现代前端开发中，CSS Modules、Styled Components等方案进一步封装了样式，但理解基础分类仍是面试高频点。
```

## Q003975

- 题型：简答
- 难度：简单

**题目**

```text
在一个后端系统开发中，常见抛出的HTTP状态码401、403、404、500分别代表什么意义？一般需要处理吗？
```

**答案**

```text
401：未认证，拒绝访问；一般具备登录的后端，没有登录访问资源时，后端程序应主动返回401
403：未获得授权，拒绝访问；登录了，但没有访问资源的授权，后端程序应主动返回403
404：资源不存在；后端程序可以定制一个标准的404页面，并提供指引
500：服务器错误；尽量不要产生这种错误给到调用方
```

**解析**

```text
【核心考点】 HTTP状态码 后端异常处理
【题目解析】
本题考查后端开发中常见HTTP状态码的含义及处理必要性。状态码是客户端与服务器交互的标准化反馈，正确返回状态码有助于前端定位问题、提升用户体验。面试中常以此考察候选人对RESTful API设计的理解。
【参考答案要点】
401 Unauthorized：未认证，拒绝访问。通常用户未登录或Token过期时返回，后端应主动返回401，前端据此跳转登录页。
403 Forbidden：未获得授权，拒绝访问。用户已登录但无操作权限（如普通用户尝试删除管理员内容），后端应返回403，前端提示权限不足。
404 Not Found：资源不存在。请求的URL或资源ID无效，后端应定制标准404页面，提供导航或搜索建议。
500 Internal Server Error：服务器内部错误。代码异常或数据库故障导致，应尽量通过异常处理避免暴露给调用方，建议记录日志并返回友好提示。
【面试角度】
回答时需强调主动处理的必要性，例如“401和403必须明确返回，否则前端无法区分未登录和无权限”，体现对前后端协作的理解。
【易错提示】
常见混淆：401和403的区别（认证 vs 授权）；500应避免直接暴露堆栈信息，需统一异常处理。
```

## Q003963

- 题型：简答
- 难度：中等

**题目**

```text
vue之中的computed 和 watch 的区别和运用的场景
```

**答案**

```text
computed 是计算属性：计算属性依赖其它属性计算值，并且 computed 的值有缓存，职友集当计算值变化才会返回内容，他可以设置getter和setter。
watch是监听器： 监听到值的变化就会执行回调，在回调中可以进行一系列的操作。

计算属性一般用在模板渲染中，某个值是依赖其它响应对象甚至是计算属性而来；而侦听属性适用于观测某个值的变化去完成一段复杂的业务逻辑。
```

**解析**

```text
【核心考点】 Vue.js响应式原理 computed vs watch
【题目解析】
本题考查Vue.js中computed和watch的区别及应用场景。两者都用于处理响应式数据变化，但设计目的和使用方式不同。computed是计算属性，基于依赖缓存；watch是侦听器，用于执行异步或复杂逻辑。
【参考答案要点】
computed（计算属性）：
- 依赖其他属性计算值，具有缓存特性，只有依赖变化时才重新计算。
- 支持getter和setter，通常用于模板中展示派生数据。
watch（侦听器）：
- 监听指定数据变化，执行回调函数。
- 适用于异步操作、复杂业务逻辑或需要监听多个数据变化时。
应用场景：
- computed：如显示全名（firstName + lastName）、过滤列表等。
- watch：如搜索框输入防抖、路由变化处理、数据持久化等。
【面试角度】
回答时建议结合实际代码示例，如“在项目中，我使用computed计算购物车总价，用watch监听用户输入实现实时搜索”，能体现实战能力。
【易错提示】
不要混淆computed和methods，computed有缓存而methods每次调用都执行；watch的deep选项用于深度监听对象，但需注意性能开销。
```

## Q003986

- 题型：简答
- 难度：较难

**题目**

```text
简述Nginx如何实现负载均衡？
```

**答案**

```text
步骤：
1、部署应用：部署同一个应用的多个负载
2、配置Nginx：在Nginx的conf.d目录添加一个conf配置文件；在配置文件中，使用upstream块指向多个应用负载，并可配置策略；在server中，指定域名和端口，并通过指定location的http_proxy，指向upstream
3、配置DNS：将第2步配置的域名指向第2步中的机器IP地址即可
4、访问：通过域名访问，即是负载均衡的访问
```

**解析**

```text
【核心考点】 Nginx负载均衡 反向代理
【参考答案要点】
Nginx实现负载均衡的步骤如下：
1. 部署应用：部署同一个应用的多个实例（负载），确保各实例功能一致。
2. 配置Nginx：在Nginx的conf.d目录添加一个conf配置文件；在配置文件中，使用upstream块指向多个应用负载，并可配置策略（如轮询、权重、IP哈希等）；在server块中，指定域名和端口，并通过location的proxy_pass指令指向upstream。
3. 配置DNS：将第2步配置的域名指向Nginx服务器的IP地址。
4. 访问：通过域名访问，Nginx根据配置策略将请求分发到不同的应用实例，实现负载均衡。
【题目解析】
本题考查Nginx作为反向代理实现负载均衡的核心流程。负载均衡是分布式系统和高可用架构的关键技术，Nginx支持多种策略（如轮询、least_conn、ip_hash），面试中常深入追问策略选择和配置细节。注意：步骤2中的upstream配置是核心，需明确proxy_pass的用法。
【易错提示】
常见错误：混淆Nginx负载均衡与DNS轮询。Nginx是应用层负载均衡，可基于请求内容分发；DNS轮询是传输层简单分发，无法感知后端状态。面试中建议补充健康检查和会话保持等进阶话题。
```

## Q003998

- 题型：简答
- 难度：较难

**题目**

```text
项目中为何要用缓存？如何理解nginx + tomcat + redis 集群缓存？
```

**答案**

```text
1：最直接的表现就是减轻数据库的压力。避免因为数据读取频繁或过大而影响数据库性能，降低程序宕机的可能性

2：nginx常用做静态内容服务和代理服务器，直面外来请求转发给后面的应用服务。nginx本身也能做缓存，比如静态页面的缓存什么的。而tomcat是应用服务器，处理JAVA WEB程序功能等。
```

**解析**

```text
【核心考点】 缓存原理 Nginx+Tomcat+Redis集群
【题目解析】
本题考查缓存的作用及典型Web架构中各组件的分工协作。缓存的核心是减轻数据库压力，提升响应速度；Nginx作为反向代理和静态资源服务器，Tomcat处理动态请求，Redis提供分布式缓存。
【参考答案要点】
1. 缓存作用：减少数据库查询次数，降低I/O开销，提升系统吞吐量，避免因数据访问频繁导致数据库性能瓶颈或宕机。
2. Nginx+Tomcat+Redis集群理解：
- Nginx：作为反向代理，接收外部请求，分发到Tomcat集群，同时缓存静态页面，减轻应用服务器压力。
- Tomcat：处理Java Web动态请求，执行业务逻辑。
- Redis：作为分布式缓存，存储热点数据（如用户会话、商品详情），Tomcat从Redis读取数据，减少数据库访问。
【面试角度】
回答时建议结合实际项目中的缓存策略，例如“我们使用Redis缓存商品列表，设置过期时间，并采用缓存预热和穿透防护”，能体现深度。
【易错提示】
注意区分Nginx缓存和Redis缓存的用途：Nginx缓存静态内容，Redis缓存动态数据，两者互补而非替代。
```
