
**解析**

```text
【核心考点】 Java集合框架 数据结构基础
【题目解析】
本题考察Java中常见数据结构的掌握程度，属于基础知识类题目。需要列举出Java集合框架中常用的数据结构类型及其对应的实现类。
【参考答案要点】

【延伸知识】
Java 8+中HashMap在链表长度超过8时转为红黑树，优化了哈希冲突严重时的性能。另外，ConcurrentHashMap是线程安全的哈希表实现，面试中常与HashMap对比。
```


```text
对于==：
如果是用于基本数据类型的变量比较，则直接比较其存储的 “值”是否相等；

如果是用于引用类型的变量的比较，则比较的是所指向的对象的地址
对于equals:
equals方法不能作用于基本数据类型的变量
如果没有对equals方法进行重写，则比较的是引用类型的变量所指向的对象的地址
如String、Date等类对equals方法进行了重写的话，比较的是所指向的对象的内容
```

**解析**

```text
【核心考点】 Java基础 运算符
【参考答案要点】
== 运算符：
- 用于基本数据类型时，比较的是值是否相等。
- 用于引用类型时，比较的是内存地址是否相同。
equals 方法：
- 不能用于基本数据类型。
- 默认继承自Object类，比较的是引用地址。
- 许多类（如String、Integer、Date）重写了equals方法，用于比较对象内容是否相等。
【面试角度】
面试中常结合String常量池考察，例如“String a = new String("abc"); String b = "abc"; a==b 和 a.equals(b) 的结果分别是什么？”，需注意new创建的对象在堆中，常量池中的字符串在方法区。
【易错提示】
重写equals时，必须同时重写hashCode方法，否则在HashMap等集合中会导致逻辑错误。
```

## Q003699

- 题型：简答
- 难度：简单

**题目**

```text
ArrayList和LinkedList区别
```

**答案**

```text
1、ArrayList是实现了基于动态数组的数据结构，LinkedList基于链表的数据结构。
2、对于随机访问get和set，ArrayList优于LinkedList，因为LinkedList要移动指针。
3、对于新增和删除操作add和remove，LinkedList比较占优势，因为ArrayList要移动数据。
```

**解析**

```text
【核心考点】 Java集合框架 ArrayList LinkedList
【题目解析】
本题考察Java中两个常用List实现类的区别，是Java基础面试高频题。原答案正确，从底层数据结构、随机访问性能、增删操作性能三个维度进行了对比。
【参考答案要点】
1. 底层数据结构：ArrayList基于动态数组实现，LinkedList基于双向链表实现。
2. 随机访问性能：ArrayList支持通过索引快速随机访问（O(1)），LinkedList需要从头或尾遍历（O(n)），因此ArrayList在get和set操作上更优。
3. 增删操作性能：LinkedList在头部或中间插入/删除元素时，只需修改节点指针（O(1)），而ArrayList需要移动后续元素（O(n)），因此LinkedList在add和remove操作上更优。但尾部插入两者性能相近（ArrayList均摊O(1)）。
4. 内存占用：ArrayList只需存储数据元素，LinkedList需要额外存储前后节点指针，内存开销更大。
5. 适用场景：ArrayList适用于频繁随机读取、尾部插入的场景；LinkedList适用于频繁头部/中间插入删除、或需要实现队列/双端队列的场景。
【面试角度】
```

## Q003742

- 题型：简答
- 难度：简单

**题目**

```text
override和overload的区别
```

**答案**

```text
override（重写）：
1.方法名、参数、返回值不同。
2.子类方法不能缩小父类方法的访问权限。
3.子类方法不能抛出比父类方法更多的异常（但子类方法可以不抛异常）。
4.存在于父类和子类之间。
5.方法被定义为final时不能被重写。
overload（重载）：
1.参数类型、个数、顺序至少一种不相同。
2.不能重载只有返回值不同的方法名。
3.存在于父类和子类、同类中。
```

**解析**

```text
【核心考点】 Java面向对象 多态
【题目解析】
本题考查Java面向对象编程中两个核心概念：方法重写（Override）和方法重载（Overload）。两者都涉及方法的多态性，但应用场景和规则有显著区别。重写发生在父子类之间，用于实现运行时多态；重载发生在同一类中，用于实现编译时多态。
【参考答案要点】
Override（重写）：
1. 方法签名：方法名、参数列表、返回值类型必须相同（Java 5后允许协变返回类型）。
2. 访问权限：子类方法不能缩小父类方法的访问权限（如父类public，子类不能是protected）。
3. 异常声明：子类方法不能抛出比父类方法更宽泛的异常（但可以不抛或抛出子类异常）。
4. 适用范围：存在于父类和子类之间，是继承关系的体现。
5. 限制：被final、static、private修饰的方法不能被重写。
Overload（重载）：
1. 参数列表：参数类型、个数、顺序至少有一种不同。
2. 返回值：不能仅通过返回值不同来区分重载。
3. 适用范围：存在于同一类中，也可在父子类之间（但通常视为重载而非重写）。
【易错提示】
常见错误：混淆返回值在重载中的作用，认为返回值不同即可构成重载。实际上，编译器仅根据方法签名（方法名+参数列表）识别方法，返回值不参与。
【面试角度】
面试中常结合多态原理提问，例如“重写如何实现运行时多态？重载如何实现编译时多态？”建议结合JVM方法调用机制（虚方法表、静态分派）深入回答。
```

## Q003796

- 题型：简答
- 难度：简单

**题目**

```text
说一下面向对象的概念？
```

**答案**

```text
面向对象是一种程序设计的思想，它把现实世界中的事物（对象）看作是一个个独立的个体，并通过它们之间的交互来实现程序的功能。面向对象的程序设计主要基于以下几个概念：
• 类（Class）：是一种抽象的数据类型，用于描述一类具有相同特征和行为的对象。类定义了对象的属性和方法，并且可以创建实例化对象。

• 对象（Object）：是类的实例化对象，具有特定的属性和行为。

• 封装（Encapsulation）：是一种隐藏对象内部细节的机制，把对象的状态和行为封装在一个抽象的类中，对外只暴露必要的接口。

• 继承（Inheritance）：是一种定义新类的机制，通过从现有类继承属性和方法，创建一个新类，并且可以在新类中添加新的属性和方法。

• 多态（Polymorphism）：是一种在运行时选择合适的方法实现的机制，同一个方法可以被不同的对象调用，并且可以根据对象的类型选择不同的实现方式。

面向对象的程序设计使程序更易于维护、扩展和重用，也更符合人类的思维习惯，因此得到了广泛的应用。
```

**解析**

```text
【核心考点】 面向对象编程 OOP概念
【题目解析】
本题考查面向对象编程（OOP）的基本概念，是软件开发的基础知识。面向对象是一种程序设计范式，它将数据和行为封装在对象中，通过类和对象、继承、多态等机制实现代码的复用和扩展。回答时应涵盖核心概念：类、对象、封装、继承、多态。
【参考答案要点】
1. 类（Class）：类是对象的模板，定义了对象的属性（数据）和方法（行为）。例如，“学生”类可以有姓名、年龄等属性和学习、考试等方法。
2. 对象（Object）：对象是类的实例，具有具体的属性值。例如，“张三”是“学生”类的一个对象，年龄为20岁。
3. 封装（Encapsulation）：将数据和操作数据的方法绑定在一起，并对外隐藏内部实现细节，只暴露公共接口。这提高了代码的安全性和可维护性。
4. 继承（Inheritance）：允许一个类（子类）继承另一个类（父类）的属性和方法，并可以扩展或重写。例如，“大学生”类可以继承“学生”类，并添加“专业”属性。
5. 多态（Polymorphism）：同一个方法在不同对象上可以有不同的行为。例如，不同形状的对象（圆形、矩形）都有“计算面积”方法，但实现不同。
【面试角度】
面试中，除了定义，建议结合实际编程语言举例说明，例如“在Java中，使用class关键字定义类，通过new创建对象，使用private实现封装，extends实现继承，方法重写实现多态”。同时，可以提及面向对象与面向过程的区别，展示对编程范式的理解。
【易错提示】
注意区分“类”和“对象”的概念，类是对对象的抽象，对象是类的具体实例。另外，封装不是简单的信息隐藏，还包括对内部状态的保护和控制。
```

## Q003704

- 题型：简答
- 难度：中等

**题目**

```text
JAVA的线程安全—Synchronized
```

**答案**

```text
synchronized是Java中的关键字，是一种同步锁。它修饰的对象有以下几种：
1. 修饰一个代码块，被修饰的代码块称为同步语句块，其作用的范围是大括号{}括起来的代码，作用的对象是调用这个代码块的对象；
2. 修饰一个方法，被修饰的方法称为同步方法，其作用的范围是整个方法，作用的对象是调用这个方法的对象；
3. 修改一个静态的方法，其作用的范围是整个静态方法，作用的对象是这个类的所有对象；
4. 修改一个类，其作用的范围是synchronized后面括号括起来的部分，作用主的对象是这个类的所有对象。
```

**解析**

```text
【核心考点】 Java线程安全 synchronized关键字
【题目解析】
本题考查Java中synchronized关键字的用法，属于多线程编程的核心知识点。synchronized用于实现线程同步，确保同一时刻只有一个线程执行被修饰的代码块或方法，从而避免数据竞争。
【参考答案要点】
1. 修饰代码块：作用于大括号{}内的代码，锁对象是调用该代码块的对象实例，需指定锁对象如synchronized(this)。
2. 修饰实例方法：作用于整个方法，锁对象是调用该方法的对象实例，相当于synchronized(this)包裹整个方法体。
3. 修饰静态方法：作用于整个静态方法，锁对象是类的Class对象，对所有实例共享，相当于全局锁。
4. 修饰类：作用于synchronized(类名.class)括号内的代码块，锁对象是类的Class对象，与静态方法锁相同。
【面试角度】
面试常问synchronized与Lock的区别，以及锁升级机制（偏向锁→轻量级锁→重量级锁），建议深入理解底层实现。
【易错提示】
注意修饰静态方法和修饰类时，锁对象是Class对象，而非实例对象，因此对所有实例生效，容易与实例锁混淆。
```

```text
虚拟机栈：线程私有，主要存放基本数据类型（int、char、float...）和对象的引用
本地方法栈：线程私有，为虚拟机使用到的 Native 方法服务，如 Java 使用 c 或者 c++
编写的接口服务时，代码在此区运行
堆：线程共享，主要存放对象的实例和数组
```

## Q003739

- 题型：简答
- 难度：中等

**题目**

```text
java中sleep()和wait()的区别？抽象类和接口的主要区别是？
```

**答案**

```text
java中sleep()和wait()的区别：

1.所属类不同
wait() 是Object中的实例方法
sleep()是Thread的静态方法。
2.唤醒机制不同。
wait() 没有设置最大时间情况下，必须等待对象调用notify() 或notifyAll()方法。
sleep是到指定时间自动唤醒。
3.锁机制不同。
wait()释放锁，调用对象的wait()方法导致当前线程放弃对象的锁（线程暂停执行），进入对象的等待池（wait pool），只有调用对象的notify()方法（或notifyAll()方法）时才能唤醒等待池中的线程进入等锁池（lock pool），如果线程重新获得对象的锁就可以进
sleep()只是让线程休眠，让出cpu资源，不会释放锁,当休眠时间结束后，线程会恢复到就绪状态，但是不会立刻执行，可能会有其他优先级高的线程抢占资源。
4.使用位置不同。
wait()必须持有对象锁，写在同步方法或者synchronized()语句块中。
sleep()可以使用在任意地方。
5.sleep()必须捕获异常
wait()，notify()和notifyAll()不需要捕获异常。

抽象类和接口的主要区别是：

1、抽象类和接口都不能直接实例化。如果要实例化，抽象类变量必须指向实现所有抽象方法的子类对象，接口变量必须指向实现所有接口方法的类对象。
2、抽象类要被子类继承，接口要被类实现。
3、接口只能做方法申明，抽象类中可以做方法申明，也可以做方法实现。
4、接口里定义的变量只能是公共的静态的常量，抽象类中的变量是普通变量。
5、抽象类里的抽象方法必须全部被子类所实现，如果子类不能全部实现父类抽象方法，那么该子类只能是抽象类。同样，实现接口的时候，如不能全部实现接口方法，那么该类也只能为抽象类。
6、抽象方法只能申明，不能实现。
7、抽象类里可以没有抽象方法
8、如果—个类里有抽象方法，那么这个类只能是抽象类
9、抽象方法要被实现，所以不能是静态的，也不能是私有的。
10、接口可以继承接口，并且可多继承接口，但类只能单—继承。
11.接口可以通过匿名内部类实例化。接口是对动作的抽象，抽象类是对根源的抽象。抽象类表示的是，这个对象是什么。而接口表示的是，这个对象能做什么。
```

**解析**

```text
【核心考点】 Java多线程 线程同步
【题目解析】
本题考查sleep()和wait()的区别，以及抽象类和接口的区别，是Java基础高频面试题。sleep()和wait()都用于暂停线程，但所属类、唤醒机制、锁行为不同。抽象类和接口在设计层面有本质区别。
【参考答案要点】
sleep()与wait()区别：
1. 所属类不同：sleep()是Thread的静态方法，wait()是Object的实例方法。
2. 唤醒机制：sleep()到时间自动唤醒；wait()需notify()/notifyAll()唤醒，或设置超时时间。
3. 锁机制：sleep()不释放锁；wait()释放锁，进入等待池，被唤醒后重新竞争锁。
抽象类与接口区别：
1. 设计层面：抽象类表示“is-a”关系，接口表示“can-do”能力。
2. 方法实现：抽象类可以有抽象方法和具体方法；接口在Java 8后可以有default和static方法。
3. 构造方法：抽象类可以有构造方法；接口不能有。
4. 多继承：类只能单继承抽象类，但可以实现多个接口。
【易错提示】
注意wait()必须在同步块中使用，否则会抛出IllegalMonitorStateException。抽象类中可以有成员变量，接口中变量默认是public static final。
```

```text
抽象类和接口的区别
```

```text
* 抽象类中可以定义成员变量，而接口中定义的成员变量实际上都是常量。
```

```text
3. 构造器：抽象类可以有构造器；接口不能有构造器。

```

```text
其主要的工作原理如下
1、对要存储的数据使用key-value的形式，对key做hash计算后，按数组存储，查询效率高
2、如果hash计算后，有相同的key，该hash值相同 的使用链表
3、如果链表长度超过8，使用红黑树
```

```text

【题目解析】

1. 存储结构：HashMap内部维护一个Node数组（桶），每个Node可以是链表或红黑树节点。
2. 哈希计算：对key的hashCode进行二次哈希（扰动函数），然后与数组长度-1做与运算，得到存储位置。
```

```text
c、一个类可以实现多个接口；
```

```text
【核心考点】 Java面向对象 抽象类 接口
【题目解析】
本题考查Java中抽象类和接口的区别，是Java面试中的经典问题。两者都是实现抽象层的机制，但在设计理念、语法特性、使用场景上有显著差异。回答时应从定义、特点、区别等角度全面阐述。
```

```text
重写：出现在类型继承的场景中，子类具有与父类相同签名（相同方法名、相同参数个数与类型、相同返回值）的方法，子类这个方法就叫重写父类方法，用于实现面向对象的多态
```

## Q003705

- 题型：简答
- 难度：较难

**题目**

```text
JAVA的线程安全———synchronized
```

**答案**

```text
synchronized 关键字，代表这个方法加锁,相当于不管哪一个线程（例如线程A），运行到这个方法时,都要检查有没有其它线程B（或者C、 D等）正在用这个方法(或者该类的其他同步方法)，有的话要等正在使用synchronized方法的线程B（或者C 、D）运行完这个方法后再运行此线程A,没有的话,锁定调用者,然后直接运行。它包括两种用法：synchronized 方法和 synchronized 块。

Java语言的关键字，可用来给对象和方法或者代码块加锁，当它锁定一个方法或者一个代码块的时候，同一时刻最多只有一个线程执行这段代码。当两个并发线程访问同一个对象object中的这个加锁同步代码块时，一个时间内只能有一个线程得到执行。另一个线程必须等待当前线程执行完这个代码块以后才能执行该代码块。然而，当一个线程访问object的一个加锁代码块时，另一个线程仍可以访问该object中的非加锁代码块。
```

**解析**

```text
【核心考点】 Java线程安全 synchronized 并发编程
【题目解析】
本题考查Java中synchronized关键字的原理和用法。synchronized是Java内置的同步机制，用于解决多线程并发访问共享资源时的线程安全问题。回答需涵盖作用、用法、原理三个层面。
【参考答案要点】
1. 作用：synchronized保证同一时刻只有一个线程执行被修饰的代码块或方法，实现线程互斥，防止数据竞争。
2. 用法：
- 修饰方法：在方法声明前加synchronized，锁是当前实例对象（静态方法锁是类对象）。
- 修饰代码块：指定锁对象，如synchronized(this)或synchronized(obj)，粒度更细，性能更好。
3. 原理：基于Java对象头中的Monitor（监视器锁），每个对象关联一个Monitor，线程进入synchronized时尝试获取Monitor，成功则执行，失败则阻塞等待。
4. 注意事项：synchronized是重量级锁，但Java 6后引入偏向锁、轻量级锁优化，性能提升。另外，synchronized可重入，即同一线程可多次获取同一把锁。
【面试角度】
面试官可能追问synchronized与Lock的区别，或volatile与synchronized的区别。建议深入理解底层原理（如Monitor、锁升级过程），并结合实际场景说明使用时机。
【易错提示】
常见错误：认为synchronized只修饰方法，忽略代码块用法；混淆synchronized与volatile（volatile仅保证可见性，不保证原子性）。
```

## Q003768

- 题型：简答
- 难度：较难

**题目**

```text
接口和抽象类的区别
```

**答案**

```text
抽象类
其中包含抽象方法的类，但是也可以包含成员变量和成员方法
1. 抽象方法必须为 public 或者 protected（因为如果为 private，则不能被子类继承，子类便无法实现该方法），缺省情况下默认为 public
2. 抽象类不能用来创建对象
3. 如果一个类继承于一个抽象类，则子类必须实现父类的抽象方法。如果子类没有实
现父类的抽象方法，则必须将子类也定义为 abstract 类

接口
接口中可以包含变量和方法，但是变量会隐式的指定为 public static final，
方法会被隐式的指定为 public abstract，并且接口中的方法不能任何具体实现。
也就是说接口中都是抽象方法。接口是一种极端抽象的类型。
语法层面的区别：
1. 抽象类中可以包含具体的实现方法，而接口中只能有 public abstract 方法
2. 抽象类中的成员变量可以是各种类型的，而接口中只能有 public static final类型
3. 抽象类中可以包含静态代码块和静态方法，而接口中不可以
4. 一个类只能继承一个抽象类，但是可以实现多个接口
设计层面的区别：
1. 抽象层次不同，抽象类对整个类整体进行抽象，包括属性、行为；而接口只是对类
的局部行为进行抽象。比如，门和警报的例子：门都有 open 和 close 的动作，可以定义一
个抽象类 Door，包含 open 和 close 方法。这样所有的门都可以继承这个抽象类，从而包
含了这两个方法。另外报警功能alarm是一种延伸的功能，但是不可以加到抽象类Door中，
因为并不是每个门都有报警的功能。所以需要定义一个接口，接口中包含 alarm 方法，这
样需要有报警功能的门来实现这个接口，没有则不需要。
2. 跨域不同，抽象类和子类之间体现的是一种继承关系，父类和子类在概念本质上相
同的。接口则不然，接口和其实现者不需要有任何关联，接口的实现者仅仅是实现了接口的
规定的规范。
3. 设计层次不同，抽象类是自下而上的设计，先有多个子类，然后抽取共同特性，形
成了抽象类。而接口则不同，接口的设计的时候根本不知道会有什么实现者以什么形式来实
现。接口只是一种实现定义好的规范。
```

**解析**

```text
【核心考点】 Java面向对象 抽象类 接口
【题目解析】
本题考查Java中抽象类和接口的区别，是面试高频题。两者都是实现抽象的方式，但设计理念和语法规则有显著差异。抽象类用于描述“是什么”的关系，接口用于描述“能做什么”的能力。
【参考答案要点】
1. 定义：抽象类用abstract class定义，接口用interface定义。
2. 方法：抽象类可以有抽象方法和具体方法；接口中方法默认public abstract，Java 8后支持default和static方法。
3. 变量：抽象类可以有任意类型变量；接口中变量默认public static final。
4. 继承：类只能单继承抽象类，但可以实现多个接口。
5. 构造器：抽象类有构造器，接口没有。
6. 设计目的：抽象类用于代码复用，接口用于定义契约。
【面试角度】
回答时建议结合设计模式举例，如“模板方法模式常用抽象类，策略模式常用接口”，能显著提升答案深度。
【易错提示】
Java 8后接口可以包含default方法，这缩小了抽象类和接口的差异，但核心区别（单继承vs多实现）依然存在。
```

- 难度：较难

**题目**

```text
数据结构-双向链表 代码实现
```

**答案**

```text
public class MyDoubleLink {
public int linkSize = 0;
public Node head = null;// 头结点
public Node tail = null;// 尾结点
// 使用内部类定义节点
public class Node {
public Object data;
public Node prev = null;
public Node next = null;
public Node(Object data) {
this.data = data;
}
}
/**
* 添加节点至尾部
* @param data
*/
public void addLast(Object data) {
linkSize++;
Node newNode = new Node(data);
if (head == null) {
// 第一个元素
head = newNode;
return;
}
if (tail == null) {
// 第二个元素
tail = newNode;
tail.prev = head;
head.next = tail;
return;
}
// 将新节点的指针和 tail 节点建立关系
tail.next = newNode;
newNode.prev = tail;
tail = newNode;
}
/**
* 删除指定位置的节点
* 遍历到指定节点，将指定位置的上一个节点与下一个节点指针建立关系
* @param index
* @return
*/
public boolean delete(int index) {
if (index < 0 || index >= linkSize) {
return false;
}
linkSize--;
// 删除的是头结点
if (index == 0) {
// 只有一个头结点
if (head.next == null) {
head = null;
return true;
}
head = head.next;// 删除头结点
head.prev = null;
return true;
}

// 删除的是尾节点
if (index == (linkSize - 1)) {
tail = tail.prev;
tail.next = null;
return true;
}
Node tmpNode = head;
// 遍历链表，获取被删除的节点
for (int i = 0; i < index; i++) {
tmpNode = tmpNode.next;
}
// tmpNode 是被删除节点，将其上下两个节点之间建立关系
tmpNode.prev.next = tmpNode.next;
tmpNode.next.prev = tmpNode.prev;
return true;
}
/**
* 获取指定位置的节点
* @param index
* @return
*/
public Node get(int index) {
if (index < 0 || index >= linkSize) {
throw new RuntimeException("指针越界");
}
Node tmpNode = head;
// 遍历节点，获取指定位置的节点
for (int i = 0; i < index; i++) {
tmpNode = tmpNode.next;
}
return tmpNode;
}
/**
* 打印链表上所有节点的数据
*/
public void print() {
Node tmpNode = head;
for (int i = 0; i < linkSize; i++) {
System.out.println(tmpNode.data);
tmpNode = tmpNode.next;
}
} }
```

```text

1. 节点定义：使用内部类Node，包含data、prev（前驱指针）和next（后继指针）。
2. 链表结构：维护head（头结点）和tail（尾结点）引用，以及linkSize记录节点数。
3. 添加操作：实现添加节点至尾部的方法，需更新尾结点的next和新节点的prev。
```

```text
　　 int temp;//临时存储用于交换数字用

for(int i = 0;i<iArray.length-1;i++){
//比较两个数据大小，如果前面的大则交换
if(iArray[i]>iArray[i+1]){
//交换逻辑 start

iArray[i] = iArray[i+1];
```

```text
【核心考点】 排序算法 冒泡排序 Java实现
【题目解析】

public static void main(String[] args) {
int[] a = {9,8,7,2,3,6,5,1,4};
int temp;
for (int i = 0; i < a.length - 1; i++) {
for (int j = 0; j < a.length - 1 - i; j++) {
if (a[j] > a[j+1]) {
temp = a[j];
a[j] = a[j+1];
a[j+1] = temp;
}
}
}

System.out.print(num + " ");
}
}
}
```

```text
1、一般情况下，利用JAVA的内类机制，在抽象类的测试驱动程序内引入内类，让内类实现对被测试抽象类的继承，然后把它作为引用体，这样对内类的测试就等价于对被测试抽象类的测试；
2、如果抽象类被具体类继承，那么，在创建该具体类的测试驱动程序时要继承抽象类的测试驱动程序，在以后的回归测试中，只要执行最底层的测试类，就可以对其父测试类重新执行一次测试，同时将测试结果分别返回。
```

```text
【核心考点】 抽象类测试 单元测试 Java
【题目解析】
本题考查面向对象编程中抽象类的测试策略。抽象类不能直接实例化，因此测试时需要特殊处理，通常通过继承或匿名内部类来实现。
【参考答案要点】
原则一：使用内部类继承抽象类
在测试驱动类中定义内部类，继承被测试的抽象类，并实现其抽象方法。然后对内部类的实例进行测试，从而间接测试抽象类的具体方法。

如果抽象类已被具体子类继承，则在创建具体子类的测试驱动时，继承抽象类的测试驱动。这样在回归测试中，执行底层测试类即可同时测试父类，并将结果分别返回。

【延伸知识】
现代测试中，也可以使用Mock框架直接创建抽象类的mock对象，通过设置预期行为来测试依赖抽象类的其他类，但上述原则更适用于纯单元测试场景。
```

## Q003792

- 题型：简答
- 难度：较难

**题目**

```text
能不能自己写个类，也叫java.lang.String？
```

**答案**

```text
可以，但是java中的双亲委派机制，类加载器会找到最jdk提供的String，在不使用自定义类加载器的情况下自己写的String类没有用
```

**解析**

```text
【核心考点】 类加载机制 双亲委派模型
【题目解析】
本题考察Java类加载机制中的双亲委派模型。Java虚拟机通过双亲委派机制加载类，即当一个类加载器收到类加载请求时，会先委托给父类加载器，只有父类加载器无法加载时，才由自己加载。对于java.lang.String这类核心类库，由启动类加载器（Bootstrap ClassLoader）加载，用户自定义的java.lang.String类不会被加载，因为父加载器已经加载了JDK自带的String类，从而保证了核心类库的安全性和唯一性。
【参考答案要点】
不能。虽然语法上允许编写java.lang.String类，但由于双亲委派机制，类加载器会优先委托父加载器加载JDK自带的String类，导致自定义的String类无法被加载。除非使用自定义类加载器并打破双亲委派模型，但通常不推荐这样做，因为会破坏Java的安全机制。
【面试角度】
回答时，除了说明双亲委派机制，可以补充说明打破双亲委派模型的场景（如Tomcat的类加载器），展示对类加载机制的深入理解。同时，强调安全性和核心类库保护的重要性，能体现对Java底层原理的掌握。
【易错提示】
不要误以为可以随意覆盖JDK核心类，双亲委派机制是强制性的安全策略。另外，注意区分类加载器和类文件的概念，自定义类文件存在但不会被加载。
```

## Q003812

- 题型：简答
- 难度：较难

**题目**

```text
避免死锁的方法有哪些?
```

**答案**

```text
主要方法有：
1、尽量不要在一个线程中锁定两个或以上的临界资源（共享资源）
2、多个线程对多个临界资源（共享资源）锁的顺序保持一致
3、一次性获取所需的多个锁，如果没有全部获取，则全不获取，等待
4、对锁设定超时机制，超时释放
```

**解析**

```text
【核心考点】 并发编程 死锁
【题目解析】
本题考查死锁的预防和避免策略，属于操作系统和并发编程中的高级概念。死锁发生的四个必要条件：互斥、持有并等待、不可剥夺、循环等待。
【参考答案要点】
1. 破坏互斥条件：尽量使用无锁编程或读写锁。
2. 破坏持有并等待：一次性获取所有锁，否则释放已持有的锁。
3. 破坏不可剥夺：设置锁超时机制，超时后释放。
4. 破坏循环等待：对锁进行排序，所有线程按相同顺序获取锁。
【面试角度】
回答时建议结合实际编程语言示例，如Java中的synchronized和Lock接口，展示对并发工具的理解。
【易错提示】
避免只罗列概念，应解释每个方法如何破坏死锁条件。同时，注意区分预防和避免，预防是静态设计，避免是动态检测。
```
